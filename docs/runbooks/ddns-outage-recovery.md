# 家庭地址变化后的 WAO 恢复

2026-09-22 修复记录：Linux1 独立 cron DDNS 脚本先查询 IPv4，失败就退出，跳过 AAAA。桌面 VPN 的假 IP DNS和虚拟网卡路由又干扰出口探测。公网前缀变化后，两机 WireGuard、数据库 SSH 通道和备份连接持续使用旧地址。

## 持续更新

`deploy/network/linux1-ddns.py` 是 Linux1 既有独立更新器的受控源码。安装到 `~/.local/libexec/linux1-ddns.py`，复用原有每五分钟 cron 和 `~/.config/linux1-ddns/credentials`，不启用第二个 DDNS 更新器。`ddns-go` 空配置容器不是实际更新来源。

- AAAA 与 A 各自发现和更新，任一失败保留该类型现有记录，不阻塞另一类型。
- AAAA 只取 `WAO_DDNS_INTERFACE` 指定物理网卡的有效、非临时公网地址，默认 `enp3s0`；排除虚拟网卡、失效、临时和私有地址。
- IPv4 查询先走验证证书的公共 DNS，再绑定物理网卡访问两个 HTTPS 地址服务；两次结果相同才更新 A，避免写入代理出口。
- 网络调用有超时；失败不打印凭据或签名请求地址。使用既有 DNS 权限，不新增公网管理端口。

## 私网、数据库与备份

两节点端点刷新脚本优先查询 HTTPS 公共 DNS，避免家庭路由器仍缓存旧公网地址；公共查询失败时只接受本地解析中的全局 IPv6。不能把解析成功当成连接成功，还需观察握手时间。

Linux2 `/usr/local/lib/wao-network/` 同时安装 `refresh-mesh-endpoint.py` 与 `start-mysql-primary-tunnel.sh`。隧道和备份通过新地址连接，`HostKeyAlias` 保持原域名，继续严格校验既有主机密钥。备份脚本需要同一路径的解析器；加密恢复配置包也包含该依赖。

修复期间保持 Linux1 MySQL 写主，不提升另一台。返回复制 IO 线程若已达到十次重试上限，确认通道和源身份正常后显式重新启动原通道的 IO 线程；不得跳过事务或重置复制历史。返回通道现在明确配置每30秒重试、最多86400次，避免十分钟DNS/网络中断后永久停在离线状态；长重试不掩盖原有十分钟归档过期告警。

恢复顺序：确认权威 A/AAAA → 私网握手/SSH严格身份验证 → 原复制通道追平 → 运行归档并检查异机 COMPLETE/新鲜度 → 两应用健康 → 真实用户读写。

## 告警去重

同一次故障保留所有已成功通知过的入口集合。部分恢复、再次失败不重复刷屏；新入口持续失败可以通知一次，持续故障四小时提醒。三入口连续两轮成功才结束该故障并发送恢复通知。通知发送失败仍重试，不伪记成功。

## 验证范围

专项测试覆盖 IPv4/IPv6 各自失败、物理地址选择、IPv4 双源不一致、陈旧路由器 DNS、假 IP 拒绝、主入口波动去重和发送失败重试。生产恢复证据另存执行记录；这不代表已模拟真实断电或保证所有网络零中断。
