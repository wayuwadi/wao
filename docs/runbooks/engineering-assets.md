# WAO 工程资产入口

这里集中列出可重复使用的本地工程工具。按本次改动选择相称检查，详细参数和边界以各工具手册为准；这些工具不新增 PR / Jenkins 门禁，也不改变一个需求或 BUG 一个 PR 的交付流程。

## 按当前问题选择

| 当前问题 | 使用资产 | 直接产出 | 通过后还需要什么 |
| --- | --- | --- | --- |
| 待办/项目/日历收尾、执行安排与正文查找 | [核心体验回归](core-experience-regression.md)、[四页交互 Demo](../demos/core-experience-2026-10-03.md) | 分项测试、真实链路使用说明与桌面/手机视觉比较 | Demo 不能代替真实数据验收；整体视觉须另行确认 |
| 项目计数、截止日期与项目内查找 | [项目能力回归](projects-regression.md) | 共享收尾判定、日期空值与失败保留、关键词/筛选/历史查找回归和使用说明 | 专用持久化项目的真实操作、刷新及窄屏确认 |
| 新工作区启动失败、工具或端口不对 | [本地开发体检](local-development-doctor.md) | 分项诊断、下一步建议、可选 JSON | 启动真实应用并验收用户链路；TCP 通不等于 SQL 或账号正常 |
| 改了首页聚合、统计或文档读取，不知道性能是否变化 | [只读性能基准](read-only-performance-baseline.md) | 带版本和采样条件的报告、两轮指标对照 | 核对输出语义与采样条件；本地耗时不等于线上 P95 或优化收益 |
| 准备提交，担心并行开发造成编号撞车或文档坏链接 | [工程一致性检查](engineering-consistency-check.md) | 基线 SHA、错误、历史警告 | 复核暂存区、运行相称测试和真实链路验收 |
| 改了文档编辑、保存、草稿恢复或协同冲突 | [草稿防丢回归](document-draft-regression.md) | 11 项真实场景、私有截图和可恢复报告 | 本轮文档软删除后刷新确认；失败步骤必须保留真实状态 |
| 改了小记保存、收起恢复或多窗口更新 | [小记真实回归](notes-regression.md) | 7 类真实场景、独立源持久化核实、私有报告 | 精确软删除、双源刷新与窄屏截图；真实 AI 和同源多页签另验 |
| 检查小记正文 AI 超时、失联、重复执行和迟到结果 | [AI 执行恢复回归](notes-ai-recovery-regression.md) | 服务端 SQL/状态及上游传输故障测试、带版本报告 | 隔离结果不代表真实模型、MySQL 或部署验收；恢复环境后补验 |
| 没有服务端 AI 账号，需要用本机已登录 Codex 验收小记 | [本机 Codex 真实验收](notes-local-codex-acceptance.md) | 真实 CLI 输出、精确运行记录与浏览器操作证据 | 只处理专用合成小记；不代表生产 API、标题或配图验收 |

## 开发前与提交前

以下命令均从仓库根目录执行。使用自己已经配置、被 Git 忽略的私有环境文件，地址改为实际本地端口：

```bash
python3 deploy/scripts/dev-doctor.py --env-file .env.local-cloud --web-url http://127.0.0.1:5174
```

运行时不在 PATH 时，在体检命令提供 `--java-home`、`--maven-bin`、`--node-bin` 指向已有安装；体检不会安装工具、启动隧道或修改环境。

提交前刷新基线，并在当前分支已包含该基线后检查：

```bash
git fetch origin main
python3 deploy/scripts/check-engineering-consistency.py --base origin/main
```

检查失败先修复对应问题。历史 ADR 警告保留说明，不能通过自动重编号掩盖；已交付 migration 不修改，数据变更新增版本。

## 性能与草稿变更

性能变更前后分别采样，再比较报告：

```bash
python3 deploy/scripts/performance-baseline.py --env-file .env.local-cloud
python3 deploy/scripts/compare-performance.py /实际路径/before.json /实际路径/after.json
```

默认只读采样五个首页场景。文档读取的两个场景需要额外指定本人创建的专用验收文档 ID；不得随机挑选业务文档。保留 Git SHA、工作区状态、采样数量与数据概况，在相同条件下复测后再解释变化。

文档草稿变更先运行相应隔离测试，再按回归手册启动两个独立本地源，通过正常登录会话使用专用验收知识库。全部 11 项场景及两篇本轮文档的清理确认完成后，才能生成通过报告。工具通过实际控件进行编辑、通过刷新核实持久化，不以提示文字或接口成功单独替代结果。

清理命令默认只读预检，增加 `--apply` 才调用现有可恢复软删除。只允许处理报告登记并经身份、知识库、标题与时间核对的近期文档；没有取得精确 ID 的失败请求不自动猜测清理。

## 证据保存与接续

| 证据 | 默认位置 | 接续方式 |
| --- | --- | --- |
| 开发体检 | 标准输出，可加 `--json` | 记录失败项及执行参数，不附私有环境文件 |
| 性能报告 | `wao-server/target/performance/`，Git 忽略 | 对照原始样本，保留测量版本和条件 |
| 一致性检查 | 标准输出，可加 `--json` | 附基线 SHA、错误及历史警告，不只写“通过” |
| 草稿验收 | 仓库外系统临时目录 `wao-draft-regression/<runId>/` | 用 `DocumentDraftRegression.resume()` 恢复报告，不重复创建文档或将缺失步骤标成通过 |

临时目录可能被系统清理；需要长期留存时，复制到受控的本机私有目录。截图可能包含页面信息，不加入 Git 或公开分享。仓库内只沉淀不含凭据、正文和精确业务标识的验收结论。

上述数字是对应提交和日期的证据快照，不代表后续任意版本的测试结果。合并完成本地交付；是否已上线与线上验收结果由发布流程和用户确认。
