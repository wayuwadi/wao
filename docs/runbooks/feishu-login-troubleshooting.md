# 飞书登录配置排查

二维码和授权入口都先调用 `/api/auth/feishu/authorize`。如果返回 HTTP 502、业务码 `50201` 和「飞书登录尚未配置，请联系管理员」，故障发生在 WAO 应用配置检查，不是二维码 SDK 下载或飞书接口故障。前端立即展示业务原因；没有 WAO 业务响应的网关 502/503/504 仍保留纯读请求的退避重试。

## 核对当前运行服务

先确认公共入口实际路由到哪个后端进程，再检查该进程的配置来源。仅更新仓库中的示例或另一个节点的配置不会影响正在运行的服务。登录需要 `FEISHU_LOGIN_ENABLED=true`、非空的 `FEISHU_APP_ID`、`FEISHU_APP_SECRET`，以及正确的 `FEISHU_REDIRECT_URI`、`FEISHU_FRONTEND_URL`。

2026-10-04 的故障发生在本机临时公共服务：启动器加载 `.env.windows-local`，其中明确关闭飞书登录，且没有登录应用凭据。用户选择复用「飞书任务收集」配置的同一自建应用。先使用当前密钥解密现有应用凭据，并通过飞书应用凭证接口确认有效，再在该服务的私有追加配置 `deploy/data/windows-local/public-server.yml` 中显式设置 `feishu.login`。后续重启和制品切换必须继续加载这份追加配置，不能用默认禁用值覆盖它。

凭据只保存在被 Git 忽略且限制文件访问权限的运行目录；不得将其复制到规格、脚本参数、提交或日志。复用其他应用必须先确认应用选择，不能自动将任务收集凭据用作任意登录应用。配置修复只重启经过 PID、启动时间和制品身份核对的后端；若已有发布或本机 AI 任务运行，应等待其结束。保留原配置备份以便恢复，不重建数据库、不执行 migration。

Spring 的环境变量优先于追加 YAML：本机公共启动器在启动 `server` 时移除开发环境的 `FEISHU_LOGIN_ENABLED` 覆盖，让公共服务的私有 `feishu.login.enabled` 决定开关。只追加 YAML 而保留同名的禁用环境变量仍会失败；其他开发启动器继续使用默认禁用配置。

## 验证边界

- 二维码与普通授权接口均成功生成地址；二维码使用 `passport.feishu.cn`，普通授权使用 `open.feishu.cn`，回调指向既有公共入口，包含有效 `state`。
- 浏览器实际显示飞书官方二维码；重试、关闭重开与授权入口可用。未配置和网络失败时展示准确原因，邮箱入口仍可访问。
- 真实扫码确认和回调创建 WAO 会话仍需持有飞书账号的用户完成；二维码显示或应用凭据有效不等于完整登录验收。

本次没有新增业务服务、HTTP API 或 MCP 工具，CLI 的令牌登录能力不变；浏览器中的飞书交互不新增 CLI 命令。
