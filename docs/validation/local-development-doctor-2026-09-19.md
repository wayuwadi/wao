# 本地开发体检工具验收

## 实机链路

1. 在当前未配置工具路径的 shell 执行离线体检，正确报告 Java 未正常返回版本、Maven/Node 缺失、独立工作区前端依赖缺失及数据库变量缺失；退出 1，网络项跳过。
2. 明确提供已有 Node、Maven、私有连接文件与本地前端 / 业务服务地址。第一次指定不兼容当前 CPU 的 JDK，Java/Maven 两项失败，其余 7 项通过；未误报环境完全可用。
3. 换用已有的兼容 Java 17 后，首次 Maven 启动超过默认 4 秒，体检明确报告超时；设置 `--timeout 15` 后，Java 17.0.20、Node 24.19.0、Maven 3.9.9、前端依赖、数据库连接参数和 TCP 连接、本地业务健康与 WAO 身份、前端页面入口共 9 项全部通过，退出 0。

工具没有执行 SQL、数据库迁移、服务重启、SSH 配置或业务写入。数据库端口通过只证明 TCP 可连接；业务健康和页面可读取也不替代真实用户功能验收。本项交付对象是诊断命令，验收覆盖了它的实际失败定位与修复后复查过程。

## 自动检查

`python3 -m unittest discover -s deploy/scripts -p test_dev_doctor.py -v`：14 项全部通过。Python 标准库单元测试覆盖版本范围边界、文件字面值解析与环境变量优先、恶意命令文本不执行、凭据不回显、缺失参数、无效端口、连接失败、超时、CPU 架构错误、错误服务身份和 HTTP 跳转不跟随。测试使用临时 TCP / HTTP 服务验证请求行为，不访问生产业务数据。`py_compile` 和 `git diff --check` 通过。
