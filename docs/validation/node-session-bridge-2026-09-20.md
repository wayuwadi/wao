- Flyway 从 V156 加法迁移到 V157，新增一次性票据表，未修改既有业务表或已执行 migration。
- H2 独立连接 SQL 并发测试通过；显式开启的 MySQL 验收使用八个独立连接争抢同一随机票据，
  恰好一个成功，错误目标与到期消费均失败。本次随机票据已按准确主键和随机根会话标记删除并复查为零。
- 后端会话单测覆盖随机票据、哈希保存、过期、目标绑定、Origin、CSRF、账号绑定、主站注销、
  节点注销、跨节点撤销及并发重放。节点会话不写旧服务读取的 `wao.accountId`。
- 前端专项 11 项通过：后台建立连接、精确节点/发布白名单、独立写开关、冷却/关闭、读请求仅一次云回退、
  写失败不重放、401/403 和用户取消不跨入口重试。类型检查通过。
- 前端生产构建通过；保留现有大分块警告，未将该警告视为功能失败。
- 后端完整回归1335项，失败0、错误0、跳过8；MySQL专项另行显式执行通过。
- 生产公共 Nginx 模板在现有容器中完成独立配置语法校验；发现并修正常量不能作为 if 条件左值的问题。

## 浏览器真实链路

独立主站验收页复用已有登录态，通过临时、可移除的路径代理到本地应用；Linux2 使用相同版本网关
的隔离实例，验证反向代理的 Host/Proto/Port 链与 CORS。生产 `/api/**` 路由不变。

- 建立 Linux2 独立节点 Cookie 后，读取八个当前账号真实可见项目，并打开 Wa All in One 详情。
- Linux1随后也建立独立节点会话并读取相同八个真实项目，草稿保留，单次651ms，同样不代表正式路径性能。
- 未保存文本在连接与详情切换后保留。单次列表请求888ms，包含临时回环隧道到 Windows 的额外路径，
  不作为正式节点的延迟或吞吐指标。
- 缺少 CSRF 的 PATCH（目标为不存在的验收项目 id）返回403，未写业务数据。
- 同票据第二次兑换返回401；不受信任的 Origin 返回403。
- 正式节点 `/api/projects` 仍为404，说明受控验收没有打开生产业务入口。
