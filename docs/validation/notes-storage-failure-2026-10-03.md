# 小记草稿存储失败与恢复验收

本轮未发现新的产品缺陷，只补可复用的本地验收工具；不需要部署。

## 工具边界

`wao-web/scripts/acceptance/serve.mjs` 仅由 `npm run dev:acceptance` 使用并绑定回环地址。只有 `/notes?waoAcceptanceDraftFailure=1` 注入 `storage-failure.js`，生产 Vite 配置不加载此插件。故障只拒绝当前页面 localStorage 中小记新增/编辑草稿前缀的 setItem，不删除已有内容、不禁用登录和其他存储、不改变业务 HTTP 请求，也不影响其他页签。

页面底部“恢复草稿写入”按钮恢复当前文档原方法。点击后继续输入触发草稿重写；普通 `/notes` 不注入。带参数刷新会再次注入，不能用它作为恢复完成后的普通页面。

## 可重复步骤

按 [本机小记 AI](../runbooks/local-note-ai.md) 启动已有数据库连接的本地服务后：

```powershell
$env:WAO_ACCEPTANCE_API='http://127.0.0.1:18082'
$env:WAO_ACCEPTANCE_PORT='5243'
cd wao-web
npm run dev:acceptance
```

1. 确认没有待处理私有草稿，用正常验收账号打开 `http://127.0.0.1:5243/notes?waoAcceptanceDraftFailure=1`。
2. 新建区输入专用合成文字：内容留在输入框，提示“浏览器草稿保存失败，请保持页面打开并重试保存”，不能显示“草稿已保护”。
3. 点击底部恢复按钮，继续输入一个字；此时才显示“草稿已保护 · 有修改待保存”。点击保存并登记精确小记 ID。
4. 去掉故障参数重新打开普通小记页，确认落库正文一致。
5. 再打开带参数页面，编辑刚创建的小记，只修改标题；确认同样失败提示。恢复后再次输入、保存，普通页面重新打开确认标题与正文正确。
6. 将本轮精确小记移入可恢复回收站，刷新确认不存在，关闭验收页。不要删除其他验收者或用户的数据。

这组真实浏览器步骤已通过，截图、DOM 和精确标识留本机。保存、读取使用真实本地服务与既有数据库，没有模拟成功响应；故障仅在自己创建的验收页面注入。

工具隔离边界的自动回归：`npm --prefix wao-web run test:acceptance-tools`，本轮 16 项通过，含草稿拒写不破坏旧内容、其他存储不受影响及恢复写入。真实手动步骤不能由工具测试代替。
