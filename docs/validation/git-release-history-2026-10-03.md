# 自动 Git 更新记录验收

## 复现与修复

公网前端已到 `8ac17cbd`、后端 `206a2686`，更新说明却仍为“功能探索，入口更顺手”。原因是清单只验证人工档案一致性，不会随 Git HEAD 自动变化。现改为每次构建自动生成版本说明与完整提交档案，并调整 main 纯文档/测试批次为网页静态发布。

## 验证

- 真实隔离 Git 仓库：初始功能后仅增加文档提交、没有修改精选，版本 id 和最新标题仍更新；未合并分支不混入；全部祖先保留。宿主导出文件与直接 Git 读取结果一致，错误 SHA 被拒绝。Node 4 项通过。
- 前端 6 文件 22 项通过：分页看全、读取中、网络错误重试、重复/损坏/版本不一致拒绝、顶栏最近提交内容与路由、原更新保存屏障、精选历史与自动介绍。
- Jenkins 变更范围及依赖缓存脚本测试通过：文档/测试触发静态发布而不重启后端；无 Git 容器所需数据由宿主导出，版本一致。Windows 测试中的假 Vite 改成可执行 shebang 文件，避免空文件权限导致虚假重装。
- 类型检查与生产构建通过，保留已有大分块提示。同步最新 main（含工具菜单）后再次回归、构建，一致性 0 错误、5 组历史 ADR 重号警告。
- 本地真实应用、既有数据库和正常登录：完整读取开发实例启动时 HEAD `ce6c2928` 的 1099 条记录，初始 20 条，点击后 40 条；文档/测试可见，刷新后仍在。工具 → 本次更新显示最新五条提交，最近更新跳转正确，旧精选记录保留。
- 390px 真实视口：正文和文档宽均为 390，记录区域左右为 14/366，无横向溢出；更新介绍正常打开，验后恢复默认视口。

构建后合并 SHA 与正式静态制品另行核对，不能用开发实例的旧启动 HEAD 冒充合并版本。本地截图、日志和发布结果存本机受控 `wao-evidence/notes-ai-20261003/git-release-history/`。

## 边界

Jenkins 尚未恢复，未声称实际 Jenkins 构建通过；本次沿用已有 Windows 临时静态发布通道。只显示当前制品可达提交，未合并分支和未发布提交不会提前标成上线。后端实际部署状态不由前端提交列表推断。未新增业务 API、CLI/MCP 权限或数据库变更。自动运行命令见 `../runbooks/git-release-history.md`。

## 首次发布发现的路径缺陷与恢复

PR #1108 合并 `fb3e8470` 后，静态摘要和版本正常，但云端不可变路由拒绝根目录 `git-history.json`（404）。已验证原子回退到 `6315aac6`，未重启后端、未改路由权限。首次发布记为失败回退，不计为成功。

根因是生产仅开放 `/releases/<SHA>/assets/*` 和 `release-manifest.json`，本地 Vite 的根路径没有这个限制。将档案迁入 `assets/git-history.json`，API、开发路由、构建清单与文档同步；新增 API 路径断言及产物匹配不可变路由的回归。后续实际发布必须验证档案 HTTP 成功、摘要、首条 SHA 和版本说明一致后才收口。

路径修复本地复验：Node 4 项、前端 2 文件 7 项通过，类型与构建通过；真实页面经新资源路径读取 1103 条提交，20→40 分页正常，首条为 fb3e8470。正式修复制品发布另核对最终合并 SHA。
