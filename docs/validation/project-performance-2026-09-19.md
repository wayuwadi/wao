# WAO 性能治理验收记录

对应方案：[查询、调用与展示性能治理](../specs/project-performance-2026-09.md)。

## 对照方法

基线为 `61803f1a`。从 Git 导出原版 `DashboardService`、`KnowledgeService`，在临时目录改名编译，与本次实现共用相同 MyBatis Mapper、Java 17 进程和既有线上 MySQL 连接。数据库连接设为只读事务，MyBatis 本地缓存设为 `STATEMENT`；每场景先预热，再交替执行旧/新实现五次，记录方法墙钟耗时与 Mapper 返回行数。逐次比较完整 DTO 的 JSON 树，统计和文档结果均一致。

这不是线上 HTTP 压测：数字包含本机 Java 处理及 SSH 隧道到真实数据库的往返，不包含浏览器、Gateway 与线上 JVM 差异；五次样本不足以推断线上 P95 或整机 CPU 降幅。行数指返回应用的行数，不是数据库扫描行数。

## 同快照测量

| 场景 | 优化前中位耗时 | 优化后中位耗时 | 返回行数（前 → 后） | 查询次数（前 → 后） |
| --- | ---: | ---: | ---: | ---: |
| 首页汇总 | 77.45 ms | 19.25 ms | 441 → 3 | 4 → 3 |
| 30 天 AI 趋势 | 32.00 ms | 12.60 ms | 277 → 277 | 1 → 1 |
| 7 天任务趋势 | 83.98 ms | 19.23 ms | 554 → 554 | 2 → 2 |
| 引擎占比 | 35.28 ms | 9.47 ms | 418 → 418 | 1 → 1 |
| 30 天用量建议 | 69.18 ms | 49.62 ms | 745 → 745 | 3 → 3 |
| 单篇文档 | 177.62 ms | 14.32 ms | 174 → 1 | 2 → 2 |
| 同版本心跳的文档读取部分 | 174.01 ms | 5.33 ms | 174 → 1 | 2 → 1 |

文档测量选用同一个真实文档，该样本没有入链；有入链的文档仍需返回真实来源及摘要，不能把本表行数推广为每篇文档固定一行。另一次只读事务先读取完整出链关系，再对全部 173 篇未删除文档逐一比较新查询得到的反链集合，全部一致。MySQL CTE 只读测试另覆盖重复入链、自引用、同 id 不同类型、键分散在两个对象、已删除、已归档和空链接。

同版本心跳不再读取的全库正文相关字段合计 4,188,361 字节（约 4.0 MiB）。这是该快照的字段长度，不是压缩后的 HTTP 流量。后台存在多个保留文档页签时，暂停不可见页签进一步减少心跳次数。

监控批量上报由最多 100 条独立 INSERT 改为一条参数化 INSERT。单元测试验证整批预校验、成员归属、空批和超限；H2 Mapper 集成测试实际写入 100 条，验证自动 id、网络失败的 NULL 状态码、耗时与成员隔离。没有向线上数据库写入监控压测样本。

## 本地真实用户链路

独立工作区启动 `local-cloud` 服务（只绑定本机回环地址，关闭 Flyway、服务注册和共享定时任务），数据库通过既有 SSH 隧道连接。独立 Vite 入口复用正常登录会话，亲自操作浏览器：

1. 使用统计读取真实累计运行、Token、额度采样、用量建议；手动刷新出现“刷新中”，完成后恢复按钮并保留统计。
2. 在现有测试知识库新建唯一临时文档，输入标题与正文，观察“自动保存成功”；刷新浏览器后标题、正文与数据库版本 2 一致。
3. 切换到项目页后，临时文档的最后心跳固定在 `17:26:06`，间隔超过一分钟的两次只读检查均未变化；返回保留的文档页签后，心跳立即恢复到 `17:27:40`，内容仍完整。
4. 将本次临时文档移入回收站，确认知识库恢复原来的两篇文档，数据库软删除标记已设置；未改动已有业务文档，未清空回收站。

## 取舍与回退

没有新增数据库迁移、索引、服务端业务缓存、依赖或部署配置。前后端接口形状兼容，回退代码无需回滚数据库。文档 JSON 出链过滤仍需数据库检查来源，尚未引入独立关系表；目录/正文拆分、任务增量接口及精确监控聚合留在方案的后续候选中，不把未实施项计为收益。
