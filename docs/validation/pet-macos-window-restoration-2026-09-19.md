# macOS 宠物与工作区窗口恢复验收

## 环境与复现

2026-09-19，macOS 13.7.8 Intel，内建屏幕 1792×1120（2×）和 Redmi 外接屏幕 1920×1080（1×）。从当前 main 构建 1.1.9 原生开发宿主，独立标识 `cn.wayuwa.wao.client.dev`，通过 `WAO_WEB_DEV_URL=http://127.0.0.1:5199` 连接本地业务页面和既有真实后端。

修复前，工作区在外接屏幕为 `(2300,200)`、`1000×700`，正常退出后重新启动变为 `(1150,100)`、`500×350`；宠物也回到默认位置。使用真实 System Events 窗口信息、鼠标拖动事件与正常退出复现，不以浏览器模拟代替原生窗口。

## 修复后实测

| 操作 | 实际结果 |
| --- | --- |
| 主屏退出重启 | 工作区保持 `(206,93)`、`1100×760`；宠物保持 `(830,649)`、`260×190`。 |
| 从主屏实际拖动宠物到副屏，再退出重启 | 工作区保持 `(2300,200)`、`1000×700`；宠物保持 `(1905,716)`、`260×190`。拖动没有切换工作区可见状态。 |
| 托盘隐藏恢复 | 仅宠物隐藏，再次操作恢复同一位置，无重复宠物窗口。 |
| 实际点击宠物两次 | 工作区先隐藏、再恢复，宠物始终存在。 |
| 未登录入口 | 宠物显示“打开 WAO 登录”；主窗口关闭后，点击入口恢复登录窗口。副屏气泡完整可读。 |
| 正常退出 | 使用“退出 WAO…”和“已保存，继续”，开发进程正常结束；再次运行恢复窗口。 |

先核对退出前窗口坐标，再核对 AppKit 保存的 frame 描述和重启后的 AX 窗口坐标，避免将旧版本留下的错误位置误判成当前修复失败。正式安装版与开发宿主并存，没有安装覆盖或拷贝登录凭据。

## 边界

只生成本地 Intel 调试产物；未发布安装包、未变更客户端版本号。首次采用新的原生 frame 名称时没有历史记录，会使用默认布局；不会猜测旧物理像素记录的缩放比例。

未执行副屏物理断开、系统缩放调整、Apple Silicon 或 Windows 实机验收；屏幕消失的几何策略有单元测试，不能替代断屏实测。当前开发宿主尚未登录，原生设置慢保存、文件草稿写入期间刷新和会话失效恢复仍待正常登录后补验。没有向真实成员发送测试消息或编辑真实业务数据。
