# WAO 数字形象管理与小记配图设计草案

日期：2026-10-07。状态：待用户确认方案和 Demo。本轮交付设计，不修改业务实现、数据库或线上配置。

目标是建设 WAO 的数字形象资产管理层，让本人、家人与宠物拥有稳定档案、可复用参考素材和多套造型，并能按实际能力接入图像、视频等成熟生成引擎。首期闭环为建档、上传照片、生成并确认形象、小记配图和不准确反馈。小记只提供一个形象设置图标，不建设常驻选角面板。2026-10-07 用户已选择数字成员图库布局；本稿依据该选择收敛，新增行业平台参照与扩展模型。

## 成熟平台参照与 WAO 定位

以下为当前官方文档描述的产品组织方式。WAO 采用其中可复用的资产管理模式；能力与模型效果必须通过接入实测验证，不把管理 Demo 称为已经成熟上线的平台。

| 平台 | 官方说明的组织方式 | WAO 采用的设计 |
| --- | --- | --- |
| HeyGen | 基础造型锚定身份，不同造型可以复用同一基础；声音和动作参考分别管理 | 一个成员可有多套造型；身份、造型、声音、动作分层。来源：[基础造型与动作参考](https://help.heygen.com/en/articles/14602997-how-to-get-the-best-results-with-avatar-v-in-heygen) |
| Synthesia | 数字人集中在个人、共享等图库；可定制造型支持服装、场景等选择，功能取决于类型 | 图库是主入口，详情中管理造型；功能标识来自真实能力。来源：[图库管理](https://docs.synthesia.io/docs/synthesia-avatars)、[数字人定制](https://docs.synthesia.io/docs/avatar) |
| Runway | 图片、视频、音频可以作为参考，命名保存后跨会话复用；是否支持某类输入取决于模型 | 建立参考素材资产和清晰用途，创作端仅消费引用。来源：[参考素材管理](https://help.runwayml.com/hc/en-us/articles/52963720640275-Using-reference-media-to-guide-your-generations) |

设计判断：WAO 统一管理成员、素材、造型、默认策略和创作追溯，生成工作通过 adapter 接入已有引擎。用户不必在每个小记或未来视频页重建人物。平台的口播数字人、通用参考图角色和 3D 模型具有不同技术要求；照片建档不能自动声称已经获得声音克隆、视频口播或可驱动的 3D 模型。

人的口播和宠物的参考图创作分别进行能力验证；外部平台是否允许和支持宠物、照片建模、声音等，以对应接口和账号的实际结果为准。本轮不选择付费套餐、不创建外部人物、不上传照片或建立付费接入。

## 身份事实与形象的分层

采用五个独立概念：

1. **主体档案**：这是哪个人或宠物，包括名称、类型、关系、别名、已确认事实和归属。
2. **参考素材**：原照片、裁切输入、正侧面参考、未来动作视频或声音样本。素材具备来源、用途、确认状态与访问权限。
3. **造型及其版本**：同一成员的自然本人、日常插画等不同 Look，各自有独立 ID 和不可变确认版本。修改一套造型不会覆盖另一套；主参考照片与日常默认造型分别指定。
4. **能力接入**：某个造型在具体生成引擎中是否支持参考图生图、图生视频或口播，绑定到该引擎的资源与验证状态。
5. **创作引用**：某次小记生图用了哪个成员、造型版本、素材清单和执行出口，保留当次结果与反馈。

姓名不是唯一键；相同名字和双胞胎必须保持独立主体 ID。成员账号是操作者，主体是画中角色，二者不能混为一谈。

### 事实来源与覆盖规则

- 当前成员由服务端会话 `CurrentMember` 确定，不接受浏览器传来的 ownerMemberId。
- 本人的性别等基本事实由本人资料显式保存；本人形象绑定只能由本人建立。家人的档案由当前成员管理，不自动绑定到另一个 WAO 账号。
- 本人资料是本人性别事实的唯一写入口；形象编辑页展示它并链接到资料修改。同一事务更新资料 revision 并使依赖旧事实的形象版本待复核，避免两份资料各自漂移。
- 家人和宠物事实由档案维护者确认。性别允许未知、未填写、自定义；年龄阶段可选，不要求精确生日。宠物增加 species、品种、毛色、花纹等适用字段。
- 头像、昵称、照片、正文和模型视觉分析不能自动写入性别、年龄或成员绑定。AI 可以提出“短发、戴眼镜、白色胸毛”等外观候选，用户修改并确认后才生效。
- 缺失事实不补猜测。可先保存档案；需要特定人物但缺资料时显示待补充，或由用户选择不出现具体人物。
- “男性”不等于短发、无胡须等外观约束；外观按本人确认或照片约束，不能把性别刻板印象写成默认规则。
- 小记正文含引用、小说人物或他人经历时，不把作者强行画成叙事主角。明确选角优先；个人日常场景可使用已启用的本人默认；含多名具体人物或歧义时请求用户选角，自动任务可生成不含可识别人物的场景图。

## 首期用户链路

### 建立自己的形象

进入“数字形象”，建立本人档案并确认基本信息。上传一张即可开始，可补充正面、侧面、全身等不同角度，不把多张上传设为必经门槛。合照先由用户指出目标人物，首期可要求上传单人裁切照片，不自动认脸或合并人物。

照片保留原件，创建去除 EXIF 和旋转修正的模型输入副本。选择主参考图，确认固定外观与可变化项：脸部和特征保持，服装按照片固定或随场景调整。建立首个形象版本可以直接确认原照片作为参考，也可以生成一张插画候选再确认。候选永远不会自动成为默认版本。

生成后提供“采用为当前形象”“不像我”“调整后再生成”。反馈可以指出脸、发型、年龄表现、衣服等问题；失败或不采用仍保留已确认版本。设为本人默认后，个人场景的小记配图自动引用，无需每次上传。

### 建立家人与狗狗的形象

复用同一流程，以 person / pet 区分表单。家人没有 WAO 账号也能建档。双胞胎不共用主体或参考图标签；狗狗按真实毛色、花纹和体型建立不同主体，不仅用“狗”字描述。

首期档案及原照片仅维护者可见。娃弟若在自己的账号建档，其本人默认属于自己的账号；另一成员建立的“娃弟”家人档案不因此获得其照片权限。跨账号共享和绑定待双方明确接受后再设计。

### 在小记中使用

小记配图旁仅增加一个形象设置图标，带可访问名称和简短 tooltip；默认使用账号已确认策略，无需用户每次操作。点击打开小浮层，选择“使用本人默认”“本次指定成员与造型”或“不出现具体人物”，并提供“管理数字成员”链接。首期一次指定一个成员，不建设多人分镜、叙事角色编排或常驻角色列表。多人叙事仍由后台来源分析采用保守路径，不因简化前端而猜测具体人物。

选择主体与版本跟随小记草稿保存，重开能恢复；一次覆盖不修改全局默认。默认更新只影响之后的新任务，排队任务保留提交时版本。更换角色后重生成创建新请求号，不覆盖旧结果。旧成图不后台重画、不自动替换正文。

结果先显示预览与“使用了谁”。手动生成沿用“加入小记”确认流程；自动配图保留现有版本校验和原文保护。对指定身份的异常输出，可经视觉检查拦为待复核；无法可靠自动判断时让用户确认，不能声称程序已保证人像一致。

## 图库与详情页

用户已选择数字成员图库管理模式。新版 Demo 收敛为一个图库，点击成员进入详情；使用明确标记的示例资料、头像占位和本地上传预览，不调用 AI、不上传照片、不保存到真实账号。

| 区域 | 内容 | 交互 |
| --- | --- | --- |
| 成员图库 | 本人、家人与宠物卡片，展示当前封面与可用状态 | 新建、分类和进入成员详情；避免首页堆完整编辑表单 |
| 基础档案 | 名称、账号关联、性别、年龄阶段、确认特征 | 显式保存；事实来源可查 |
| 参考素材 | 原照片与正面/侧面/全身等用途 | 上传、选择主参考、移除；未来支持视频/音频，但未接入时不伪称可用 |
| 形象造型 | 同一成员的多套 Look 与独立版本 | 创建、确认、设为小记默认、回看版本；候选与确认版本分开 |
| 创作记录 | 使用此成员与造型的产物及来源 | 根据真实任务显示，空数据保持空白，不填造作品 |
| 小记消费入口 | 单一形象设置 icon | 小浮层选择默认、单个成员与造型、无人物；复杂管理跳转图库 |

管理入口挂在现有参考图库附近，页面名称为“数字成员图库”。详情中的素材、造型与记录是能力扩张的中心，小记保持写作优先。图像、口播、视频等能力按成员类型、造型和引擎的实际验证状态展示；当前未接入的能力仅显示明确状态，不出现可点击的假生成按钮。

移动端图库响应式重排、详情表单单列、编辑分区可浏览，主要按钮至少 44px 可点击。草稿、保存、失败与冲突状态直接显示，不藏在 hover；长名称换行，图片保持比例，浮层首次定位就位。复杂编辑沿用统一设置页布局原则，小记仅显示用户已选择的形象设置 icon。

## 服务端与数据模型

保持 Vue 3、Spring Boot 3、MyBatis-Plus、MySQL 与现有持久任务体系。新增专属领域服务，避免把档案塞进一段自由提示词或 member_preference 大 JSON。

| 表或扩展 | 核心字段与关系 | 约束 |
| --- | --- | --- |
| `member_profile` 新表 | member_id 主键、gender、自定义值、可选年龄阶段、revision、confirmed_at | 个人基本事实独立于组织 role；允许未知，不回填猜测 |
| `digital_subject` 新表 | id、owner_member_id、kind、display_name、relationship、aliases_json、confirmed_traits_json、revision、state | 全部读取按 owner 隔离；档案可归档 |
| `member_self_subject` 新表 | member_id 主键、subject_id、default_version_id、revision、auto_use_policy | 每成员一个本人绑定；事务校验主体归属与 person 类型 |
| `digital_look` 新表 | id、subject_id、name、style、current_version_id、revision、state | 一人多造型；style 不等于姓名或身份；归档造型不删主体 |
| `digital_appearance_version` 新表 | id、look_id、version_no、facts_snapshot_json、reference_manifest_json、state、generation_run_id、confirmed_at | look_id + version_no 唯一；已确认版本不可原地修改 |
| `digital_asset` 新表 | id、owner_member_id、subject_id、version_id 可空、role、MIME、byte_size、hash、private_storage_ref、state | 原图、输入副本和候选均私有；同成员去重并维护引用 |
| `digital_generation_use` 新表 | run_id、source_doc_id、source_rev、snapshot_json、payload_hash、output_asset_id、review_state | run_id 唯一；保存当次人物映射、版本、来源摘要和执行配置 |
| 小记来源选择扩展 | 类型化选择 `{mode, subjectId, versionId, narrativeRole}` | 草稿与保存 CAS 一致；明确选择覆盖默认，允许 none |

小记 Web 首期仅提交 default / explicit 单成员 / none；多角色清单属于服务端模型的后续扩展，不要求首期在浏览器暴露。

### 能力与外部模型绑定

领域模型与生成引擎资源分离。新增 `digital_provider_binding` 时使用 subject_id、look_version_id、connection_ref、provider、resource_kind、remote_subject_id、remote_look_id、capability_snapshot、status、verified_at；资源 kind 可为 reference_pack、trained_avatar 或 mesh_rig。远端 ID 只在 adapter 中解释，不作为 WAO 的主体主键。

首期通过既有出口验证 reference_pack；外部训练资源、声音和 3D 只预留类型，实际接入对应能力时再新增绑定或专用资源表。凭据通过既有安全存储的 connection_ref 获取，绝不进档案 JSON、前端或日志。素材清单始终可在 WAO 重建引擎输入；远端训练模型和权重能否导出必须按提供商验证，不能承诺跨平台直接迁移。

`ImageGenerationAdapter` 与以后 `TalkingAvatarAdapter`、`ImageToVideoAdapter` 分别实现能力接口，统一提供 capability discovery、prepareInputs、submit、poll、cancel（仅支持时）、normalizeResult。能力声明包括主体类型、可接受素材类型/数量、身份实现方式、输出媒体和已验证限制。可用状态是 connection、账号授权、主体材料、造型版本与 capability 的共同结果，不只判断页面开关。

建议默认策略按 usageKind = note_image / article_image / talking_video 等维护，首期只创建 note_image。后续口播默认声音不能覆盖小记默认形象；各媒体独立设置，仍指向同一主体。创作记录冻结主体事实 revision、lookId + versionId、输入资产 hash、provider/model、requestId、状态、用量和结果地址。

表名是设计建议，正式规格确认后再定。JSON 只容纳有界外观与当次快照；主体、归属、版本和权限关系使用明确列与外键/服务约束。照片不放入成员列表 DTO，不在公开通用 member 资料中展示。

首期复用私有参考图库的内容识别、去重与鉴权模式，将新形象资产存为领域私有资源；现有参考图可由用户明确选择后复制成档案资产，避免删除档案误删原图库。现有私有图库按字节验证类型仍需补充真实解码、像素尺寸和总量检查。私有内容存储采用既有存储条件：初版可用独立私有内容表，服务通过 storageRef 读取，后续迁对象存储无需改主体模型。阈值与模型输入数量取服务端能力配置，UI 显示实际限制。

建议服务：`DigitalSubjectService`（归属、资料、草稿 CAS）、`DigitalAppearanceService`（版本、确认）、`DigitalAssetService`（上传和私有读取）、`DigitalIdentityResolver`（账号与角色解析）、`DigitalGenerationContextBuilder`（可信快照与提示词）。Service 公共方法有 JavaDoc，核心权限和状态机有单元测试。

主体状态：draft → active → archived；形象状态：draft → generating → candidate → confirmed，失败为 failed；当前版本指针仅在显式确认时 CAS 更新。失败任务不使旧版本失效；修改关键事实后显示需复核，暂停旧默认的自动身份生图，用户确认兼容版本后恢复。

## HTTP 契约草案

全部返回 `ApiResponse<T>`；所有 owner 从会话确定；越权读取统一不暴露存在性。

| 操作 | 建议接口 |
| --- | --- |
| 个人事实读取与保存 | `GET/PUT /api/me/profile`，保存携带 expectedRevision |
| 主体列表、创建、编辑、归档 | `GET/POST /api/digital-subjects`、`GET/PATCH /api/digital-subjects/{id}` |
| 上传、私有读取、移除照片 | `POST /api/digital-subjects/{id}/assets`、`GET/DELETE /api/digital-assets/{assetId}` |
| 创建造型、生成和查询版本、确认 | `POST /api/digital-subjects/{id}/looks`、`POST/GET /api/digital-looks/{lookId}/appearances`、`POST /api/digital-appearances/{versionId}/confirm` |
| 本人绑定与默认策略 | `GET/PUT /api/me/digital-subject`，携带 expectedRevision |
| 生图能力读取 | `GET /api/assistant/image-capabilities`，返回 textToImage、referenceToImage、maxInputs、actualProvider、unavailableReason |
| 小记生图 | 扩展现有 `POST /api/assistant/article-images`，增加 identitySelection 与有界角色映射 |
| 生图任务结果 | 扩展现有 GET，返回有效人物/版本摘要、reviewState 和可执行失败原因 |

成员与造型引用示意：

```json
{
  "identitySelection": {
    "mode": "explicit",
    "subjects": [
      { "subjectId": "subject-self", "lookId": "look-natural", "versionId": "appearance-v1" }
    ]
  },
  "requestId": "新的32位稳定请求号"
}
```

示例 ID 不是现有业务数据。旧调用不带字段继续兼容；服务端按来源类型及已确认策略解析默认，资料未知时不生成可识别默认人物。相同 requestId + 相同规范化 payload 返回同一任务；相同 requestId + 不同 payload 返回冲突，包含形象版本变化，避免复用旧人物结果。

## 生图执行与提示词

链路为：小记来源版本 → 权限和主体选择校验 → 冻结事实、版本和图片清单 → 私有字节输入 → 生图 → 可用性与身份复核 → 持久结果 → 现有小记版本校验写回。

输入由服务端组装，不让浏览器提交“可信资料块”：

- 最高层业务约束：人物事实、图片与角色对应、外观保持项、未知信息不得补造。
- 当次可信 identity_context：主体 ID、角色、事实来源 revision、形象版本、确认过的特征。
- reference_manifest：图片索引属于哪个主体、原照片/当前形象/风格图用途。不把家人照片混成一个图集。
- 可变化要求：场景、姿势、衣服策略、画风。
- 原文和自由画面偏好：不可信材料，不得覆盖账号事实或工具限制。真实场景与显式虚构创作分开；首期保持日常小记语境。

生成时先用原照片或确认形象作为视觉锚点，不逐轮只引用上一张生成图，避免误差累积。双人/多人若出口容量不足，明确提示减少角色或照片，不悄悄丢参考图。稳定身份不等于像素级还原，也不承诺固定随机种子可锁定人物。

OpenAI 官方接口支持一张或多张输入图进行编辑，但官方也说明连续生图仍可能出现角色一致性问题。[图像编辑接口](https://developers.openai.com/api/reference/resources/images/methods/edit)、[图像生成限制](https://developers.openai.com/api/docs/guides/image-generation)。这是选择参考图路线的依据，不是当前 WAO 本机 CLI 已接通的证据。

### 必须先完成的执行验证

在正式编码图库前，用独立受控任务验证当前已登录本机 Codex 能否让 image_gen 实际消费参考图片字节：不能仅证明 `--image` 能供文本模型看图。检查生成调用的引用、输出身份、任务归属、唯一产物、取消和临时文件清理。使用用户明确授权的真实照片，确认本人和娃弟分别生图、狗狗保留特征，以及两个人同框不串身份。

`--image` 输入附件与 image_gen 参考图片机制之间是否可贯通是待实测项。需要调整两处用途拒绝条件、最小工具权限和输入传递，但不能直接把附件校验删除后宣称成功。若必须开放额外读图工具，新增 ADR 说明限定的受控输入文件范围，保持 shell、联网、外部 MCP 与凭据隔离。失败明确返回 `REFERENCE_IMAGE_UNSUPPORTED`，不降级成随机人物，也不自动启用付费 API。

首期只实现既有出口的 adapter，领域快照不绑定某供应商。未来 API adapter 只在另行配置获准凭据和预算后启用；视频 adapter 复用主体/版本，但须单独评估实际可用能力，不画成已开通按钮。

## 权限、文件生命周期与并发

照片、形象候选和私有缩略图均经成员鉴权读取；不能以 `/api/images/{id}/raw` 公开 URL 存原照片。输出配图沿用当前小记图床行为；“原照片私有”不意味着分享后的成图私有，预览清楚显示成图将进入小记。若要让成图仅作者可见，需要同时变更现有小记分享与图片访问契约，另行明确选择。

上传校验真实解码、MIME、大小、像素和当前成员配额；去 EXIF 输入副本不能覆盖用户原文件。模型只接收所选必要图片，不发送整个人物库。日志只记录 ID、摘要、版本、错误分类和实际用量，不记录原照片或完整个人资料。备份沿现有 Linux2 恢复方案覆盖新私有存储。

移除照片先停止新生成引用，若被当前形象或任务使用则说明引用关系并允许解除；物理清理由引用计数和运行状态决定。归档主体取消默认绑定，禁止新选角；旧小记和历史配图保留。授权撤销或资产删除后，排队和运行结果都再校验有效授权并取消/阻止写回；过往产物不会自动从用户文章中消失。清理已引用图片必须通过原有内容操作完成。

每个编辑器按 memberId + subjectId 保存本地草稿，只保存文字与选择；文件上传成功后保存私有资产 ID，失败保留待上传文件提示。加载不覆盖本地草稿。保存携带 expectedRevision，409 展示本地和服务端差异，可显式选择重载或再次保存，不自动最后写入获胜。刷新任务状态只更新状态区域，不改编辑字段。

排队时事务冻结资料与输入清单；执行前校验授权，输出完成时再次校验。人物默认被更换不改变旧任务快照；被撤销授权则取消。旧正文 revision 不匹配时保留候选并提示重新加入，不写进新正文。运行超时、配额、输入问题、出口不支持、结果未知分别展示，不自动无限重试；结果未知先恢复同任务状态。

## MCP 与 CLI

首期适合终端的能力包括档案 list/get/create/update/archive、照片 upload、形象 list/generate/confirm、本人默认设置与任务查询。正式实施时使用 wao-cli-sync，更新 `docs/specs/wao-cli.md` 能力台账、帮助与权限测试。

数字形象属于新的私有领域，不自动加入旧 workspace Token 的权限集合。MCP 建议新增明确的 digital-subjects:read/write 和 digital-assets:read/write 能力，按实时 tools/list 使用；允许查元数据和执行显式生成，不在普通工具返回中泄露原图二进制。浏览器选段插入与本地草稿操作不开放为无版本条件的批量 CLI 命令。若复用 WorkspaceMcpTools，必须同步定义、分发和权限规格。

## 分阶段落地和验收

### 先验证出口

在受控真实照片与固定小记样本上验证 reference-to-image；保留实际 CLI 版本、图片哈希、引用映射、输出、耗时和用户判断。用户确认“像本人”才作为形象路线成立依据。若出口不可行，报告缺项并调整方案，不用文字提示词当作已实现的照片形象能力。

### 再交付首期闭环

一次需求 PR 交付成员事实、本人/家人/宠物档案、私有上传、形象版本、本人默认、手动和自动小记接入及反馈。发布前新增正式规格、API 契约、数据文档及 ADR；migration 编号从最新 main 获取，校验与其他任务没有语义撞号，不改已执行迁移。

验收样本：

| 情况 | 必须观察到的结果 |
| --- | --- |
| 本人与娃弟分别配图 | 读取各自确认男性事实及独立照片，不能交换或共用身份 |
| 性别未知 | 不推断；可保存档案，具体人物生图提示补充或选择无具体人物 |
| 女性家人、两只不同狗狗 | 使用各自资料与特征，不受作者默认男性覆盖 |
| 双胞胎和多人同框 | 明确角色到图片映射，用户能识别区分；失败可退回重选 |
| 无人称、引用他人、虚构故事 | 不把当前账号强行塞进图中 |
| 多版本与换默认 | 新任务引用新版本，队列旧任务保持旧快照；撤权则取消 |
| 跨成员访问与伪造 subjectId | 列表、原图、版本、任务均不能越权 |
| 上传失败、刷新、保存冲突 | 草稿保留、明确重试、409 不覆盖本地编辑 |
| 正文改动或删除 | 晚到结果不能覆盖新正文或复活删除内容 |
| 配额或出口不支持 | 保留旧形象和原文，明确原因，不改走未获准出口 |
| 320/390/1024px | 主操作可见，无横向溢出，触屏和键盘可完成流程 |

自动测试覆盖权限、快照、requestId 冲突、版本状态和正文 CAS；浏览器真实链路覆盖建档上传、确认、自动与选段生图、刷新读回和失败重试。相似度不使用未经校准的“95%”评分，也不由 AI 自评代替本人判断。记录每个样本首次可接受率、重生成次数、实际耗时和可读到的用量，未知用量保持未知。

合并后按既有唯一发布协调者部署并核对公网实际 SHA、静态资源、服务就绪和受影响页面；本机照片链路成功不等于公网已接通。实体设备和实际人物体验由用户最终验收。
