## C 推荐技术方案

以下均为推荐设计。常规工程细节由 Sol 在 Plan 中依据当前代码收敛；不要把提议的名称当作既有接口。

### C1 页面与操作链路

保留 `/todo`，首次默认进入今天的「按天」视图；另一个页内切换为「全部待办」。返回页面记住本人上次视图和选择日期，日期切换不自动搬移任务。日历选日增加“查看当天记录”的明确入口，沿用既有事件点击打开任务，避免破坏原行为。

日页面按顺序呈现日期、收起的推荐入口、可收起的早晚固定清单、当天任务及其进展、随手记、简短事实回顾。AI 没有合格结果时不放空推荐卡；加载和失败可在主动展开处查看。固定清单默认早晨/晚上由本地当前时段选择，用户切换后本次访问不被自动切回。

任务新建输入标题并按 Enter/点添加；不要求先填完整表单。单步骤与标题相同时不重复显示一份子项。复杂编辑复用任务详情。新任务仍使用现有真实状态和责任人规则，不使用 Demo 的“待开始/在推进”替换领域状态。

快捷新建显式使用当前成员为负责人，沿用稳定 Task ID 与操作回执的创建路径。不要调用旧 POST 后依赖默认负责人或毫秒时间戳 ID；本轮观察到旧 TaskService.create 仍含这些兼容默认值。

排时为标题下的一枚时间标签：点击标签，再点时段，即开始保存，常用操作两次点击。精确时段才展开开始、结束/时长。点击外部/Esc 收起并返回触发点；未提交的精确输入留作草稿，不能因收起自动提交。排期成功反馈放在原任务附近并提供撤销。取消当天安排、改到其他日期放入浮层次级操作，保留日历拖拽。

记进展在任务下内联打开小记输入；保存后同一个文档同时可在小记页和当天查看。普通随手记无需选择任务。过去日期允许明确的“补记”，显示记录日期与实际补记时间；未来日期仅规划，不提前打完成或生成已发生进展。

前端拟新增 `components/todo/TodoDayView.vue`、`TaskSchedulePopover.vue`、`DailyRoutineSection.vue`、`TaskSuggestionSection.vue` 和 `api/dayWorkspace.ts`；名称可调整。复用 `TaskDrawer`、`InlineSubtasks`、`NoteComposer`、`taskSchedule`、现有任务 store。新日数据单独按成员/日期缓存，任务仍以同一 Task ID 为权威；切换成员清缓存，取消过期请求，避免慢响应覆盖新日期。

### C2 排时表达与兼容

保持三个既有语义：未排期没有 `start/startAt/endAt`；当日不定时只有 `start`；精确时段使用本地 ISO `startAt/endAt` 并同步 `start`。`due` 始终独立。

推荐给 TaskDetail/TaskDto 增加可空 `schedulePeriod`，取值 `MORNING/AFTERNOON/EVENING`。它只能与有日期、无精确时段组合；精确时段与粗粒度互斥。选择“不定时”清除 period 和精确时段但保留日期；“取消安排”清除所有执行安排。日历在非定时区展示“早晨”等文字，不换算成 09:00 等任意时刻。

推荐新增仅修改排时的事务操作接口，带期望任务版本与稳定 operationId。旧全文更新不能因未携带新增字段就清空 period；专用接口负责显式清除，旧接口真正切换为精确时段或取消日期时清除不兼容 period。逐个检查 TaskDetail 重建路径、子项更新、移动、导入与 MCP 写入，保留未知的新字段所需兼容规则。

时区本期固定沿用 `Asia/Shanghai` 业务日；新增事件时间使用明确时间基准，响应带偏移或明确契约。既有本地时钟 ISO 不擅自改成 UTC 语义。跨日时段复用 taskCalendarEntries，结束午夜不制造次日空事件；精确浮层允许指定次日结束，不能照搬 Demo 禁止跨日的限制。

任务执行日期是已有共享任务属性，不暗中改成成员各自排期。页面提示与权限沿用现有任务规则；参与人无修改权限时可查看，不绕过权限另写影子排期。

### C3 当前任务与每日历史

推荐增加限定于本功能的每日记录，不建设全系统事件溯源。

| 拟新增实体 | 核心内容与约束 |
| --- | --- |
| `task_day_entry` | `member_id/task_id/business_date` 唯一；关联原因、首次记录时间、当日标题/步骤/排期/状态快照、快照来源与可信边界。任务仍只有一个实体，日条目不是复制任务。 |
| `task_day_event` | 按 task_id 记录有序事实；事件类型、发生时间、业务日期、当时归属成员、修改者、受影响步骤、必要前后状态快照、操作键。日条目引用相关事件；稳定事件键唯一去重，更正/撤销追加补偿记录。 |
| `day_note_context` | `member_id/doc_id` 唯一；业务日期、是否补记、创建时上下文、版本。只记录日期归属，正文仍在 Doc。任务文档关系继续用 `TaskDetail.docs[]`。 |

排期、改期、取消安排、任务状态/步骤变化、从当日日视图保存进展时，由服务端在同一事务内更新业务和日记录。覆盖任务详情、日历、项目页及已授权 MCP/CLI 等现有写入来源；不能靠浏览器埋点或自然语言 activity 文案保证历史。历史记录写入失败时，相应业务事务失败并可恢复，不能任务已完成而日记录静默丢失。

创建、改名、步骤结构/文本、负责人/参与人变化和删除也记录必要状态版本，否则未来回看仍会被新标题或新子项覆盖。版本只保存日视图所需的任务字段，不复制任务所有附件或全文。相关 TaskService 写入口补齐事务，现有部分入口的事务不能假定已经覆盖全部变更；对外通知保持提交后触发，不把外部消息纳入可回滚数据库事务。

日条目的个人归属遵循当时负责/参与关系，操作者单独记录；查看时仍再次验证当前任务与文档权限。历史快照不能绕过权限，也不能在撤权后泄露旧标题/正文。所有权变化不把他人的旧日记复制给新负责人。

今天展示当前真实任务并保留当天已完成、已改期的痕迹；未来展示最新计划；过去展示截至该业务日末的已记录快照和事件，不套用当前标题/步骤状态覆盖旧日。晚到的补记或纠正明确标识。取消的是“今天安排”，不删除任务；改期只改变当前执行日期，过去当天已发生的进展仍保留。

重开任务会改变当前状态，但过去那次完成的事实保留；回顾中标出后来重开，不能再算一次新完成。统计区分主任务真正收尾与完成小步骤，沿用 isTaskFinished，不把“主状态已完成但子项未完”算收尾。跳过固定事项不计完成。

初始化只建立“接入时当前状态”基线和当前/未来计划。旧数据能证实的小记创建日或完成时间可标来源展示；不能把当前 tasks 或客户端 activity 倒推出完整旧日记。历史覆盖不完整时明确显示记录起点。未打开页面的日期仍应由版本化计划与持久事件还原，不依赖用户当天访问。

计划版本直接由 task_day_event 中的初始基线和结构化排期快照形成，不再新增第二套排期权威数据。版本在其有效期间覆盖的日期形成虚拟日条目，首次记录进展或变更时物化；纯读查询不写数据库。历史查询须把有效计划版本与日事件合并，不能只查询已经物化的 entry。区分“何时改动”与“安排在哪一天”，按对应日末有效版本取值；长时段按查询窗口展开，禁止无界补齐所有年份。

### C4 小记保存与关联

新增日进展保存服务，在一个事务内完成小记内容写入、日期上下文和可选任务 docs 关联；任务关联前检查编辑权限及 expectedTaskVersion。新建用稳定 Doc ID 和操作回执，正文更新使用 expectedDocRev；旧 createNote 同 ID 更新的语义不能作为并发编辑安全保证。

操作超时先查询回执，不能“已保存正文但重复再建一篇”或显示整个过程成功却漏关联。返回 Doc、任务新版本、日上下文和回执。用户后续正文输入在原不可变请求确认后用新操作保存。

普通小记未指定业务日期时按创建时间归入当日；更新正文不把它搬到编辑当天。有 day_note_context 则以明确业务日期为准并去重。编辑后正文在各入口一致，标明修改时间；本期不提供“恢复某天版本的全文”能力。解除任务关联保留本人小记与日归属；文档删除/归档遵从现有可见与恢复策略，历史默认只留不可读占位和必要元数据，不复制已删正文。

扩展 NoteComposer 的草稿上下文与提交适配，不复制编辑器。新建草稿键至少隔离账号、成员、业务日期、任务 ID 与编辑实例；切换日期、任务或模式保留草稿。默认非自动生成正文，AI 润色和标题等能力继续遵循原来的显式配置，不能因为来自待办就重新开启。

注意现有 createNote 会调用既有通知逻辑。关联上下文本身不得重复发通知，不新增本功能通知渠道；真实验收必须确认既有通知开关，避免用测试记录向真实群批量发消息。

### C5 每日固定事项

采用“规则版本 + 当天实例”，不每天创建普通 Task，不使用已退役今日节奏表或路由。

| 拟新增实体 | 推荐字段与约束 |
| --- | --- |
| `routine_template` | ID、member_id、逻辑删除/停用标识、version。仅本人管理。 |
| `routine_template_revision` | template_id、effective_from/effective_to、名称、早晨/晚上、星期集合、顺序、是否启用。版本有效期不得重叠。 |
| `routine_occurrence` | `(member_id, template_id, business_date)` 唯一；引用规则版本，保存标题/时段快照、`OPEN/DONE/SKIPPED`、记录时间、version。 |

每天/工作日/周末在首版明确为周一至周日、周一至周五、周六周日；不是法定调休日历。规则按范围按需展开，GET 不批量造实例；点击完成/跳过时幂等落库。未创建实例表示未记录，不虚构实际执行情况。

默认新增和规则修改从明天生效；当天及过去规则不被重写。同一模板明日规则多次修改更新同一未来版本并做 CAS；暂停、恢复、删除等同于创建后续停用/启用规则，历史实例保留。用户如果需要创建后当天立刻使用，可在 Plan 中一次性确认是否增加“今天开始”的选项，不静默改动 Demo 语义。

当天 OPEN→DONE、OPEN→SKIPPED；DONE/SKIPPED 可显式恢复为 OPEN。未来不可提前完成；历史只读，首版不做历史补打卡。未做不累积为待办，次日按规则独立出现。完成/跳过的操作回执与 CAS 防止多标签页互相覆盖，失败仅回退本次 UI 变化。

用户举出的生活事项用于测试 fixture 和说明，不自动写入任何真实账号。初次空清单显示“添加固定事项”；早晚事项可排序，管理在现有页内展开/抽屉完成，不新增导航。

### C6 AI 推荐

推荐依赖并行“小记顺手发现”的检索、来源与运行基础设施稳定后接入。复用不等于把发现产物自动解释成任务；跨文洞察与单篇明确行动有不同的合格标准，推荐需要独立结构化产物和验证规则。

推荐采用 `TaskSuggestion` 小模块：关联 sourceDiscoveryId/sourceBatchId（如果存在）、title、rationale、source docId/rev/excerpt、actionFingerprint、possibleExistingTaskId、状态、snoozedUntil、expiresAt、acceptedTaskId、version。成员加稳定来源/行动指纹做确定性去重；同文不同动作不可被合并。语义相似只作为候选关系，不能据同名自动合并不同任务。

状态为 CANDIDATE、SNOOZED、DISMISSED、ACCEPTED、EXPIRED。成功可以是零条；模型故障、来源失效和零候选分别表达。来源必须真实且可访问，版本与摘录可核对；验证失败拒绝候选，不回退绑定第一篇来源。

输入仅限本人可访问、未删除/归档、符合来源规则的小记和有界的本人任务摘要，用于判断已处理/已有任务。检索从近期变化结合历史索引召回，输出实际覆盖范围，不能宣称查遍全部历史。后续“已处理”的记录、明确否定、旧推荐拒绝应参与抑制。AI 生成内容不当作第二份独立事实。

模型只提取行动、理由、证据和可能关联；服务端决定权限、状态、去重、排期和写入。原文中的命令不得触发工具、联网、代码执行或改变系统规则。严格结构化输出、长度限制和来源校验；开发模型 GPT6-Sol-High 不写死为产品模型。

推荐的开启方式是成员显式启用“从小记推荐待办”；旧挖掘运行或开启顺手发现不自动等于新的用途授权。可以复用同一设置区域和预算，而非新增中心页。未启用时不后台分析，普通待办完全可用。

新推荐生成挂在既有发现流水线的有界批次上，共享租约、冻结来源、预算和受控本机 AI 出口。每批最多三条；默认有效期七天、暂缓七天。批次/调用上限沿用最终合并的发现配置，不开第二套无限扫描、并行定时器或额外付费 API 回退。关闭后不启动新批次、迟到结果不发布。新用途需要同步本机 AI 允许用途白名单与拒绝测试。

接受时由后端重新验证候选、来源、当前权限和目标任务版本。确定同一事项则关联已有任务；不确定时展示可能重复供用户选，而非只按标题复用。接受为“今天”或“未排期”两种；已有任务已有其他日期时展示改期结果再提交，不能静默覆盖。

接受事务原子保存候选状态、任务创建/关联和操作回执；新任务记录来源关系与可核对的引用，不能复制整篇私人原文。重复点击、超时重试只能得到同一个任务。同一来源后来失权时推荐/证据隐藏；已接受任务按自身权限继续存在，不因 AI 失效自动删除。私密原文不放进共享任务可见的说明里，来源打开仍逐项鉴权。

忽略是拒绝这个行动建议，不是宣称来源事实不真实；暂缓期间不因重新批次换 ID 再次出现。到期后先重新检查来源和任务是否已处理，不能机械重推。失效候选保留必要抑制信息，不在普通页面展示过期内容。

如果顺手发现尚未合并，先实现前两个独立需求并为推荐留下服务接口设计，不提交假推荐、不回退到旧三类挖掘。AI 推荐的实现与验收必须在依赖可用后完成，不能把前两项完成称为整个交接包完成。

### C7 接口及一致性

拟新增接口如下，均使用登录会话、`/api/` 和 `ApiResponse<T>`；最终命名在 Plan 对齐。member_id 来自真实会话，不能信任请求自报成员。

| 拟定接口 | 语义 |
| --- | --- |
| `GET /api/todo/days/{date}` | 本人日聚合：当前或历史任务条目、小记引用、固定事项、覆盖边界。日期窗口与列表有界，不返回全量私人正文。 |
| `GET /api/todo/days?from=&to=` | 最多一个可见月度窗口的日期摘要，支持日历回看；按需读取正文。 |
| `PUT /api/tasks/{id}/schedule-operations/{operationId}` 与同路径 GET | 期望任务版本、排期变更、稳定请求回执与查询；不修改 due。 |
| `PUT /api/todo/note-operations/{operationId}` 与同路径 GET | 原子保存稳定 Doc ID、正文版本、业务日、可选任务关联和回执。 |
| `GET /api/todo/routines`、`PUT /api/todo/routines/{id}` | 读取/创建/修订个人规则；携带 version、effectiveFrom、稳定操作标识。 |
| `PUT /api/todo/routines/{id}/occurrences/{date}` | 当天 OPEN/DONE/SKIPPED 的条件更新与幂等回执；不允许目标成员伪造。 |
| `GET /api/todo/suggestions`、`POST /api/todo/suggestions/{id}/decisions` | 读取合格候选，接受/暂缓/忽略；接受含操作键、候选版本和任务条件。 |

规则、实例和推荐操作也必须能查询原操作结果，可统一新增有界的 todo 操作回执查询接口，或由现有资源查询返回原操作回执；不能只保存一个最近 operationId 而失去长期重试去重。不要把任务专用 TASK_REPLACE 回执硬塞成各种业务操作。

推荐仅为新 todo 操作新增轻量回执存储，唯一键 `(account_id, operation_id)`，存操作类型、请求哈希和结果引用；与变更同事务，重放重新验权。未知提交结果不视为失败；同键不同请求返回冲突。并发修改返回 409、保留本地草稿；冲突后用户可确认新操作，不盲重试旧全文。

撤销提交新的补偿操作，携带成功操作保存的后置版本；仅版本与预期排期仍一致才执行。多标签页后续修改后禁用旧撤销并解释原因。任务、小记、固定实例保存成功后定向失效对应日期和日历缓存；迟到响应不覆盖较新的输入。

### C8 权限与 CLI MCP

新日聚合只提供本人成员数据；每条任务/文档再使用既有服务鉴权，不能因为历史快照或推荐引用绕过权限。模板与实例按成员隔离，候选按成员及来源隔离。日志仅记录 ID、版本、状态与错误分类，不记录完整小记、提示词或凭据。

CLI/MCP 本期保留既有任务/文档操作，其修改仍通过公共业务服务产生必要日记录。新日聚合、粗粒度排时、固定事项和推荐决策暂只开放浏览器：前者聚合私人记录，后两者需要独立授权与用户反馈语义；旧令牌权限不能默默扩展。此为首版推荐边界，按 wao-cli-sync 在能力台账逐项记录；后续脚本需求明确且有权限范围时再开放，而非以“Web 专用”为永久借口。

### C9 迁移与回滚

采用新增表及向后兼容字段；本轮不预占 ADR/Flyway 编号，尤其不修改并行的 V174。先服务器/数据库兼容新增数据，再发布前端；前端在能力不可用时回到全部待办，不把已有数据当空数据覆盖。

新历史记录从明确启用时刻开始；规则历史和回执不靠重新扫描复原。关闭新页面/推荐开关时保留日记录、规则、候选反馈和原始任务/小记。数据库 rollback 不删新表、不倒改已执行 migration。若旧后端会丢弃新增 TaskDetail 字段，不允许简单回退该二进制；先加兼容修复或暂停相关写入。

不为首版增加全局事件总线、向量数据库或通用工作流引擎。复用 MySQL 事务与现有队列。日/月聚合按成员+日期索引，有界展开规则，避免每次打开页面全库扫描或逐条任务查询。

## D 分阶段执行计划

推荐按三个独立需求、三个 PR 交付；每个 PR 内部按下表步骤开发，不能再按前后端拆成半成品 PR。若后续用户以单一 WAO 分享任务下发，以“一链接一 PR”重划交付单元。

| 阶段 | 用户可见结果 | 实施内容与顺序 | 验证与完成条件 | 失败收口 |
| --- | --- | --- | --- | --- |
| 0 Plan 核对 | 明确可以实施的计划 | 核对本交接包、当前 main/脏工作区、并行发现接口、模板生效与推荐默认值；列出文件/迁移/权限变更。仅计划。 | 用户确认方案，实际模式允许执行；不以文档齐全代替开发完成。 | 列出具体差异，普通技术细节自行定；只询问产品取舍。 |
| 1 日视图融合与便捷排时，一个 PR | 在待办安排今天、写进展、改期、回看昨天；小记与日历保持一致 | 先写增量规格/ADR；TaskDetail/DTO 排时兼容；最小日记录与回执；覆盖服务写入；原子日小记；日聚合；TodoDayView 和浮层；日历进入当天。迁移、服务、前端、测试同一需求。 | 完整浏览器闭环与刷新回读通过，包含跨日/撤销冲突/改期保留历史/草稿恢复；全部待办和现有任务收尾回归通过。 | 服务/迁移未就绪则不开放新日视图；保留旧入口和草稿；阻塞项不伪报完成。 |
| 2 每日固定事项，一个 PR | 在同一页完成早晚清单，修改规则并回看当天记录 | 依赖阶段 1 日页；规则及版本、实例与回执；按日期聚合；页内管理、排序、跳过/恢复；空清单由用户创建。 | 当天/明天/过去隔离，规则生效、并发和暂停恢复通过；实际刷新后保持，未打开日页仍能按有效规则回看。 | 固定模块失败局部重试，不阻断普通待办和小记；不把读取失败渲染为无固定事项。 |
| 3 AI 待办推荐，一个 PR | 从真实来源找回事项，接受后复用或创建真实任务 | 依赖阶段 1 与稳定的发现基础设施；增加独立推荐用途与授权；结构化候选/证据验证/抑制；原子接受与回执；收起入口、来源、暂缓/忽略；台账。 | 有真实 AI 与真实浏览器证据；有行动正例、已处理反例、来源失效、重复接受、关闭迟到结果等验证。仅静态 fixture 不足交付。 | AI 失败保留正常待办，明确失败原因；依赖不通则保留阶段 3 未完成，不用假数据替代。 |

每阶段实现后自审与本需求相称的 diff，复测实际受影响路径。只读调研结束不反复全仓规划；已经通过且未变化的检查不无意义重复。

## E 验收与交付标准

### 用户链路清单

| 前置条件 | 用户操作 | 预期结果 |
| --- | --- | --- |
| 本人有待办且另有仅项目可见任务 | 进入按天与全部待办 | 个人归属规则一致，不能将仅项目可见任务混进个人日页。 |
| 未排期任务另有截止日期 | 时间标签选择今天晚上 | 两次点选触发保存，展示“晚上”；刷新、小记返回、日历一致，due 不变。 |
| 精确时段跨午夜 | 日历拖动到其他日；再从日页编辑 | 保持本地时间持续长度与跨日范围；午夜结束不多一天零时长事件。 |
| 已改期且保存成功 | 撤销；另一标签页改动后再撤销 | 无后续修改可恢复原安排；有后续修改拒绝覆盖，草稿和远端数据都不丢。 |
| 任务昨天有步骤进展/小记，今天未结束 | 改到明天，随后修改标题并重新打开 | 今天/明天反映当前计划；昨天保留当日事实，改期/重开不擦除过去记录。 |
| 主任务完成但仍有未完子项 | 查看按天、全部待办、日历 | 保留现有未收尾判定；步骤完成不等于任务收尾，不级联修改独立父子任务。 |
| 日页未保存小记或精确时间草稿 | 切日期、切任务、刷新、断网 | 草稿按账号/日期/任务隔离恢复；取消浮层不自动提交，不串到其他成员。 |
| 日小记保存发生响应丢失 | 查询、刷新、重试原操作 | 只有一个 Doc，任务关联和日期上下文完整；后来输入不被旧回执覆盖。 |
| 当日日页保存一条进展 | 在小记页编辑，再从日历回看该日 | 指向同一 Doc ID；正文更新一致，日期不随编辑时间漂移，显示修改时间。 |
| 过去日期无可靠任务历史 | 打开历史并补记 | 不生成伪完成；标记覆盖边界和真实补记时间。 |
| 个人没有固定事项 | 进入每日固定并新增 | 诚实空状态，无预置狗狗事项；规则生效日期清楚可见。 |
| 早晚有固定规则 | 今天完成/跳过，切到明天和昨天 | 当天分别记录 DONE/SKIPPED；明天重新开始；昨天不被今天操作修改。 |
| 某模板今天与过去已有记录 | 改名、改星期、暂停、恢复 | 默认次日起新版本生效；过去标题/时段/状态不变；今天未做不滚成欠账。 |
| 两页同时操作同一固定实例 | 一页完成、另一页跳过 | 稳定唯一实例；旧版本冲突，不出现一份完成一份跳过。 |
| AI 未开启、运行失败或成功无候选 | 打开待办与推荐区 | 普通待办可用；未开启不扫描；失败不冒充零结果；无候选不凑建议。 |
| 小记包含明确行动，同时存在同一事项的待办 | 查看来源并接受 | 原文/版本/理由可核对；已确定关联复用任务，不按同名强行合并。 |
