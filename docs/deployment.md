# 部署和数据保护

公开 `main` 是唯一源码来源。公开 CI 运行无生产凭据的检查；维护者 Jenkins 串行构建受信任 `main`、保存不可变制品，并交给既有运行协调器。数据库、上传文件、私有配置和密码库密钥不属于 Git 工作区。

## 日常发布策略

有写入权限的开发者可在验证通过后自行合并 PR，不要求第二人审批。`main` 仍要求 `secrets`、`local-install` 检查通过、分支保持最新并解决审阅讨论；禁止强推和删除。合并后沿既有 Jenkins 轮询、静默窗口和串行协调器发布，核对实际版本、就绪状态及相关页面后才报告上线。此策略不向 Fork、PR 或无写入权限的贡献者授予生产凭据。

## 现有 Windows 生产安装

Jenkins 使用 `deploy/jenkins/windows-build-deploy.ps1`，由维护者提供独立的 `-RuntimeRoot` 和 `-SourceRoot`。运行根目录保留工具、配置、发布队列与历史制品；源码可以重新检出，但运行根目录不能被 `git clean` 或源码更新覆盖。

服务器私有 `deploy/data/windows-server/production-build.private.json` 配置：

```json
{
  "legacyMigrationsDirectory": "C:/WAO-private/legacy-migrations",
  "legacyMigrationSha256": "<SHA256 of the original V33 resource>"
}
```

V33 从当前部署制品原样取得，保持字节和 SHA256，不手工重写。Maven 的 `legacy-migration-compat` profile 将其复制到构建资源，公开源码不保存旧 Webhook。构建脚本再次验证最终 JAR 中的字节哈希；资源缺失、哈希错误或位于公开源码目录内时拒绝发布。

带兼容资源的生产 JAR 仍含旧迁移内容，只保存在私有构建和生产目录，不能上传到公开 Release、制品附件或源码压缩包。面向社区的制品须从公开源码进行普通构建，不启用此私有 profile。

因此原数据库的已执行 Flyway 校验和保持有效，不运行 `repair`，不修改历史表，也不重新执行旧初始化 SQL。新安装不提供兼容目录，直接使用公开迁移和独立空数据库。

首次切换时，私有 `open-source-commit-map.private` 把旧发布 SHA 对应到脱敏后的同一版本。后续直接使用公开历史；找不到唯一映射时构建失败，不猜测发布范围。

## 切换与回退

1. 备份并核对原 Git 镜像和本地 bundle；保存 Jenkins job、构建入口、配置、当前版本和制品哈希。
2. 创建数据库一致性备份，同时保护匹配的密钥与文件资源；记录数据目录和 Flyway 校验和。
3. 保持当前服务运行，先通过安全检查和测试，再仅暂存构建，核对 JAR 兼容资源、版本和制品完整性。
4. 等运行批次结束后切换 Jenkins SCM 和入口，从公开 `main` 发布，核对实际版本、公网就绪和持久数据。
5. 失败时恢复旧 job 和构建入口，沿现有协调器切回原制品。不要通过覆盖业务数据库处理发布失败。

真实备份位置与验证结果存放在私有运维记录，不把凭据或数据库转储提交到公开仓库。

## 稳定性与资源上限

本机 AI 执行器默认同时执行 2 个任务，可通过 `wao.ai.local-notes.max-concurrency` 设置为 1–16。满载时任务继续留在数据库队列，不提前领取或标记失败；下一轮有空位后继续。该限制按服务实例生效，调大前应核对主机内存和 CLI 进程开销。

AI SSE 等待连接默认上限 16，可通过 `wao.ai.stream.max-concurrency` 设置为 1–128。满载返回 503，不创建新任务。连接等待上限默认五分钟（`wao.ai.stream.wait-timeout: PT5M`），到期只结束等待，不改变任务状态；任务超时仍由队列与执行器负责。等待期间每 15 秒发送注释心跳，连接断开后回收等待线程；已入队任务继续执行，结果从历史记录读取。浏览器离开页面会关闭连接，无数据等待上限为 330 秒。

普通文件正文请求默认最多同时处理 2 个，可通过 `wao.files.max-concurrent-transfers` 设置为 1–16。上传、替换、下载、媒体读取及预览共用限额，覆盖 GET/HEAD 和响应写出；满载返回 503 与 `Retry-After: 2`。元数据和其他业务接口不占此限额。现有 MySQL/对象存储仍使用字节数组，此措施限制并发内存峰值，不代表已改为流式存储。Markdown 预览在读取正文前检查 2MiB 上限。

前端类型检查与 `npm run test:stability` 同时进入公开 CI 与 Windows Jenkins 发布入口，相关回归测试失败阻止发布。完整 `test:unit` 仍保留供维护使用；2026-10-29 本轮检查为 2221 通过、57 失败及 14 个运行错误，独立主分支抽查亦复现菜单等旧测试失败。经维护者确认，本次先以稳定性回归集作为新增门禁，不把历史全量结果报告为通过。考勤后台先刷新所有成员当天事实，再逐一补齐历史；历史失败单独记录，且同一实例不会重叠执行两个同步周期。

验收重点：满载时其他业务可访问；等待连接关闭后任务仍保留；超大 Markdown 不读取正文；文件存储不可用时仍遵循既有 MySQL 副本回退。回退沿既有协调器切换旧制品，本次不包含数据库迁移。完整流式文件读写和生产备份恢复演练不在本次变更内。

## 考勤后台同步配置

当部署使用 `wao.scheduling.enabled=false` 时，普通 `@Scheduled` 考勤任务不会注册。维护者可在独立的生产私有配置中显式设置 `wao.attendance.scheduling-enabled: true`，仅开启已启用成员的 Moka 考勤后台同步；开发环境默认不启用。应用重启后自动注册，默认启动 10 秒后同步一次，此后每次完成后等待 15 分钟，成功后继续渐进补齐历史。

全局调度正常启用时仍沿用原有每刻钟同步，独立调度不会重复注册。普通网络或服务故障保留连接为可重试状态，下个周期继续；过期会话仅普通重登一次，验证码或接管确认仍暂停并在日历显示原因，不沿用过去的单次接管授权。

验收应观察生产服务自身的 `attendance-sync-` 线程日志和持久化刷新时间，而不能用手动调用服务代替。日志每周期仅记录可同步、成功和失败数量，不输出账号、远端响应或凭据。`wao.attendance.initial-delay` 和 `wao.attendance.sync-delay` 为 ISO-8601 时长，默认 `PT10S` / `PT15M`。
