# WAO Design System / UX 规范

日期：2026-09-19。对应产品体验审计 B17，并约束状态反馈、可理解性和后续页面新增。

本规范是**新改动的复用基线和存量迁移准则**，不是“全站已经统一”的验收声明。当前没有通用按钮、卡片、表单、空状态、加载状态或弹窗组件套件；不要假设它们已经存在。保留 WAO 现有视觉语言，每次只统一一个完整用户旅程。

## 1. 来源、适用范围与协作边界

- 运行时样式以 [tokens.css](../../wao-web/src/styles/tokens.css) 和 [base.css](../../wao-web/src/assets/base.css) 为准。当前为 Vue 3 / TypeScript / Ant Design Vue 技术栈，不采用旧原型中的框架建议。
- [原始设计交接](../../init-design/README.md)提供视觉来源；其中模拟登录、演示数据、旧导航和内容最大宽度不是当前行为依据。现有内容宽度 token 为 `none`，不得为了对齐旧原型重新限制所有页面。
- 业务状态、权限、保存和执行契约以当前规格及已采纳 ADR 为准。文案改进不能偷偷改变实际执行规则。
- 项目管理、知识库、小记、密码本、草图内部由对应维护者负责，本轮不批量迁移。共用壳层的修改要回归这些模块的入口与页签，但不顺手重写内部逻辑。
- 新页面优先使用下列已存在组件与变量。确需新增共用组件时先用一个真实流程验证，再逐步迁移；禁止仅为代码整齐全站替换。

## 2. 页面应让用户回答的七个问题

1. 这是做什么的？标题说明用户任务，副标题补充作用对象和范围。
2. 最重要的信息是什么？第一层先放当前任务、异常或结果，而不是系统配置和技术指标。
3. 我能做什么？一个主要操作，次要操作退到邻近工具栏或更多菜单。
4. 下一步在哪里？按钮用“动词 + 对象”，例如“上传文件”“重试保存”“创建任务并开始”。
5. 点击后发生什么？执行、发布、覆盖、付费、对外发送等后果在动作前可理解；不要用“确定”掩盖后果。
6. 没数据时如何开始？说明尚无数据的原因，提供真实创建/导入入口；不要拿加载失败当空数据。
7. 失败后如何恢复？保留输入与已成功的结果，明确可重试范围、原因和可行动的下一步。

首页起点参考 [起步引导规格](../specs/phase-1-home-start-guide.md)；功能目录参考 [浏览与整理分离](../specs/phase-1-navigation-browse-mode.md)。这些规则不要求所有页面变成同一种布局。

## 3. 视觉基础

### 3.1 颜色与层级

| 用途 | 现有变量 | 使用规则 |
|---|---|---|
| 主操作、当前选择 | `--wao-primary`、`--wao-primary-hover`、`--wao-primary-soft` | 每个操作区保持清楚的主次；选中不能只依赖颜色 |
| 页面与卡片 | `--wao-bg-page`、`--wao-bg-card` | 大背景和内容容器分层；不要每页创造另一套背景颜色 |
| 次级区域与悬停 | `--wao-bg-sub`、`--wao-bg-hover` | 辅助分组，不额外堆叠阴影 |
| 标题与正文 | `--wao-text`、`--wao-text-2`、`--wao-text-3` | 任务说明、字段标签、关键结果保持可读；不要把必要信息全部放进弱色 |
| 辅助信息 | `--wao-text-weak`、`--wao-text-faint` | 时间和非关键补充；弱色不代表可以省略对比度检查 |
| 边界 | `--wao-line`、`--wao-line-control`、`--wao-divider` | 区分卡片、交互控件和内容分隔 |
| 成功 | `--wao-success-strong`、`--wao-success-bg` | 必须有已完成事实；不能用于启用开关或“请求已受理” |
| 注意 | `--wao-warning-strong`、`--wao-warning-bg` | 即将受限、部分结果、需要确认或处理；同时给文字 |
| 错误/危险动作 | `--wao-danger-strong`、`--wao-danger-bg` | 区分执行失败与破坏性动作，不把一整页染红 |

深色模式复用同名变量。不要复制一套局部浅色常量后声称支持主题。品牌展示、图表分类和既有深色 Toast 可以保留明确例外，但新增例外要说明用途。当前未做全站对比度测量，token 存在不等于任意背景组合都合格。

### 3.2 字体、间距、圆角

| 项目 | 复用基线 | 注意事项 |
|---|---|---|
| 字体 | `--wao-font`；代码用 `--wao-font-mono` | 不为单页另加载字体；普通产品文案不使用等宽字体 |
| 页面标题 | 原设计 20–22px / 700 | 登录与文档标题有既有例外；不能用极大标题挤掉主任务 |
| 卡片标题 | 14px / 600 | 与正文区分，不靠不同渐变区分模块 |
| 普通正文 | 原设计 13–13.5px | 长段落优先采用文档正文尺度，不压缩为微型提示 |
| 文档正文 | 14.5px、行高约 1.95 | 长文本允许自然滚动；内容阅读优先于单屏塞满 |
| 辅助文字 | 11.5–12.5px | 不把错误、字段名和执行边界缩到 8.5/9px；原设计最小 10.5px 仅作非关键例外 |
| 卡片内边距 | 14–16px | 先按内容层级分组，避免嵌套卡片层层吃掉宽度 |
| 卡片间距 | 12–14px | 同一页面使用有限的节奏，不为每个块随意取值 |
| 控件尺寸 | 原设计主按钮 32–34px、输入 34–40px | 窄屏按实际触控可用性放宽，不能为保留一行而缩小按钮文字 |
| 圆角 | `--wao-radius-card` 12px、`--wao-radius-control` 8px、`--wao-radius-modal` 14px | 状态标签才使用 `--wao-radius-pill`；不要所有容器都做胶囊 |
| 阴影 | `--wao-shadow-card-hover`、`--wao-shadow-pop`、`--wao-shadow-modal` | 仅在对应层级使用，普通内容卡以边框为主 |

字号和间距目前没有完整的全局 token API；以上是现有设计尺度，不得直接引用不存在的 `--wao-space-*` 或 `--wao-font-size-*`。提取变量应与具体迁移一起交付。基础样式在窄屏将表单输入设为 16px，页面局部样式不应无意抵消输入可读性。

## 4. 已有组件与复用前提

| 组件/工具 | 可以复用 | 不应假设 |
|---|---|---|
| [MarkdownEditor](../../wao-web/src/components/ui/MarkdownEditor.vue) | 已有富文本/Markdown编辑、图片等输入能力 | 组件本身不替调用方负责服务端保存、成员隔离或失败重试 |
| [SaveHint](../../wao-web/src/components/ui/SaveHint.vue) | `saving`、`savedAt`、`failed` 的保存回执 | `failed` 文案声称“内容已留在本机”；仅在调用方确认草稿已落盘时适用。内存保留或存储失败必须另给真实状态，不能复用此承诺 |
| [WaoPagination](../../wao-web/src/components/ui/WaoPagination.vue) | 页码、跳页、上一页/下一页及禁用态 | 分页组件不负责后端查询、总数准确性和筛选条件恢复 |
| [ToastHost](../../wao-web/src/components/ui/ToastHost.vue) + [toast](../../wao-web/src/composables/toast.ts) | 状态播报、错误常驻、关闭、长文本换行、暂停计时 | Toast 不是表单唯一错误容器，也不代表操作可以重试 |
| [DemoBanner](../../wao-web/src/components/ui/DemoBanner.vue) | 辅助介绍或明确的演示提示 | 当前可关闭且 `storageKey` 读写未隔离成员/捕获失败；不得用作唯一、永久可见的成熟度标记或一般持久偏好组件 |
| [ResourceMenu](../../wao-web/src/components/ui/ResourceMenu.vue) | 现有资源菜单的按钮、定位和键盘实现参考 | 仍有业务图标依赖，不等于已经存在通用无依赖 Menu；本轮不改兄弟模块的使用方式 |
| [TabBar](../../wao-web/src/components/tabs/TabBar.vue) | 固定首页、页签打开/关闭/右键/拖动和键盘入口 | 不另造页面内部的全局页签持久化系统 |
| [AiSessionResult](../../wao-web/src/components/ai/AiSessionResult.vue) | 执行结果、材料、原因与下一步的现有展示 | 结果不等于验收；缺少结构化证据时不得猜测完成量或失败原因 |
| [useActionNoteDraft](../../wao-web/src/composables/useActionNoteDraft.ts) | 行动计划草稿保护的实现参考 | 是特定业务协议，不是可以任意替换全站保存逻辑的通用表单库 |

## 5. 按钮、卡片、表格和筛选

- 主按钮只承载当前主要动作；取消/返回使用次级样式，删除/覆盖等使用语义明确的危险样式和必要确认。
- 图标按钮同时有可访问名称和悬停说明。动态动作说明当前状态或下一步，例如“当前深色，切换跟随系统”。装饰图标不参与名称。
- 使用原生 `button`、`a`、`input`、`select`。可点击卡片内有独立操作时，不嵌套按钮；标题链接/按钮与菜单按钮分开。
- 表格第一列说明对象，状态有文字，行操作不依赖悬停才可发现。筛选后无结果要保留筛选条件并提供清除入口。
- 搜索输入应保留已输入内容；“无搜索结果”和“读取失败”分别展示。功能搜索继续使用 [navigationCatalog](../../wao-web/src/config/navigationCatalog.ts) 的原名、别名与用途。
- 窄屏优先换行或切换布局；确实需要横向浏览的表格提供明确滚动区域。不得缩小所有字来塞入视口。
- 数据指标应说明时间范围、单位、来源和更新时间。尚未读取用“读取中/暂不可用”，不是 `0`；历史快照不能标成实时正常。

## 6. 表单与弹窗

- 字段标签持续可见；placeholder 只放示例，不能替代标签。极简模式仍要保留可访问名称。
- 默认值有业务依据；用户已选值不可被后台刷新覆盖。高级参数可以折叠，执行范围、费用与不可逆后果不能藏在高级设置里。
- 保存状态放在编辑区附近：输入已变更、草稿保留、保存中、已保存、失败。按用户/记录隔离草稿，不能把别人的旧草稿恢复到当前表单。
- 正在保存时防止重复提交；保存以提交时快照为准，返回后不能清掉请求期间新增的输入。冲突时保留双方信息并要求明确解决，不能静默覆盖。
- 弹窗第一次出现就定位正确；使用已有 Teleport/浮层策略，先计算位置再显示。内容过长时让主体滚动，标题、关闭与主要动作保持可达。
- 弹窗提供标题关联、合适的 dialog 语义、进入焦点、键盘关闭和关闭后焦点恢复。未保存输入的关闭/跳转遵守现有草稿保护，而非一律丢弃。
- 弹窗内字段错误就地说明，并可回到错误字段；不把原始堆栈、密钥或不必要的内部配置暴露给用户。

## 7. 状态与反馈契约

| 状态 | 用户必须知道 | 操作/反馈 |
|---|---|---|
| 初始 | 功能用途、最短开始路径 | 一个可用主入口 |
| 空数据 | 当前确实没有记录、如何创建 | 创建/导入入口；不是伪造示例记录 |
| 读取中 | 正在读取哪个范围 | 保持布局稳定，不提前显示“暂无数据” |
| 执行/保存中 | 系统在处理、输入是否已保留 | 即时状态，防重复提交，不覆盖编辑 |
| 成功 | 哪一步已完成、结果在哪里 | 本地状态更新，必要时短 Toast；下一步可见 |
| 失败 | 失败范围、已保留内容、恢复方式 | 页面内错误与重试；输入不清空 |
| 部分成功 | 哪些成功、哪些失败、未知有哪些 | 保留已成功结果，只重试失败部分须有真实接口支持 |
| 无权限 | 当前操作不可用、合理的申请/返回入口 | 不伪装成空数据，不泄露无权对象详情 |
| 数据异常/过期 | 不能确认什么、旧值是否可参考 | 区分无效数据与有效的零值；重新读取 |

- 新错误 Toast 显式使用 `toast(message, icon, { tone: 'error' })`；默认状态消息约 2.6 秒，错误默认常驻。只在确有需要时改时长，不能借超短时长隐藏错误。
- `role="status"` 用于普通状态，`role="alert"` 用于需要立即注意的错误；避免轮询每次都重复播报整页。
- 需要用户修复的问题必须在页面留下恢复入口，不能只依赖已经消失的提示。先确保真实恢复，再增加动效。
- “请求已接受”“已排队”“执行结束”“发布成功”“用户已验收”分别描述；启用开关不是运行健康检查。

## 8. AI 产品交互边界

- 输入目标优先，系统已知的项目上下文和合理默认值应复用。来源不确定的推断显示为建议，不能伪造已配置账号或已连接电脑。
- AI 的计划、参数建议和结果摘要必须能核对依据；重要执行范围由用户看见并决定。
- 当前 Plan 沿用 [ADR-093](../adr/093-ai-run-codex-plan-mode.md)：先规划再自动执行，不能文案化成“只给方案”。首页与会话共用 [模式说明](../../wao-web/src/config/aiExecutionModes.ts)。
- 真正的“计划预览 → 用户确认 → 执行”需要独立的权限与状态契约，不能靠改按钮名称假装已经实现。
- 结果页先给结论、已保存材料和下一步，技术日志按需展开。未提供验收或完成证据时明确未知，不替用户宣布任务成功。
- 推荐下一步只创建可审阅的草稿或清楚的入口，不默默执行对外发送、发布或覆盖操作。

## 9. 新页面与迁移的交付条件

使用 [UX 验收清单](review-checklist.md) 记录证据。新页面必须先写一段用户任务和状态契约，再挑选已有组件与 token；不得先创造另一套 UI 风格。

本规范尚未解决的存量工作包括：各页按钮/卡片样式迁移、弱色与小字号对比度检查、可编辑页面的完整草稿恢复、演示成熟度常驻标记、弹窗的完整焦点管理及所有核心流程的新成员验收。它们继续按审计优先级独立交付，不通过批量改样式或勾选文档代替验收。
