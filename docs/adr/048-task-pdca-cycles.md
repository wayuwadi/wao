# ADR-048：PDCA 复用任务状态并在详情 JSON 保存多轮闭环

- 状态：已接受
- 日期：2026-08-11

## 背景

WAO 已有任务状态、步骤、子任务、日期和跨项目待办，足以表达计划与执行；但任务完成后只会进入归档，
没有结构化位置记录目标是否达成、偏差原因和下一次怎么调整。另建一套 PDCA 事项表会复制任务、权限、
日历、分享和 AI Run 链路，用户也要在两套系统之间搬运同一件事。

## 决策

- PDCA 作为任务的可选增强，P/C/A 使用 `task.detail_json.pdcaCycles[]` 持久化；D 直接投影任务状态与步骤进度。
- 每次闭环保留一轮不可覆盖的记录。开启下一轮时新增轮次，把上一轮 `act` 带入新轮 `plan`，并把任务重开为待办。
- 不为 PDCA 新增数据库表或状态值。阶段是展示投影，不参与现有任务状态机、通知和 AI Runner 协议。
- 只有明确带轮次的任务进入 PDCA 汇总，历史普通任务不做猜测性迁移。
- 任务公开分享包含 PDCA 记录；它与描述、子任务一样属于用户主动分享的任务上下文，不包含成员、评论和活动。

## 结果

- 日常事项沿用现有真实数据源、草稿防丢、多人同步、日历和 AI 能力，同时补齐持续改善闭环。
- 多轮记录会增加 `detail_json` 大小，但个人任务的短文本轮次远低于 MySQL JSON 容量；若未来需要跨任务统计或全文检索，
  再迁移到独立关系表，当前 DTO 已给轮次稳定 id。
- 已复盘轮次在界面只读；需要修订时通过新一轮记录新认识，避免事后覆盖历史结论。
