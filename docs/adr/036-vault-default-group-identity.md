# ADR-036：密码库默认分组按标记识别，不按名字识别

## 状态

已采纳。取代 ADR-024 中「未分组按名称识别」的那一条，ADR-024 的其余决定（归属到人、越权按 404）继续有效。

## 上下文

ADR-024 把「未分组」从全局唯一的 `vg-default` 改成每人一个，识别方式定为**按名字**（`name == '未分组'`），
插入时用固定 id `vg-default-<memberId>`。

这两件事凑在一起有个洞：分组名是用户自己的，可以随便改。成员一旦把自己的「未分组」改名，
`ensureDefaultGroup` 就再也找不到它，于是每次都去插入 `vg-default-<memberId>`——这个主键已经被那行占着，
`DuplicateKeyException` 冒到 `GlobalExceptionHandler` 变成 `409`。而 `ensureDefaultGroup` 是
`GET /api/vault` 的第一步，结果是这个成员的**整个密码库再也读不出来**。

线上就是这么坏的：`vg-default-wd` 被改名成 `Amer` 之后，该成员每次进密码库都拿到 409。
前端 `hydrate()` 对每个域独立容错，读失败就保留 fixtures，于是页面上摆出一整屏演示凭据——
用户看到的是「密码本一直只显示假数据」，看不出后端在报错。

## 决策

- `vault_group` 新增 `is_default`，默认分组的身份由这一列维持，与名字无关：改名之后它还是默认分组，
  仍然不可删除、仍然是新建条目的默认落点。
- 名叫「未分组」但没有标记的分组就是普通分组，可以正常删除——名字不再有特殊含义。
- 存量数据在 V45 里按 id 还原标记（`vg-default` 与 `vg-default-<memberId>` 两种历史写法），
  同一成员命中多行时只保留一行。
- 默认分组的 id 仍优先取可读的 `vg-default-<memberId>`，但**先查再插**；被占用或超过 32 字符时退回时间戳 id。
  并发插入撞车时捕获 `DuplicateKeyException` 并复用赢的那一行，读列表不因为写竞争而失败。
- `VaultGroupDto` 增加 `isDefault`，前端据此判断默认分组，不再自己按名字猜。

## 后果

- 改名不再打断读取；已经踩坑的成员在 migration 之后立刻恢复，不需要人工改库。
- 前后端对「哪个是默认分组」的判断收敛到同一个字段，不会再出现「后端不让删、前端却显示可删」这种分歧。
- 读密码库仍然会在缺默认分组时写一行（懒创建），这是 ADR-024 就有的行为，本次只是让它幂等。
- 配套的两处兜底也一并收紧：`GET /api/vault` 失败时前端不再退回 fixtures，而是清空并显示错误与重试
  （真实凭据页面上出现演示条目，比空着更糟）；`DataIntegrityViolationException` 的日志带上根因，
  否则任何唯一键冲突在日志里都长得一模一样，只能靠翻库定位。
