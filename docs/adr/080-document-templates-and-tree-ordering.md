# ADR-080：文档模板使用独立快照表，文档树排序整树原子提交

## 状态

已采纳。

## 上下文

知识库文档已有 `folder_id` 与 `ord`，但界面不能调整顺序或跨文件夹移动；模板则完全没有真实数据源。若把模板做成前端固定选项，用户另存的内容无法跨设备恢复，也会违反真实业务数据必须后端持久化的原则。逐篇 PATCH 拖拽结果还会产生中间态：部分请求成功、部分失败后，树中可能重复或遗漏文档。

## 决策

- 模板存入独立的 `doc_template` 表，不把模板伪装成普通文档。正文沿用 `DocBlockDto` JSON 快照，来源文档删除后模板仍可使用。
- 模板按 `created_by` 隔离；服务端从当前会话确定成员，列表、修改、删除及从模板创建均校验归属。
- “另存为模板”提交编辑器当前正文块，避免 600ms 自动保存窗口内点击按钮时复制到旧版本；同时保留 `source_doc_id` 供追溯。
- 从模板新建文档时，服务端在同一事务内校验知识库、文件夹与模板归属，再复制正文。新文档标题仍为空，让用户按当天或当次用途命名。
- 拖拽提交知识库当前全部文件夹与文档 id。服务端验证文件夹和文档恰好各出现一次，再在事务内写入 `folder_id + ord`；任何遗漏、重复、跨库 id 都整体拒绝。
- 前端先乐观展示拖拽结果；保存失败恢复旧树，并保留目标顺序供“重试”。

## 后果

- 模板是可跨设备恢复、可管理的真实数据，不依赖演示 fixtures。
- 拖拽一次请求即可完成同文件夹排序或跨文件夹移动，不暴露部分成功状态。
- 整树请求大小随单个知识库文档数增长；当前个人/小团队规模可接受。若单库达到数万篇，再改为带版本号的局部移动命令。
