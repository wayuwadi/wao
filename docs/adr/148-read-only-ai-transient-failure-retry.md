# ADR-148：只读 AI 在最终失败前完成三次有界尝试

## 状态

已采纳。

## 背景

ADR-138 已让开发型 AI Run 在 AI CLI 非零退出或调用异常后按项目配置恢复，默认是首次执行加两次重试。
聊天复盘、人生复盘、周报、每日建议、网页助手、文档润色和点子调研则共用另一条只读 AI 链路：本地 Codex
或服务端模型 API 一次瞬时失败就进入终态，用户仍要手工点击重试。定时预热使用同一链路，因此也会把偶发故障
直接计为本轮失败。

不能在通用自动化执行器外层无条件重放。部分执行器会创建任务、发送通知或同步外部数据；请求已经产生副作用但
响应丢失时再次执行，可能制造重复任务和消息。

## 决策

- 本地只读 Codex 的一次领取最多执行三次，三次共用同一个业务运行、临时空仓库、安全沙箱、提示和硬截止时间。
  非零退出、调用异常和空答复可重试；中间部分输出全部丢弃，只向服务端回传最终成功答复或第三次失败。
- DeepSeek 与受信模型网关的 Chat Completions 最多请求三次。网络异常、HTTP 408 / 425 / 429 / 5xx、空响应和
  空答复可重试；鉴权、参数等其他 4xx 立即失败，内容截断要求用户缩小材料，不做无意义重放。
- 每次模型 API 重试使用短退避；线程中断立即停止并保留中断标记。三次尝试不切换账号、模型或供应商，不把故障
  隐藏成伪造结果。
- AI Run 继续使用 ADR-138 的项目级配置。自动化任务不增加通用外层重试；其中的开发 AI Run 和只读 AI 生成分别
  由各自幂等执行边界恢复，通知、同步和业务写入不被盲目重放。
- “三次”统一指最多三次总尝试，即首次失败后最多自动重试两次。业务正常返回的拒绝、用户阻塞和校验明确不可恢复
  的输入错误不属于瞬时故障。

## 后果

复盘、报告、建议、调研和网页只读 AI 的偶发 CLI 或模型网关故障不再立即要求用户介入；三次都失败时仍保留真实
最终错误。代价是失败请求可能延长等待并增加模型用量，但次数、硬截止时间和可重试状态均有上限。
