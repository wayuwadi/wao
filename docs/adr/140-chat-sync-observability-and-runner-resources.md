# ADR-140：聊天同步按指纹增量核对，Runner 上报机器资源

## 状态

已采纳。

## 上下文

共享聊天已经能双向桥接飞书，但双节点各自保存内存水位，会重复拉取相同窗口；每分钟编辑回看也会重新解析
未变化消息，图文消息尤其可能重复下载并转存图片。用户还无法看到夜间当日核对一次新增了多少聊天内容，
也无法在同一页面比较多台已连接执行电脑的 CPU、内存与磁盘余量。

Prometheus、Grafana 和主机 Agent 能提供更完整的时序监控，但现有架构明确不运行整套监控栈；为本需求引入新的
高权限常驻 Agent 也会扩大部署与隐私边界。现有 Runner 已经以十秒心跳连接 WAO，适合上报不含进程、用户和
目录明细的有界资源快照。

## 决策

- 飞书入站消息保存由正文、删除状态、回复关系与发送者组成的 SHA-256 指纹。指纹未变化时不解析正文、不下载
  图片、不写消息；变化时仍覆盖同一 `feishu_message_id`。
- 实时新消息和一天编辑回看分别使用主库中的水位与十分钟租约；同一时刻只有一个后端节点访问飞书，整批成功
  才推进水位，失败释放租约并保留原水位。
- 自动化每天上海时间 00:10 核对前一自然日，手动入口核对当日。每次运行记录扫描、新增、更新与“新增正文
  UTF-8 字节 + 新下载图片原始字节”；该口径可归因但不冒充 MySQL 索引页或文件系统精确分配量。
- Runner 使用 Python 标准系统接口读取 CPU 核数和区间利用率、物理内存、Runner 工作盘容量与余量，通过既有
  鉴权心跳持久化。不上报进程、用户名、完整目录、文件列表或凭据；旧 Runner 明确显示等待新版上报。
- 机器资源复用 AI 控制台“执行电脑”视图，聊天核对历史放在聊天页双向同步面板，不增加重复一级菜单。

## 后果

- 历史总量增长不会扩大实时同步窗口；一天回看仍受当日消息量影响，但未变化图文不再产生图片下载和磁盘增长。
- Runner 指标是最近一次心跳快照，不是长期监控时序；节点离线时页面保留采集时间，不能把旧值当作当前在线值。
- 聊天任务空间指标用于比较每次同步的业务内容增量；需要数据库文件、容器层或整机历史趋势时应另立运维监控
  方案，并明确采集权限。
