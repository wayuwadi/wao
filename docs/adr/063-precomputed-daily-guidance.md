# ADR-063：首页每日建议改为主节点定时预生成

## 状态

已由 ADR-151 重新启用并调整用途。主节点预生成、成员隔离、只读 Runner 和当天缓存边界保持不变，生成内容改为成长教练。

## 背景

ADR-062 已把建议按成员和自然日保存，但当天没有缓存时仍由首页请求同步触发 Codex。这样每天首次访问仍可能等待
最长五分钟；页面刷新也会先展示“正在读懂处境”的生成态，和“打开即看”的用户结果不一致。

WAO 的 `member`、`task`、`project` 与 `member_preference` 已是权威数据源，Linux 主节点也已有唯一启用的后台调度
职责，因此无需新增演示数据、模型接口或建议表。

## 决策

- Linux 主节点启动两分钟后开始检查，此后每三十分钟为全部真实成员补齐当天缺失的 `daily-guidance` 缓存；已有
  当天结果时不调用 Codex。跨过上海时区自然日后，下一轮检查生成新一天的数据。
- 从节点不启用该任务，避免双节点重复生成。单个成员生成失败不阻断其余成员；Runner 离线或本轮失败时保留缺失
  状态，下一轮自动重试，不写入固定文案冒充结果。
- Codex 最长五分钟的同步等待放进专用单线程执行器，调度线程只负责投递；上一批尚未完成时跳过新批次，避免
  阻塞行动提醒、自动化、日历同步等其它 Spring 定时任务，也不堆积重复批次。
- 首页挂载只调用 `GET /api/daily-guidance` 读取预生成结果，缓存缺失时不再自动调用耗时 `POST`。用户明确点击
  “换一组”仍可同步生成并覆盖当天结果。
- 成功读取的当天结果按成员写入浏览器 `sessionStorage`。同一标签页刷新时先立即展示该副本，再在后台用服务端
  权威结果校准；关闭标签页后不长期保留这份任务衍生内容。

## 后果

- 正常情况下，成员首次打开当天首页时结果已在服务端准备完成；同一标签页刷新连短暂的读取占位也不会出现。
- 凌晨 Runner 持续离线、刚创建成员或当天预热尚未完成时，首页会诚实说明后台正在准备并允许重新读取，但不会
  把等待转嫁成一次页面内模型调用。
- 当前成员规模适合串行预热。若成员数增长到单批三十分钟仍无法完成，应基于真实执行时长设计限流队列，而不是
  直接提高并发占满日常 AI Runner。
