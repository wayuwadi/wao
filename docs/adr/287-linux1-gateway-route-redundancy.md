# ADR-287：云端为 Linux1 Gateway 保留两条独立回源路径

状态：采用（2026-09-27）。补充 ADR-158 的反向 SSH 回源方案；数据库写主与复制角色不变。

## 故障证据

2026-09-27 09:21，公网就绪请求超时，云端到 Linux1 的 `127.0.0.1:9000` 反向 SSH
隧道在五秒内无法连接；同一时刻 Linux1 本机 Gateway 返回 200，云端经 WireGuard
`10.66.0.3:9000` 和 Linux1 公网 IPv4 直连均在约 0.08 秒内返回 200。Linux2 Gateway
也可响应，但其业务数据库仍依赖 Linux1 写主，不能把单次容器健康当作整站可用。

## 决策

- 云机 `/etc/hosts` 保留 `linux1.wayuwa.cn → 127.0.0.1` 作为反向 SSH 通道身份。
  当解析到该云机专用 loopback 映射时，Gateway 渲染和优先就绪探针改用固定的
  WireGuard 私网地址 `10.66.0.3:9000`。其他主机维持原有解析行为。
- Nginx 将原 `127.0.0.1:9000` 设为备用上游。计划摘流 Linux1 时，私网与
  反向 SSH 两条地址必须同时标记为 `down`；不能让备用地址绕过发布摘流。
- Jenkins 从云机核验 Linux1 时先探测 WireGuard，再探测反向 SSH。两条均失败
  才认定 Linux1 不可回流。Nginx 配置继续使用 IPv4 字面地址并通过 `nginx -t`
  与原子重载校验。

## 边界与回退

该变更只解决云机到 Linux1 Gateway 的单路径故障。Linux2 到 Linux1 写库链路、
`wao-return` 复制和家庭上行压力仍需单独修复。ADR-253 曾记录 WireGuard 上的大附件
吞吐不佳；上线后须用真实图片/附件下载验证，不能用小型就绪响应替代。
若私网大流量无法接受，恢复 ADR-158 的 SSH 隧道主路由并保留私网备路由，或在
维护窗口内重新测量后调整；不得禁用数据库就绪检查来消除告警。
