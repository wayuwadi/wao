# ADR-195：考勤以可逆覆盖存储，并通过加密 Moka 员工会话联动每日节奏

- 状态：已接受
- 日期：2026-09-03

## 背景

成员需要在 WAO 日历查看自己的 Moka 考勤、工时与缺卡，并让真实打卡自动完成每日节奏，而不再每天手点“完成”。
Moka 有官方开放平台考勤接口，但开放平台需要企业授权和 API 密钥；当前可用条件只有成员登录邮箱与稍后放入个人密码本的
密码。Moka 当前员工端提供统一账号登录及“我的出勤”数据接口，但它属于站内接口，可能随 Moka 发布变化。

旧版今日节奏规格明确不接公司真实考勤；这个边界已不能产生目标结果，需要以本 ADR 和新规格显式替代，且不能因此
放宽密码本的成员隔离或把远端失败伪装成成功。

## 决策

- `attendance_connector` 每个成员一行，仅引用其密码本条目；会话以 `WAO_VAULT_KEY` 做 AES-256-GCM 加密，密码明文只在
  发起登录的调用栈中短暂存在。
- 登录使用 Moka 当前统一账号流程，明确不传 `force`。验证码、并发会话确认或登录失败均转为需要用户处理的状态；缓存
  会话失效后只自动重登一次。
- `attendance_day` 将远端值与手工模拟值分栏保存，`manual_override` 决定有效值。恢复操作只清空模拟栏，远端原值不丢失。
- 只落库计算所需的上下班时间、工作日/请假/休息类型和异常摘要，不保存远端原始 JSON、位置、照片或附件。
- 工时统一按分钟先扣除 60 分钟午休，再换算成两位小数小时。上下班不完整或请假时工时为空；周均、日均仅以有工时的
  非请假日为样本，避免用请假或缺卡稀释结果。
- 工作日判断复用今日节奏的大小周和当天覆盖结果。考勤只同步 `CLOCK_IN` / `CLOCK_OUT` 系统项，并增加
  `completion_source=ATTENDANCE`；同步只可改写同来源值，不能覆盖用户手动完成事实。
- 定时器每 15 分钟先同步当天，成功后再按自然月向前补齐一段，直至覆盖包含本月在内的近 12 个月；历史游标只在整段成功后推进，失败可续跑，并以带超时的数据库租约避免多应用节点重复请求。打开当天每日节奏时仍只对超过 5 分钟的当天缓存做一次尽力刷新，外部失败不阻断面板。
- 前端在既有日历提供考勤模式开关和范围指标，不新建第二套日历。考勤始终限制为当前成员本人。

## 远端兼容边界

当前实现基于 2026-09-03 Moka 员工端实际发布资源核对的登录与考勤路径，并为地址提供部署配置覆盖。解析器只读取稳定的
语义字段并容忍外层包装变化。若企业后续提供官方开放平台凭据，应另立变更迁移到
[Moka 官方开放平台考勤接口](https://people.mokahr.com/docs/api/view/v1.html)，而不是长期扩大站内接口耦合。

## 后果

- 日历、大小周、考勤和每日节奏使用同一份工作日与打卡事实；用户仍可用可逆模拟值验算跨日、请假和缺卡场景。
- 密码不会出现在考勤表、接口响应、日志或提交历史中；服务端与 `WAO_VAULT_KEY` 同时失陷的信任边界仍与密码本一致。
- 首次真实同步必须由成员在密码本保存 Moka 密码并在考勤设置中选择该条目；未完成前只能验收手工模拟与内部联动，系统
  必须显示“尚未配置”，不得声称已经同步 Moka。
