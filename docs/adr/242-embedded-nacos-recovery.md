# ADR-242：保护现有嵌入式 Nacos 的完整恢复点

## 状态

已采纳。保持 ADR-001 的目标基线；本变更不升级实际运行的 2.3.2。

## 背景与决策

2026-09-20 实机 Nacos 为 standalone、无 Docker 挂载，Derby 和协议数据在容器可写层。
现有 WAO SQL / 部署配置备份不包含这些数据。重建容器可能丢失配置及权限。

先保留当前版本，获取干净停机后的完整容器镜像和检查信息，再启动原容器。
拒绝外部数据库、挂载卷、非 standalone、强制终止退出码，以及快照期间容器重新启动。
由独立 systemd 定时器在 120 秒后尝试重启原容器，脚本退出也执行恢复。
这不是不停机快照，也不是 Nacos 自动高可用。

Jenkins 部署持有共享维护锁，Nacos 停机和重新就绪窗口持有排他锁。
必须先安装 tmpfiles 锁文件，并确认新版部署脚本生效，才启用每日备份定时器。
手工应用重启也需取得同一共享锁。备份加密和传输不继续占用维护锁。

完整镜像包含认证配置，原始暂存目录权限 0700，归档仅加密后跨机传输；
成功后清理镜像标签和暂存目录。两端保留至少七份且七天内不清理。
原来的运行容器、配置、镜像版本不被替换。

Linux1 恢复使用 network none、不映射端口、无生产卷、1 CPU、1.5 GiB、512 PID；
限制 JVM 可见 CPU 为 2，避免 Java 8 按宿主核心数创建过多线程。
校验原镜像 ID、就绪、现有账号认证、全部命名空间及配置正文摘要一致后清理。
它验证恢复点可启动及配置可读，不冒充已经完成客户端切换、权限矩阵或 Nacos 故障接管验收。

## 运维

Linux2 每日 03:50（随机两分钟）备份；Linux1 独立检查超过 30 小时未完成、空间和恢复失败，
每月首个周日 06:15 做隔离恢复。30 小时是告警阈值，不是保证的 RPO。
安装步骤和实际证据见 `docs/runbooks/nacos-recovery.md`。
