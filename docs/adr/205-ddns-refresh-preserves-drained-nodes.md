# ADR-205：摘流期间持续更新健康节点的公网地址

## 状态

已采纳，修订 ADR-051 对 DDNS 暂停的处理。

## 背景与决策

2026-09-08 登录和小记保存出现 502/504。云端仍指向主节点旧公网地址；主节点新地址健康，从节点的 `slave.down` 使 `deployment.lock` 长期存在，每分钟地址刷新一直跳过。

摘流标记表达节点是否接流，不再充当整个地址刷新流程的锁。自动刷新读取并保留 `master.down` / `slave.down`，仅当未摘流节点健康时更新地址。刷新和手动摘流共用 `flock` 进程锁，串行化读取状态、渲染、校验、重载，避免并发刷新把摘流节点恢复。进程结束自动释放锁；旧 `deployment.lock` 保留兼容但不再阻止地址刷新。两个节点都摘流时保留现有配置。

## 验收

回归覆盖长期从节点摘流、旧锁残留、主节点地址变化后正确更新且从节点仍为 down、持锁时跳过、配置不变不重载、校验失败回滚，以及原有摘流时旧 worker 退出行为。线上先通过现有摘流脚本重新渲染主节点地址恢复服务，再由 PR 发布固化。
