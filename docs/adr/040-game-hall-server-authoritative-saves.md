# ADR-040：游戏厅采用服务端权威规则与通用成员存档

## 状态

已采纳。

## 上下文

WAO 需要加入可以随手玩、关掉后继续、长期挑战个人纪录的小游戏。首个游戏是 4×4 数字合成，但后续还可能加入每日猜词、数独或记忆挑战。如果每个游戏都把状态只放在浏览器，换设备会丢档；如果每个游戏各建一套账号和存储，后续扩展成本又会快速增加。

游戏分数和随机出牌也不能只由前端提交最终结果，否则多个页面会互相覆盖，历史纪录无法证明来自一串合法操作。

## 决策

- 新增 WAO 原生一级模块“游戏厅”，默认位于“工具”组，并进入现有内置菜单注册表，名称、图标、分组、排序和显隐仍可配置。
- 用 `game_save` 保存成员在每个 `game_key` 下唯一的活动存档，用 `game_run_record` 保存结束或主动重开的历史战绩；这两张表供后续小游戏复用。
- 首个游戏键为 `number-merge`，页面名为“数字熔炉”。移动、合并、计分、随机生成 2/4、胜利与终局判断全部在 Java 服务端执行，前端只提交方向。
- 每份存档带单调递增的 `revision`。移动、撤销和重开都使用 `WHERE id = ? AND revision = ?` 条件更新；旧页面提交过期版本时返回 409，并重新读取服务端快照，不覆盖新存档。
- 活动存档保存一步前态，允许撤销最近一次有效移动。主动重开会把走过至少一步的棋盘归档，结果分为 `WON`、`GAME_OVER`、`RESTARTED`。
- 达成 2048 后不强制结束，玩家可以继续挑战 4096、8192；历史最高分、最高数字、累计步数、对局数与达成次数跨设备累计。

## 后果

- 页面刷新、重新登录或更换设备后都能继续当前棋盘，历史成绩归属当前 WAO 成员。
- 服务端每次有效移动都有一次数据库写入，换取可恢复、可并发保护的真实存档；小游戏规模下该负载可接受。
- 新增规则不同的游戏时可以复用通用表和游戏厅入口，但仍需为该游戏实现自己的服务端规则校验，不能直接信任前端分数。
- 内置菜单注册表从旧版本升级时会保留已有八项的用户定制，并自动补入“游戏厅”默认项，避免新增模块清空旧配置。
