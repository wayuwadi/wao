# ADR-165：每次 AI Run 都产出用户可读的 HTML 报告

## 状态

已采纳。

## 背景

ADR-055 建立了 AI Run HTML 报告的上传、隔离托管和任务关联能力，但为了避免普通小改动产生占位文件，
当时把报告定义为可选产物。实际使用中，用户需要从每次运行统一回看 AI Plan、关键判断、功能入口和人工验收方法；
报告可选会导致同一入口时有时无，也让失败运行缺少可分享的执行档案。

用户需要的是可审阅的公开判断依据，不是模型内部隐藏推理。单元测试、自动化测试、构建和部署等系统级检查继续保留在
提交、PR、运行摘要和 CI 日志中，不重复写入面向功能验收的 HTML 报告。

## 决策

- Runner 提示每次开发型 AI Run 都必须在运行级路径生成 UTF-8 单文件 HTML 报告，不再由 AI 判断是否值得生成。
- 报告固定覆盖本次公开 AI Plan、面向用户的关键判断与取舍、改动后的应用功能入口，以及用户可直接执行的验收步骤和
  真实结果；不得记录隐藏思维链、凭据、命令参数、单元测试、自动化测试、构建或部署检查。
- Runner 继续只采集可显示在 WAO 时间线里的 `plan` 与用户可读消息，明确排除 thinking、命令、文件和工具调用。
  如果 AI CLI 在写报告前异常结束，Runner 用这些公开内容、任务地址和终态生成最小兜底报告；缺失信息明确标注未知，
  不伪造功能入口或验收结果。
- AI 生成的报告仍优先上传。已有报告为空、超限、编码错误或上传失败时继续把本次运行标记为失败，不用兜底覆盖坏文件，
  避免把产物错误静默伪装成成功。
- 报告仍复用 ADR-055 的 10MB 限制、隔离托管、稳定 URL、继续优化覆盖和本机清理规则。任务执行档案与首页 AI Run
  详情沿用 `reportUrl`，统一把入口标为“HTML 报告”。

## 后果

- 成功、失败和执行前异常的开发型 AI Run 都有稳定报告入口；报告的信息密度按真实公开内容变化，但不再缺席。
- 运行摘要、Git 历史和 CI 日志仍是系统级验证证据的权威来源，HTML 报告专注于用户如何找到和验收功能。
- Runner 脚本更新后新领取的运行才执行强制报告规则，既有历史运行不回填没有生成过的报告。
