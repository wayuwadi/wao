# ADR-262：Jenkins 运行时探针与触发兜底

## 状态

已接受（2026-09-24）。补充 ADR-099、ADR-144；保持 main 单并发和五分钟批处理。

## 问题

2026-09-24 06:21 Linux2 原地更新 OpenJDK 21，02:38 启动的 Jenkins JVM 未重启。
页面和签名 webhook 仍可返回成功，但 SCM polling 无法启动 `cp`，报
`Failed to exec spawn helper`，并在失败日志末尾显示 `No changes`。
作业停留 #473，提交没有进入队列，常规构建失败通知也不会运行。
10:26 重启后 Git 检查恢复，重新投递 main push 自动生成 #474。

## 决策

- 外置 systemd timer 每两分钟从 loopback 检查**正在运行的 JVM**能否启动 `/usr/bin/true`。
  通过既有本机反向代理认证和 CSRF crumb 请求固定只读 Groovy 探针；不开放新的公网入口、不保存令牌。
- 只有明确的 spawn-helper 错误连续两次、间隔小于五分钟、没有运行构建且控制器未 quiet down 时，
  才请求既有 `/safeRestart`。重启尝试前持久化三十分钟冷却，响应丢失也不重复重启。
  HTTP 失败、Git 网络故障、其他进程错误只报告，不强杀、不重启服务器、不关闭 JDK 安全更新。
- 状态保存在 `/var/lib/wao-jenkins-health/status.json`，异常使 oneshot 单元失败并写 journal。
  同时列出当前构建和排队原因，报告超过十五分钟的队列、超过六十分钟的构建、最近十分钟的 SCM polling 错误。
  此阶段不新增对外通知渠道；用户仍可通过既有 Jenkins 页面和系统日志查看。
- main 作业保留 GitHub push，增加 `H/5 * * * *` SCM 轮询，只在检测到变更时补触发，
  用于漏投 webhook、维护重启后尚未构建的提交。仍使用五分钟静默窗口与单并发，不定时空跑发布。
- 探针与单元由控制器安装和版本化配置更新一并管理；恢复机制本身不依赖构建能否启动。

## 验证与限制

恢复策略用故障注入单元测试验证。真实控制器只执行只读探针，核对运行构建、队列及子进程正常，
不在生产替换 JDK 或制造故障。无法连接控制器时保留错误并等待人工处理；无外部告警服务时 journal
不能替代主动通知。构建内部数据库、网络和测试失败仍由原流水线报告，不用重启掩盖。

## 回退

停止并禁用 `wao-jenkins-health.timer`，从 main 作业移除 SCM 定时轮询并同步本文件对应配置。
保留 GitHub push 触发。不要修改凭据、删除构建历史或中断正在运行的发布。
