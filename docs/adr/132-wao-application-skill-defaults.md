# ADR-132：WAO 应用级 Skill 使用固定版本默认装配

- 状态：Accepted
- 日期：2026-08-27

## 背景

ADR-095 已实现项目显式绑定审核 Skill、运行快照和 Codex 隔离装配，但同一个通用 Skill 仍要在每个
项目重复选择。WAO 作为 AI Run 的能力治理方，需要能把少量长期通用能力设置为“对 WAO 应用生效”，
并让后续新建运行自动发现，而不是要求每台 Runner 或每种 AI CLI 各自安装。

当前没有通用 MCP 注册表、运行级短期凭据签发和跨 CLI MCP 适配器。只增加一个 MCP 开关不会让工具在
运行中真实可用，还可能让个人 MCP 权限进入组织任务，因此不能把展示状态冒充运行能力。

## 决策

- 新增 WAO 应用级 Skill 绑定，管理员从市场当前公开的 Codex Skill 中选择最多十个固定审核版本。
- 新 AI Run 入队时合并 WAO 应用级绑定与项目绑定；同一 Skill 同时存在时项目固定版本优先，历史运行
  继续保留当时的版本、哈希和来源，不受后续设置变化影响。
- Runner 继续复用现有不可变包下载、SHA-256 校验和运行级 `CODEX_HOME` 装配，不继承电脑上的全局 Skill。
- 运行详情显示能力来自“WAO 默认”还是“项目设置”，管理员可从系统设置查看加载、空数据、保存中、
  已保存和失败重试状态。
- 非 Codex 引擎仍失败关闭，不静默忽略已启用 Skill。跨 KAI 适配必须在真实适配器完成后逐一开放。
- 本期不创建通用 MCP 仓库或无效的“对 WAO 生效”开关。后续实现必须同时具备端点注册、工具白名单、
  Secret 引用、短期运行凭据、Runner 适配和调用审计，且不能继承个人 MCP 授权。

## 影响

- 管理员只维护一次通用 Skill，所有项目之后的新 Codex Run 都能得到同一审核版本；项目仍可显式覆盖版本。
- 修改或撤销默认绑定是可逆操作，只影响之后入队的运行。
- 启用 WAO 默认 Skill 会使非 Codex 运行在入队前明确拒绝，直到对应 KAI 适配器真实可用。
- MCP 需求保持未实现状态，页面和接口不展示伪连接、伪工具或不可执行的配置。
