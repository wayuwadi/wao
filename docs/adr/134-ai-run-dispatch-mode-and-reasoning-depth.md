# ADR-134：AI Run 明确选择批量派工方式和思考深度

- 状态：Accepted
- 日期：2026-08-27
- 调整：[ADR-091](091-ai-run-model-selection.md)、[ADR-113](113-merged-task-ai-run.md)、[ADR-124](124-ai-run-high-reasoning-default.md)

## 背景

项目任务列表的批量接口已经支持逐条创建运行与合并为一次运行，但页面只展示“合并给 AI”，用户无法继续使用
彼此独立的上下文、分支和验收链路。首页自主目标入口也没有展示单次 Codex 思考深度；已有派工面板只有
`medium / high`，无法为低复杂度工作主动换取更快响应和较低消耗。

批量派工方式和思考深度都会改变实际运行边界，不能只做前端标签：选择必须进入原有受控接口、持久化运行记录并
由 Runner 明确执行。

## 决策

- 项目任务列表选中任务后同时提供“单独给 AI”和“合并给 AI”。单独模式为每条任务创建独立 AI Run；合并模式
  仍要求至少两条同项目主任务，并沿用 ADR-113 的同一上下文、分支、通知和状态联动。
- 页面初始仍不选任务且不提供全选；只有一条任务时只显示“单独给 AI”，避免把等价操作误称为合并。
- Codex 受控推理强度扩展为 `high / medium / low`，默认仍为 `high`。前端所有选择器都读取服务端允许列表，
  不自行维护枚举或默认值。
- 首页自主目标在 Codex 工作流下展示高、中、低思考深度，并将本次选择随目标一并入队；其他 AI 工具不展示、
  不提交无效参数。
- 单次选择继续固化到 `ai_task_run.reasoning_effort`，领取协议原样下发给 Runner；运行详情必须正确展示低档，
  未知未来值原样显示而不误标为中档。

## 结果

用户可以按任务是否共享上下文选择批量运行边界，也能在首页按复杂度选择单次思考投入。接口、数据库记录、
Runner 参数和运行档案保持一致，不会出现页面显示一种方式而后台按另一种方式执行。
