# ADR-271：首台可验证通知与完整发布时间

- 状态：已采纳
- 日期：2026-09-24
- 来源：用户希望在第一台服务器完成后先验证产品，并在飞书卡片直接看到发布时间
- 调整：ADR-157 的常规发布顺序与 ADR-234 的单张成功通知

## 决策

常规完整发布先更新 Linux1 并确认新镜像和网关健康，然后从公网摘除旧版 Linux2，把新版网页发布到云端。只有云端路由确认为 Linux1 独立承载、网页版本为目标 Git SHA、公共 API 可用时，才发送“首台发布完成，可先验证”的蓝色阶段通知，附正式 WAO 入口和北京时间。随后继续更新 Linux2；双节点和公共入口均通过后发送绿色最终成功通知，附最终完成时间、从拉取代码起的耗时与本次改动。

蓝卡只表示 Linux1、新版网页和普通公网 API 可验证，Linux2 独有的 Codex 出站、部分 AI/运维路由仍需等绿卡。首台完成不提前回写 GitHub 成功状态，也不把 Jenkins 构建标为成功。若后续失败，再发送红色失败卡并注明首台曾就绪。

从库首次重建、显式允许离线、或特殊数据库维护窗口跳过阶段通知，继续按 Linux1 → Linux2 → 云端完成后通知。仅网页改动沿用静态快路径，只发送最终结果。通知遵守既有成功消息策略；策略不可用时不阻断部署，失败告警仍保留。

## 影响

普通功能的人工验证可以与 Linux2 发布并行。新版网页会在 Linux2 仍为旧版时先对用户可见；公网普通 API 在此期间只走已更新的 Linux1，主节点专属路由可能暂时运行旧版，因此阶段卡明确限制验证范围。完整发布失败时仍保留失败结论，不以阶段卡代替最终成功。
