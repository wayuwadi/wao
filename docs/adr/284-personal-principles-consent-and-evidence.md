# ADR-284：多人准则按成员确认，提示只基于可归属的事实

状态：实施中（2026-09-26）。

## 背景

WAO 浏览器版需要多人共同制定生活准则，支持红线、必做、多做、少做、可以做、暂不做和建议，并在首页以很小的自留地提示当下最相关的一条。用户希望未来根据睡眠时间、屏幕使用时间等数据监督执行，但现有浏览器无法读取操作系统的应用时长，电脑联网和 Runner 心跳也不能证明人在操作。

## 决策

- 准则由真实成员创建；适用人可以多选和全选当前成员目录。其他成员逐条自行接受或撤回，发起人不能代替授权。全选是当下成员快照，不自动覆盖将来加入的人。
- 用 `personal_principle` 保存当前版本，`personal_principle_revision` 保存每次修改的规则快照，`personal_principle_target` 保存成员逐条确认，`personal_principle_checkin` 保存本人按日期提交的记录。编辑采用版本冲突检测。规则的参与状态和记录分开，历史记录注明当时版本。
- 本次支持本人手动记录、设定时间后的站内待记录提示、多人独立确认及首页轻提醒。未记录只能称为“待记录”，不能称为违规。本人标记“需要调整”才显示本人反馈的待关注。建议不作遵守判断。
- “屏幕使用时间”作为待接入来源可以写在准则中，但保持“待数据”；不伪造授权或使用时长。WAO 页面打开、Runner 心跳、设备在线都不生成偏离结论。后续真实来源需要逐人授权、身份归属、数据新鲜度和可撤回能力，另行设计并验收。
- 站内首页自留地只显示一条动态提示和管理入口；完整列表、规则依据、版本与记录放独立页面。默认不将某人的记录分享给其他成员；他人只能看到规则内容与参与状态。
- 只实现浏览器版，不恢复独立桌面客户端。视觉复用轻量 CSS 层次和微交互；窄屏与减少动态效果设置降级。

## 验收

1. 真实成员选择、全选、创建、他人确认与撤回、本人记录、编辑冲突和版本历史均可完成；相互看不到他人的记录。
2. 首页仅占一张卡片，按真实状态选一条内容；无数据和未授权时不出现违规通报。
3. 390px 窄屏无业务水平滚动，减少动态效果模式无位移动画，交互与滚动流畅。

## 后续边界

操作系统屏幕时间、持续本人操作证据、站外推送与共享通报需要可信采集和授权契约。本次不声明具备这些来源。接入后需按人、设备、窗口、规则版本和提醒通道记录判断依据，且每个窗口每个通道只投递一次。
