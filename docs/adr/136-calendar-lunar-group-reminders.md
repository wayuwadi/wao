# ADR-136：扩展既有重要日链路承载阴阳历提醒并用 Union ID 安全群通知

## 背景

日历已经能展示任务、CalDAV、中国与国际节假日，并有 `family_important_date` 的公历年度提醒和幂等飞书私聊投递。
新需求增加农历录入、提醒事项类型、可选群通知和搜索。如果另建一套前端演示日历或静态节气表，会产生重复模型和不可验证通知；如果直接拿登录 Open ID 在群里 `@`，则会因为飞书 Open ID 按应用隔离而错人或失效。

## 决策

- 保留 `family_important_date` 表和 `/api/calendar/important-dates` 兼容接口，新增历法、农历月日、通知方式和目标群字段；既有行以 `SOLAR + DIRECT` 为默认值。
- 服务端用 `lunar 1.7.7` 完成双向转换、逐日匹配农历年度发生日和二十四节气生成；前端只展示服务端结果。
- 日历提醒事项不进入任务表；创建入口先让成员明确选择任务或提醒，保持“需要完成”与“只需提醒”两个领域的状态语义。
- 群列表复用飞书群聊同步应用的真实群接口。保存群提醒时必须确认当前身份有 Union ID，且能在目标群的 Union ID / Open ID 两份成员列表中通过唯一昵称配对；投递前再次确认。
- 搜索先覆盖当前视图已加载的真实事件，不增加全库伪搜索接口；点击结果统一切换到该日，能打开领域详情的继续打开，CalDAV 等只读源显示预览。

## 取舍

- 保留历史表名会留下技术命名与产品语义不完全一致，但避免改表、搬数据和滚动部署期间的双写风险。
- 当前搜索范围是当前日期窗；它能精确定位当前已加载事项，但不是跨全部年份的全文检索。未来若真实使用需要跨年搜索，再增加服务端聚合查询契约。
- Union ID 与唯一昵称双列表配对需要两次飞书群成员读取，保存与投递会多一次外部开销；这是避免错误 `@` 成员的必要成本，失败时明确重试而不降级猜测。

## 结果

既有公历私聊提醒保持兼容；农历事项、节气和群提醒使用可追溯真实数据源。群通知在无法证明配置人身份时停止发送，避免产生看似成功但实际通知错人的结果。
