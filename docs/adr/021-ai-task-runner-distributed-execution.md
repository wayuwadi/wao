# ADR-021：WAO 采用中央队列与本地 Codex Runner 执行开发任务

## 状态

已采纳。

## 背景

WAO 的任务已经可以生成公开 Markdown 地址，但仍需要人把地址复制给 AI。娃哥与娃弟的
电脑都登录了 Codex，任务可能同时有 5–10 个；如果直接在某一台电脑的主工程目录启动，
会与日常开发互相覆盖，也无法知道账号当前有多少任务在跑。

## 决策

- WAO 服务端只做中央队列：保存项目级开关、Git 仓库、默认分支、文件夹名、首选电脑、
  项目并发上限、节点心跳和运行结果。
- 每台开发电脑运行 `deploy/ai-runner/wao-ai-runner.py`。首次用十分钟有效的一次性配对码
  换取节点令牌；令牌和 Codex/GitHub 登录态只保存在本机。
- Runner 领取任务后，以最新 `origin/<default-branch>` 创建独立 Git worktree 和
  `ai/wao-<run-id>` 分支，再用 `codex exec --json` 启动独立非交互会话。官方把
  `codex exec` 定义为脚本或 CI 场景的非交互入口，并支持 JSON 事件输出和独立工作目录：
  <https://learn.chatgpt.com/docs/developer-commands#codex-exec>。
- 本机并发上限与项目并发上限同时生效；项目可固定到一台电脑，也可由任意在线且有空位的
  Runner 自动领取。节点超过三分钟没有心跳时，未完成任务自动重新排队。
- 入队时任务状态变为“AI 进行中”；Codex 退出码为 0 时变为“待验证”，失败则回到“进行中”。
- 首页是运行控制台，展示在线电脑、槽位占用、正在运行和最近完成；卡片可回到原任务。
- 开发阶段 Runner 默认使用 `danger-full-access` 以完成 GitHub、部署和线上验收，但安装说明
  明确建议使用专用系统账号或隔离电脑。正式版本前需恢复受限权限、审计与令牌轮换。

## 后果

- 日常 Codex 对话与自动任务互不占用同一个会话，源码修改也通过 worktree 隔离。
- 多台电脑不需要共享 Codex 凭据；WAO 数据库泄露也拿不到本机 Codex 或 GitHub 登录态。
- Runner 电脑必须保持在线并完成 Codex/Git 登录；没有在线节点时任务会安全停留在队列。
- 同仓库并行任务仍可能在合并时发生语义冲突，Codex 必须遵守仓库“一任务一 PR”规则，
  从最新 `main` 开始并在合并前重新检查。
