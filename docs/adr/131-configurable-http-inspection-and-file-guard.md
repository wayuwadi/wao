# ADR-131：HTTP 巡检参数化，文件下载保留一次性票据底线

## 状态

已采纳。

## 背景

ADR-115 已把 HTTP 性能巡检接到真实 AI Run，但巡检频率、指标范围和治理规模写死在代码里，自动化页面也只给飞书同步任务展示配置按钮。文件模块则把 50MB / 10MB 上限与算术验证码写死，无法按当前使用场景调整。任务同时要求多处长列表分页，主要目标是减少页面一次铺开的内容，而不是改变数据来源。

## 决策

- HTTP 巡检保留固定的内置任务 id 和真实 `JobHandler`。配置使用系统级持久化键保存指标窗口、Top N、单次最多治理接口数与启动通知 Webhook；频率和时间同时转换成 Spring 六段 Cron 写回 `automation_job`，使双节点条件领取与下一次触发时间继续生效。
- 频率先提供每天、工作日、每周一三个常用选项。Top N 决定任务看到的候选池；单次治理数限制一个 AI Run 实际处理的接口数，且不能超过 Top N。仍只创建一个任务和一个 AI Run，不按接口拆分并制造通知风暴。
- 自定义通知群复用通用 Webhook 注册表，只发送一次包含自动触发原因的启动卡片；未选择时沿用既有默认通知。AI 生命周期后续通知保持原系统规则，不把通知路由扩张成新的运行级数据模型。
- 普通文件与用户主动上传图床的上限保存到 `system_setting`，允许范围不超过当前部署基线。后端执行最终校验；损坏配置回落到 50MB / 10MB 默认值。
- 公开下载的算术题允许关闭，但确认页、短时一次性票据、文件绑定和用完即废全部保留。这样满足少一步输入的便利诉求，同时不推翻 ADR-020 对公开直链重放的防护。
- 自动化运行记录补充 `runAt` 与 `durationMs` 响应字段，前端按真实时间排序后每页 10 条。请求监控两表使用现有 50 / 100 条有界结果各自前端分页 20 条；网页托管使用不含正文的元数据列表前端分页 10 条。

## 后果

- 修改巡检计划与文件策略无需重新发布；错误范围在接口层与服务层同时被拒绝，设置失败保留原值。
- 关闭算术题会降低对自动识别下载页脚本的阻力，但一次性票据仍阻止拿到文件直链后的零成本重放；若未来要完全公开下载，必须单独安全评审，不能复用这个开关。
- 当前三处分页解决可见内容过长问题，但不宣称服务端游标分页收益。若网页托管元数据量增长到影响接口耗时，再增加兼容的服务端分页契约并用真实指标验收。
