# ADR-191：WAO 应用统一读取、回复并持久编排群聊润色

## 状态

已废止（2026-09-15，由 ADR-231 取代）。网页文字润色工作台仍保留。

## 背景

WAO 已有成员级润色提示词、真实模型路由和前后历史，但用户在飞书发送大段口语化文字时仍要打开网页、复制原文、
等待结果再复制回群。现有 WAO 飞书自建应用已经具备目标群消息读取、成员身份换算和官方消息回复能力；生产环境中
登记的通用 Webhook 未必属于目标群，因此不能把 Webhook 当作功能启用的硬前提。

## 决策

- 现有 WAO 自建应用每 15 秒读取一次新消息，同时把用户消息分发给快速收集和群聊润色；群聊润色按配置的显示名精确
  匹配 mention。默认通过飞书官方应用接口回复原消息，并以运行 id 生成稳定 uuid；管理员也可显式选择 Webhook 发送结果。
- 每条消息先按飞书身份解析真实 WAO 成员，再冻结该成员当前提示词。未绑定时明确拒绝，不回退管理员或默认成员。
- 新表 `feishu_text_polish_run` 以 `message_id` 唯一，保存 AI、发送和历史收口状态。AI 使用既有持久只读队列；模型 API
  和本地 Codex 的选择、事实保真提示与瞬时重试策略和网页润色保持一致。
- 生成结果后先原子认领发送，再按 UTF-8 有界分段通过应用回复或明确选择的 Webhook 发出；全部发送成功后才用稳定记录 id 写入
  `text_polish_record`。发送中节点失联时标记为状态不确定，不自动重发，避免重复群消息。
- 用户主动 @机器人的直接答复不受自动通知静默时段影响。Webhook 地址继续由通用注册表 AES-256-GCM 加密，配置接口
  只保存稳定 id 和触发名称。

## 后果

- 飞书和网页共用同一份成员提示词与历史，用户不需要维护两套润色产品。
- 轮询延迟最多约一个周期；不需要额外公开回调或新的飞书应用凭据。
- 应用回复不依赖额外群 Webhook，避免错群和缺配置；外部 Webhook 仍无幂等回执，网络断开点无法同时保证必达和绝不重复。
