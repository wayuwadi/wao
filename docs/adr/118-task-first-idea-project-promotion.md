# ADR-118：点子从任务进入并在验收后升级为项目

- 状态：Accepted
- 日期：2026-08-25
- 调整：[ADR-107](107-project-centered-idea-lifecycle.md)

## 背景

ADR-107 已经用规划中项目取代独立点子聚合，但仍保留了“点子库”入口，并让每句刚记下的想法立即创建项目。
这会让尚未执行、尚未验收的一句话过早占用项目层级；与此同时，用户通过日常任务或飞书快速收集记录的真实
想法又无法在第一轮交付后原地成长为长期项目，仍需人工重建上下文。

任务已经承载一句话、描述、子任务、AI Run 和人工待验证状态，项目则适合承载多轮目标。继续维护第三个新点子
入口不能增加真实能力，只会让同一件事有两种录入方式。

## 决策

1. 新想法统一通过现有“新建任务”与飞书快速收集入口记录，不再提供独立点子库导航；规划中项目继续在项目页
   按真实状态展示。
2. 只有状态为“待验证”或“已完成”的主任务可以人工执行“升级为项目”。这表示至少一轮工作已经进入验收，
   不用已经退役的 PDCA 表单重复表达检查过程。
3. 升级在一个服务端事务中完成：以任务稳定 id 生成唯一项目 id、创建并开始项目、把原任务移动为该项目的第一轮。
   重试返回同一项目，不重复创建，也不丢任务描述、子任务、运行历史或活动记录。
4. 升级后的项目保持“进行中”；后续每个新想法作为该项目的新任务继续执行、待验证和人工完成。完成一轮任务仍不
   自动完成项目。
5. V83 独立点子表、接口、资产和归并逻辑继续保留；`/ideas` 仅作为历史归并兼容页，不再创建新点子或规划中项目。
   物理清理仍需确认真实存量已经归并并另立 ADR。

## 后果

- 一句话先成为低成本任务，只有经过一次真实交付和验收才占用项目层级；项目后续迭代继续复用任务和 AI Run。
- 任务升级会改变其所属项目，但历史 AI Run 记录保留原始运行快照；任务当前入口统一指向升级后的长期项目。
- 旧点子仍有归并出口，导航和新建入口的退役不等于删除历史数据。
