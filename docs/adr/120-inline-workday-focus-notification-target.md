# ADR-120：今日重点在保存操作旁明确选择通知群

## 状态

已接受（2026-08-26）。

## 上下文

ADR-117 复用了成员级通知目标，在三个重点保存后建立群承诺，但通知目标只能在完整的「调整节奏」弹窗中修改。
主操作区既看不到当前目标，也无法在保存前就地修改，成员容易把已保存的旧目标或系统默认 Webhook 误认为本次主动选择。

仓库已有真实 Webhook 注册表、飞书应用群聊列表和成员偏好持久化链路，不需要新增群目录或把目标塞进单次发送请求。

## 决策

- 在「保存今日重点」左侧放置紧凑通知目标选择器，明确展示“不发群”或当前目标名称；选择器列出已启用 Webhook 与机器人真实所在群，不自动选中系统默认项。
- 目标选择立即写入当前成员的 `workday-rhythm-config-v1.energyNotification`。保存期间禁用重点提交；失败时保留原配置并允许重新选择。
- 选择“不发送群通知”只关闭 `notifyFocus`；精力补给项目仍按成员已有开关决定是否通知。
- 单次重点通知请求仍只传日期。服务端继续按会话重读成员偏好，前端不能越过持久化配置直接指定发送目标。
- 选择器实现为可复用前端组件，集中处理真实目标列表、加载、空数据、错误、窄屏和当前选择状态。

## 后果

- 成员在主要保存动作前即可确认或修改通知群，不再把系统默认项当作隐式目标。
- 目标变更与重点保存之间有明确顺序，避免新旧群竞态；代价是首次选择要多一次成员偏好写入。
- 没有可用 Webhook 或群聊时只允许不发送，并引导先完成真实配置，不提供演示目标或默认回落。
