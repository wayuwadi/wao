# ADR-160：Jenkins 外部状态回写不改变生产发布结果

## 状态

已接受（2026-08-30）。

## 上下文

WAO 的 main 流水线在生产验收通过后向 GitHub 写回 commit status。Linux1、Linux2、云入口、数据库主从
和公共 API 均已验证成功时，GitHub API 的一次瞬时 TLS EOF 仍可能让 Declarative `post success` 返回非零，
最终把已经完成的生产发布显示为失败，并触发一条误导性的失败通知。

## 决策

- GitHub commit status 请求使用有限连接/总超时，并对全部可重试错误最多重试五次。
- 网络或 GitHub API 在重试后仍不可用时只写 Jenkins 告警，保持已经由测试、部署与生产探针决定的构建结果。
- SHA、状态枚举或必需凭据不合法仍立即失败；这些属于本地流水线配置错误，不是外部可观测性故障。
- 后继批次仍会覆盖批次范围内各提交的最终状态，因此一次回写缺失不会改变线上版本基线。

## 后果

外部状态页短暂不可用不再制造“生产失败”假象。Jenkins 控制台保留明确告警，运维可以补发状态或等待后继
批次修正；生产验收本身的任何失败仍严格阻断并保持原有摘流策略。

## 回退

如需重新把 GitHub 状态回写设为强门禁，应单独增加发布前的 GitHub 可用性预检，而不是在生产部署完成后
修改构建结果。
