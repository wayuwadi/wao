# ADR-277：发布结束后通知与计划摘流告警

- 状态：已采纳
- 日期：2026-09-24
- 取代：ADR-271 的首台可验证阶段通知和提前切换网页

## 背景

常规发布在 Linux1 完成后提前发布新版网页，并主动摘流 Linux2。固定在 Linux2 的部分接口因此不可用；云端独立就绪监控每分钟探测三个节点，又把滚动发布中的计划摘流报告为故障，随后发送恢复消息。

## 决策

常规完整发布恢复 Linux1 → Linux2 → 云端顺序。Linux1 完成并回流后继续更新 Linux2；两台应用节点都通过健康检查后才切换公网网页。Jenkins 仅在双节点、云端和公共入口验收通过后发送成功通知；失败仍发送失败通知。纯网页发布保持静态制品快路径。

云端独立监控读取 Nginx 摘流标记。标记在两小时内时，不累计对应节点的直接就绪检查失败；公网主入口始终照常检查。标记过期后节点继续失败会正常告警，避免意外留下 `down` 标记而无限静默。监控程序在发布准备阶段同步到云端，确保当次滚动发布即使用新判定。告警去重、两次失败门槛和恢复通知保持原规则。

## 边界

固定在 Linux2 的 VPN 出口、微信公众号白名单和本地媒体卷接口，在 Linux2 应用替换期间仍可能短暂不可用。恢复发布顺序缩短版本不一致窗口，不等于这些接口已具备双机容灾。要消除这个单点，需要另行设计共享媒体存储、双机合规出口及服务切换；不能仅改 Nginx 把请求转到 Linux1。
