# ADR-103：飞书个人收集优先使用已授权的消息轮询

## 状态

已接受（2026-08-23）。

## 背景

ADR-102 的事件回调链路已上线，但实机核对发现飞书开放平台尚未配置该回调，
Verification Token 和 Encrypt Key 也不能通过现有 App ID / App Secret API 读取。直接开启
无校验的公开回调会扩大伪造入口，而 WAO 的群聊归档已在用同一应用凭据成功读取目标群消息。

## 决策

1. 开启快速收集后，各 API 节点每 15 秒用 `tenant_access_token` 主动读取目标群最近消息。
2. 通过飞书 Bot Info API 取得当前应用机器人 `open_id`，只处理用户发送、未撤回且精确
   提及该 `open_id` 的消息，不以“任意 mention”代替。
3. 轮询和事件回调共用 ADR-102 的 `message_id` 持久唯一键；Linux / Windows 重叠扫描、
   请求时间窗重叠或后续开启回调都不会重复建任务。
   本 ADR 将 ADR-102 中“优先 event_id”的应用层选键修正为“优先 message_id，缺失时才用 event_id”，
   不修改已执行的 V85 migration。
4. 每次只查最近两分钟，成功后前移内存水位；关闭功能时也前移水位，不在日后开启时
   补造大量历史任务。
5. 公开回调作为可选的低延迟入口保留；配置官方 Token / Encrypt Key 后可同时使用。

## 后果

快速收集可以直接复用现有真实授权上线，不再把飞书开发者后台的人工配置当成功能启用前置。
代价是最多约 15 秒延迟和每分钟四次读消息请求；任务幂等性仍由 MySQL 保证。
