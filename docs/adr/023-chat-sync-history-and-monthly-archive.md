# ADR-023：飞书群聊历史补录与按月归档

## 状态

已采纳。

## 上下文

群聊同步首次配置后需要补录既往消息；若只能同步当天，操作人员必须等待定时任务逐日执行，无法补齐历史。原配置还要求人工选择一个固定文件夹，月份变化后容易把新消息写进旧目录。

服务部署在多个节点上，定时器会在每个节点运行。未对到期任务进行抢占时，多个节点可能同时执行同一个群聊同步任务，产生重复 API 拉取和重复成功记录。

机器人发送的飞书 interactive 卡片以消息类型 `interactive` 返回。若按未知消息类型降级，知识库里只有 `[interactive]`，无法阅读通知内容。

## 决策

- `POST /api/feishu/chat-sync/run` 保留可选 `day` 参数；自动化配置页提供日期选择，允许立即补录指定历史日。日期为空时仍同步当天。
- 群聊同步配置只选择知识库，不再选择文件夹。服务端按同步目标日期获取或创建名称为 `YYYY 年 M 月` 的文件夹，再将当天文档写入该目录；同日仍通过标题 upsert，重复补录不会产生重复文档。
- 到期任务执行前以 `id + next_fire_at` 作条件更新抢占执行权。只有抢占成功的节点会调用真实执行器，随后写入运行记录；其余节点直接跳过，避免重复拉取外部 API。
- 将 interactive 卡片的标题、正文与字段提取成可读文本写入群聊文档；不能提取内容时才降级为「[机器人卡片]」。
- 使用稳定存在的 `ri-chat-3-line` 作为群聊同步任务图标，并通过新增 Flyway migration 修正已部署数据。

## 后果

- 可从 2026-07-01 起按日补录，不需要改动服务器时间或等待定时器。
- 文件夹会按月自然增长，配置页更少一个易失效的选择项。
- 一次到期调度只会消费一次飞书消息查询，运行记录与实际请求一致。
- 已保存的旧 `folderId` 设置不会再影响新同步，保留在配置表中以兼容既有数据。
