# ADR-178：微信公众号登录使用单一出口并验证真实配置

## 状态

已采纳。补充 ADR-167 与 ADR-168。

## 背景

系统设置原先用 App ID、App Secret、回调 Token 是否非空判断“配置完整”，保存后便宣称登录页可获取真实二维码。
但微信获取公众号 `access_token` 还会校验 App 凭据、账号状态与服务器出口 IP 白名单。生产 Nginx 又把认证请求分给
两个家庭网络应用节点，管理员即使为一个出口配置了白名单，另一节点仍会返回 `40164`。服务端只返回笼统提示，
并丢弃微信错误码和响应中的实际出口 IP，导致“系统显示已配置、登录仍失败”。

## 决策

- 字段非空只称为“已保存”，不再称为“可用”。设置页加载完整配置或保存后，调用
  `POST /api/settings/login/wechat-official/verify`，通过微信稳定版令牌接口做真实验证。
- 服务端把微信 `40013`、`40125`、`40164`、`48001` 与 `50004` 转为可执行中文诊断；`40164` 只展示微信返回的
  实际出口 IP，不返回 App Secret、access token 或其他凭据。
- 公众号认证、消息回调与配置验证在云 Nginx 固定到 Linux 主节点，不跨两个家庭出口轮询。配置读取和保存仍使用
  共享数据库并走普通双节点；主节点不可用时明确失败，不以另一出口制造新的白名单要求。
- 获取令牌改用微信稳定版 `POST /cgi-bin/stable_token`，成功后继续写入共享 Redis，两个应用实例不各自刷新令牌。

## 后果

管理员可以在系统设置看到“真实验证通过”，或直接拿到需加入公众号后台白名单的当前主节点出口 IP。家庭公网 IP
变化仍需在微信公众平台更新白名单，这是微信官方权限边界，WAO 不伪造自动更新能力。公众号登录对主节点形成明确
依赖，但避免了双出口随机失败；飞书与邮箱登录不受影响。
