# ADR-075：WPF 原生 Windows 客户端与自托管完整性更新

## 状态

已采纳。

## 背景

任务 `t17869345652730` 要求新增名为 WAO 的原生 Windows 应用、集成桌面宠物，并在主仓代码发布后让本机
应用通过更新图标一键更新。参考界面是 ChatGPT/Codex 一类桌面工作台，但需求不是把现有网页套进窗口。

仓库已有真实的邮箱会话、项目、任务、AI Run 与自动化 API，可用于第一版原生链路。仓库是私有 GitHub
仓库，Actions artifact 需要登录且有保留期限，不能直接作为普通客户端的更新源；当前也没有 Authenticode
证书、Microsoft Store 账号或 MSIX 签名材料，不能伪造一个可信发布者安装器。

## 决策

- 新增 `wao-windows/`，使用 .NET 8 WPF 实现原生界面，直接调用既有 `/api/**`，不嵌入 WebView，也不复制
  Vue 页面或演示数据。首期能力与原生 iOS 的真实接口边界一致：邮箱会话、项目/任务、AI 派发与运行、自动化。
- 密码不持久化；服务端 `WAO_SESSION` Cookie 使用 Windows DPAPI 的 CurrentUser 范围加密后保存到本机
  `LocalAppData`。退出、401 或不可解密时删除本机会话并回到登录页。
- 桌面宠物使用同进程独立 WPF 透明置顶窗口，支持稳定初始位置、拖动、隐藏、打开主窗口和刷新。宠物只消费
  客户端已读取的真实 AI 状态，不额外制造或缓存任务结果。
- main CD 新增 Windows runner 构建任务，生成自包含 `win-x64` 主程序和独立单文件更新器。构建产物由现有
  云节点部署发布到 `/downloads/windows/`，而不是依赖私有 GitHub artifact；通知仍由统一 CD 发送一次。
- 客户端读取禁止缓存的 `latest.json`，只接受 HTTPS 包地址和合法 SHA-256。下载校验成功后解压到临时目录，
  再把更新器复制到包外运行；更新器等待主程序退出，备份当前目录、替换、重新启动，失败则恢复备份并记录日志。
- 采用每用户可写目录中的便携包作为首期分发形态，不请求提权。取得 Authenticode 证书前不发布伪签名 MSI/MSIX，
  也不声称能消除首次下载的 SmartScreen 提示；后续签名属于独立安全交付任务。

## 影响

- Windows 用户只需首次下载和解压，后续成功的 main 发布会形成可由客户端一键应用的版本，不再人工重复下载。
- 每次 main CD 增加一个 Windows runner 构建；Windows 构建失败会阻止部署，避免网站已发布但客户端更新清单
  或 ZIP 缺失。云端线上探针会验证更新清单格式与 ZIP 的 Range 下载。
- 完整性依赖 WAO HTTPS 和清单 SHA-256，能发现传输或存储损坏，但不替代发布者身份签名。代码签名材料具备后，
  应新增 ADR 说明密钥保管、签名流水线、时间戳服务与轮换方式。
