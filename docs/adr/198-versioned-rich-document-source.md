# ADR-198：高级文档以版本化 JSON 为事实源并保留 Markdown 投影

## 状态

已采纳。修订 ADR-015 中“所有编辑内容只以 Markdown 保存”的范围：任务描述等紧凑编辑器继续只存 Markdown；知识库文档、小记和文档模板采用本 ADR。

## 上下文

文档需要表格合并、分栏、提示块、公式、流程图、附件、媒体与画板引用。Markdown 可以提供可读降级，但无法无损表达这些节点的全部属性；只保存 Markdown 会在刷新、模板复制或分享时丢失结构。与此同时，分享、搜索、AI 检索和旧客户端仍需要稳定的文本格式。

## 决策

- `doc` 与 `doc_template` 增加 `content_json`、`content_markdown`、`content_version`。当前版本固定为 1；Tiptap JSON 是完整排版事实源，Markdown 是同步生成的可读投影。
- API 新增可空 `content = { version, document, markdown }`，并保留 `blocks`。新客户端同时提交二者且服务端以 `content` 为准；旧客户端提交 `blocks` 时清空高级字段，避免读到过期 JSON。
- 老数据不批量转换。读取优先级为高级内容、Markdown 投影、旧块；用户首次真实编辑保存后惰性升级。
- 文档 PATCH 可带 `expectedRev`。新编辑器必须携带读取到的版本并使用数据库 CAS；冲突返回 409，本机草稿不得覆盖服务器。旧客户端不带版本时继续兼容旧写入语义。
- 本机文档草稿进入 IndexedDB，以成员和文档隔离并记录基础版本；冲突只允许载入服务器版或将本机草稿另存副本。
- 服务端只接受节点、标记和属性白名单；URL 限制为安全协议，颜色限制为固定色板，不接收原始 HTML、脚本或任意样式。

## 后果

- 文档可以无损保存高级排版，同时 `.md` 分享、搜索与 AI 链路不需要理解编辑器 JSON。
- 双写增加校验与兼容复杂度，但明确的事实源优先级避免滚动发布期间互相覆盖。
- 本轮不引入字符级协同、评论、修订模式和历史版本；现有在线成员与光标行提示保留。
