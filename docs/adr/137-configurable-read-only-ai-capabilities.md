# ADR-137：问问 AI 与聊天复盘使用可配置的只读 AI 能力

## 状态

已接受（2026-08-27）。本 ADR 补充 ADR-041、ADR-088、ADR-128 与 ADR-130；不改变功能开发 AI Run 的工具权限和账号路由。

## 上下文

“问问 AI”和聊天复盘固定依赖默认本地 Codex，用户无法复用设置页中已经真实验证的 Codex Token、DeepSeek API Key
或受信模型网关。聊天复盘也只能手动启动，首页把开发运行与复盘拼成两个不分页的短列表。直接把任意 API Provider
升级成开发 AI Run 会错误暗示它具备仓库、工具调用和 Runner 会话能力，因此必须把只读分析能力与可写开发能力分开。

## 决策

- 建立只读 AI 能力列表：本地 Codex、已启用的 Codex 账号、DeepSeek 与固定受信模型网关。接口只返回 id、名称、模型、
  执行方式和可用状态，永不返回 Token、API Key 或 OAuth 凭据。
- Codex 能力仍经 assistant-v2 Runner 的临时空仓库、独立 `CODEX_HOME` 和 `read-only` sandbox 执行；DeepSeek 与模型网关
  仅走服务端 Chat Completions，无工具、无联网代理、无文件系统或业务写入权限。调用失败直接失败，不跨 Provider 静默降级。
- `ai_assistant_run` 固化当次 `ai_capability_id`。服务端 API 任务使用独立 `provider_queued / provider_running` 状态，领取、完成、
  失败与超时均通过数据库 claim token 和主键 CAS 收口；终态立即清除完整提示。
- 聊天复盘的手动运行、重试、再次运行和自动运行都固化 AI 能力。全局自动策略可启停，可设置 5 分钟～7 天间隔、
  最近 5～100 条消息或 1～168 小时、关注重点和 AI 能力；多 API 节点以数据库到期 CAS 保证每个计划点只创建一次。
- 首页新增统一 AI 活动只读查询，以稳定类型 `FEATURE_DEVELOPMENT / CHAT_REVIEW` 合并真实终态数据，按完成时间分页，
  支持全部与分类筛选；功能开发卡片仍打开完整运行详情，聊天复盘卡片打开原报告。
- 登录后的桌面顶栏增加标准“问问 AI”入口，移动端继续使用已有浮动入口；助手会话可在发送前切换能力并持久化本机偏好。

## 后果

用户可以把已录入并验证的 DeepSeek 或受信网关用于只读问答和复盘，又不会误获得开发任务权限。自动复盘有明确频率下限、
真实消息范围和跨节点去重。首页活动类型以后可扩展，但新增类型必须先有真实持久化来源和契约，不能用演示记录占位。
