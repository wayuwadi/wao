# ADR-232：本地验收后交付，用户负责线上验收

## 状态

已接受（2026-09-17）。用户明确要求提高 AI 开发效率，并确认保留 PR 合并；本 ADR 取代 ADR-202 的发布跟进与线上二次验收要求，保留一个需求或 BUG 一个 PR。

## 决策

- AI 在本地开发，直接复用既有线上数据库连接完成相称测试和真实用户链路验收；不为常规开发另建数据库。
- 本地验证通过后按既有授权执行详细中文提交、推送功能分支、创建 PR、Squash Merge 到 main。合并完成即交付本地验证证据、PR 链接和合并 SHA。
- AI 默认不等待 Jenkins 完成、不监控后续发布、不创建发布回访，也不再做一次线上验收；用户负责线上体验验收。用户另行请求发布跟进或线上问题排查时，按该次请求执行。
- Jenkins 五分钟合批、严格滚动部署、自动健康检查和通知继续运行；不修改流水线、版本状态或功能积分规则。合并成功不能表述为上线成功。
- 本地验收受阻时如实报告未验证项，不把编译成功包装成真实链路通过，也不自动切回发布后补验的旧流程。
- 线上数据库连接不扩大数据变更权限：继续保护凭据，不修改已执行 migration；验证沿用已有授权和数据范围，破坏性生产操作仍需明确授权。测试中的清库、重置和迁移脚本不得因切换连接而误用于真实业务数据。

## 验证

检查 AGENTS、项目交付 Skill 和方法论引用的一致性。正常需求在本地验收与 PR 合并后收口；无需为纯规则调整运行应用或发布验收。旧 ADR 保留为历史，本规则不追溯改写此前的测试记录。
