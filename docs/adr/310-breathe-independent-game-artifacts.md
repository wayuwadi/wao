# ADR-310：页面内单机游戏的独立构建与静态制品

状态：已接受，2026-10-03 用户确认整体 A2 与工程拆分方向。实施中，不代表发布路径已验收。

## 背景

七款完整玩法需要按款独立交付，不应让主站更新重建所有游戏或让游戏更新触发后端。保留 ADR-049 单仓库、ADR-264 浏览器维护边界及 ADR-291 当前拓扑约束；不恢复旧游戏业务服务、账号体系或数据库。评估细节见 `docs/plans/breathe-game-artifacts-proposal.md`。

## 决策

- `wao-game` 与 `wao-web` 并列，继续 Vue3、TypeScript、Vite。正式代码在 `games/<gameId>`，设计在 `demos`，后者永不进入正式制品。第一款Canvas2D，无第三方引擎；实际重复后才提取共享运行能力。
- 主站保留呼吸、静坐、布局选择、轻量入口，按需加载 `wao-game/host`。同源iframe加载当前游戏独立入口，切走销毁。CSS与键盘归属隔离；同源iframe不是安全沙箱，不接收任意来源URL。
- `wao-game/protocol` 为版本化schema。channel=`wao-game`、protocol=1、gameId、随机instanceId、单调seq；origin/source/封套/负载均校验。开始、暂停、恢复、主题、音频、尺寸、快照、销毁具有明确边界；规则版本独立。首次ready后init，超时显示重试；恢复必须用户动作。
- 主站存档服务持有稳定IndexedDB事务；游戏只提交校验后状态，不读取账号、不上传。revision CAS检测跨页冲突；导入备份和覆盖同事务完成。主站变更不改变存档命名空间。
- 每款制品 `/play-assets/<id>/<GitSHA>/` 不可变，包含独立manifest及逐文件SHA256。catalog以revision CAS原子切换单款指针；旧制品保留。游戏更新和回滚不得改变其他款指针或清理旧资源。
- 主站专属改动复用游戏制品；单游戏改动只构建实际依赖；协议或共享代码变化按依赖扩大测试。更新现有change planner，游戏路径不能落入未知路径全量后端发布。
- Jenkins与当前获授权静态通道使用相同打包、校验、安装与catalog切换规则。第一次先安装游戏制品再激活主站；前端发布不重启后端或更改数据库。实际协调者、通道、版本必须现场复核。

## 取舍与兼容

代价为显式父子通信、焦点转移、失败提示与版本兼容测试；收益是销毁边界、样式隔离、独立构建和单款回滚。原生组件直嵌难以独立发布；跨源iframe引入存储分区和通信权限，均不选。主站只锁定本次进入时的不可变游戏URL，游玩中不热切版本。

旧六款存档保留，不能把旧SVG下载当成可续玩记忆，不伪造新旧玩法迁移。第一款只新增自身schema，其余按顺序扩展注册。规则变化必须先备份迁移，并兼容已正式发布档。

## 验证

除玩法与存档验收，还必须证明主站更新不构建游戏、单款更新不覆盖其他制品、旧资源持续可加载、回滚能运行；记录同机构建与加载体积和真实发布耗时。尚未执行的项目在进度文档保留未勾选。ADR编号在同步main时再次核对。

## 首款实施补充

`change-plan.py`区分主站、游戏与共享schema/protocol的真实依赖，未登记游戏拒绝构建；流水线脚本变更仍扩大验证，但只有后端运行输入变化才导致后端发布。`ci-build-frontends.sh`保留主站静态制品并按款构建；`game-release.py`的安装及catalog切换不清理旧版本。Nginx仅开放catalog与版本路径中的游戏资源，未知路径404，禁止回退主站HTML。

2026-10-03现场确认当前获授权通道为Windows临时静态发布，主站仍指向`/var/www/wao/windows1-dev/dist`。本款不改变后端拓扑。该通道适配与上线验证尚未完成，必须留下实际操作证据后再宣告交付。
