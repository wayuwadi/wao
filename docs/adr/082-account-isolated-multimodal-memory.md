# ADR-082：把个人记忆建模为独立的成员私有多模态资料域

## 状态

已采纳。收紧 ADR-078 的 MCP 读取与写入范围；组织级统一资产检索仍遵循 ADR-046，不再被称为“个人记忆”。

## 背景

ADR-078 先用固定“共享记忆”知识库打通了 Codex MCP，但固定知识库和组织资产检索天然是共享域。WAO 由两位成员共同使用，生活经历、偏好和长期规划若继续落在共享库中，会发生账号串台。原有工具也只写文字，不能让成员把照片、录音、视频或文件作为生活资料原件保存。

“训练个人生活数据”不能被解释成已经完成模型训练：当前没有稳定的 embedding、OCR、语音识别或视觉模型服务，也没有外部 ChatGPT/Codex 历史的官方可靠批量接口。用演示摘要或空向量库替代会制造无法核验的能力。

## 决策

- 新建 `personal_memory`，正文、附件元数据和附件原件都与 `member_id` 同行存储；所有读写条件同时包含主键和成员。
- 浏览器端成员来自 `CurrentMember`，MCP 端成员来自令牌摘要匹配结果，均不接受客户端指定成员。
- 页面支持人工文字和单份多模态原件上传；附件最大 50MB，列表不加载 BLOB，下载时单独鉴权。
- MCP `save_memory` 写入同一表并标记 `ai`；`search_memory` 仅查询令牌所属成员，返回最多五条、总正文最多 10000 字和可追溯站内链接。
- 页面内 AI 助手仅在有当前成员 id 时加入该成员的个人记忆候选；任务挖掘等组织级后台调用不传成员，也不读取个人域。
- 关键词检索只承诺字面召回。媒体内容仅保存真实原件和人工说明，不伪造 OCR、转写、视觉理解、向量化或模型微调。
- ADR-078 创建的固定共享知识库保留为历史协作资料，不删除存量数据；从本决策起不再承接新的个人 MCP 记忆。

## 后果

- 两位成员可以共用 WAO 部署和组织协作区，但个人记忆的列表、附件与 AI 上下文互不串台。
- 人工与 AI 采集落在同一权威数据源，成员能编辑或删除 AI 沉淀的内容。
- 媒体理解暂时依赖人工说明；未来接入可靠模型时，应新增异步处理状态、可核对的衍生文本和独立 ADR，不能覆盖原件。
