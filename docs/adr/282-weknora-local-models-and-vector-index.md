# ADR-282：Mac 本地模型为 WeKnora 提供向量索引与中文问答

- 状态：已采纳
- 日期：2026-09-25
- 修订 ADR-210、ADR-216 中的「无本地模型」「Wiki-only」初始部署限制；WeKnora 仍独立运行在 Linux2。

## 背景

WAO 的知识库与小记已按 ADR-216 传到独立的「WAO 同步知识库」，但目标库初始只有 Wiki 索引，问答模型依赖外部 API。用户要求使用自己的 Mac 为中文内容提供向量化与问答，在浏览器中管理本地模型，并能在电脑开机联网时继续处理同步内容。

## 决策

1. WeKnora、PostgreSQL、Redis 和备份仍在 Linux2；Mac 仅运行 Ollama 模型服务和本机浏览器管理页。模型文件、推理和向量计算在 Mac 完成。WAO 原文仍是事实来源，WeKnora 保存派生副本。
2. Ollama 只监听 Mac 回环地址。Mac 通过已有 SSH 身份向 Linux2 建立回环端口的反向隧道；Linux2 只在 WeKnora Docker 网关监听转发端口，防火墙仅允许该 Docker 网络访问。WeKnora 后端的 `OLLAMA_BASE_URL` 指向此转发端口，不把未认证模型端口发布到局域网或公网。
3. Mac 登录后自动启动模型服务、管理页和自动重连隧道。管理页只绑定 `127.0.0.1:18782`，提供服务与连接的启动/停止，以及已安装模型的加载/卸载。电脑关机、休眠或网络断开时不冒充模型可用；这是单机依赖，不视为高可用。
4. 初始中文问答模型选 Qwen3 4B Instruct，向量模型选 BGE-M3（1024 维）。先在「WAO 同步知识库」保留 Wiki 并启用向量索引，然后用 WeKnora 官方重解析 API 为已有的知识库与小记文档建立向量。创建仅选择该库、使用本地问答模型的「薇娜拉」助手。改变嵌入模型需重新索引，不能混用不同模型的向量。
5. WAO 原有夜间同步计划负责后续增量内容；本地模型服务在电脑开机联网时提供能力，不另建绕过 WAO 权限与来源校验的数据同步。同步传输、解析、向量入库、问答及引用分别核对。其他已有助手的外部模型配置不因本决策自动改变。

## 验收

- 从 WeKnora 容器通过受限转发调用本机 Ollama，确认中文 Embedding 输出 1024 维，问答模型返回中文。
- 知识库与小记的已有文档重解析完成后，核对目标文档数、失败数、向量条数及维度；超长文档通过较小分块单独重试。
- 使用「薇娜拉」对真实小记提问，核对答案、引用的 WeKnora 文档及回到 WAO 原文的链接。
- 浏览器管理页显示真实运行状态；停止模型服务或隧道时应明确不可用，恢复后可继续处理。
