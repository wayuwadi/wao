# ADR-081：今日节奏按成员选择飞书群并在真实记录后通知

## 状态

已采纳。

## 上下文

ADR-079 将今日节奏的模板和每日记录放在成员偏好中，并因当时没有明确的通知授权与目标而不发送提醒。后续需求明确要求：
成员每次记录喝水、首次记录当天冥想后通知群聊，通知位置可由成员在精力补给卡片中配置，同时“调整节奏”不能只配置时间线。

仓库已有真实的飞书自建应用凭据、机器人所在群列表和向指定群发送卡片的开放平台客户端。应用密钥属于系统级敏感配置，不能复制到成员偏好或浏览器；目标群和动作开关则是成员自己的产品偏好，不能做成全局唯一值。

## 决策

- 在 `workday-rhythm-config-v1` 中向后兼容地增加 `energyNotification`：总开关、通道、Webhook 配置 `id/name`、群 `chatId/chatName` 与项目通知开关。旧配置若已有 `chatId` 自动识别为群聊通道，不迁移数据库。
- 精力补给卡片右上角提供设置入口；“调整节奏”弹窗同时展示通知配置和时间线配置。成员可按稳定配置 id 选择系统设置中的已启用 Webhook，也可继续从飞书开放平台返回的机器人所在群中选择；浏览器不接触 Webhook 地址或应用密钥。
- 前端先把当天真实记录写入当前成员的 `workday-rhythm-day-YYYY-MM-DD`，成功后再调用 `/api/workday-rhythm/energy-notifications`。服务端按当前会话重新读取同一成员的通知配置和当天记录，不接受前端自报喝水次数或冥想完成状态。
- 服务端按成员选择的通道，解密指定 Webhook 或使用系统已加密保存的飞书应用凭据向指定群发卡片；卡片标明成员、日期和真实记录，并提供“打开今日节奏”入口。Webhook 被停用、删除或不可读时明确失败，不静默改发系统默认群。
- 喝水每次 `+1` 都通知；冥想仍遵守 ADR-079 的“当天是否至少完成一次”模型，仅从未完成变为完成时通知，撤销记录不伪装成一次冥想。
- 记录保存与通知是两个可见阶段。通知失败不回滚已经真实保存的记录，页面保留本次待通知动作并提供原位重试；重试采用至少一次投递语义。

## 后果

- 每位成员可以选择不同 Webhook 或目标群及不同动作开关，配置与每日数据都能跨设备恢复。
- 浏览器和成员偏好中不保存飞书 App Secret 或 Webhook，已有系统级凭据继续加密存储。
- 所选 Webhook 不可用，或飞书应用未配置、机器人不在任何群、开放平台暂不可用时，页面会展示真实失败原因，记录本身仍可保存，不会伪造“已通知”。
- 当前同步投递没有独立通知流水表；网络在飞书已收消息但响应丢失时，人工重试可能产生重复卡片。若后续需要统计、去重或后台补偿，再提升为独立投递领域表。
