# ADR-084：今日节奏的精力补给改为成员可配置项目

## 状态

已采纳。修订 [ADR-081](081-workday-rhythm-member-energy-notifications.md) 中写死喝水与冥想动作的配置和通知模型。

## 上下文

“今日节奏”的精力补给最初只有写死的“喝水 +1”和“至少冥想一次”：前者累计次数，后者用布尔值表示当天是否完成。
成员已经可以配置群通知，却不能决定每个项目是反复累计还是每天只记录一次，也不能增加自己的补给项目。继续为每个新项目增加独立字段会让成员偏好、页面和通知接口不断出现专用分支。

## 决策

- 在成员偏好 `workday-rhythm-config-v1` 中增加 `energyItems`，每个项目保存稳定标识、名称、提示、点击机制和是否通知。点击机制只有“累计次数”和“每天一次”，项目数量限制为 1—8 个，保证完整配置仍在成员偏好 4,000 字符上限内。
- 每日偏好 `workday-rhythm-day-YYYY-MM-DD` 增加按项目标识保存的 `energyRecords`。累计项目每次点击加一；每天一次项目首次成功后当天禁用，不把重复点击伪造成新记录。
- 旧配置读取时把 `notifyWater`、`notifyMeditation` 迁移到两个默认项目；旧每日记录中的 `waterCount`、`meditated` 同样映射到新记录。新版保存期间继续写这两个旧字段，保证 API 滚动发布和旧节点读取默认项目时兼容。
- 通知请求继续只提交项目标识和日期。服务端从当前成员配置读取项目名称、机制和通知开关，再从当前成员当天记录复核次数；客户端不能自报名称、次数或完成状态。
- 设置弹窗允许增加、删除和编辑补给项目，并在项目内选择点击机制与通知开关。草稿防丢、保存中、失败重试和跨设备恢复沿用现有成员偏好链路。

## 后果

- 成员可以按自己的生活节奏配置最多八个真实补给动作，而不需要新增表或为每个动作改接口。
- 删除项目不会删除历史偏好原文，但当前页面只恢复仍在配置中的项目，避免已移除项目继续出现或发送通知。
- 当前仍只保存每日结果，不提供长期趋势分析；需要历史统计时应把记录提升为独立领域数据，而不是扫描偏好键。
