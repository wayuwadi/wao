# ADR-269：Linux1 仅接收缺少的镜像

- 状态：已采纳
- 日期：2026-09-24
- 来源：用户要求缩短主线部署中 Linux1 镜像上传时间

## 决策

Jenkins 在打包阶段构建四个应用镜像，并拉取 Compose 所需的三个固定第三方镜像。Linux1 部署前对比每个目标镜像的 Docker ID，只把 Linux1 缺少的镜像打成压缩包上传；若全部已有，则不生成也不发送镜像包。

安装器接收包含全部七个镜像名称与目标 ID 的清单。导入增量包后，逐项检查 ID 并写入本次 Git SHA 标签；镜像缺失或 ID 不符时发布失败。远端镜像在检查与安装之间被清理时，下次节点重试重新比较并补传。首次部署或固定镜像更新时仍发送完整缺失内容，不依赖 Linux1 在发布窗口访问 Docker Hub。

## 影响

仅改部署脚本、单个后端模块或第三方镜像未变化时，可以省去重复上传和导入其他镜像。一次性包的压缩和传输移到远端比较后执行；未测量的新发布不预设节省秒数。Linux1、Linux2 顺序滚动和节点健康检查保持原有约束。
