# ADR-077：退役原生 Windows 客户端并聚焦 Web

## 状态

已采纳。

## 背景

ADR-075、ADR-076 引入了 .NET 8 WPF 客户端、桌面宠物、自更新发布链路和原生飞书回调协议。第一版桌面体验
没有达到预期，同时复制 Web 已有页面和功能会形成第二套界面、状态管理、自动更新与实机兼容性维护成本。当前
产品验证更需要集中迭代已经稳定使用的 Web 入口，而不是同时维护两个用户端。

这里退役的是面向最终用户的原生 Windows 应用。生产架构中的 Windows Server/WSL2 从节点、Windows AI
Runner、DDNS、Docker 与远程部署脚本仍是 Web 服务高可用和 AI 执行基础设施，不属于客户端退役范围。

## 决策

- 删除 `wao-windows/` 的 WPF 主程序、桌面宠物、核心库、更新器和测试，停止开发与发布原生 Windows 客户端。
- main CD 不再运行 .NET Windows runner，不再生成或部署 `WAO-win-x64.zip` 与 `latest.json`，生产探针也不再
  验证客户端制品。
- 云 Nginx 移除 `/downloads/windows/**` 的下载路由；Web 前端仍由现有入口统一交付。
- 服务端飞书授权移除只供 WPF 使用的 `windows` 场景、`callbackUrl` 参数和 loopback 重定向签名载荷，保留
  Web 的扫码、授权、工作台、浏览器和账号绑定场景。
- ADR-075、ADR-076 与两份原生 Windows 规格标记为已取代或已退役，保留历史背景，不把过去决策改写成从未发生。
- Windows 从节点、Windows AI Runner 及相关运维链路保持不变；“Windows 基础设施”不等于“Windows 客户端”。

## 影响

- 产品功能与交互只需在 Web 端实现和验收，减少重复 UI、桌面兼容性、安装分发、自更新和登录协议的维护面。
- 原生客户端已有代码与公开下载入口停止维护，历史安装包不会再收到更新；后续若重新启动桌面端，需要新任务和
  新 ADR 重新评估产品体验、技术选型、签名发布与长期维护预算，不能直接恢复已退役协议。
- Web 生产部署仍会覆盖 Linux 主节点、Windows/WSL2 从节点与云前端，双节点故障转移能力不受本决策影响。
