# ADR-129：Runner 生成可审核的机器与应用记忆报告

## 状态

已采纳。补充 ADR-110；仅对“不得把本机生成状态当作第二权威库”的规则作受控例外。

## 背景

统一记忆中心已经覆盖个人、组织和项目，但仍依赖人工或业务运行主动提交，无法回答“某台电脑积累了哪些
可复用经验”以及“某个 AI 应用在各电脑上沉淀了什么”。OpenAI 官方 Codex 本地记忆保存在每台主机的
`CODEX_HOME/memories/`，没有可按账号从云端批量拉取这些内容的 API；Computer History 又只在获得成员
明确授权的 macOS 桌面端可用，不能由 WAO 服务端代为开启。

直接上传整个 Codex Home 会把登录凭据、会话证据和临时状态带出电脑，也会重新形成与 WAO 冲突的权威源。
把目录不存在时的空结果伪装成记忆同样没有业务价值。

## 决策

- 在既有权限范围之外增加 `machine` 与 `application` 两个可审核范围。机器 id 使用已配对 Runner id；
  应用 id 来自 Runner 已上报的真实引擎能力。普通成员可查看和提交候选，只有管理员可发布、驳回或废止。
- Runner 每 24 小时在空闲时检查一次官方 `CODEX_HOME/memories/`。只读取该目录内的普通文本文件，跳过
  符号链接、二进制和超限内容；总输入有界，并在进入模型前再次遮盖常见 Token、密码和私钥。
- 原始文件不离开电脑。Runner 把脱敏后的有界文本作为明确标注的不可信引用，交给关闭 shell、网页、MCP、
  多 Agent 等工具的 Codex 生成机器报告和 Codex 应用报告；只上传结构化报告，不上传登录文件、原始会话或证据。
- 服务端以 `runner_id + scope_type + scope_id` 保持一篇稳定文档。正文未变化只刷新采集时间；变化时生成
  不可变候选版本，管理员审核后才进入正式记忆。失败记录最近尝试和脱敏错误，六小时后重试；目录不存在时
  明确显示没有真实来源，不创建空白文档。
- WAO 的已发布版本仍是唯一权威源。采集是单向候选导入，不修改本地 Codex 记忆，也不自动把候选注入 AI。
  手工创建、版本历史、冲突保护和敏感凭据拒绝规则继续适用。

## 后果

- 记忆中心可以按电脑或应用维护真实、可追溯、可审核的记忆报告，后续新增 Runner 引擎时不需要新增权限模型。
- 首次产出仍依赖成员在 Codex 中主动启用本地 Memories 并产生合格内容；WAO 不绕过产品授权，也不伪造报告。
- 模型摘要可能遗漏或误分类，因此默认候选审核是必要门槛；原始本地文件不上传，审核者只能核对报告正文与来源电脑。
