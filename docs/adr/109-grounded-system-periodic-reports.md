# ADR-109：系统周期报告使用任务与 AI Run 的确定性快照

## 状态

已采纳。

## 背景

WAO 已经有手工输入材料的“周报生成”和成员私有的“人生回顾”，但两者都不是系统建设视角：前者不读取
系统数据，后者不统计 AI 开发运行。日报、周报、月报如果继续依赖模型概括，还会把空数据扩写成看似完整的
进展，且在 Runner 离线时无法按时产出。

## 决策

- 新增团队共享的“系统报告”模块，提供日报、周报、月报切换和前后周期浏览；低频入口收口到首页理念卡片，保留原路由但不再占用侧栏。
- 报告只聚合数据库中的真实项目、任务和 `ai_task_run`：保存生成时的系统存量统计，以及周期内新建/完成
  任务和创建的 AI Run 清单。没有数据时保存 0 和空清单，不补示例或 AI 文案。
- 日报覆盖上海自然日；周报覆盖周一至周日；月报覆盖自然月。默认从每天 00:00 起每 24 小时刷新最近完整的三类周期，团队可以持久化修改起始时间、1/3/6/12/24 小时频率和自动报告类型。
- Linux 主节点在启动后也补齐最近一个已经结束的日、周、月，唯一 `(period_type, period_key)` 和 upsert
  保证重启、手动补齐与定时触发幂等。其它 API 节点关闭调度，但所有已登录成员都可读取和手动补齐。
- 团队可选择汇总新建任务、完成任务、AI Run 与 Token；每次生成只读取所选来源，并把汇总项写进快照，避免日后设置变化篡改旧报告语义。
- 报告是周期快照；重新补齐同一周期会更新同一份快照，不新增重复历史。

## 后果

- 报告不依赖模型、外部接口或个人记忆，固定时点可以稳定产出，所有明细都能回到任务页面核对。
- `task.created_at` 在 V79 之前无法可靠回填的旧种子数据不会伪造为某个周期的新建任务，但仍计入系统存量。
- 当前只覆盖系统建设的核心事实；若以后把部署耗时、线上健康或飞书通知回执纳入报告，需要先建立对应的
  可查询持久化数据，不能从记忆或文本摘要猜测。
- 高频自动刷新会重复扫描最近完整周期，因而频率只开放 1/3/6/12/24 小时的有界选项；默认仍为低成本的 24 小时。
