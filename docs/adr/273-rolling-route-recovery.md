# ADR-273：首台检查失败后的滚动路由恢复

- 状态：已采纳
- 日期：2026-09-24
- 来源：构建 #501 的首台公网检查遇到短暂 502/504 后失败，下一轮构建摘流 Linux1 时因 Linux2 仍被摘流，出现公网 API 不可用采样
- 调整：ADR-271 的首台可验证流程

## 决策

常规双节点发布在摘流 Linux1 前，先从云端确认 Linux2 Gateway 健康、恢复 Linux2 的公网路由，并检查公共 API。任一步失败都不开始滚动发布。首台发布后的公网版本、路由和 API 检查允许最多六次检查，间隔十秒；只有全部通过才发送阶段通知。检查持续失败时记录失败，并尝试恢复健康的旧 Linux2 路由，避免把下一次构建留在单节点状态。

完整发布仍保留持续可用性采样；真实不可用采样会让最终发布失败。特殊数据库维护窗口和显式离线模式不套用常规双节点的预检条件。
