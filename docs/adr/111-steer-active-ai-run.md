# ADR-111：运行中的 AI Run 通过中断当前回合并恢复会话接收新输入

## 状态

已采纳。扩展 ADR-027 的结束后续跑能力。

## 背景

AI Run 执行期间，任务详情只允许停止任务；追加输入仅对成功或失败的运行开放。用户在 AI 已经执行时想到
新的约束，只能等待结束再续跑，AI 可能沿错误方向继续消耗时间。当前 Runner 使用 `codex exec`、Claude Code
和 Qoder 的非交互 JSONL 进程，这些进程没有可复用的网页输入通道，单纯保存评论不能改变当前执行。

## 决策

- `POST /api/ai/runs/{runId}/continue` 同时接受 queued / claimed / running 运行。每次只保留一条尚未被
  Runner 接收的 `pending_input`；上一条未接收时拒绝覆盖，避免用户输入静默丢失。
- queued 阶段的补充随首次 claim 一起进入初始提示。running 阶段由 Runner 在既有三秒控制轮询中读取；
  Runner 结束当前 CLI 回合、取得 session id 后，精确确认消费该正文，再用同一 session 和 worktree 恢复。
- 停止信号优先于追加输入。无法取得可恢复 session id 时明确失败，不用新会话伪装“同一线程”。
- 如果输入恰好在 CLI 自然结束后、完成回传前到达，服务端不写终态，而是把同一次运行固定排回原电脑；
  下一次 claim 消费输入并恢复刚回传的 session，收口竞态。
- 任务详情对活动运行展示 Markdown 输入框，发送中、等待执行电脑接收、已接收和失败状态均来自真实 API
  状态；运行时间线永久记录用户补充和 Runner 接收事件。

## 后果

- 用户无需等整次运行结束即可纠正方向，已完成的正确工作和同一 CLI 上下文继续保留。
- 每次活动输入会结束并重新启动一个 CLI 回合，可能增加少量上下文和 token；多个回合的真实用量合并到同一
  AI Run，不把中断的非零退出码当成任务失败。
- 一次只允许一条待接收输入，换取明确的投递状态和简单的失败恢复；连续快速输入需要等上一条被 Runner 接收。
