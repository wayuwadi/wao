# ADR-187：爬虫能力以源码资产管理，不直接进入通用调度器执行

- 状态：已接受
- 日期：2026-08-31

## 背景

任务要求为后续自动化脚本新增“爬虫能力”管理入口，并提到具体爬虫代码会从群聊提供。当前仓库的
`automation_job` 表达的是已经绑定受控 `JobHandler` 的运行实例；ADR-010 明确规定描述性步骤不是可执行代码，
未知 handler 必须失败关闭。任务公开原文没有附带爬虫源码、目标站点、认证方式或运行资源限制。

把任意源码直接当作自动化任务执行，会绕过现有执行器登记、凭据隔离、资源上限和审计边界；用示例脚本或静态结果
填充页面又会把演示数据冒充真实能力。

## 决策

- 新增独立的 `crawler_capability` 源码资产表和“爬虫能力”页面，保存名称、说明、Python / JavaScript 语言、真实源码、
  启用状态、修改人、时间和递增版本号。
- 页面覆盖加载、失败重试、空数据、保存中、失败保留输入与本机草稿；更新和删除携带版本号，服务端条件写入，避免
  多人编辑时静默覆盖。
- “启用”只表示允许后续受控执行器引用，不表示脚本已经运行。源码不进入 `AutomationService`，也不产生虚假的运行记录。
- 具体群聊代码收到后由用户通过页面保存；若要实际运行，必须单独确定目标站点授权、凭据来源、依赖、网络与资源限制，
  并登记受控 `JobHandler` 或隔离执行器。

## 后果

- 后续爬虫代码有独立、可检索、可编辑的真实入口，不再与调度实例混在一起。
- 本次交付不声称具备任意代码执行能力；这一限制在页面直接展示，避免用户把“已启用”误解成“已执行”。
- 源码目前以组织共享资产保存；不得把 Token、密码或 Cookie 写入源码，凭据继续由密码本或部署配置提供。
