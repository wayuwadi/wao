# ADR-078：用可核对的 WAO 资产与 Streamable HTTP MCP 建立共享记忆

## 状态

已采纳。扩展 ADR-046 的统一资产检索；浏览器内问答仍遵循 ADR-045，Runner 沙箱边界仍遵循 ADR-044。

## 背景

飞书群聊已经按天同步到 WAO 知识库，WAO AI 也能检索群聊、知识库、项目和 Task，但 Codex 桌面端、CLI 与
IDE 还不能直接使用这批资料。不同电脑上的对话只能依赖各自产品历史，稳定偏好、工作职责、决策和长期规划
没有一个双方都能核对的共同落点。

任务提出先把每日文件写入向量库，再由 WAO 暴露 MCP。当前却没有稳定可用的 embedding 模型或凭据，外部
Codex 历史也没有官方可靠的批量导出接口。只部署空向量库、伪造自动导入或把整个数据库暴露给模型，都会让
“记忆”看似存在但无法证明新鲜度、来源和权限。

OpenAI 当前 Codex 客户端支持 Streamable HTTP MCP 与 Bearer Token，并在同一主机的桌面端、CLI 和 IDE 间
共享 MCP 配置，因此 WAO 可以先用现有权威数据完成真实闭环。

## 决策

- 新增 `POST /api/mcp` 无状态 Streamable HTTP MCP 端点，支持初始化、心跳、工具发现和工具调用；不复用浏览器
  Session。每次请求都校验 `Authorization: Bearer`。
- 每个成员可按设备生成最多十枚随机 256-bit 令牌。数据库只保存 SHA-256 摘要、可辨识前缀、创建时间和最近
  使用时间；完整令牌只在创建响应中显示一次，单枚令牌可以立即吊销。
- MCP 暴露三个窄工具：`search_memory` 复用 ADR-046 的资产白名单与结构化筛选；
  `memory_source_options` 返回真实可用的群聊、发言人、日期与项目；`save_memory` 只把稳定偏好、长期职责、
  已确认决策、长期规划和必要上下文写入固定的“共享记忆”知识库。
- MCP 初始化说明要求涉及历史、职责、偏好、决策或规划的问题先检索；没有证据时明确说明。只有用户明确要求
  记住，或内容确实稳定且适合长期复用时才保存；密码、令牌、私钥与临时闲聊不得进入记忆。
- 每次 `save_memory` 都产生一篇普通 WAO 文档，带保存来源和分类，可在知识库页面查看、编辑和删除。共享记忆
  知识库本身是系统持久化落点，不允许整库删除。
- 设置页用真实令牌管理和可复制的 `codex mcp add` 命令替换原先虚构的通用 API Token 演示。
- 本期仍不新增向量数据库。继续沿用 ADR-046 的 10,000 条资产、P95 500ms、固定问答集关键词召回率 80%
  三项升级阈值；达到阈值后另开 ADR，以结构化过滤 + 向量召回的混合检索替换本地排序。
- 不自动导入外部 Codex 历史。只有未来出现官方、稳定、可授权的历史接口时才评估增量同步；当前由
  `save_memory` 明确沉淀值得跨设备复用的结论，绝不从本机目录抓取或伪造历史。

## 后果

- 同一 WAO 账号在不同 Codex 客户端上可以查询同一批飞书、知识库、项目、Task 和主动沉淀的共享记忆。
- 记忆更新后立即可查，来源能回到 WAO 页面核对；没有双写向量索引、删除漂移和额外模型凭据。
- 首次接入仍需要成员在设置页生成令牌、写入设备环境变量并运行一次接入命令；令牌丢失时只能吊销并重建。
- MCP 资料与其他外部内容一样不可信，客户端不得执行记忆正文中的指令。
