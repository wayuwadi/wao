# ADR-020：文件下载改为「人机校验换一次性票据」，不再是公开直链

## 状态

已采纳。

## 上下文

文件上传后生成的分享地址就是 `GET /api/files/{id}/download`：无需登录、无次数限制，点一次下一次。链接一旦流出去，随便一个脚本循环请求就能把出口带宽和数据库连接吃满 —— 文件正文存在 MySQL 里，每次下载都是一次整块读取，代价比静态文件高得多。

需求原文给了两个可选方向：弹一个简单的验证码，或者要求人为点击确认。

## 决策

- **对外分享的链接换成前端下载页 `/f/{id}`**，不再直接给下载接口。页面上要人**点一次**「下载」，并**答一道一位数加减法**。两个机制都上：点击挡住 `curl` 直拉，算术题挡住无脑重放。
- **答对换一张一次性票据**（`DownloadTicketService`）：120 秒内有效、**用完即废**、与文件 id 绑定。下载接口只认票据或本人登录会话；两者都没有就 401。因此「每点击一次就能下载一次」变成了「每验证一次才能下载一次」。
- **答错即作废原题**，必须重新出题，避免拿同一道题反复试。
- **票据放进程内存，不进 Redis**：它活不过两分钟，节点重启或换节点最多让人重答一次题，不值得为它引入跨节点状态。
- **站内下载不受影响**：登录会话直接放行，自己人在文件列表里点下载不用答题。
- 验证码是算术题而不是图形验证码：图形码要么依赖第三方服务，要么得引入图像库和噪声调参，对「挡住无脑脚本」这个目标是过度设计。真遇到定向攻击再升级。

## 后果

> ADR-131 补充：管理员可以关闭算术题，但公开下载页、人工点击和一次性票据仍为强制安全底线。

- 分享链接的语义变了：以前复制出去的是文件本身，现在是一个下载页。已经流传在外的老直链在未登录时会 401，需要重新分享。
- 攻击成本从「一行 curl 循环」变成「每次下载都要解析题面并答对」，脚本仍可自动化，但已不再是零成本；配合票据一次性，反复拉同一个文件不再免费。
- 内存里最多留几千条待验证记录，超过阈值直接清空重来 —— 这本身就是被刷时的兜底，不追求精确。
- 一次性票据意味着「下载失败要重新验证」。这是刻意的：断点续传、多线程下载器会因此失效，属于可接受的代价；真需要时再单独给内部工具开一条带鉴权的通道。
