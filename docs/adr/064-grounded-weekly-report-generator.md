# ADR-064：周报生成复用只读 Codex 并保留本机编辑草稿

## 状态

已采纳。复用 ADR-041、ADR-044 的本地 Codex 队列和安全边界；不引入第二套模型凭据。

## 背景

用户的周报原始材料经常只有一句话或几条零散工作记录，需要快速整理成工程化结构，但生成式模型容易把模糊进展扩大成
“已完成”、补写不存在的指标或擅自承诺下周事项。WAO 已有真实在线状态可见的本地 Codex 只读队列，无需新增模型供应商或
伪造规则模板。

逐段编辑属于尚未落库的本地输入。若重复生成直接替换现有结果，会违反 WAO 的草稿防丢原则；而为一份临时周报立即新增
数据库历史、分享和跨设备同步，会扩大本期需求和隐私数据面。

## 决策

- 新增成员可见的“周报生成”原生模块和专用 `POST /api/weekly-report/generate` 接口。
- 后端使用 `AiAssistantService.runReadOnlyJob`，只把本次原始记录放进有界提示；不检索其它 WAO 资产，不进入 AI 聊天历史。
- 模型只能返回 `completed`、`progress`、`risks`、`nextPlan` 四个非空字符串字段。服务端解析并校验完整 JSON，失败时要求
  重试，不使用静态兜底周报。
- 提示明确禁止新增项目名、状态、指标和承诺；栏目缺失事实必须输出待补充标记。
- 前端让四段内容独立编辑，以当前成员 id 分隔 `localStorage` 草稿；保存状态对用户可见。
- 再次生成先保存为候选版本，只有用户明确采用才替换当前编辑；复制始终使用当前编辑稿。
- 专用 Nginx 路径保留 330 秒读取超时并关闭自动重放，和服务端五分钟 Runner 等待一致。

## 后果

- 一句话和多条记录都能使用同一真实 AI 链路生成，并可逐段校对原文、编辑和复制。
- 页面刷新可恢复当前设备草稿，但本期不提供跨设备周报历史；界面明确称为“本机草稿”，不伪装服务端保存。
- 结构化 JSON 约束能发现不完整输出，但不能形式化证明每句话都忠实，因此界面持续展示原始记录并提醒成员最终核对。
