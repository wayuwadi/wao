# ADR-046：AI 助手使用可筛选的统一 WAO 资产检索

## 状态

已采纳。取代 ADR-045 中“只检索最近 120 篇飞书聊天文档”的范围；成员级会话和 Runner 安全边界不变。

## 背景

AI 助手已经能引用同步到知识库的群聊，但无法限定群聊、发言人和日期。查询几个月前的内容时，近期文档的
候选上限会直接漏掉正确记录。知识库文档、项目和 Task 也都是 WAO 内可追溯的业务资产，如果助手只能读取
聊天，同一个问题仍要由用户手工在多个模块之间搬运上下文。

引入向量数据库还需要稳定的 embedding 模型、增量索引队列、删除同步、权限过滤和备份恢复。当前 Codex
OAuth / Responses 问答链路不提供 embedding，当前数据规模也可以由同库的有界候选查询覆盖；只部署一个
空的向量库不会提高召回，反而会制造第二份可能过期的数据。

## 决策

- 建立逻辑上的统一资产检索层，首批资产类型为 `chat`、`knowledge`、`project`、`task`。每个候选都统一提供
  类型、标题、站内链接、正文和可用的更新时间，回答必须列出实际引用资产。
- 默认检索四类资产；请求可以限定资产类型、群聊 id、发言人显示名、群聊归档日期范围和项目 id。日期来自
  `飞书群聊 · YYYY-MM-DD` 的归档标题，不用文档最后编辑时间冒充消息日期；发言人筛选后只向模型提供该发言人
  的消息行。
- 来源选项由 `/api/assistant/source-options` 从真实配置和业务表返回，前端不写死群名、成员或项目。当前群聊
  同步只配置一个目标群，但接口和请求使用数组，后续多群归档可保持契约兼容。
- 检索直接读取现有权威表：聊天和知识库文档最多各 500/300 条候选，项目最多 300 条，Task 最多 600 条；
  先做结构化过滤，再按问题的中文二元/三元片段、标题加权进行排序，最终最多传 5 个来源、10,000 字上下文。
- “整个 WAO 的资产”采用安全白名单，不包含密钥库、系统配置、登录凭据、Runner 令牌、成员私人助手会话等
  敏感或个人数据。新增业务域要显式增加资产适配器并复核权限，不能通过反射或全库导出自动暴露。
- 本期不新增向量数据库和 embedding 表。出现任一条件时重新做检索评估并另开 ADR：可检索资产超过 10,000
  条、有界检索 P95 超过 500ms，或固定问答集的关键词召回率低于 80%。届时统一资产结构作为混合检索入口，
  向量召回必须与现有结构化条件共同过滤，并具备增量更新、删除和重建能力。

## 后果

- 用户可以把搜索范围固定到某个群、某位发言人和历史日期，也能一次询问知识库、项目与 Task，引用仍可回到
  WAO 原始页面核对。
- 数据更新立即可检索，没有双写和索引延迟；当前规模下无需维护新的数据库、模型凭据和备份链路。
- 本地排序不是语义向量检索，同义表达可能漏召回；通过固定评估集和上述阈值决定何时升级，而不是凭主观感觉
  提前增加基础设施。
