# ADR-159：饮食管理保存真实三餐与低风险自我观察

## 状态

已接受（2026-08-29）。

## 背景

WAO 已有形象管理的成员私有工作区，但缺少把工作日、休息日三餐提前安排并用实际结果复盘的入口。任务希望从
《黄帝内经》的角度改善饮食质量和效率，但系统没有经过授权校验的经典全文、营养数据库、医疗档案或专业审核，
不能把模型或固定规则包装成体质判断、胃病诊断和个性化处方。

## 决策

- 新增原生个人模块「饮食管理」，分别保存工作日与休息日的三餐模板、真实用餐记录、成员自述档案和备餐事项。
- 采用成员唯一的 `food_workspace` JSON 快照；服务端校验所有业务记录，首次进入返回空集合，不插入示例餐单。
- 用餐记录按日期与餐次保持唯一，保存食物标签、时间、准备时长、1～5 分主观质量和舒服/一般/不舒服三档餐后感受。页面仅从真实记录汇总次数、
  平均耗时和食物观察，不持久化或信任派生的“适合”结论。
- 《黄帝内经》只用于“饮食有节、按日常节律安排、观察自身反应”的文化提示，不伪造原文与出处，不提供药膳、方剂、
  穴位、治疗、热量或营养处方；持续、严重或紧急不适引导成员咨询合格医务人员。
- 编辑内容先落本机草稿，再自动同步服务端；失败后保留草稿并显式重试。备餐到期状态按当前日期计算，未接入外部投递时
  只声称站内提醒。
- 内置菜单注册表升级版本并补入稳定 id `food`；旧注册表保留已有改名、分组、排序与显隐配置。

## 后果

成员可以把“吃什么”从临时决定变成可复用模板，并用自己的实际感受和耗时持续调整；换设备后仍能读取同一份工作区。
本期不会告诉成员“胃属于什么体质”或哪种食物具有医学效果。若以后接入营养分析、经典原文引用或专业健康建议，必须先取得
可靠数据授权、专业审核，并新增高风险能力 ADR。

## 回退

前端菜单和路由可以独立隐藏；`food_workspace` 只保存新增成员数据，不改变既有业务表。回退应用版本时保留数据表，重新发布
本版本即可恢复读取，不需要破坏性迁移。
