# ADR-114：空闲后自动执行录入最早的待办

## 状态

已采纳。

## 背景

任务通常在有想法时先录入，真正派工时只是打开任务、点击 AI Run、选择 Plan 后开始。这个重复动作会让已经
明确可做的任务长期停在列表里。此前额度驱动的“自主进化”已经暂停，而且它负责从资料生成新建议，不应被
复用来执行用户已录入的真实任务。

## 决策

- 首页“最近完成”列表上方提供独立的自动派发开关、空闲小时数、项目、任务状态和触发通知群配置，默认开启、
  默认 2 小时、默认项目为“Wa All in One”、默认状态为“待办”，空闲时长允许设置 1 到 168 小时。
  状态支持多选“待办 / 收集中 / 进行中”；“AI 进行中 / 待验证 / 已完成”不开放给无人值守调度。
  通知目标来自加密的通用 Webhook 注册表，未指定时沿用系统默认目标。加载、未保存、保存中、已保存和失败重试
  状态都必须可见；一分钟状态轮询不得覆盖本地草稿。
- 空闲时间沿用 AI Run 最近创建或结束时间；仍有 `queued / claimed / running` 运行时不派发，并在运行结束后
  重新计时。
- 候选只取人工选择的单个项目与来源状态，且项目必须已启用真实 AI 工作流并配置 Git 仓库、任务没有活动主任务
  运行，再按服务端 `created_at` 最早优先。默认只推进“Wa All in One”的“待办”；进行中和收集中只有被明确
  选中时才可进入候选，AI 进行中、待验证和已完成始终不由无人值守调度擅自重跑。
- 自动派发复用现有 AI Run 入队、任务状态、Runner、PR、部署和飞书通知链路，并为 Codex 固化 `plan_mode =
  true`；默认引擎不是 Codex 时继续使用该引擎的真实能力，不伪造 Plan 支持。
- 自动派发入队时向策略选择的通知群单独发送“闲置时间已自动推进任务”卡片，写明空闲阈值与 Plan 模式；同一时刻
  不再重复发送通用“任务已派给 AI”卡片。通知失败不回滚已经真实入队的任务，但最近检查结果必须明确提醒修复目标。
- 独立单例状态保存开关、阈值、下次检查窗口和最近结果。Linux 主节点每分钟轮询，数据库用自身时钟原子抢占
  五分钟检查窗口；Windows 从节点明确关闭调度器，误配双开时仍不会重复派发。
- 人工 AI Run 的 Codex 选择器默认开启 Plan，但保留本次手动关闭能力。本决策取代 ADR-093 的“默认关闭”。

## 后果

- 用户所选项目和状态中录入最早的任务会在系统真实空闲后自动开始，看到结果后再自然补充反馈，不必重复完成固定派工操作。
- 没有符合条件的待办、项目未接入工作流、没有兼容 Runner 或分享地址缺失时，只记录真实原因并等待下轮检查，
  不创建占位任务或演示运行。
- 默认开启会改变升级后的调度行为；用户可在首页随时关闭，关闭只停止后续自动派发，不取消已入队运行。
