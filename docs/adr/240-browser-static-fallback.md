# ADR-240：浏览器静态资源直连与同版回退

状态：采纳；默认云端，直连另行验收后开启。

## 决策

主站地址、Vue Router、账号 Cookie 和 API 地址保持原有语义。Vite 只把构建资源地址改为 /releases/完整SHA/assets/。云端小型启动器等待静态请求处理器就绪后才加载入口及样式；浏览器不支持或禁止 Service Worker 时有界等待后直接使用云端同版文件。

Service Worker 仅处理同源、无查询参数、无 Range 的版本化 assets GET；不接管导航、API、用户上传、OAuth、流式连接和任何写操作。节点请求不带 Cookie 或调用方请求头，不允许重定向。每份响应验证该版本清单的长度和 SHA-256，完整下载成功后才交给浏览器；失败尝试下一启用节点，最终回退原始同源请求。返回新 Response，避免节点 Response.url 改变相对依赖解析来源。

节点白名单固定为两台 Linux 的可信 HTTPS origin。运维清单指定总开关、静态开关、强制云端、逐节点开关和允许版本；配置读取失败默认云端。清单有效期30秒，故障节点冷却60秒，不随机分流，不对已有页面做自动刷新。清单下载1.5秒、节点清单2.5秒、单文件12秒超时，最大静态文件32MiB。完整缓冲和哈希校验增加少量内存与首字节等待，换取下载中断时不会执行半份资源。

实机故障演练补充：等待响应头最多1.5秒，已响应文件继续使用剩余下载预算。避免离线节点消耗完整12秒下载窗口；不会把正在正常传输的大文件也强制限制为1.5秒。

版本化资源使用浏览器常规缓存，不增加 Cache Storage，也不缓存账号数据。发布保留已有节点开关，仅将安装完成的新版本加入允许列表；列表外旧页面仍使用保留的云端文件。错误清单会阻止发布，不自动重置运维开关。

此前动态分包错误自动刷新可能丢失编辑状态。本次默认改为提示手动恢复，保留用户当前输入。没有对业务请求增加自动重试。

## 验收与启用

测试覆盖直连、无凭据、错误版本、损坏内容、节点断网、强制云端、未知节点、未批准版本、写请求不重试和故障冷却。构建后核对登录页面及延迟加载。生产默认不启用直连；先在独立验收页面验证真实浏览器下载与节点失联回退，再切开关。

运维文件：云端 /etc/wao-public-edge/routing.json。直连启用需 enabled、staticEnabled 为 true，forceCloud 为 false，目标节点 enabled 为 true，并有已验证版本。Linux2 的公共可信入口尚未验收时保持 false。

回退：原子将 forceCloud 改为 true。现有页面下一批请求在至多30秒配置缓存后使用云端；正在进行的静态请求在有界超时内回退，不刷新页面。极端处理器代码故障可将 /edge-static-worker.js 替换为仅 fetch(event.request) 的版本并保留该文件，不能简单删掉文件就假设旧客户端已卸载。

依据：[Vite 公共基础路径](https://vite.dev/guide/build#public-base-path)、[Service Worker 响应 URL 的解析语义](https://developer.mozilla.org/en-US/docs/Web/API/FetchEvent/respondWith)。
