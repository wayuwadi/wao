# ADR-286：节点故障时显式单节点应急发布与独立构建入口

- 状态：已采纳
- 日期：2026-09-27
- 调整：ADR-285 在唯一健康节点上禁止继续完整发布的决定；正常双节点滚动发布仍按 ADR-285 执行

## 背景

Linux2 同时承担 Jenkins 与应用主节点。Linux2 故障时，Linux1 可以继续提供服务，但 Jenkins 构建或第二节点部署失败会阻止新代码到达网页入口。维护者接受个人应用在应急更新期间短暂不可用，要求机器故障时继续使用健康节点，代码或构建失败时终止。

## 决策

1. 正常发布仍先 Linux1 后 Linux2，双节点和公共入口均通过才报告双节点成功。
2. Jenkins 提供默认关闭的 `ALLOW_MASTER_OFFLINE`：Linux2 发布前不就绪，或 Linux1 已完成相同 SHA 的安装与云端就绪验证而 Linux2 随后部署失败时，可保持 Linux2 摘流，发布 Linux1 与云端。Linux1 构建、安装或就绪失败必须终止，不能被此开关掩盖。若 Linux2 失败后无法确认 Linux1 和公共入口健康，也必须终止。
3. `ALLOW_SLAVE_OFFLINE` 在 Linux1 SSH/Docker 预检失败且 Linux2 健康时，可摘流 Linux1，允许 Linux2 单节点更新；Linux1 可连接后出现的代码或安装失败仍终止。两个离线开关不得同时使用，也不与从库重建或 Linux2 专属基础设施变更混用。
4. 当 Jenkins 自身不可用时，Linux1 控制台可从独立干净 checkout 构建与安装精确的 `origin/main` SHA；安装脚本复用 Jenkins 的网页构建、镜像构建、源码归档和节点验证。浏览器制品通过手动 GitHub Actions 托管 runner 构建，使用已有云端部署身份，在云端确认 Linux1 直接数据库就绪后，摘流未同步新版本的 Linux2，更新路由与静态页。Linux2 应用本身健康但 Jenkins 故障时也可走此路径。此路径不会使用本机作为唯一构建机，也不在云机部署数据库或应用容器。
5. 单节点成功须明确标记降级节点、公共入口已验证版本和待补齐事项；不宣称双节点成功。故障节点恢复后，重新对同一目标 SHA 执行正常双节点发布，确认双方一致后再取消降级状态。

## 限制与验收

- 两台应用都不健康、共享数据库不可写、构建失败、云端回源不就绪、Nginx 配置失败时不发布。单节点原地替换可能短暂返回 502/504；最终就绪和前端 SHA 未通过时不得报成功。
- 手动云端工作流必须在 Linux1 控制台打印 `WAO_LINUX1_EMERGENCY_RELEASE_VERIFIED=<SHA>` 后触发，同一 SHA 不允许由手工口述缩写代替。工作流无法远程读取 Linux1 的镜像清单，因此保留这一步人工交接；未来若增加可信的节点版本 API，可自动核对。
- Linux2 专属 AI VPN、Runner 领取与部分主节点路由在 Linux2 故障时不能保证可用；此应急路径优先恢复普通网页和双节点路由的业务 API，不能宣称所有功能完整。
