# ADR-259：任务拖拽使用个人顺序，取消隐含嵌套

日期：2026-09-23。

用户确认表格与四象限拖拽用于调整顺序，仅影响当前成员并跨设备保留；截图中的子任务列表同样适用。

- 表格行和子任务行上半区插入前方，下半区插入后方，用插入线反馈位置；拖到行中央不再变成子任务。
- 只在同一父级内调整顺序，不改变已有父子关系；子任务跨任务/父级移动继续通过属性里的显式移动操作进行。
- 四象限同区卡片可排序，跨区保留既有优先级移动行为；优先级仍是任务共享字段，个人顺序单独保存。
- 复用成员偏好 API，键 task-order-v1:project:<id>、task-order-v1:all、task-order-v1:subs:<id>。
  同项目表格和四象限共用顺序，子任务使用稳定 id；不改变编号、正文、项目或创建时间。
- 顺序只读取登录成员的偏好；新成员不继承旧账号状态，迟到响应不能写入新账号。排序失败保留本机草稿，提供重试与刷新恢复；保存期间继续拖动串行写入最新顺序。
- 筛选不删除隐藏任务的排序信息。个人偏好服务端持久化，跨设备重新读取；不新增数据库 migration。
- 排序偏好上限 60000 字符，其他偏好继续限制 4000 字符；过大时明确失败，不声称保存成功。

验收覆盖前后插入、同级保护、跨区优先级、刷新恢复、成员隔离、失败重试、在途保存与筛选隐藏项保留。

## 本次验收记录

- 前端相关 4 个测试文件、27 项测试通过，包含排序保存、草稿恢复、成员切换、连续拖动和子任务/四象限组件；后端成员偏好额度与账号维度测试通过。
- 受影响文件 ESLint、TypeScript 与 Vite 构建通过；构建仅有既有大包提示。工程一致性检查无新增错误，保留 4 个历史 ADR 重号警告。
- 本地应用连接既有数据库，以真实项目“娃哥的能良工作”验证：表格把 #1157 拖到 #1040 前，显示保存成功，刷新后顺序恢复；切换四象限同区顺序一致，再拖回原顺序并刷新，回表格保持一致。任务编号、子任务归属和优先级保持不变。
- 本次真实数据中的各主任务只有一条内嵌子任务，内嵌多条排序通过组件测试覆盖，未为验收向真实项目添加测试任务；跨设备读取由新客户端状态测试覆盖，未在第二台实体设备登录验收。
