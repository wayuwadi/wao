# ADR-194：今日节奏倒计时使用服务端每日实例保存运行状态

## 状态

已接受（2026-09-03）。本决策扩展 ADR-101 的清单模板与每日实例。

## 背景

每日必做原先只有手动完成状态。若倒计时仅存在浏览器内，刷新、关闭页面、换设备或浏览器后台降频都会让固定时长失真，也无法让历史记录证明这次仪式真实走完。

## 决策

- 清单模板增加 `CHECK` 与 `COUNTDOWN` 两种完成方式；倒计时模板保存固定秒数，界面以分钟配置并限制为 1—1440 分钟。
- 每日实例快照类型和固定时长，并保存开始时刻与累计秒数。开始、暂停和重置通过当前成员受限的接口原子更新，客户端不提交已耗时或完成事实。
- 服务端按上海时区和已保存开始时刻计算剩余时间；读取面板或操作计时器时发现归零，自动写入完成时间。前端使用本次服务端剩余时间与本地经过时间流畅展示，并在归零时回写确认。
- 倒计时项目不能通过普通完成接口提前勾选；重置会清除计时与完成状态，以便开始新一轮完整时长。
- 既有记录由数据库默认值兼容为 `CHECK`；系统联动项固定为普通打卡，不改变计划、考勤和卦象联动语义。

## 后果

- 倒计时在刷新和换设备后仍可信，浏览器只负责显示，完成事实由服务端判定。
- 新增一次向后兼容 migration 和一个计时操作接口；不需要高频服务端写入或独立定时任务。
- 页面打开或计时操作会收口已到期但尚未回写的倒计时，短暂离线不会丢失经过时间。
