# ADR-039：用外部应用注册表驱动独立应用菜单与嵌入页

## 状态

已采纳，扩展 ADR-038 中 WAO 只承载菜单、页签与同域 iframe 壳的决策。自媒体 Agent 仍采用 ADR-038 的共享 Session 和独立部署方式。

## 上下文

自媒体 Agent 首次接入时，WAO 把模块 id、菜单元数据、路由、健康检查地址和 iframe 地址写死在前端。即使 Agent 自身可以独立发布，菜单改名、换组或后续接入第二个独立应用仍要修改并重新发布 WAO，壳层继续成为所有外部应用的发布耦合点。

系统已经有全局 `system_setting`、动态导航和通用页签能力，适合把外部应用元数据提升为服务端配置。已有 `navigation.media-agent.*` 配置已经在线使用，升级过程必须保留其名称、分组、排序与显隐状态，也必须兼容三节点滚动发布期间的旧前端。

## 决策

- 新增版本化全局配置 `navigation.external-apps`，保存最多 30 条外部应用记录。每条包含稳定标识、菜单名、Remix Icon、分组、排序、显隐、应用入口与可选健康检查地址。
- WAO 使用统一受保护路由 `/apps/:appId` 和通用 iframe 壳；新增外部应用不再增加 Vue 路由或页面组件。
- 菜单项使用 `external:<appId>` 命名空间，与内置 `ModuleId` 隔离；已持久化的 `mediaAgent` 页签自动迁移为 `external:media-agent`。
- 注册表未保存或损坏时，从 `navigation.media-agent.*` 合成默认 `media-agent` 记录。首次保存新注册表后以新键为准，显式空列表不会恢复默认应用。
- `/media-agent` 永久重定向到 `/apps/media-agent`；旧 `/api/settings/navigation/media-agent` 读写接口保留为兼容适配层。
- 应用入口和健康检查地址只允许站内绝对路径或无用户信息的 HTTPS 地址，拒绝 `javascript:`、协议相对地址和明文 HTTP。
- 站内应用可以沿用 `WAO_SESSION`。跨域 HTTPS 应用能否嵌入及共享身份由其 Cookie、CORS 和 CSP 决定，WAO 不绕过浏览器安全策略。
- 删除注册记录只删除 WAO 菜单和通用页面配置，不删除独立应用服务、数据库或部署产物。

## 后果

- 后续接入独立应用时，只要它已经有可访问的页面入口，就能在系统设置注册菜单，无需修改或重新发布 WAO。
- 外部应用的网关路由、静态目录、服务部署和共享身份契约仍由各应用自己的工程与运维配置负责，注册表不替代基础设施发布。
- 稳定 `appId` 成为页签、本地缓存和直达 URL 的契约，保存后不可在设置页修改；需要更名时应新建记录并按计划迁移旧链接。
- 全局注册表整体保存，新增、编辑、删除和排序共享一个原子快照；所有成员看到相同菜单。
