# ADR-251：四库一致性备份与异机增量日志恢复

## 范围

用户明确确认备份 wao、tools、wayuwa、tkwork。Linux2 目前是这四库的写入源，Linux1 的现有在线复制仍仅包含 wao，不能混淆复制和独立备份。

format=3 快照使用 MySQL 9.7 的 single-transaction 与 source-data=2，四库一次导出并记录一致的 binlog 文件、位置和源 UUID。独立 DDL 备份锁覆盖导出，非 InnoDB 或缺库即拒绝发布。format=1/2 的恢复继续兼容。

每天全量，两端加密保存至少七份且保留七天；只有新备份完成异机校验后才清理过期副本。Jenkins 本机日备保持，完整异机归档每周纳入一次，避免每天重复数 GB 构建归档挤占 250GB 节点。Jenkins 缺失不再阻止四库恢复点发布，清单明确记录缺项。

## binlog

每五分钟轮转一次，使用 mysqlbinlog 的原始协议读取已关闭日志，校验长度、事件校验和与原始 SHA256，加密压缩后传输，远端验证密文和元数据后才发布 COMPLETE。源 MySQL 原有日志保留策略不被脚本修改。

归档按 source_uuid/文件名隔离。额外用户库出现时拒绝扩大范围，主库只读时拒绝继续把它当作写主。后续 MySQL 接管必须同步调整备份源和重新建立全量起点，不能直接跨源 UUID 拼接日志。

日志只清理所有现存 format=3 快照最早起点之前的文件；无可用起点时不自动删除。全量和日志产出前均检查 20% 磁盘余量，空间不足失败并告警，不以删除必要日志换取假成功。

## 恢复

无网络、无宿主数据库卷、无公开端口的临时 MySQL 9.7 导入全量。核对四库表清单和 CHECK TABLE，再解密连续日志到指定文件/位置，在一个 mysqlbinlog 和一个 mysql 连接中回放。目标先于全量、来源不同、缺日志、摘要不符或位置越界均拒绝。

隔离库事件调度关闭，二进制日志关闭，回放跳过源 GTID；该实例用于恢复验证，不能直接把它当已建立复制的生产副本。

五分钟是归档调度间隔，不是零丢失保证。以最后异机完成坐标和实际恢复演练报告为准；首次大日志归档或慢链路可能超过间隔。独立节点每五分钟检查，超过十分钟未完成归档告警。

官方依据：[MySQL 9.7 mysqldump](https://dev.mysql.com/doc/refman/9.7/en/mysqldump.html)、[mysqlbinlog](https://dev.mysql.com/doc/refman/9.7/en/mysqlbinlog.html)。
