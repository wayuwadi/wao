# ADR-010：自动化任务的执行范围——真实 Cron 触发 + 模拟执行，不做外部系统集成

## 状态

已采纳。

## 上下文

自动化模块此前是纯前端演示：`AutomationView.vue` 的「运行」「暂停」「重新授权」按钮只弹 toast，不改变任何状态，数据来自 fixtures。种子数据里的任务（飞书群聊沉淀、手机相册备份、账单邮件归档、证件到期提醒）都依赖外部系统（飞书开放平台、NAS、邮箱 IMAP）。

把这些任务接到真实的飞书 / NAS / 邮箱 API 是一次次独立的对外集成（各自的鉴权、限流、错误处理、Secrets 管理），工作量和风险都远超「让自动化模块可用」这个目标，也不是本轮能安全交付的范围（涉及外部凭据、真实数据读写）。

但如果只做 CRUD 不做任何真实调度，自动化模块仍然只是「更好看的静态页面」，没有回应「完善自动化功能」的核心诉求：任务应该能真的按计划跑起来、真的能产生运行记录。

## 决策

- `automation_job` 新增 `cron_expr`（标准 5 段 Cron，可为空）与 `next_fire_at`；新建任务时留空则只能手动触发，非空则进入真实调度。
- `JobSchedulerService` 用 `@Scheduled(fixedDelay = 60_000)` 每分钟轮询 `next_fire_at <= now` 且未暂停的任务，调用 `AutomationService.executeScheduled` 记录一次运行并用 `CronExpression.next()` 推进下一次触发时间——**触发时机是真实的**。
- 执行内容是**模拟的**：`executeScheduled` 直接写入一条「成功 · 自动执行」的运行记录，不会真的去拉飞书消息或扫描 NAS；`steps_json` 仍是给人看的描述性文本，不是可执行配置。
- 手动触发（`POST /api/jobs/{id}/run`）、暂停 / 恢复、重新授权均落库并产生真实状态变更与运行记录，不再是纯 UI 反馈。

## 后果

- 用户新建一个带 Cron 表达式的自动化任务后，能观察到它真的按计划产生运行记录，这比纯演示前进了一步，且不引入外部系统集成的安全与运维负担。
- 运行记录的「结果」目前总是可预测的（正常任务成功、待修复任务失败），不反映任何真实业务结果；把某个具体任务接入真实执行引擎（如「飞书群聊 → 知识库沉淀」真的调用飞书 API）需要新的 spec + ADR，届时应替换 `executeScheduled` 中对应任务的模拟逻辑，而不是扩大这个通用调度器的职责。
- 种子数据（`V8__automation_seed.sql`）里的 4 个任务保持 `cron_expr = NULL`（沿用原展示型 `schedule_label`），避免刚上线就产生大量无意义的模拟运行记录；只有新建任务显式填写 Cron 才会被调度。
