# ADR-102：飞书收集使用成员身份与持久事件幂等

## 状态

已接受（2026-08-23）。

## 背景

原有快速收集将任何可读群消息写入一个全局项目，识别不出发言人时回退到固定成员，且仅在单 JVM
内存去重。这会造成普通聊天被误记、任务归错人，以及飞书重试或双节点回调时的重复任务。

## 决策

1. 只处理含 @提及的目标群文本/富文本消息；语音条只回复转文字指引。
2. 使用发言人飞书 `open_id → account_identity → account.member_id` 确定唯一任务归属。未绑定时拒绝创建，
   不使用默认负责人。
3. “记录任务”和“记录想法”都创建个人待办，这与用户要求的“自己的任务列表”一致；
   不在没有明确授权时将个人想法发布到团队共享点子库。
4. 捕获任务不设截止日期；标题去除记录意图前缀，完整内容保留在描述。
5. 新增 `feishu_quick_collect_event`，用唯一事件键先占位再创建任务；记录创建、拒绝或失败结果。

## 后果

用户不用先打开 WAO，而且回执、任务详情和 TODO 列表三者指向同一真实数据。代价是第一次使用者
必须先绑定飞书身份，并多一张事件幂等与结果追溯表。
