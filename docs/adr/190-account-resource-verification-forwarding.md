# ADR-190：账号资源与验证码转发采用双令牌、加密消息和飞书可重试投递

- 状态：已接受
- 日期：2026-09-01

## 背景

任务原文描述了公司账号库、多个平台登录依赖手机号验证码，以及短信经“验证码接收”群集中转发后，爬虫按当前
使用的手机号查找验证码并自动登录。现有“密码本”按成员私有（ADR-024），不能改成组织共享而破坏个人敏感数据
边界；现有“爬虫能力”只保存源码资产（ADR-187），也没有短信数据源、取码接口或飞书转发状态。

手机短信来源与爬虫运行环境没有随任务提供固定厂商 SDK。硬编码示例短信、随机验证码或假飞书结果都会把演示数据
冒充真实能力；把同一 Token 同时交给手机和爬虫，又会让只需读取验证码的爬虫获得伪造短信权限。

## 决策

- 新增组织共享 `account_resource`，保存平台、账号名称、登录标识、规范化手机号、备注、启停状态和递增版本；密码
  使用既有 `WAO_VAULT_KEY` 做 AES-256-GCM 加密，列表只返回 `hasSecret`，显式查看时才解密一次。个人密码本保持不变。
- 手机通过标准 HTTPS JSON 入站，不绑定某个短信转发 App。入站 Bearer Token 与爬虫只读 Bearer Token 分开生成、
  分别轮换，只在生成响应中显示一次，数据库只存 SHA-256 摘要。
- 入站消息以外部消息 id 或内容指纹幂等；短信正文和解析出的验证码均加密落库。只有验证码/校验码/动态码/OTP 等
  明确语境中的 4–8 位数字才会识别为验证码，避免把手机号、订单号或日期误当验证码。
- 中国大陆 `+86` 与无区号手机号统一规范化后匹配账号。爬虫默认只能取得五分钟内的最近验证码，调用方最多放宽到
  十分钟，避免错误使用旧码；验证码消息保留三十天，并在后续入站时清理过期记录。
- 飞书投递复用通用 Webhook 注册表，可选择稳定配置 id，留空时使用系统默认机器人。飞书失败不回滚已经接收的短信，
  页面显示失败原因并允许重试；已经成功或重复入站的消息不会再次发送。验证码是五分钟级时效消息，不受普通系统通知
  的静默时段抑制，但所选机器人停用或不可用时仍失败关闭。

## 后果

- 账号资源、短信转发与爬虫取码形成真实闭环，外部手机只需能发送标准 HTTPS 请求，不依赖演示数据或特定供应商。
- 获得手机入站 Token 的设备不能读取历史验证码；获得爬虫 Token 的程序不能新增短信、读取账号密码或使用 WAO 会话。
- 服务端与 `WAO_VAULT_KEY` 同时失陷时仍可解密敏感内容，信任边界与 ADR-009 一致，不宣称零知识加密。
- 首次生产使用仍需用户在页面选择真实飞书机器人、生成两枚令牌，并把它们分别配置到真实手机转发器和爬虫环境；
  未完成配置时页面明确显示“尚未生成”，不会伪造已接入状态。
