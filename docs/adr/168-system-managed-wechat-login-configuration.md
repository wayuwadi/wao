# ADR-168：系统设置统一管理微信公众号登录配置

## 状态

已采纳。

## 背景

ADR-167 已交付微信公众号带参二维码、关注与四位验证码登录的真实链路，但 App ID、App Secret、回调 Token
只能写入两台服务器的私有环境文件。任务 `t1788148473577` 要求把配置入口放进“系统设置 → 系统登录配置”。
继续只依赖环境变量会让业务管理员无法判断当前配置是否完整，每次换密钥还要发布并重启服务。

## 决策

- 新增“系统登录配置”入口与 `/api/settings/login/wechat-official` 读写接口，集中管理公众号登录开关、App ID、
  App Secret、回调 Token 和微信后台服务器地址。
- App Secret 与回调 Token 复用 `VaultCryptoService` 以 AES-256-GCM 加密写入 `system_setting`；接口只返回
  脱敏值和“已设置”状态。密钥输入框留空表示保留现有密文，浏览器永远拿不到明文。
- 认证服务在每次创建二维码、校验回调或读取用户资料时读取同一份运行时配置快照。保存 App 凭据后清理 Redis
  中缓存的微信 access token，使新配置无需重启即可用于两台应用节点。
- 数据库配置优先；某一项尚未保存时回退 ADR-167 的部署环境变量，保证滚动发布与回滚期间旧配置继续可用。
  微信 API 与二维码域名仍是部署基线，不开放给表单改写，避免把认证凭据发送到任意主机。
- 启用时必须具备完整的 App ID、App Secret 与回调 Token；不生成静态二维码、测试账号或演示成功状态。
  关闭公众号登录不影响飞书与邮箱登录。

## 后果

管理员可在页面完成加载、编辑、保存、失败重试和停用；未保存草稿离开页面前会得到确认。原环境变量成为首次
迁移和紧急回滚的兼容来源，不再是日常改配置的必经路径。生产端到端验收仍需认证公众号真实权限、微信后台明文
回调配置和实际微信账号，不能由单元测试冒充。
