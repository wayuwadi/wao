# ADR-121：自动任务统一遵守可配置断网时段

## 状态

已采纳。

## 背景

WAO 所在网络每天 00:00 到 06:00 会因 VPN 中断而不可用。HTTP 性能巡检原定 01:30 创建真实 AI Run，
最早待办自动派发也会在任意五分钟检查窗口触发；两条链路在已知断网时段执行只会留下可避免的失败。
断网规律还会被后续自动功能复用，不能散落成多个调度器里的硬编码判断。

## 决策

- 在现有 `system_setting` 保存一个系统级每日断网窗口，设置页可启用或停用并编辑开始、结束时间。默认启用
  `00:00–06:00`，按 `Asia/Shanghai` 判断；开始时间包含、结束时间不包含，并支持跨午夜窗口。
- 自动化 Cron 调度器与“空闲后执行最早待办”在窗口内不领取任务。Cron 任务保留原计划点，网络恢复后沿用
  既有补跑语义；自动派发不抢占数据库五分钟窗口，恢复后可立即参与下一次轮询。手动触发不受限制。
- HTTP 请求性能巡检从每日 01:30 调整到 06:30，确保其读取真实指标和创建 AI Run 都发生在默认恢复时间之后。
  已执行的 V93 不修改，使用 V94 更新现有任务的 Cron、展示文案与下次计划时间。
- 起止时间相同会造成“全天断网”歧义，因此拒绝保存；配置损坏时服务回落到安全默认值，不用伪造在线状态。

## 后果

- 已知断网不再制造自动任务失败，调整断网规律无需发布代码；后续需要网络的调度器可复用统一服务。
- 断网窗口只约束无人值守触发，不阻止管理员在窗口内明确手动执行。窗口结束时到期 Cron 可能补跑，仍保留
  既有按原计划点推进、不丢业务日期的行为。
