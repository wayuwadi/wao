# ADR-110：以消息指纹同步飞书原消息编辑并转存图片

## 状态

已接受（2026-08-25）。

## 背景

ADR-102/103 已用 `message_id` 解决回调、轮询和双节点重复建任务，但幂等行为只有“重复即忽略”。
飞书用户常在第一次 @ 机器人记录后继续编辑原消息补充细节；接收事件不会为这类客户端编辑提供一条
可依赖的新建事件，而现有近两分钟轮询也无法重新看到较早创建的消息。富文本里的图片此前同样未进入
任务描述。

## 决策

1. 保持 `message_id → target_id` 的一对一关系，在收集事件表新增最近一次成功同步的
   `source_fingerprint`。相同指纹是重推，直接忽略；不同指纹是原消息编辑，更新既有任务。
2. 内容变化由数据库条件更新把事件状态原子切到 `PROCESSING`，双节点只有一个认领成功。成功后保存
   新指纹，失败保留旧指纹，使下一轮能重试。
3. 新消息的 15 秒、两分钟增量轮询不变；新增每分钟一次的 24 小时回看。回看使用飞书返回的当前正文，
   不伪造“编辑事件”，也不无界扫描全部历史。
4. 原消息编辑用窄 SQL 只更新标题和描述；WAO 内的状态、负责人、排期、结构化详情与协作内容保持不变，
   即使网页端同时保存也不以旧详情覆盖新输入。
5. 富文本 `img` 节点使用既有消息资源下载接口取得真实字节，按内容去重转存 `image_blob`，然后在原位置
   写入 `/api/images/{id}/raw` Markdown。任何凭据和飞书临时地址都不进入任务或 Git。
6. 图片链路失败时不降级成无图任务；首次创建的瞬时失败允许后续轮询重新认领，避免错误表情成为终态。

## 后果

用户可以把同一条飞书消息当作短时间内持续完善的任务草稿，且不会制造多条 WAO 任务。代价是每分钟
额外读取一次目标群近 24 小时消息；单次仍受飞书分页完整性门禁保护，超限或接口失败只记录真实错误，
不影响原有新消息增量链路。
