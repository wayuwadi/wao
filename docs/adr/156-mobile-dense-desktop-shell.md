# ADR-156：手机应用壳恢复桌面同构的高密度左栏

## 状态

已采纳，取代 ADR-145 中“成员级手机底栏作为主导航”的决策。

## 背景

ADR-145 用“项目 / 小记 / 更多”底栏降低了入口数量，但真实使用反馈表明，WAO 的主要价值来自同时观察多个
模块和运行状态。手机壳隐藏左栏、页签和顶栏动作后，用户每次只能看到少量入口与大块留白，信息密度远低于
PC，完整工作台也增加了一次跳转。

直接把手机 viewport 伪装成桌面宽度虽然视觉最接近 PC，却会关闭任务详情、密码查看、表单和浮层等已经验证的
手机专用交互，并把文字和触控目标缩小到不可可靠操作。因此应用壳应同构，业务交互仍按真实手机宽度响应。

## 决策

- 手机应用壳恢复纵向左栏，复用桌面菜单注册表、路由、分组和选中态；不建立第二套数据源。
- 左栏、顶栏、页签和首页间距在 `max-width: 760px` 下使用紧凑尺寸，正文继续使用既有手机响应式规则。
- 手机忽略桌面分组折叠状态，菜单区域独立滚动；手机不启用桌面拖拽、右键和停靠编辑。
- 手机继续保留悬浮新建任务、全屏聊天、安全区和 16px 表单控件等可操作性规则。
- 停止在工作台展示或更新 `mobile-bottom-nav-v1`；保留服务端已有偏好值，不做破坏性清理。

## 影响

- 用户无需先进入“更多”即可浏览所有可见模块，并能像 PC 一样保留页签上下文。
- 主内容宽度减少，因此业务页仍应维持各自的手机单列、可换行和全屏详情规则；新页面不能依赖桌面最小宽度。
- 旧成员底栏配置暂时成为休眠数据。若后续真实验收证明窄左栏不适合某类设备，可在不丢失成员选择的情况下
  回退或提供显式壳模式切换。
