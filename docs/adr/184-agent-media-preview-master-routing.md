# ADR-184：内容素材预览固定到 Linux 主节点

## 状态

已采纳。

## 背景

Agent 图片和视频素材记录在共享 MySQL，但原文件保存在接收上传请求的节点本地卷。内容编辑器增加持久化实时封面预览后，如果上传和读取继续经过双 Gateway 负载均衡，后续读取可能命中没有该文件的另一节点。

## 决策

- 云 Nginx 将 `/api/agent/publish/media` 的上传、列表和原文件预览统一固定到 `wao_ai_gateway` 对应的 Linux 主节点，并禁止失败自动重放。
- Agent 新增 `GET /api/agent/publish/media/{mediaAssetId}/content`。接口从当前 WAO Session 推导工作区，只返回属于该工作区、且实际存在于当前节点的文件。
- 响应使用数据库保存的媒体类型和内联文件名，不返回存储路径；非本工作区、其他节点或文件缺失均明确失败。
- 既有发布任务仍按素材记录的 `node_id` 执行；本决策只统一后续内容素材的上传与浏览入口，不迁移或伪造历史文件。

## 后果

- 新上传图片可以在编辑器实时预览、刷新后继续读取，且不会因负载均衡随机失效。
- Linux 主节点不可用时素材操作会明确失败，正文草稿和其他双节点只读能力不受影响。
- 若以后改用共享对象存储，应另写 ADR 撤销主节点固定路由，并保留工作区鉴权与内联响应契约。
