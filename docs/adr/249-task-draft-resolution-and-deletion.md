# ADR-249：冲突草稿收口与删除任务防复活

## 状态

已采纳，补充 ADR-248。

## 问题

恢复其他窗口的草稿后，保存或采用服务器版本只清理当前窗口副本，原窗口副本仍会被再次恢复。任务删除前清理草稿还会导致删除失败后丢失未保存内容。旧全文 PUT 在服务端记录缺失时走新建路径，可能将已删除任务复活。

## 决策

- 草稿恢复记录来源及不可变修订标识，随当前草稿持久化。保存确认或明确采用服务器版时，同时清理未再变化的来源副本；来源窗口后来输入的内容保留，不整包清空其他窗口草稿。
- 删除先停止当前任务的去抖保存，等待本窗口在途写入收口，再发送 DELETE。只有成功后才清理草稿、冲突状态并记成员隔离的删除标记。失败恢复任务和草稿；迟到响应不重建状态。
- 删除标记禁止旧窗口草稿再次恢复。服务端列表缺少的既有任务草稿（带版本或永久编号）留在本机存储，不插回任务列表，也不自动上传；缺失可能意味着删除或权限撤销。真正未提交的新建草稿仍可恢复。
- 服务端复用删除后保留的永久编号登记：任务不存在且曾分配编号时，旧 PUT 和新操作接口都拒绝重建；携带既有版本或编号的缺失任务也拒绝创建。无需新增表。返回 404，浏览器停止把明确拒绝当作待确认保存。
- 本次不自动删除已经存在的业务任务，也不抹除其他窗口新增内容。已被旧版复活到服务器的任务需由用户再次明确删除。

## 验收

覆盖跨窗口恢复后处理冲突再刷新、来源窗口继续输入、删除失败、删除与在途保存、缺失旧任务不回放、原新建任务重试以及服务端有版本/无版本旧草稿拒绝重建。
