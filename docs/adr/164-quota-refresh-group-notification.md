# ADR-164：真实额度上升时发送群通知

## 状态

已采纳。补充 ADR-031、ADR-065、ADR-083 与 ADR-163，不改变额度供应商、采样频率和通知总门禁。

## 背景

WAO 已能从集中 OAuth 账号和 Runner 本地 Codex 接口读取真实额度，也会在周额度过低时提醒，但额度窗口重置后只能靠
用户反复打开首页发现。用户希望当剩余额度从较低值回升（例如 80% → 100%）时，在当前 WAO 群收到通知，以便及时安排任务。

## 决策

- 集中 Codex/Claude 账号沿用 Linux 主节点每十五分钟的供应商同步，本地 Codex 沿用 Runner 每五分钟的脱敏额度上报；不新增
  轮询、估算或演示数据。
- 为两类来源保存独立的脱敏通知基线，只包含窗口标识、剩余百分比与重置时间，不保存令牌或供应商原始响应。首次采样只建立
  基线；同一窗口剩余百分比上升时，通过通用 Webhook 注册表中的当前默认机器人发送“AI 额度已刷新”卡片。
- 下降、持平、新出现或消失的窗口只更新基线，不发送刷新通知。多个窗口同一轮上升时合并为一张卡片，列出账号和每个窗口的
  前后比例，避免群消息轰炸。
- 群通知遵守总开关、上海时区沉默时段和“自动化通知”开关；策略阻止时不补发旧事件。真实发送失败时不推进通知基线，下一次
  真实采样继续重试。比较、发送与基线推进由数据库行锁串行化，双 API 节点不会重复发送同一刷新事件。通知处理失败不得阻断
  额度保存、Runner 心跳或自主调度。

## 后果

- 用户无需持续查看首页，也能在额度真正变多时从当前 WAO 群获知可用额度。
- 新表 `quota_refresh_notification_state` 只保存通知比较所需的脱敏状态；账号删除后留下的基线不包含凭据，不影响业务，可在后续
  数据维护中清理。
- 通知最迟随现有采样周期到达；供应商或 Runner 没有返回可靠额度时不发送，也不会伪造成 100%。
