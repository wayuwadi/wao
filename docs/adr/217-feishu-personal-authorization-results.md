# ADR-217：个人表情授权响应判定与可刷新结果页

- 日期：2026-09-09
- 状态：已采纳
- 补充 ADR-215，不改变个人授权与身份隔离边界。

## 问题与证据

用户补齐重定向地址、用户身份表情及持续访问权限后仍看到统一的授权失败提示；刷新回调页又显示授权过期。原实现用 `hasNonNull("error")` 判断错误，连空字符串也会拒绝，且所有令牌请求失败均被提示为权限问题，没有安全诊断日志。

飞书官方 SDK 的 `core/accesstoken/access_token.go` 对 `/oauth/v3/token` 以非零业务码或**非空**错误内容判断失败；空错误字段不能覆盖有效令牌。该判定缺陷由回归用例证实，但历史请求未记录响应分类，不能断言它已解释所有线上失败。

来源：https://github.com/larksuite/oapi-sdk-go/blob/v3_main/core/accesstoken/access_token.go

## 决策

- 保留现有 OAuth 地址、JSON 请求、PKCE、会话绑定、一次性 state、真实用户身份校验、权限检查与加密持久化；只将空 `error` 视为无错误。
- 区分应用凭据、授权码、权限、无效响应与请求异常；页面显示安全说明和本地产生的诊断号。日志仅含固定分类、HTTP 状态、数值业务码及诊断号，不保存外部错误描述、异常原因链、授权码、密钥或令牌。
- 回调处理后以 303 跳转 `/api/auth/feishu/reactions/result`。结果 HTML 在发起浏览器会话内保留十分钟，刷新结果页不调用令牌兑换；无结果或已过期时显示授权入口。结果页使用 no-store、no-referrer、DENY。
- 普通飞书登录回调、历史个人授权和提醒反馈行为保持兼容；不自动代替成员同意授权，不追补历史表情。

## 验证

覆盖空错误字段成功、非空错误失败、缺失权限拒绝、首次兑换与刷新、HTTP/网络错误安全分类、日志与异常脱敏、结果页刷新不重复兑换、会话隔离和结果过期。线上需重新发起个人授权确认成功结果，未通过前不能把构建成功当成授权已修复。
