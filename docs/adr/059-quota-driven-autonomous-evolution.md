# ADR-059：首页周额度与空闲自主进化

## 状态

已采纳。补充 ADR-021、ADR-031、ADR-032，不改变 AI 账号凭据和 Runner 的安全边界。

## 背景

WAO 已经能保存 Codex / Claude 的真实额度快照，也能把一句目标创建成任务并交给 AI Runner，
但两条链路彼此独立：用户要去设置页逐个查看额度，系统也不会在长时间无人派工时利用即将刷新的额度。
首页现有“自主目标”仍要求用户先想好目标，不提供可直接执行的改进建议。

## 决策

- 首页只展示 AI 供应商真实返回的七天窗口，统一换算成“周剩余百分比”；查询失败、没有周窗口或
  快照未知时明确显示未获取，不用 `0%` 或 `100%` 猜测。
- 首页提供服务端维护的改进建议清单。每条建议都是可直接交给既有自主目标链路的完整目标，点击后
  仍创建真实任务、独立 Git worktree，并走本地验证、PR、部署和飞书通知。
- 新增每 15 分钟检查一次的自主进化调度器。最近 12 小时没有任何 AI 任务、没有活动运行，且某个
  已启用集中账号的真实周剩余额度不低于 50% 时，系统在 WAO 自身已启用的项目工作流里轮换选择一条
  建议并自动派发。
- 调度前刷新 Codex / Claude OAuth 账号额度。只有本次刷新成功、周窗口可解析且默认引擎与账号匹配时
  才能自动派发；自定义 API、Qoder 和未知额度不参与阈值判断。
- 本次同步后的真实周剩余额度低于 50% 时，通过全局飞书 webhook 发橙色提醒；提醒键由账号和供应商返回的
  重置时间组成（缺失重置时间时回落到当前自然周），同一额度周期只发送一次，发送失败不写提醒键并在下轮检查重试。
- 用数据库中的单例状态行原子推进下次检查时间，避免双节点同时派发。状态同时记录最近检查结果、
  自动运行和建议，首页据此说明为什么正在等待或暂停。
- 自动任务继续复用 AI Run 的排队、完成通知；因此群里会看到开始做什么，以及完成后的结果和验收入口。

## 后果

- 周额度展示和自动触发都有可追溯的供应商快照，不会把未知额度包装成可用额度。
- 无人操作 12 小时后系统最多派发一项改进；新运行会重新开始 12 小时空闲计时，不会连续刷任务。
- 没有真实周额度、WAO 工作流、匹配的执行引擎或公网分享地址时只记录原因，不创建占位任务。
