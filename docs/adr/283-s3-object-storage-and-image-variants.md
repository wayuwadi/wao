# ADR-283：图片与附件迁往 S3 兼容对象存储

状态：实施中（2026-09-25）。

## 背景

`image_blob.content` 和 `file_blob.content` 目前保存在 MySQL。生产库约有 3,725 张图片、1.12 GiB 原图和 18 个附件、61.68 MiB。小记已有按需 JPEG 预览，但每次首次请求仍从 MySQL 读取原图并解码；数据库、主从复制和 SQL 备份都承担二进制正文。

## 决策

- 使用 S3 API 作为应用的二进制存储边界，自建 Garage 三节点集群（Linux1、Linux2、云节点），私有 bucket，仅 WAO 服务端持有读写密钥。选择 Garage 是因为它面向小规模自建异地集群；不采用已归档的 MinIO 社区仓库。对象接口保持 S3 兼容，未来可更换供应方。集群部署、数据备份和监控不依赖 MySQL 复制。
- MySQL 保留 id、名称、类型、尺寸、摘要、项目权限及对象 key；图片和附件原有 `/api/...` URL、权限和下载票据不变。对象永不直接公开，不在浏览器中暴露签名 URL。
- 图片上传保存原件，同时生成适合列表的轻量预览变体。压缩变体可以有损；原件的字节语义不变。GIF、SVG、WebP 等未验证转换的格式保留原样。不能承诺所有图片“2 MB 无损变 200 KB”。
- 采用扩展、回填、切换、收缩四阶段：先新增可空对象 key 并兼容双读；复制历史字节到对象存储并逐件核对长度和 SHA-256；再把新写入切到对象存储并观察；最后在有可恢复备份且经过独立审批后分批清理 MySQL 正文。任何阶段都可用旧正文回退，清理前不降低旧链接可用性。
- 迁移期间若对象不可读但 MySQL 正文尚在，回退读取旧正文；对已经没有 MySQL 正文的对象读取失败返回服务不可用，绝不伪装为图片不存在。对象写入成功但 SQL 事务失败时容忍孤儿对象，由独立审计清理；删除/替换时也延迟清理旧对象，避免并发请求读到缺失正文。
- 可读 WebDAV 导出和加密恢复备份必须在清理旧正文前改为支持对象来源；完成一次从对象存储恢复的演练后才能收缩列。现有 Linux2 `wao-return` 复制异常必须先修复或明确隔离，不能在复制落后时做大批量数据清理。

## 验收条件

1. 三节点 Garage 健康、私有读写和跨节点故障演练通过；对象访问密钥只存在服务器私有配置。
2. 图片与附件的新建、读取、替换、删除、下载、Range 流式播放、缩略图、权限和原链接在混合数据及单节点故障下通过真实业务验收。
3. 历史迁移逐件校验 SHA-256 和长度，记录总数、失败数、重试及抽样实际 HTTP 下载一致性；保持新写入与历史回填并行安全。
4. 可读导出、恢复备份及恢复演练覆盖 S3-only 行；备份与生产对象存储不共用唯一失效域。
5. 清理 MySQL 正文前获得明确授权和可回退快照；清理后统计 MySQL 数据量下降，全部 URL 继续有效。
