# ADR-283：图片与附件迁往 S3 兼容对象存储

状态：实施中（2026-09-25）。

## 背景

`image_blob.content` 和 `file_blob.content` 目前保存在 MySQL。生产库约有 3,725 张图片、1.12 GiB 原图和 18 个附件、61.68 MiB。小记已有按需 JPEG 预览，但每次首次请求仍从 MySQL 读取原图并解码；数据库、主从复制和 SQL 备份都承担二进制正文。

## 决策

- 使用 S3 API 作为应用的二进制存储边界，自建 Garage 三节点集群（Linux1、Linux2、云节点），私有 bucket，仅 WAO 服务端持有读写密钥。选择 Garage 是因为它面向小规模自建异地集群；不采用已归档的 MinIO 社区仓库。对象接口保持 S3 兼容，未来可更换供应方。集群部署、数据备份和监控不依赖 MySQL 复制。
- MySQL 保留 id、名称、原始类型/尺寸/摘要、项目权限及线上对象的类型/尺寸/摘要/key；图片和附件原有 `/api/...` URL、权限和下载票据不变。对象永不直接公开，不在浏览器中暴露签名 URL。
- 附件音视频的 HTTP Range 请求在 S3 来源上只取所需字节，并核对响应范围、长度和对象 SHA-256 元数据；保留 MySQL 正文时仍可回退读取，旧 MySQL 附件维持原有裁剪行为。完整下载继续逐件核对正文摘要。
- 用户选择在线 PNG 改用**像素无损 WebP**，原始 PNG 永久放入独立加密 WebDAV 归档，路径在 30 天滚动备份目录之外。归档必须上传后再下载、解密并校验 SHA-256，才能标记数据库。线上转换还须复核尺寸、逐像素内容与 ICC 配置，只有更小时才切换；APNG、异常/不支持的 PNG 保持原格式。`/raw` URL 不变，但成功优化的图片字节和 MIME 类型从 PNG 改为 WebP；原 PNG 通过归档恢复工具取回。不能承诺所有图片“2 MB 无损变 200 KB”。
- 图片上传先保存原件并生成适合列表的轻量 JPEG 预览；Linux2 定时批处理在 S3 模式、写主来源与返回副本校验通过后，依次回填对象、补齐缺失的大图预览、归档原 PNG、优化 WebP，并与离线对象备份互斥，持续处理新上传图片。归档前原件继续在 MySQL 或 S3 在线保留。GIF、SVG、JPEG 等格式不改原件；轻量预览可以有损且不取代原件。
- 采用扩展、回填、归档/优化、切换、收缩五阶段：先新增可空对象 key 并兼容双读；复制历史字节到对象存储并逐件核对长度和 SHA-256；独立归档每张原 PNG 后再优化为像素无损 WebP；新写入切到对象存储并观察；最后在有可恢复备份且经过独立审批后分批清理 MySQL 正文。清理前仍可用旧正文回退；清理后回退须使用已验证的对象和原件归档。
- 迁移期间若对象不可读但 MySQL 正文尚在，回退读取旧正文；对已经没有 MySQL 正文的对象读取失败返回服务不可用，绝不伪装为图片不存在。对象写入成功但 SQL 事务失败时容忍孤儿对象，由独立审计清理；删除/替换时也延迟清理旧对象，避免并发请求读到缺失正文。
- 可读 WebDAV 导出和加密恢复备份必须在清理旧正文前改为支持对象来源；完成一次从对象存储恢复的演练后才能收缩列。现有 Linux2 `wao-return` 复制异常必须先修复或明确隔离，不能在复制落后时做大批量数据清理。

## 验收条件

1. 三节点 Garage 健康、私有读写和跨节点故障演练通过；对象访问密钥只存在服务器私有配置。
2. 图片与附件的新建、读取、替换、删除、下载、Range 流式播放、缩略图、权限和原链接在混合数据及单节点故障下通过真实业务验收。
3. 历史迁移逐件校验 SHA-256 和长度；原 PNG 归档独立回读，WebP 转换逐像素复核；记录总数、失败数、重试及抽样实际 HTTP 下载；保持新写入与历史回填并行安全。
4. 可读导出、恢复备份及恢复演练覆盖 S3-only 行；原 PNG 加密归档保留在滚动清理路径之外，备份与生产对象存储不共用唯一失效域。
5. 清理 MySQL 正文前获得明确授权和可回退快照；清理后统计 MySQL 负载与数据量下降、对象存储实际占用及总体存储成本，全部 URL 继续有效。旧 S3 PNG 对象至少在 WebP 激活七天后，并经原件归档、线上 WebP、独立恢复备份及引用核验，另行获批清理。
