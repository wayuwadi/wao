# ADR-133：在记忆中心统一管理 Codex 连接

## 状态

已采纳。调整 ADR-078 中把 MCP 设备管理放在设置页的入口位置，不改变 ADR-082、ADR-110 的数据、权限和令牌契约。

## 背景

统一记忆中心已经成为个人、组织、项目、机器和应用长期记忆的顶层入口，但 Codex 设备令牌、授权范围和接入说明仍位于
“设置 → Codex 记忆 · MCP”。用户要核对记忆内容时必须进入记忆中心，要连接同一份记忆时却要切换到设置页；记忆中心
里的“管理 Codex 设备授权”也会把用户再次带离当前模块。

设备授权虽然包含安全配置，但它服务的是记忆读取和候选写入链路，不是站点或账号通用设置。继续保留两个入口会让用户
误以为这是两套记忆能力，也增加接入后返回核对真实记录的路径成本。

## 决策

- 记忆中心增加“记忆内容 / Codex 连接”二级入口；五类记忆范围仍只属于“记忆内容”，不把设备连接伪装成第六种记忆范围。
- 原 MCP 令牌、授权、接入命令和验证说明完整迁入“Codex 连接”，继续使用现有真实接口和全部加载、失败、空数据与操作状态。
- 设置页删除“Codex 记忆 · MCP”菜单，避免同一功能存在两个可编辑入口。
- 旧 `/settings?tab=memory-mcp` 与更早的 `/settings?tab=api` 在路由进入前重定向到
  `/memories?section=mcp`，避免收藏或历史链接先显示错误页面再跳动。
- 本次只调整前端信息架构，不修改 MCP 端点、令牌存储、范围授权或发布审核语义。

## 后果

- 用户可以在一个顶层模块中完成“管理记忆 → 连接 Codex → 返回核对”的闭环，设置页只保留通用系统和个人设置。
- 旧链接仍可访问新入口，但新的内部链接和文档统一使用记忆中心地址。
- “Codex 连接”首次打开才读取设备令牌；直接进入连接页不额外读取五类记忆列表，减少无关请求和错误状态干扰。
