# ADR-188：Linux2 统一生成加密异地备份并上传 123 云盘

## 状态

已采纳。

## 背景

WAO 的 MySQL 业务数据、Jenkins 控制器和 JumpServer 持久化数据分别位于两套本地备份或生产目录。Linux1 的
MySQL 脚本只生成本机七天归档，实际主机上没有对应 cron/systemd 任务；Jenkins 也只在 Linux2 本机保留七份。
因此现状无法抵御家庭主机磁盘损坏、误删或整机丢失。用户提供 123 云盘作为异地目标，123 云盘官方支持为指定
文件夹签发独立应用密码的 WebDAV 读写授权。

## 决策

- Linux2 是唯一打包点。每天导出 WAO MySQL 主库，复用 Jenkins 最近一次停写生成的校验归档；短暂停止
  JumpServer 后纳入其 `config`、`data`，并纳入生产私有环境和证书。完成本地归档后立即恢复 JumpServer，
  云端上传不扩大停机窗口。
- Redis 只承载可重建的会话/缓存，Nacos 服务注册会由实例重建，Docker 镜像和源码来自 Git/Jenkins；这些派生
  数据不进入每日全量备份。图片、文档和 AI Run 报告均已持久化到 WAO MySQL，随全库导出覆盖。
- 归档在离开主机前使用独立口令进行 GnuPG AES-256 对称加密，并切成 1 GiB 分片。每片记录 SHA-256；上传全部
  分片且逐个核对远端大小后，最后上传 `manifest.json` 作为完整提交标记。
- 123 云盘只使用限定备份文件夹、读写权限的 WebDAV 应用密码，不使用账号登录密码。应用密码和加密口令以
  root-only 文件留在 `/etc/wao-backup`，不进入 Git、Jenkins 凭据或备份归档；加密口令必须另存于异机密码库。
- Linux2 本地保留 7 天，远端保留 30 天。删除只匹配严格 UTC 时间目录；恢复工具只下载、校验并解包到空目录，
  不提供自动覆盖生产的入口。

## 后果

每日全量备份比增量仓库占用更多上传带宽，但恢复链路不依赖特定备份软件数据库，适合当前个人/小团队数据量。
WebDAV 不保证断点续传，1 GiB 分片让失败重试只重传缺失或大小不符的分片。备份任务依赖 Jenkins 当日一致性归档；
控制器持续繁忙或 123 云盘授权失效会让任务明确失败并保留本地证据，不会把旧归档冒充当天成功。

首次启用需要用户在 123 云盘生成专用应用密码并在 Linux2 交互配置。仓库只部署程序和 timer，不生成、记录或猜测
外部账号凭据。真实验收必须看到首次 service 成功、远端时间目录及一次解密到隔离目录的恢复演练。

## 回退

禁用 `wao-offsite-backup.timer` 即停止新备份，不影响现有 MySQL、Jenkins 或 JumpServer。本地和 123 云盘既有
加密归档保持可恢复；只有在确认不再需要且已有替代备份后，才单独删除远端目录和 `/etc/wao-backup` 凭据。
