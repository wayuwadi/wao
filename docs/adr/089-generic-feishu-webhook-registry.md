# ADR-089：飞书 Webhook 从单例升级为加密的通用机器人注册表

## 状态

已采纳。

## 上下文

ADR-019 为任务、评论和 AI 运行通知提供了一项全局飞书自定义机器人 Webhook。它解决了凭据不进 Git、
换群无需重启的问题，但“通知 · 飞书 Webhook”只能改一条匿名地址：使用者无法知道它对应哪个群、有什么用途，
也不能提前维护其它机器人供今日节奏等功能复用。

今日节奏中显示的“WAO”群并不来自这条 Webhook。它是“自动化 → 飞书群聊同步知识库”保存自建应用凭据后，
通过飞书开放接口实时列出的机器人所在群。自建应用按 `chat_id` 发消息与自定义机器人 Webhook 是两种独立通道，
不能用一个看似相同的群名掩盖配置来源。

## 决策

- 新增 `feishu_webhook_config`，每项保存稳定 id、名称、用途、启用状态和是否为现有系统通知默认目标。
  Webhook 地址继续用 `WAO_VAULT_KEY` 经 AES-256-GCM 加密，密文与随机 nonce 分列落库；列表和写入响应只返回
  脱敏地址，编辑其它字段时留空表示保留原地址。
- 提供列表、新增、编辑、删除和指定配置测试 API。第一项自动成为系统默认；把另一项设为默认时原默认项自动卸任；
  删除默认项时提升最近修改的剩余项。停用默认项即可暂停现有系统通知，不用制造“没有路由目标”的中间态。
- 只接受 `open.feishu.cn` / `open.larksuite.com` 的官方 HTTPS 自定义机器人路径，拒绝任意内网或第三方 URL，避免
  “发送测试消息”变成服务端请求伪造入口。异常与通知失败日志不记录 URL 或上游异常原文。
- V78 直接搬运 ADR-019 的 `enc:<nonce>:<ciphertext>`，迁移过程不解密。新注册表默认项同时镜像旧
  `feishu.webhook.*` 键，保证滚动发布与紧急回滚期间旧节点仍使用同一个目标；注册表被删空后写持久接管标记，
  不再让部署环境中的旧地址把用户删除的配置“恢复”回来。
- 设置页入口改名为“Webhook配置”，提供可识别名称、用途、脱敏地址、启停、默认路由、测试与增删改查。
  原设置页里的 CalDAV 演示卡片删除；真实的成员级 CalDAV 账户管理继续只在日历页维护。

## 后果

- 现有任务、评论、AI 运行和按项目通知无需改调用方，统一使用注册表的系统默认机器人。
- 今日节奏等业务可按稳定配置 id 接入同一注册表，不需要再各自存一份 Webhook 密钥；精力补给通知已提供 Webhook
  与飞书应用 `chat_id` 两种显式通道，旧成员配置继续使用原群聊通道，避免升级后改变投递目标。
- 数据库与 `WAO_VAULT_KEY` 同时泄露时仍可解密地址，信任边界与 ADR-019、密码本一致；这不是零知识存储。
- 旧 `/api/settings/feishu-webhook` 接口在滚动发布窗口继续兼容，新客户端使用 `/api/settings/webhooks`。
