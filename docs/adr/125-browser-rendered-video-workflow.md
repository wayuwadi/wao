# ADR-125：浏览器本地合成可控视频工作流

## 状态

已采纳。

## 上下文

成员希望制作一支约三分钟的 WAO 功能介绍视频，并能在站内看见、调整制作过程。ADR-074 已撤下
依赖额外平台 API Key 的视频生成：Codex / ChatGPT 订阅没有可复用的视频生成接口，网页自动化和预制
占位文件也都不是可靠实现。

本需求的核心是“把已有功能组织成可审核的介绍视频”，不要求生成写实镜头。WAO 已有 Agent 工作区、
媒体素材持久化与同域嵌入能力；现代浏览器也提供 Canvas 捕获和 MediaRecorder，可把确定性的文字动效真实
编码为 WebM，不需要第三方模型、额外账单或伪造异步进度。

## 决策

- 在自媒体 Agent 中新增“视频工作流”，首份项目是总时长 180 秒的 WAO 功能介绍分镜。
- 分镜标题、字幕、时长、主题色、启停和顺序都由成员人工控制；服务端按工作区持久化并用版本号阻止旧稿覆盖。
- 合成在浏览器中按真实时长执行，使用 Canvas 动效、全程字幕和 Web Audio 生成的原创轻音乐；不声称有 AI
  配音、屏幕录制或模型生成画面。
- MediaRecorder 成功产生真实 WebM 后才上传并把项目标记为“已导出”。取消、浏览器不支持、编码失败或上传
  失败都保留草稿，并提供明确重试。
- 视频工作流 API 固定到 Linux 主节点。该节点保存现有 Agent 媒体卷，上传、回放与下载必须落到同一节点；
  主节点不可用时明确失败，不回退到另一节点制造文件不存在的问题。
- ADR-074 继续有效：本决策没有恢复 `/api/agent/videos/**` 生成接口，也不接入任何非官方订阅身份。

## 后果

- 成员可不配置任何视频供应商就得到真实可播放的介绍视频，并在合成前逐镜审核。
- 三分钟成片需要页面保持打开约三分钟；这是浏览器实时编码的显式成本。切到后台可能被浏览器节流，页面会提醒
  保持当前标签页可见。
- 当前画面是信息图与字幕，不是自动屏幕录制或真人配音。若未来接入真实配音、截图采集或服务端离线编码，必须
  通过新 ADR 说明凭据、版权、资源和失败恢复边界。
