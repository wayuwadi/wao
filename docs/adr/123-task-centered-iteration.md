# ADR-123：迭代回归任务边界

- 状态：Accepted
- 日期：2026-08-26
- 调整：[ADR-107](107-project-centered-idea-lifecycle.md)、[ADR-118](118-task-first-idea-project-promotion.md)

## 背景

项目详情曾增加“项目最终目标 / 当前迭代”概览，并把任务的一轮执行包装为项目级多轮闭环；随后又允许把待验证或
已完成任务移动到新项目。真实使用表明，这两处设计把一次具体改进错误地提升成长期项目：项目页重复展示任务
状态，任务详情也出现了与日常执行无关的“升级为项目”入口。

任务已经具备描述、子任务、AI Run、待验证和完成状态，足以承载同一事项的持续补充与人工验收。项目仍是任务、
文档和成员的组织空间，不需要再表达一套“当前迭代”。

## 决策

1. 项目详情移除“项目最终目标 / 当前迭代”概览，项目头部之后直接进入任务、文档、文件、记忆与动态页签。
2. 任务详情移除“继续长期迭代 / 升级为项目”，任务在原所属项目中持续编辑、运行和验收。
3. 删除 `POST /api/tasks/{id}/promote-to-project` 及其前后端专用实现，不再提供隐藏入口或兼容写操作。
4. 已经通过旧能力移动到项目中的历史任务和项目保持原状；本变更不迁移、不删除业务数据。
5. 普通项目创建、项目设置、任务创建与批量 AI Run 保持可用；批量运行任务不再隐式改变项目状态。

## 后果

- 用户只在任务层维护一次改进的进度和验收，项目页恢复为任务组织视图。
- 旧升级接口调用将返回不存在；当前前端和公开 API 契约不再产生该请求。
- ADR-107 的历史点子归并结论继续有效；ADR-118 的任务升级决策由本 ADR 取代。
