# ADR-013：任务分享链接——公开只读页 + Markdown 直读地址双形态

## 状态

已采纳。

## 上下文

需求是「每个任务可以直接点击复制链接，并支持公网访问，这样我可以直接把链接给 AI，让 AI 去生成」，规则是主任务链接含子任务，子任务链接只含该子任务本身。

只做一个免登录的 Vue 页面不够：AI 拿到链接后通常是发一次普通 HTTP GET，SPA 返回的是空的 `index.html` 壳子，正文要执行前端 JS 才出得来。只有具备浏览器能力的 AI 才读得到，这恰恰不是「复制链接给 AI」这个用法的常态。

反过来，只做一个返回 `text/markdown` 的接口，人点开看到的是一坨纯文本，分享给同事的体验很差。

## 决策

同一份内容出两种形态，共用一个 `ShareService`：

- `GET /api/share/tasks/{id}` / `GET /api/share/tasks/{id}/subs/{subId}` 返回 JSON，给前端分享页 `/s/t/:id/:subId?` 渲染，这条路由 `meta.public = true`，不过登录守卫。
- `GET /api/share/tasks/{id}.md` / `GET /api/share/tasks/{id}/subs/{subId}.md` 直接返回 UTF-8 的 `text/markdown` 全文——这条是给 AI 的，一次 GET 就是完整上下文。

抽屉里的「复制链接」给出两个选项，文案直说各自的用途（「给人看」/「给 AI 用」）；展开某个子任务时，复制的范围自动收敛到该子任务。

分享视图是**投影**而不是完整任务：只有标题、状态、优先级、截止、项目名、描述、图片、子任务；负责人、参与人、评论、活动时间线一律不出现在 `SharedTaskDto` 里——不是靠调用方记得过滤，而是这个 DTO 根本没有这些字段。

子任务用稳定 id 定位；没有 id 的历史数据回落到 `<taskId>#<下标>` 合成键，前后端用同一套规则（`data.subKey` / `ShareService.subKey`）。

## 后果

- **任何人拿到链接就能看到任务内容，链接即凭据。** 当前实现里，任务 id 是 `t` + 毫秒时间戳，可枚举性不低——猜到一个存在的 id 就能读到那个任务的描述。这在当前阶段（个人 / 小团队、系统本身尚无鉴权层）可以接受，但**不适合放到有外部成员的正式环境**。收敛路径是给分享加一层不可猜的 token（`share_token` 表，按任务生成随机串，可撤销、可设有效期），届时 `/s/t/:id` 换成 `/s/:token`，本 ADR 需要更新。
- 分享内容永远是实时的，没有快照语义：任务改了，已发出去的链接看到的就是改后的内容。这符合「让 AI 读当前状态」的用法。
- `.md` 路径依赖 Spring 的 `PathPattern` 对「段内字面量后缀」的支持（`/tasks/{id}.md`）。任务 id 本身不含 `.`，不会和后缀混淆。
