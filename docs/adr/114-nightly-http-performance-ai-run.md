# ADR-114：用真实 HTTP 指标驱动每日性能治理 AI Run

## 状态

已采纳。

## 背景

浏览器端到端监控已经能看到成员真实经历的网络、网关和服务端完整等待时间，但发现慢请求后仍依赖人工
截图、建任务和派工。原自主进化按 ADR-059 已暂停，而且它只接受用户直接可感知的资产建议，不能为了本需求
重新启用或把通用技术巡检伪装成资产建议。

当前监控显示 `/api/tasks` 是最高频的主要慢路径。代码核对发现任务列表先读取全部任务，再为每条任务单独
查询所属项目并解析权限，形成随任务数增长的 N+1 查询。

## 决策

- 任务列表先一次读取当前成员可见项目 id，再用 `task.project_id` 既有索引一次批量取回任务；单任务读取和
  不可见资源统一返回 404 的权限边界保持不变。
- 新增独立夜间性能巡检，不恢复已暂停的自主进化。Linux 主节点每天 23:30 聚合最近 24 小时全体成员的
  去身份化 HTTP 指标；从节点默认关闭。
- 最近窗口有真实数据时，在现有「Wa All in One」工作流创建一条 AI Run。任务正文只写方法、路径、次数、
  状态和耗时聚合，不写成员 id、请求参数、正文或凭据；没有数据时不创建空任务。
- 日任务标题包含上海自然日，同一天已有同标题任务时跳过。项目、负责人、默认引擎和首选执行电脑均从
  现有持久化配置解析，不硬编码环境 id。
- AI 必须先判断是否有可实施优化；有证据才修根因并做真实链路对比，指标健康或证据不足时据实结束，
  不为产生提交引入缓存、演示数据或无依据改动。

## 后果

慢请求从发现到治理进入既有 Task、AI Runner、PR、部署和飞书通知闭环，同时与已暂停的通用自主进化保持
隔离。每日运行会消耗一次真实 AI 额度；没有监控数据、工作流未启用或部署配置缺失时明确跳过或报错，
不会伪造一次成功巡检。
