# ADR-107：用规划中项目承载点子全生命周期

- 状态：Accepted
- 日期：2026-08-24
- 取代：[ADR-098](098-idea-library-and-isolated-research.md)

> ADR-118 进一步把新点子入口收敛到任务，并增加验收后的项目升级；本 ADR 的历史点子无损归并决策继续有效。

## 背景

独立点子库虽然能保存多轮 AI 迭代，但八阶段、调研确认、会议结论和 MVP 门禁让“先做一版再逐步优化”的日常场景承担了不必要的流程成本。同时点子、项目、任务和知识文档重复表达同一件事，用户需要在多个页面维护状态。

现有任务和 AI Run 已具备正确边界：AI 成功只让任务进入“待验证”，同一 Run 可以沿用会话继续优化。真正缺少的是一个不会随单轮执行结束的长期容器。

## 决策

1. 新点子直接创建为“规划中”项目；点子库入口只是规划中项目的想法箱，不再创建独立 `idea`。
2. 项目表达最终目标，任务表达一轮工作，AI Run 表达一次执行。任务或 Run 不得自动完成、搁置项目。
3. 项目首次明确开始推进时进入“进行中”并只发送一次团队通知；快速收集保持静默。
4. 项目可以人工完成、搁置或恢复。完成本轮任务不等于完成项目。
5. 项目说明和其他知识文档按需创建在项目知识库；不默认把整个知识库注入 AI。
6. V83 点子表不删除。归并时复用明确关联的项目，生成稳定历史文档，旧资产只补项目出链，不移动或复制。

## 后果

- 用户从想法到多轮交付只维护一个项目，仍可复用任务、AI Run、知识库和工程记忆。
- 不再提供强制产品方法论门禁；需要调研、会议或验收模板时使用普通项目文档。
- 存量接口暂时保留，后续只有在确认所有旧点子已归并后才能另行 ADR 决定是否物理清理。
