# ADR-206：反向发布隧道动态解析真实公网地址

## 状态与问题

采纳，补充 ADR-158、ADR-203。Linux1 在线，但隧道服务硬编码主节点旧公网 IP，造成连续重连失败。主机 TUN DNS 返回 198.18.0.0/15 虚拟地址；重连过程中还发现服务端残留的旧隧道持续占用 2201，导致新转发失败。使用实时真实地址、关闭该连接的 IPQoS 标记并释放经核对归属的失效隧道后，原 Jenkins 地址的 SSH 操作恢复。未单独断言 QoS 或 TUN 是超时的唯一原因。

## 决策

隧道启动器先使用系统 DNS 的真实公网 IPv4；遇到虚拟地址或解析失败时，通过校验证书的 HTTPS DNS 查询真实 A 记录。仅接受公网 IPv4，失败退出由原 systemd 重启策略重试，不缓存或硬编码公网 IP。

隧道连接使用 IPQoS=none，不改变全机网络策略。SSH 保留域名 HostKeyAlias、严格主机密钥校验、原专用密钥及原 loopback 端口 2201/17897，不开放新公网监听，不修改账号授权。系统服务通过固定路径调用启动器，配置和密钥只留在主机。

## 验证与回退

测试覆盖普通 DNS、虚拟地址回退、非公网拒绝、解析失败与 SSH 身份/端口约束。线上先备份服务配置，再安装并重启单个隧道，以 Jenkins 原连接地址执行 hostname 及实际发布验证。回退恢复原服务备份；不能把固定公网 IP 作为长期方案。
