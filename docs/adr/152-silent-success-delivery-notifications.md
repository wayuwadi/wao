# ADR-152：交付成功保持静默，失败才主动通知

## 状态

已采纳。

## 背景

ADR-146 已把 AI Run 与 Jenkins 的终态卡片压缩为行动信息，但成功仍各发送一张卡片。飞书快速收集消息现在会在
任务进入 AI Run 队列后添加飞机表情，WAO 页面也持久化运行、部署和待验证状态；成功卡片再次复述相同结果，仍会
打断群聊。真正需要主动打断用户的是执行失败或终态不明。

快速收集创建成功时已经使用 `DONE` 表情表示“任务已记录”。同一机器人再次给同一消息添加相同 `DONE` 不能可靠
形成新的可见状态，因此 AI 完成不能复用该表情冒充新的反馈。

## 决策

1. AI Run 成功后不再发送“AI 任务待验收”卡片；来自飞书快速收集的任务在事务提交后给原消息添加飞书官方
   `CheckMark` 完成勾，与既有 `DONE`（已收集）和 `StatusInFlight`（已入队）明确区分。网页创建等没有真实飞书
   原消息的任务保持静默，完成结果继续在 WAO 任务和运行详情中查看。
2. AI Run 失败或未报告终态时继续发送一张短卡片，保留真实原因和任务详情入口；通知失败不回滚运行结果。
3. Jenkins 成功时不调用飞书 Webhook；GitHub 提交状态、Jenkins 记录和线上版本仍完整保存。Jenkins 失败卡片只保留
   失败原因与“查看 Jenkins 详情”按钮，不再展示批次、提交和节点摘要。
4. 本 ADR 取代 ADR-146 中 AI/Jenkins 成功卡片以及 Jenkins 失败范围卡片的决策，并收窄 ADR-144 中“每批发送一次”
   为“每个失败批次最多发送一次”。

## 后果

- 正常交付不再产生群卡片；快速收集发起人仍可从原消息的飞机和完成勾感知 AI 进度。
- 非飞书来源任务的成功提醒由 WAO 页面承担，不伪造消息关联，也不回落到可能属于其他群的全局 Webhook。
- 失败通知更短；批次提交、节点状态和完整日志需要通过 Jenkins 详情查看。

## 验收

- 服务测试证明成功运行只调用完成表情服务，失败与终态不明仍生成短卡片；表情测试覆盖完成勾、事务提交时序、
  无原消息和飞书接口失败降级。
- Shell 测试证明成功结果不会调用 Webhook，失败 JSON 只有失败原因和 Jenkins 详情按钮。
- main 部署后核对 Jenkins 成功日志没有飞书发送步骤、失败分支仍保留通知调用，并验证线上版本包含本次提交。
