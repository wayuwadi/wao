# ADR-096：WAO 作为跨设备 AI 长期记忆的唯一权威源

## 状态

已采纳。补充 ADR-078、ADR-082，并取代 ADR-087 中“成功 Run 自动生成正式项目记忆”的写入规则。

## 背景

个人记忆、项目工程记忆与历史共享记忆此前分别存储，版本、审核与设备授权边界不一致。Codex 本机生成记忆
属于单机状态；把它与 WAO 双向同步会形成双权威、循环覆盖和难以审计的冲突。组织和项目知识还需要先审核
再进入 AI 上下文，而个人明确要求记住的内容需要跨设备立即可用。

## 决策

- MySQL 中的 `memory_document` 与不可变 `memory_revision` 是长期记忆的唯一权威源。个人、组织、项目共用
  文档模型，但每次读写都同时限定 `scope_type + scope_id`；越权或枚举其他范围统一返回 404。
- 个人人工或 MCP 写入立即发布。组织成员和项目成员只能创建候选；管理员、超级管理员或项目负责人发布。
  驳回、废止、失效和回滚都保留历史，回滚通过从旧版生成一个新发布版本实现。
- 正文、当前版本指针与 `memory_outbox` 同事务提交，保存完成后另一设备下一次请求即可查询。outbox 只驱动
  派生索引；五分钟任务补偿失败事件，每日 03:30（Asia/Shanghai）检查版本指针、附件和索引一致性。
- 一期只做范围内的有界关键词检索，最多五条、正文合计 10,000 字。索引不可用时查询权威表，不伪造结果。
  达到单范围 10,000 条、P95 超过 500ms 或固定问答集召回低于 80% 时，另写 ADR 评估混合检索。
- `memory_source` 只保存 Task、Run、文档、PR、部署或外部 URL 的引用与摘录哈希，不复制完整对话；附件
  绑定不可变版本且继续执行 50MB 限制。使用日志不保存设备令牌或完整正文。
- `/api/mcp` 保留为个人兼容入口；新增带个人、组织、项目上下文的 MCP URL。个人提供 `save_memory`，组织
  和项目只提供 `propose_memory`，所有范围还提供查询、详情和分类能力。令牌吊销或授权变更立即生效。
- 不读取、不写入或同步各主机的 Codex Home 记忆文件；断网写入明确失败并由客户端重试，一期不建本地队列。
- 旧表先主写并影子写统一模型，对账后切换主写；旧 API/工具名适配新模型。旧表至少在一次生产备份恢复演练
  后才停止读取，暂不删除。

## 后果

- 个人、组织和项目获得一致的版本、来源、授权和跨设备语义，审核前候选不会污染 AI 上下文。
- 新 AI Run 只产生可追溯候选；ADR-087 产生的历史正式记忆按已发布 v1 迁移。
- 关键词检索无法覆盖所有同义表达，但性能和降级边界可测，后续升级有明确触发门槛。
