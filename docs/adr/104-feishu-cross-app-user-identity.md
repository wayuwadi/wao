# ADR 104：飞书跨应用用 Union ID 归属个人任务

## 状态

已接受（2026-08-23）。

## 背景

WAO 登录应用与群聊机器人应用不是同一个飞书应用。生产真实 `@`
消息已被轮询识别，但发言者的机器人应用 Open ID 与登录时保存的 Open ID
不同，因此被正确但误判为 `SENDER_NOT_BOUND`。

飞书官方定义 Open ID 仅在单应用内稳定，Union ID 在同开发商的多应用间稳定。

## 决策

- `account_identity` 同时保存提供方原始主体与 Union ID，两者都必须唯一归属。
- 每次飞书登录都补齐或刷新 Union ID；已有 Open ID 绑定不失效。
- 回调消息直接使用发件人对象中的 Union ID。
- 主动轮询只返回机器人应用 Open ID，因此分别以 Open ID 和 Union ID 读取目标群成员，
  仅在两份列表的昵称都唯一时换算；重名或不完整时拒绝归属。
- 既有身份的生产回填只能在“群成员昵称唯一”且“WAO 飞书身份显示名唯一”
  时执行，执行前后都校验一对一，不做模糊匹配。

## 后果

个人任务不再依赖恰好相同的应用 Open ID，且不会因同名把私人待办记给别人。
旧账号在下次飞书登录时会自动补齐；本次两名已验证成员可按上述唯一规则受控回填。
