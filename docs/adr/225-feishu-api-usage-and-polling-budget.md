# ADR-225：飞书实际调用排行与跨节点轮询冷却

## 状态
已采纳（2026-09-10）。补充 ADR-127、ADR-140、ADR-176。

## 背景与证据
任务 t1789002761096 图片显示当月 969,423 / 1,000,000 次，已用 96.94%。这是租户月总量，
不能用接口每秒限流策略解释，也不能通过多建同租户应用提升额度。
官方规则来源：https://www.feishu.cn/content/article/7618896174031834060 。具体额度与升级条件以管理员后台为准。
旧代码无覆盖整月的接口计数，不能断言 969,423 次中的第一名。代码可确认：
共享聊天每次同步都读取成员，双节点释放执行租约后可紧接着重复读取；快速收集双节点各自轮询，
每分钟回看 24 小时并为尚未派工的合格消息逐条查询表情，消息数量和分页会放大请求量。

## 决策
- 在群聊客户端 HTTP 拦截器记录每次实际出站尝试，含业务失败和网络失败。缓存命中不计数；分页逐页计数。
  方法与归一化路径按北京时间自然日原子累加，双节点共用 MySQL；独立事务使业务回滚不抹掉出站事实。
  不记录请求正文、参数、凭据、群、成员或消息身份。写入失败记录缺失告警，不阻断原业务，也不伪造补数。
- 新增 `GET /api/feishu/chat-sync/api-usage`，沿用已登录业务访问控制，返回本月已观测排名：
  `endpoint`、`requests`、`firstObservedAt`、`lastObservedAt`，统一 `ApiResponse`。
  不含飞书登录、Webhook、其他应用及上线前历史，不能用此数冒充租户账单。
- 自动化的飞书群聊同步配置显示只读排行、观测起点、占比、加载/空数据/失败重试；刷新不调用飞书。
- 后台先拉消息，空窗口不读成员；非空窗口使用按令牌和群隔离的五分钟成员缓存，失败不缓存。
  手动读取成员接口保持实时；后台昵称变更最多滞后五分钟。
- 实时与编辑任务原子检查租约和上次成功时间，完成后冷却一个配置周期，避免双节点交错重复。
  快速收集也使用共享持久水位。租约最长 60 分钟，异常释放；崩溃时到期接管。
  新消息仍使用既有周期，定时唤醒与冷却相位可能额外等待一个周期。失败不推进水位，保留既有两分钟恢复窗口。
- 全天编辑/撤回/旧消息表情兜底默认改为五分钟，仍覆盖 24 小时；新消息轮询和事件订阅不关闭。
  已订阅事件保持低延迟，未订阅的旧消息变更和飞机表情可能等待五分钟，双节点相位可能再增加一个周期。
  可用原有 `wao.feishu.quick-collect-edit-poll-ms` 和 `wao.feishu.shared-chat-edit-poll-ms` 覆盖。
- V150 新增日统计表及快速收集租约行，不修改已执行 migration。统计行按日与有限接口聚合，每次请求一次轻量写入。

## 验收
客户端缓存、失败重试与路径脱敏；轮询被占用不请求飞书、失败不推进水位；空消息不查成员；
页面真实排名与失败重试。上线后用真实后台流量确认排行增长、跨节点共享水位及现有消息链路。
未获取官方租户账单前不承诺完整月排名或节省百分比。
