# ADR-055：AI Run 可产出并关联持久化 HTML 报告

## 状态

已采纳。

> 报告“按价值可选生成”的决策已由 [ADR-165](165-mandatory-ai-run-html-report.md) 更新为每次开发型 AI Run 必须生成；
> 其余托管、安全、稳定 URL 与清理规则继续有效。

## 背景

AI Run 目前永久保存文本摘要和进展时间线，但分析、调研、方案、决策依据与验收证据常常更适合用
结构化单文件 HTML 呈现。已有 HTML 托管可以在文件页手动上传，却与产生内容的运行脱节：用户要
自己搬运文件，也无法从任务档案直接确认某份报告属于哪次执行。

强制每个小改动都生成报告会制造没有信息价值的占位文件；把报告写进 Git 又会污染产品仓库，并让
非代码类产物依赖代码发布周期。

## 决策

- Runner 为每次运行提供 `<root>/.wao-run-reports/<run-id>/report.html` 专用产物路径，并在提示词中
  说明：只有分析、调研、方案、决策或验收信息值得长期沉淀时才生成，普通小改动不得凑占位报告。
- 报告必须是 UTF-8、自包含或只引用公网绝对资源的单文件 HTML，最大 10MB；产物目录在 Git worktree
  外，AI 不得把报告加入仓库提交。
- CLI 会话结束后，Runner 校验文件并通过带节点令牌的
  `POST /api/ai/runner/runs/{runId}/report` 上传。服务端再次复用 `HostedPageService` 的文件、编码与
  sandbox 校验，不给 Runner 普通登录会话或任意托管页修改权限。
- 托管页 id 固定为 `run-report-<run-id>`，首次公开后缀为 `ai-run-<run-id>`。同一次运行继续优化时
  更新同一页面；用户在文件页人工修改过标题或后缀后，后续上传只替换 HTML 正文。
- AI Run DTO 返回 `reportUrl`。首页运行详情与任务执行档案在报告存在时展示新窗口入口；托管页被
  用户删除后入口随下一次查询消失，不保留失效链接。
- 报告上传失败不能静默丢失：原任务若本来成功，Runner 将本次运行改为失败并回传具体原因；原任务
  已失败时保留原退出码并追加报告错误。未生成报告不影响正常完成。
- 上传成功后本机产物立即清理；未上传产物与 worktree 一样最多保留七天后回收。托管正文继续由
  MySQL 持久化并进入现有备份，不依赖 Runner 在线。

## 后果

- 有价值的 AI 产物可以从运行记录直接打开和分享，文本摘要仍保留为快速浏览与失败兜底。
- 不新增第二套公开页面安全边界，报告继续受 ADR-042 的 CSP sandbox 与无缓存规则约束。
- Runner 脚本属于主机级依赖，业务 CD 不自动重启或覆盖正在运行的 Runner；管理员需通过现有
  “更新 Runner”能力下发脚本后，新运行才会开始自动收集报告（见 ADR-043）。
