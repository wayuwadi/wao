# ADR-047：“天人一卦”采用服务端每日唯一卦象与受约束 AI 反思

## 状态

已采纳。复用 ADR-044～046 的本地 Codex、成员级会话与只读安全边界。

## 背景

WAO 希望把《易经》与《黄帝内经》的传统思想融合成一个可每天使用的个人产品，例如为自己起一卦并获得 AI
辅助反思。现有 AI 助手已经有真实的本地 Codex Runner 和成员级持久化会话，不应另造一套模型凭据或用静态文案
伪装 AI。

卦象如果完全由浏览器生成，刷新、换设备或同时打开多个页面会得到不同结果；如果让大模型自行“起卦”，又无法
验证六爻、变爻和文王卦序是否一致。另一方面，《黄帝内经》涉及传统医学语境，不能把模型生成的内容包装成诊断、
处方或有现代医学证据的结论。

## 决策

- 新增原生个人模块“天人一卦”，进入可改名、换组、排序和隐藏的内置菜单注册表。
- 服务端模拟传统三枚硬币法：每枚硬币等概率记 2 或 3，连续六次得到初爻到上爻的 6/7/8/9；6、9 为变爻。
- 六爻由服务端映射到八卦结构和文王六十四卦序。存档同时保存爻值、本卦号和之卦号，读取时重新计算并校验，
  不相信浏览器提交的卦名或卦号。
- `tianren_daily_reading` 按 `(member_id, reading_date)` 唯一；当天重复请求和并发创建都返回同一份存档。
  日期固定使用 `Asia/Shanghai`。卦象按成员隔离，最近最多返回 60 条。
- 起卦必须由用户主动点击；页面打开不会悄悄生成结果。关注点先作为本机草稿防丢，提交后进入成员私有的
  `ai_assistant_conversation`，每日记录只关联会话 id，不重复保存敏感正文。
- AI 解读仍进入现有本地 Codex 只读队列，使用服务端拼装、浏览器不可篡改的卦象上下文，不混入无关的 WAO
  资产检索结果。专用长请求固定路由 Linux VPN 主节点并沿用 330 秒超时。
- 专用提示词只允许把《易经》象征主题与《黄帝内经》关于四时、起居、饮食、情志的传统生活观用于自我观察；
  禁止伪造古文、篇章和权威出处，禁止诊断、药物、方剂、穴位、治疗方案与确定性吉凶预测。
- 页面明确标注“文化反思，不是医疗建议”；持续、严重或紧急身体不适必须建议咨询合格医务人员。

## 后果

- 每位成员每天得到一份可解释、可验证、跨设备一致的卦象，AI 历史沿用现有个人问答知识库。
- 产品在 Codex Runner 离线时仍能展示真实卦象和历史，但明确禁用 AI 解读并提供重连，不用静态回复冒充在线模型。
- 本期不收录或生成经典原文全文，也不建设中医诊疗知识库；需要逐条经典引文或医疗功能时，必须先取得可靠授权
  数据源、专业审核和新的高风险 ADR。
