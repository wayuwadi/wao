# ADR-325：WAO 应用改动默认交付到公网

- 状态：已接受
- 日期：2026-10-05
- 范围：WAO 浏览器应用的开发交付
- 取代：ADR-232 中“合并即完成 AI 交付”的默认结束条件；其他验收和安全边界保留

## 背景

用户在手机小记布局修复合并后明确要求：“公网部署，后面 WAO 应用改动都默认部署公网”。后续功能交付需要让已验证改动在真实使用入口可用，无须每次再等待一条部署指令。

## 决策

1. 应用改动按现有一个需求一个 PR 流程完成本地验收、提交和合并后，默认继续公网发布。交付以实际版本、资源、服务就绪和受影响页面证据为准；合并与上线分别报告。
2. 复用唯一发布协调者、已运行或排队批次及当前已有授权通道，保留 Jenkins 一分钟批处理和禁止并发行为。实际版本已覆盖本次提交时不重复切换。
3. 纯前端以及文档/测试批次只发布静态制品，不为发布说明重启后端；后端和数据库改动沿用既有完整发布与数据恢复要求。
4. 不扩展凭据、数据和网络授权，不绕过失败检查或破坏性数据门禁。发布通道受阻时报告阻塞，不将“已合并”包装为“已上线”，不将后台等待默认交给用户。
5. 保留本地真实链路验收要求。发布后的检查确认交付可用，不能替代未完成的本地验收。实体设备最终体验及任务关闭仍由用户负责。
6. 当次明确要求只设计、只本地验证或暂不发布时遵循当次指令。本决定不适用于其他项目，也不恢复独立客户端发布，不创建无请求的后台定时监控。

## 落地

同步项目 `AGENTS.md`、`.codex/skills/wao-dev-batch-delivery/SKILL.md` 及发布协调引用。旧 ADR 保留历史，不覆盖其原文。交付文章按实际证据记录发布状态。
