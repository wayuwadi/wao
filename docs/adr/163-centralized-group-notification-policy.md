# ADR-163：群聊通知使用统一策略门禁

## 状态

已采纳。

## 背景

ADR-155 的通知设置只控制任务与 AI Run，项目静音又留在综合设置页；日历、今日节奏、自动化提醒和 Jenkins 失败通知各自
直接调用飞书。用户看到“群通知总开关”时会合理地认为它覆盖全部群通知，但实际关闭后仍可能收到提醒或发布告警。
同时，综合设置页没有每日沉默窗口，无法在不逐个关闭通知源的情况下管理休息时间。

## 决策

1. 继续使用 `system_setting.notification.policy.v1` 保存管理员共享策略，以新增 JSON 字段扩展，不新建表、不修改已执行
   migration。读取旧 JSON 时为群提醒和 Jenkins 失败通知采用开启默认值，沉默时段采用关闭默认值。
2. 总开关和上海时区沉默时段成为所有 WAO 业务群通知的共同前置门禁；任务类再叠加既有事件类型、项目静音和 Webhook
   开关。私聊、站内动态、飞书表情回执和用户主动发送的桥接聊天不属于群通知。
3. 沉默窗口为每日开始时间（含）到结束时间（不含），支持跨午夜。到点提醒命中沉默时记录为跳过，避免窗口结束后集中
   补发旧提醒；人工发送则返回明确未发送原因。
4. Jenkins 从本机 WAO 公共只读接口获取“失败通知是否允许”的最终结论，接口不暴露完整策略。接口不可达或旧版本没有
   接口时失败开放，因为应用不可用本身正是不能丢失失败告警的场景。
5. 通知设置迁到 `/notification-settings` 独立页面，项目级通知也在同页管理；旧 `/settings?tab=notifications` 入口重定向。

## 后果

- 管理员在一页即可判断当前是否会发群通知，并统一管理 Jenkins、任务和提醒。
- 系统设置关闭不会误伤个人飞书私聊；测试 Webhook 仍能在关闭业务通知后验证地址是否有效。
- 新增群通知发送端必须接入共同门禁，并在规格中明确它属于通知、私聊还是用户消息。

## 验收

- 服务、前端和 Jenkins 脚本测试覆盖策略读取、跨午夜判断、页面草稿与外部发送端门禁。
- 生产部署后核对独立页面、公开门禁接口、线上版本和 Jenkins 终态日志。
