# ADR-141：使用 WAO 真实运行记账提供统一用量菜单

## 状态

已采纳。

## 背景

TokenTracker 是成熟的 MIT 开源本地用量工具，但其 CLI Dashboard 固定绑定本机回环地址，数据来自运行它的
单台电脑，页面静态资源和 API 也使用站点根路径。直接把它注册成 WAO 同域外部应用会产生无法加载的资源和
API 冲突；只放一个 `localhost` 链接则只能在安装服务的那台电脑使用，不能满足 WAO 跨设备查看的入口语义。
启用 TokenTracker 云同步还需要成员另行注册并主动上传本机数据，不应由 WAO 默认代替成员授权。

WAO 已按 ADR-026 让 Runner 从 Codex、Claude Code 和 Qoder 的真实结束事件读取用量，并把运行级输入、输出、
缓存、总 Token 与供应商实际返回的金额保存到 `ai_task_run`。数据仪表盘已经按天展示这条真实记账链，但没有
一级菜单，用户只能从首页次级按钮或命令面板进入。

## 决策

- 不部署或代理 TokenTracker 的本机 Dashboard，也不启用其可选云同步。
- 把现有 `/dashboard` 注册为内置模块，在「工具」组新增默认可见的「使用统计」菜单，并在 WAO 页签内打开。
- 全局内置菜单注册表升级版本；旧注册表升级时补入新默认项，同时保留已有菜单改名、分组、排序、显隐和打开
  方式定制。
- 页面继续只展示 Runner 真实回传的数据。未回传用量保持“未回传”，Codex 等工具没有返回金额时不估算成本。

## 后果

成员可以从任意登录 WAO 的设备进入统一用量页面，查看 WAO 派发运行的真实统计，不需要在每台浏览设备安装
本机服务。该页面不会声称覆盖 WAO 之外的本地 AI 会话；以后若需要跨设备收集其它会话，应新增获得成员明确
授权的 Runner 上报协议，而不是把单机 `localhost` 页面伪装成中央数据源。
