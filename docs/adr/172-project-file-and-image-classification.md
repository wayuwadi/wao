# ADR-172：项目资料复用全局文件、图床与隔离 HTML 存储

## 状态

已采纳。

## 上下文

全局“文件与图床”已经有三条真实链路：普通文件与图片存主节点 MySQL，HTML 存为带公网地址的隔离托管页。但三类记录没有项目归属，项目详情原有“文件”页签也只有历史名称和大小、没有稳定资产 id，因此此前已下线。用户需要按项目汇总 Markdown、HTML、图片和 AI 产出报告，并在 WAO 内直接查看。

## 决策

- 给 `file_blob`、`image_blob`、`hosted_page` 增加可空 `project_id`。历史记录保持未分类，不猜测归属；全局入口继续展示当前成员可见的全局和项目资产。
- 项目详情恢复“文件”页签。上传时按真实文件类型分流到既有三套服务端校验和存储，不复制正文，也不新增演示数据；项目可见性沿用 `ProjectService`。
- UTF-8 Markdown 最大 2MB，可由登录成员读取正文并继续使用统一 `marked + DOMPurify` 净化渲染；其它普通文件保持下载，不尝试在服务端转换未知格式。
- HTML 继续使用 `/api/pages/{slug}` 公网分享出口，并嵌入带 `sandbox` 的站内 iframe 预览；不把不受信任 HTML 注入 WAO DOM，也不授予同源身份或表单权限。
- AI Run HTML 报告在生成时继承运行的 `project_id`，无需用户再次归档；项目图床仍使用既有公开只读图片地址。

## 后果

- 三张表增加项目索引；资产正文与公开链接保持原寻址方式，历史分享不失效。
- 删除项目时不级联删除资料，外键会把资产的 `project_id` 置空，避免项目误删同时抹掉仍在外部分享的文件；原公网地址保持有效。
- 项目部门关系当前没有独立、稳定的数据模型，因此本次只按项目分类，不伪造“项目部”层级。
