# ADR-153：通知中心聚合真实系统事件并单独记录成功登录

## 状态

已采纳。

## 背景

应用壳右上角长期只有“通知中心建设中”的占位提示。任务、AI Run、成员与低频报表已经有真实持久化数据，
但现有 `account_identity.last_login_at` 只保留每种身份最后一次登录，无法回答成员登录频率，也不能把历史次数
从最后登录时间推算出来。

## 决策

- 右上角铃铛打开通知抽屉，聚合任务创建、任务完成、AI Run 终态和成功登录四类真实事件；事件从现有业务表
  与新增的 `account_login_event` 查询，不复制成另一份通知流水。
- 每次邮箱、飞书或微信完成真实登录、注册或成员认领后写一条登录事件；单纯绑定登录方式不计入登录频率。
  发布前没有逐次登录记录，因此不回填历史次数。
- 登录统计按上海时区展示最近 7 天、30 天次数与最后登录时间，团队内已登录成员共享查看；不记录 IP、设备、
  User-Agent、邮箱或外部身份标识。
- 每名成员的已读水位写入已有 `member_preference`，首次打开前以最近 7 天事件作为未读范围；标记已读只推进
  当前成员水位。通知抽屉最多返回最近 30 条事件，未读总数独立统计并在前端封顶显示 `99+`。
- AI 使用统计、系统报告和请求监控继续使用现有真实页面与接口，通知中心只提供低频入口，不复制报表数据。

## 后果

- 用户能从任意受保护页面查看最新系统动静、真实成员使用频率和低频统计入口，铃铛不再是占位功能。
- 历史任务和 AI Run 可以作为真实动态展示；登录频率只能从本 migration 上线后开始累计，空数据明确显示
  “尚未记录”，不能解释为成员没有使用 WAO。
- 当前“操作记录”覆盖已有可靠时间与操作者语义的核心事件。若以后纳入文档编辑、设置变更或部署事件，
  必须先建立对应的审计字段或持久化事件，不能从更新时间猜测操作者。
