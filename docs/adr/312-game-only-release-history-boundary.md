# ADR-312：单款游戏发布与主站提交记录的版本边界

日期：2026-10-03。状态：已接受，落实用户明确要求的游戏独立发布范围。补充ADR-310和ADR-311，不改写历史决策。

## 问题

裂隙交付同步主线后，真实流水线组合测试发现ADR-311的`--full-web`让纯游戏逻辑更新也重建主站，违背本轮“游戏专属改动只构建、测试和发布受影响游戏”的明确约束。主站内嵌的版本说明又不能单独改成游戏SHA，否则与主站字节不一致。

## 决策

- 变更计划先按真实依赖生成。仅游戏制品需要更新且主站无依赖变化时，保留当前主站制品、SHA和与它绑定的提交档案，只构建/发布受影响游戏。
- 游戏manifest、catalog与发布证据记录其独立SHA和规则/通信兼容版本。主站版本说明继续准确描述该主站制品，不谎称主站已包含后来单独发布的游戏提交。
- 主站、共享host、存档schema/目录元数据、部署路径变化仍构建主站；文档/纯测试等没有游戏制品变化的批次仍按ADR-311刷新主站档案。下一次主站发布的完整Git历史自然包含此前游戏提交。
- 不单独篡改旧主站的不可变Git档案，不增加业务接口/后端数据库或独立历史服务。游戏回滚仅切单款catalog，不刷新主站说明。

## 验证与代价

`test_ci_composition.py`以临时真实Git差异运行现用`ci-build-frontends.sh`，分别覆盖dino逻辑、rift逻辑、主站、共享host、文档、纯游戏测试：只构建实际游戏；游戏专属包不触发主站构建；文档/测试继续刷新主站。外部构建/SSH明确替身，另验证单款部署不激活主站。

取舍为主站最近更新只对应主站版本，单独游戏发布通过游戏清单与交付报告追溯；保持主站SHA和记录一致，避免为展示提交记录重复构建主站。本款首次接入本就修改host，仍构建并发布主站与裂隙，复用恐龙制品。
