# ADR-130：聊天复盘融合共享聊天并补齐高密度交互

## 状态

已接受（2026-08-26）。本 ADR 增补 ADR-088 与 ADR-127；原按飞书归档自然日复盘的历史数据和 API 保留。

## 上下文

独立“聊天复盘”菜单与共享聊天割裂，低频入口占据导航，且只能按飞书归档日期发起。共享聊天已经可靠保存 WAO 与飞书的
同一消息流，因此可以从用户正在阅读的真实消息直接选择范围。聊天页还存在页边距不足、消息动作纵向占位、飞书富文本多图
顺序丢失、固定悬浮按钮遮挡输入区和轮询间隔不可配置的问题。

## 决策

- 退休独立菜单；聊天界面后续按 [ADR-154](154-floating-shared-chat-entry.md) 收口为右上角悬浮框，旧 `/chat-reviews` 地址兼容打开悬浮框中的复盘。聊天框页头提供“复盘”按钮，历史页面和旧 API 继续兼容读取。
- 新入口只接受 `MESSAGES / HOURS` 与整数范围：最近 5～100 条或 1～168 小时。服务端在点击时查询
  `shared_chat_message`，把最多 500 个真实消息 id 固化到运行；不存在或过大时明确拒绝，不补演示消息、不截断正文。
- worker 按快照 id 读取消息，图片只传 `[图片]`，撤回只传 `[消息已撤回]`，继续使用 ADR-088 的无工具安全队列、
  60,000 字动态输入门禁和四段报告校验。该 `ai_assistant_run` 是实际 AI 任务；首页 AI 运行列表用“聊天复盘”标签展示对应档案。
- 成功报告以复盘运行 id 幂等生成公开 HTML，同时写入固定 `kb-chat-reviews`“聊天复盘”知识库。两项写入处于同一数据库事务；
  任一失败则运行失败，不把残缺结果标为成功。worker 接管重入时覆盖同一托管页和同一知识库文档。
- 飞书入站富文本中的每个图片节点按原顺序转存并写回同一条消息正文，不再把首图放入单图字段。页面把引用和表情操作移到气泡
  横向外侧，删除低价值“来自飞书”行，但保留作者区的小型“飞书”来源标识。
- 共享聊天配置增加 5～3,600 秒轮询间隔，与群选择一起事务保存；页面允许用秒或分钟编辑，服务端统一保存秒。调度器每秒检查
  是否到期，配置缩短后无需重启进程。
- “问问 AI”和音乐的收起态入口支持 Pointer Events 拖拽，位置按入口分别保存在浏览器；视口变化时把坐标限制回可见区域。

## 后果

聊天复盘从阅读消息到 AI、公开报告、知识库形成同页闭环；旧报告不迁移、不删除。聊天密度提高，多图保持消息级身份，悬浮入口
不再只能占据固定角落。共享聊天的真实同步时延由用户控制，但最短 5 秒限制避免无界请求频率。
