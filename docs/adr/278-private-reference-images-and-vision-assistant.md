# ADR-278：个人参考图以私有原图接入只读 AI 问答

## 状态

已采纳。

## 背景

原有图床 `/api/images/{id}/raw` 是公开只读地址，适合任务正文等既有分享链路。参考图库收的是成员随手截的界面和资料，若直接复用公开图床 URL，任何获得地址的人都可读取原图。现有页面 AI 问答只传文字；把图片 URL 拼进提示词不等于模型获得视觉输入。

## 决策

- 新增 `reference_image` 私有表和成员鉴权原图接口，独立于公开图床，不改变旧 URL 和已有图片行为。文件名仅用于基础检索；首版不虚构 AI 标题、OCR 或版权许可信息。
- 同成员按 SHA-256 唯一去重，使重复上传和未知结果后的重试有稳定结果。原图正文不进入列表响应，最多 10MB，服务端按文件签名识别格式。
- `AssistantChatRequest` 可携带最多四个参考图 ID。服务端逐张校验当前成员归属，只允许本地 Codex 能力，禁用本次联网检索。运行记录保存 ID；只有领取该运行且持有效 claim token 的 Runner 能按索引读取原图。
- Runner 将每张原图放入本次临时空仓库，以 `codex exec --image` 作为模型输入；页面只读沙箱仍关闭 shell、多代理、本机 `view_image` 和联网搜索，结束后删除临时目录。图片自身视作不可信参考资料，不能改写系统指令。
- 会话消息保留安全的成员鉴权图片链接，供本人刷新后回看。不自动把私有图共享到项目或外部 AI Provider。

## 后果

- 私有图库与公开图床有两套图片正文存储，换来清晰的权限边界；后续若要统一存储，需先设计图床访问范围及旧公开 URL 兼容。
- AI 带图提问依赖已更新的本地 Runner 与支持图片附件的 Codex CLI。Runner 未更新时现有脚本哈希门禁会让能力显示不可用，不降级为纯文字问答。
- CLI 首版不开放私有图片的二进制上传和 Runner 令牌取图；这是浏览器会话与专用 Runner 之间的受控链路。若后续出现终端批量收图需求，再设计对应设备令牌范围及命令。
