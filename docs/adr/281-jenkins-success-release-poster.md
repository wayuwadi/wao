# ADR-281：Jenkins 成功发布卡片内附真实批次发布图

- 状态：已采纳
- 日期：2026-09-25

## 背景

Jenkins 成功通知目前只有提交标题。成员看到「参考图库」等新功能上线时，还要另找入口、再由人工制作宣传图。成功卡片应让群成员一眼看到本批次的功能描述和可用入口，同时保留构建详情与现有通知门禁。

## 决策

1. 只在**生产发布成功且双节点、云端、公共入口验证通过**后，为这一批次生成一张 PNG，嵌入现有一张飞书成功卡片。不另发一条群消息；影子构建、无需部署、失败及策略静默不生成或发送发布图。
2. 图中文字来自 Jenkins 已冻结的 `WAO_COMMIT_MESSAGE` 批次标题，最多展示三项，剩余显示数量。功能类型按 Conventional Commit 前缀决定。只有提交 scope 与同一提交的 `wao-web/src/config/nav.ts` 路由 id 对应时，才展示实际页面名称和 URL，并给首个可打开的功能加「打开功能」按钮。未知 scope、服务或部署改动不猜测入口；完整范围仍以提交与 Jenkins 详情为准。
3. 用随仓库交付的确定性 Java 渲染器、中文子集字体和预编译 Java 17 JAR 生成 PNG。Jenkins 运行时只需既有 Java 21 JRE，不调用图像生成模型，不把提交文本发送给额外 AI 服务。字体来自 Google Fonts 的 Noto Sans SC，按 OFL 子集化并改名，授权文件同仓库保留。
4. 用既有私有 `FEISHU_APP_ID` / `FEISHU_APP_SECRET` 换取飞书应用令牌并上传图片，得到 `image_key` 后作为卡片 `img` 元素发送到原有 `FEISHU_COMMENT_WEBHOOK_URL`。临时请求和令牌文件只在本次通知中存在，不进入日志、Git 或卡片。
5. 字体、渲染、凭据或上传失败时，记录安全摘要并发送原有文字成功卡；飞书明确拒绝图片卡时，仅重试一次去掉图片的成功卡。网络超时的投递结果不明时不盲目重发，避免重复消息。图片能力不能把已经完成的生产发布改判失败。现有成功通知策略、失败告警与 Jenkins 按钮保持不变。

## 验收

- 在本地用真实路由配置和批次提交标题生成单项、多项、无入口 PNG，检查中文、长标题、数量和入口；功能描述只引用提交标题。
- Shell 测试模拟飞书取令牌、上传图片和 Webhook，检查生产成功含 `img_key`，上传失败退回文字卡；失败和无需部署卡无图片。
- 首次真实群通知确认飞书客户端显示图片，而不只显示 `image_key` 文本；若没有出现，按通知日志区分凭据、图片上传和卡片渲染问题。
