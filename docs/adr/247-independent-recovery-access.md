# ADR-247：通过云机提供独立的受限维护入口

## 背景与决定

原有开发电脑到 Linux1 的 SSH 经过 Linux2 上的反向隧道。Linux2 故障时，这条维护入口也会中断。
在 ADR-244 的 WireGuard 私网之上增加云机跳板账号 `wao-recovery`，分别直达两台 Linux 的 SSH。
业务流量和两 Linux 间复制保持原有直连路径；云机 3M 带宽只承载这条备用维护连接。

该账号只接受管理员明确安装的 Ed25519 公钥，不复制开发电脑的私钥。
禁止命令会话、SFTP、密码登录、反向转发、代理转发、TTY 和任意目标转发。
允许的转发目标仅为 `10.66.0.3:22` 与 `10.66.0.2:22`。
Linux 目标机仍以各自已有账号及公钥验证身份，不继承云机 root 权限。

安装器先用 `sshd -t` 和 `sshd -T` 检查完整候选配置与实际账号策略，再备份、替换并 reload。
不重启 SSH，不改变既有用户的认证规则。专用 Include 放在主配置末尾，避免 Match 影响后续全局项。
既有未知同名账号或不同策略文件拒绝覆盖。重新运行相同公钥不会重复添加授权。

## 验收与限制

2026-09-20，从当前 Windows 电脑分别经云机登录两 Linux 成功，目标看到的连接来源为 `10.66.0.1`。
云机命令会话和转发到 Redis 端口均被拒绝。云机主机公钥通过既有已验证 SSH 通道取得，客户端严格验证主机身份。
未停止现有反向隧道，没有模拟整机断电。该入口依赖云机、目标 Linux 与对应 WireGuard 链路；不是独立物理带外管理。

操作与撤销见 [维护入口手册](../runbooks/recovery-access.md)。
