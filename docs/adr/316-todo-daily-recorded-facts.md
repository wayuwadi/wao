# ADR-316：待办日视图以任务版本和真实事件回看

状态：已采纳（2026-10-03）

## 背景

原任务只有当前内容及 `completedAt`。改期、重开或改名后，用当前任务重算旧日期会改写用户已经做过的事；把小记正文复制到另一个日记模型也会分叉。用户已经确认在现有待办中融合每日规划、小记与日历，并保护原有低负担小记体验。

## 决策

从 V178 实际执行时刻起记录基线，仅承认此后事务内发生的任务变更和真实小记。每次业务写入追加成员范围内的任务快照事件；日条目仅物化真实变更。日计划从事件的日末有效版本推导，历史事件按业务日查询；迟到补记另存实际发生时刻。不根据当前任务或 `completedAt` 捏造旧日事实。任务与文档原实体继续是编辑权威，日快照只供历史回看。日小记直接保存为现有 Doc，任务关联继续使用 `TaskDetail.docs[]`。

新增操作使用账号加 UUID 的回执和原业务版本条件。排时的粗粒度时段独立存储，绝不换算为虚构的几点钟；截止日期不随执行安排更改。日页面与操作仅开放已有浏览器会话，MCP/CLI 令牌不自动获得新权限。固定事项与 AI 推荐保留为后续独立交付。

## 影响

新增 `wao_todo_recording_scope`、`wao_todo_task_day_event`、`wao_todo_task_day_entry`、`wao_todo_day_note_context` 和 `wao_todo_operation_receipt`，以及 TaskDetail 可空字段。旧版本若不能保留新字段，不应在用户使用粗时段期间直接回退到会丢字段的二进制。关闭新页面时仍保留记录表与原任务、小记；已执行迁移不倒改。历史查询再次应用当前项目和文档权限，不以快照绕过撤权。
