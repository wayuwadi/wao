# ADR-018：知识库删除一律软删除，回收站保留 7 天

## 状态

已采纳。

## 上下文

知识库这块的删除有两个问题：文档和文件夹**根本删不掉**（界面上没有入口），而知识库的删除是**直接物理删除**，连同其下所有文件夹与文档一起从库里消失，误删无从挽回。

文档是写出来的东西，误删的代价比误留高得多。参照飞书 / Notion 的常识做法：删除先进回收站，保留一段时间后自动清理。

## 决策

- `kb` / `kb_folder` / `doc` 三张表各加 `deleted_at`（非空即在回收站）、`deleted_by`，文件夹与文档另加 `cascade_del`。**所有读路径都必须带「未删除」条件**。
- 保留期 **7 天**（`KnowledgeService.TRASH_DAYS`）。到期由 `TrashPurgeScheduler` 每小时扫一次、物理删除。清理按 `deleted_at < cutoff` 执行，是幂等的，两个节点各跑各的也无害。
- **级联删除的标记**：删知识库时其下文件夹 / 文档一并标记 `cascade_del = 1`，表示「随父级被删」。这类条目：
  - 在回收站列表里**不单独展示** —— 删一次却冒出十几条，会让人以为删多了；
  - 恢复父级时**一并恢复**。
- **恢复要有容身之处**：恢复一篇文档 / 一个文件夹时，若它的父级还躺在回收站里，把这条链上的父级一起恢复。否则「恢复成功」但界面上什么也没出现。
- **小记知识库不可删除**：它是全局「新建小记」的落点，删掉会让入口指向空气。后端直接拒绝，前端也不给删除按钮。
- 回收站是知识库域的入口（知识库总览页右上角），暂不做成全局回收站 —— 项目、任务、密钥库各自的删除语义不同，等它们也有软删除需求时再统一。

## 后果

- 删除从「不可逆操作」降级为「可逆操作」，因此界面上**不再需要二次确认弹窗**：点删除、给一句「7 天内可恢复」的提示即可，少一次打断。
- 表会保留最多 7 天的墓碑数据。文档正文是 JSON 列，量级可控。
- 所有查询都要记得过滤 `deleted_at` —— 这是这个方案最容易出错的地方，`KnowledgeService` 里统一收口成 `aliveKbs() / aliveFolders() / aliveDocs()` 三个私有构造器，新增查询照抄即可。
- 唯一约束、外键在软删除下不会自动放开（例如同名文件夹）。当前这几张表没有业务唯一约束，暂不受影响；以后加约束时要考虑把 `deleted_at` 一起纳入。
