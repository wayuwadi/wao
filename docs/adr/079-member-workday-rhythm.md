# ADR-079：工作日节奏复用成员偏好保存模板与每日真实记录

- 状态：已接受
- 日期：2026-08-17

## 背景

现有 `/api/schedule` 来自 `schedule_item` 只读内容表，其中仍有原型种子数据，不能承载成员自己的工作日计划、打卡和跨设备状态。
任务域适合明确事项，行动计划适合跨周长期目标，但“现在该做什么、今天是否守住各时间边界”需要一个轻量的每日执行入口。

任务提出的计划已经给出完整的 24 小时时间块，无需调用 AI 编造安排；通知、健康目标和法定调休判断则缺少本任务范围内可靠且必要的实现条件。

## 决策

- 新增“今日节奏”个人模块，以任务给出的七段安排作为可编辑模板，并按上海时间在浏览器内计算当前时间块、进度与下一段。
- 模板保存到成员偏好 `workday-rhythm-config-v1`；当天重点、时间块完成、喝水次数、冥想和是否执行保存到
  `workday-rhythm-day-YYYY-MM-DD`。现有偏好接口已由会话限定成员，且数据量小于 4,000 字符上限，不新增表和 migration。
- 每次可观察操作都先保留本机草稿，再写服务端；失败保留草稿并允许重试，成功才清理本机副本。
- 时间块必须按展示顺序首尾相接、完整覆盖一天。跨午夜区间使用环形分钟计算，不依赖设备所在时区，页面统一采用上海时间。
- 今日重点只保存用户输入并链接真实待办；不复制任务状态。喝水不设推荐次数，不输出健康判断。
- 默认仅周一至周五执行，成员可按天覆盖。法定调休、飞书提醒或推送通知留给有可靠日历/通知契约的独立变更。

## 结果

- 计划从静态文字变成可以每天查看、执行、记录和跨设备恢复的真实产品闭环。
- 复用偏好接口减少后端数据模型和滚动部署风险；若未来需要历史趋势、统计查询或提醒投递，再将每日记录提升为独立领域表。
- 页面不会把种子日程、自动完成或未经授权的健康建议展示为真实数据。
