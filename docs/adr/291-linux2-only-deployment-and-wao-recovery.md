# ADR-291：Linux2 作为唯一部署节点

状态：已采用（2026-09-27）；Linux2 单节点发布已由 Jenkins #586 验收。

2026-09-27，用户确认 Linux1 已正式下线并重装为其他用途。Linux2 是此后所有服务的唯一 Linux 部署节点。WAO 不再要求或尝试向 Linux1 安装应用、复制 MySQL、归档日志、传输备份或进行健康检查。云端静态发布与公共入口仍需单独验收。

## 现场状态与恢复门槛

- 变更拓扑决定不等于数据库已安全切换。检查时 Linux2 共享环境仍设 `WAO_MYSQL_PRIMARY=linux1`、`MYSQL_WRITER_HOST=10.66.0.3`，本机 `wao_app` 被锁；应用连不上已下线的写库。
- Linux2 的 `wao-return` SQL 线程因 MySQL 1062 停止。已获取 GTID 到源节点事务 782049，而只执行到 626682。不能将这个副本直接声明为完整写主，也不能跳过冲突事务来让复制状态变绿。
- 保留现有数据库、relay log、快照、binlog 和 123 云盘可读副本。先验证可恢复的最新权威数据，比较业务记录与用户可见内容，制作独立恢复点，并明确无法恢复的时间/事务范围。只恢复 `wao` 库，不覆盖 Linux2 的 `tools`、`wayuwa`、`tkwork`。
- 数据覆盖、提升本机 WAO 写权限及清理历史备份分别记录决策。确认恢复点前，禁止把应用连接和备份来源配置改成 `linux2` 后直接开放写入。

## 单节点目标

- WAO MySQL 写主与应用在 Linux2 本机；应用、Agent、Gateway、Nacos、Redis、Garage 使用已验证的本机地址。旧 Linux1 隧道与复制不再作为可用性或备份门槛。
- Jenkins 发布只验证并更新 Linux2 和云端静态制品；Linux2 原地部署可能短暂中断。发布结果与飞书通知须清楚标示单节点，并在公共 `/api/edge/ready`、浏览器真实业务保存/刷新和静态版本通过后宣布成功。
- 由于没有第二台 Linux 主机，原异机 peer backup 不再满足容灾要求。建立可独立恢复的异地加密全量备份和日志链，实测隔离恢复；123 云盘可读导出只作为内容副本，不等于完整数据库备份。

## 迁移范围

先完成数据保全与恢复，再切换生产写主和应用；之后改造部署、路由、备份与监控，最后做端到端验收。旧双节点 ADR 和 runbook 仅保留历史记录，以本 ADR 的生效日期为界。

## 发布与备份边界

- 生产共享环境设置 `WAO_DEPLOY_TOPOLOGY=linux2-only`。Jenkins 应跳过 Linux1 SSH、应用安装、静态副本与就绪探测；云 Nginx 的唯一 WAO Gateway 上游是 Linux2。浏览器制品发布仍校验 Linux2 与公共入口；后端原地发布允许短暂中断。
- 旧双机 peer 全量与 binlog 定时任务、Linux1 MySQL 隧道不能继续承担备份/可用性职责。停用它们不删除历史快照。新的云端链已经启用且首个全量/闭合 binlog 验证通过；此刻的验证尚未覆盖未来每次运行和按任意时间点的 binlog 回放。云节点只有约 40 GiB 系统盘，没有自动删除逻辑；容量门槛会拒绝新的快照并发告警，保留期限和删除范围须另定。
- 123 WebDAV 本次复核返回 401。可读导出当前只通过本机 `--inventory`，未证明新的云端同步成功。恢复后的本机 inventory 读到 1413 篇知识内容、582 条任务；它是内容副本，不是完整数据库备份。
