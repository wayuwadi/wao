# ADR-019：飞书凭据存进加密的系统配置表，自动化任务挂真实执行器

## 状态

已采纳。

## 上下文

两个需求同时落到「飞书」上：

1. 系统要有一个**全局通知 webhook**，凡是需要「说一声」的地方都发到同一个飞书群机器人。
2. **飞书群聊消息同步知识库**：每天 23:59 把当天 00:00 起的群聊记录写成一篇文档，识别每条消息是谁发的，聊天里的图片要能长期打开。

两件事都需要凭据（webhook 地址、自建应用的 App ID / Secret），而凭据既不能进 Git（`AGENTS.md` 明令禁止），也不适合只走环境变量 —— 换个群、换个应用就要改 `deploy/.env` 再重启两个节点，配置权还被锁在运维手里。

自动化模块此前只有「真实触发时机 + 模拟执行结果」：`cron_expr` 到点会触发，但执行步骤是描述性文本，没有任何真实调用（ADR-010）。群聊同步是第一个必须真跑的任务。

## 决策

- **新增 `system_setting` 表**（V17）存全局唯一一份的键值配置。敏感键（`feishu.webhook.url`、`feishu.chat-sync.app-secret`）复用密钥库那把 AES-256-GCM 密钥（`VaultCryptoService`）加密后落库，密文带 `enc:` 前缀。读接口只回 `SettingService.mask` 的脱敏形态，明文只在服务端调飞书时解出来用。**前端永远读不到明文**，凭据也不落 Git、不落环境变量，用户自己在界面上填。
- **保存表单时 null 表示「不修改」**：密码框留空即保留原值，用户不必每次改个群名都重新粘一遍 App Secret。
- **自动化任务加 `handler` 列**：非空时由对应的 `JobHandler` 实现真的执行，运行记录写执行器返回的文案；为空时仍是模拟运行。执行器抛异常不往上传，只落一条「失败 · 原因」的运行记录 —— 一个任务炸了不该中断调度器对其它任务的轮询，也不该让手动触发接口 500。
- **群聊同步的落地口径**：
  - 一天一篇文档，标题 `飞书群聊 · YYYY-MM-DD`，同一天重复运行**按标题覆盖**同一篇（`KnowledgeService.upsertAutoDoc`），不在知识库里堆同名文档；
  - 时间窗口固定 `Asia/Shanghai` 的 00:00:00–23:59:59，与需求里「今天早上零点到今天晚上 23:59」一致；
  - 发言人按配置里的 open_id → 人名映射还原（娃哥 / 娃弟 / 机器人通知）。配置页可以直接从飞书拉群成员列表来建这份映射；没映射到的退回一段可辨识的短 ID，而不是丢掉发言人；
  - **聊天图片转存本地图床再引用**：飞书的资源地址要带令牌才能取，直接引用等于第二天就打不开。单张图下载或转存失败只跳过这一张，不让整次同步失败。

## 后果

- 换群、换应用、换 webhook 都在界面上完成，不需要改部署文件、不需要重启。
- 拿到数据库 **且** 拿到 `WAO_VAULT_KEY` 的一方仍能解出凭据 —— 这是服务端静态加密，不是零知识方案，与密钥库同一套信任边界（ADR-009）。
- 加密密钥现在同时守着密钥库和系统凭据：`WAO_VAULT_KEY` 一旦轮换，两边的密文都要一起重写。
- 飞书应用需要开通读取群消息、群成员与资源下载的权限，且机器人已在目标群里；权限不足的表现是配置页上一条明确的飞书错误码提示（`code=50203`），不是静默失败。
- 群聊记录会连图片一起进图床与 MySQL，长期跑下来占用随聊天量增长；到需要清理时再单独立项。
