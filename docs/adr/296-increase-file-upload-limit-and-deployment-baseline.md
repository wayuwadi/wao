# ADR-296：普通文件上限提高到 200MB，请求体部署基线提高到 1GB

## 状态

已采纳。

## 背景

文件设置页面、`FileSettingsService`、浏览器文件库、Spring multipart、Linux2 Nginx 和公共边缘入口分别施加 50MB 或 52MB 限制，106MB 的安装包在设置页就被拦下。原 ADR-131 的 50MB 部署基线已不满足大文件归档。

## 决策

- 普通文件业务默认值和可配置最大值均提高到 200MiB；原本保存为 50 的系统设置一次性升级为 200，其他管理员自定义的更小值保持不变。图床单图仍最多 10MiB。文件上传、替换和共用真实文件库的入口受同一服务端限制。
- Spring 单文件基线为 1GiB，multipart 请求体上限为 1030MiB；Linux2 Nginx 和公共边缘入口采用相同的 1030MiB 请求体限制，留出表单开销。该基线仅表示基础设施接收请求体的上界，不能绕过 200MiB 文件业务校验。
- 当前文件正文会在服务端整体读入内存，生产环境还同时写入 S3 和 MySQL。为支撑 200MiB 文件，将应用容器上限从 2GiB 调至 3GiB，JVM 最大堆从 1GiB 调至 2GiB。未完成流式上传、下载及存储改造前，不开放 1GiB 单文件业务上限。
- 文件设置仍通过既有 HTTP API 保存。CLI/MCP 本次不新增配置命令：这属于系统管理员页面参数，当前工作区令牌没有系统设置写权限；如需脚本化管理员配置，应另行设计专用权限。

## 验收与边界

- 设置页可以保存 200MB，201MB 被前后端拒绝；普通文件上传 106MB 应通过真实链路验收，超过设置值仍应由服务端拒绝。图床 10MB 边界保持不变。
- 基线允许 1GB 请求体进入服务端，但业务上限仍为 200MB；不能将 1GB 请求体基线描述为已经支持 1GB 文件上传。高并发大文件与 1GB 文件需另立流式传输和存储方案。
