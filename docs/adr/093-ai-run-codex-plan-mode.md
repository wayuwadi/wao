# ADR-093：AI Run 支持无人值守 Codex Plan 工作流

## 状态

已采纳。

## 背景

AI Run 原先只有模型、推理强度和执行节点可选，Codex 收到任务后直接进入实现。复杂任务需要先梳理步骤时，
用户无法为单次派工表达 Plan 偏好。Runner 又是无人值守的 `codex exec --json` 进程，不能把计划阶段的问题
留在本地终端等待人工选择，否则运行会一直占用槽位。

当前 Codex CLI 的非交互 `exec` 命令没有公开的 `--plan` 参数，严格配置也不接受虚构的 mode 字段。因此
不能只在页面展示一个不生效的开关，也不能依赖交互式终端按键。WAO 需要在现有稳定的 JSONL 执行链路中
明确下发可验证的 Plan 工作约定。

## 决策

- 派工选择器仅在 Codex 下展示 Plan 模式开关，默认关闭，不改变存量行为。
- 服务端用 `ai_task_run.plan_mode` 固化单次选择；重跑沿用原值，领取协议显式下发，运行详情可审计。
- Runner 在初次运行和续跑提示词最前面注入 Plan 工作约定：先使用计划工具形成或更新可执行计划，然后
  连续实现、测试、提交、部署，不能在只输出计划时结束运行。
- 计划阶段需要选择时自动采用标签含 `(Recommended)` 的推荐项；没有推荐标记时采用第一项。只有确实缺少
  必要信息才允许阻塞，避免后台任务为普通取舍等待人工。
- Claude Code、Qoder 与未开启开关的 Codex 保持原行为。

## 结果

用户可以在每次 Codex 派工时选择是否先规划；选择会跨队列、重跑和续跑保持一致。实现不伪造当前 CLI
不存在的参数，也不把无人值守 Runner 改成脆弱的交互式终端自动按键。未来 Codex 非交互 CLI 若提供稳定的
原生 Plan 参数，可在保持 `plan_mode` 契约不变的前提下替换 Runner 的提示词适配层。
