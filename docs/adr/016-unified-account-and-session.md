# ADR-016：统一账号、多身份绑定与服务端共享会话

## 状态

已采纳。

## 背景

旧登录态只在浏览器 `localStorage` 保存一个外部 `userId`。飞书标识与本地成员 id 不一致时，前端会回退为第一个成员“娃哥”；后端也没有可信会话，因而两个人可能显示成同一身份，接口无法判断真实操作者。

## 决策

将“WAO 账号”和“登录身份”分离：

- `account` 一对一关联组织成员 `member`，是权限与数据归属的唯一主体。
- `account_identity` 保存邮箱、飞书、微信等外部身份；唯一约束保证一个外部身份只能绑定一个 WAO 账号，同一账号每种提供方最多一个身份。
- `password_credential` 只保存 BCrypt 哈希，并记录失败次数与短时锁定；不保存明文或可逆密码。
- 登录成功后签发 HttpOnly、SameSite=Lax 的 `WAO_SESSION` Cookie。会话存入主 MySQL 的 Spring Session JDBC 表，两台应用节点共享同一会话，不依赖负载均衡粘性。
- 第三方身份首次出现时优先按已验证资料精确匹配尚未绑定的成员；无法唯一匹配时要求用户在一次性认领页选择尚未认领的既有成员，避免静默创建错误账号。
- 已登录用户从“账号与登录”页面绑定其他身份。外部身份已属于别的账号时拒绝自动合并，后续由显式账号合并流程处理。
- `member` 中的“娃哥”“娃弟”保留稳定主键以兼容既有项目、任务负责人外键，但它们是数据库中的正式成员记录，不是前端 Mock。组织目录从真实 API 加载，资料修改直接更新该记录。
- 部署脚本将 `.env.secrets` 作为 Docker Compose 的显式环境文件，确保无论 Docker 是否经 `sudo` 执行，所有应用节点都获得一致的飞书配置。

## 接口保护

除健康检查、登录回调、公开分享和公开图片内容外，`/api/**` 默认要求服务端会话。前端启动时调用 `/api/auth/session` 恢复会话，不再从 `localStorage` 恢复身份。

## 后果

首次发布会让旧的前端模拟登录失效，用户需重新登录。微信网页登录需要微信开放平台网站应用的 App ID、App Secret 和审核通过的回调域名；未配置时入口显示明确提示，不影响邮箱与飞书登录。
