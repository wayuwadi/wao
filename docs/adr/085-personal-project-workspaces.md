# ADR-085：用成员隔离的快照承载个人项目工作台

## 状态

已采纳。

## 上下文

成员日常需要打开大量测试环境、运维后台、知识页面和项目工具，现状依赖浏览器收藏夹或文档登记。外部应用注册表解决的是管理员为全体成员接入可嵌入应用，不适合保存每个人的私有工作链接；项目的 AI Run 配置只描述代码仓库和执行电脑，也不应混入导航数据。

## 决策

- 新增内置“工作台”模块和 `personal_workspace` 表。每条记录归属一个成员，可以选择关联一个对该成员可见的项目。
- 分组与链接使用版本化 JSON 快照保存。工作台编辑是一个小规模、强聚合的整体操作，原子替换可避免分组移动链接时出现半成品；服务端仍逐项规整字段、数量、稳定 id 和 URL 协议。
- 一个成员可以创建多个空间；所有读写都同时校验空间 id 与成员 id，不向其他成员泄露空间是否存在。
- 只保存用户主动登记的标题、地址、环境和备注，不探测外部站点、不推断账号状态，也不复制外部系统内容。
- 草稿只在浏览器本地保留，服务端保存成功后删除；删除空间时浏览器同步清理该空间草稿。

## 后果

- 娃哥和娃弟可以在同一 WAO 实例中维护各自的项目空间，互不干扰；同一成员也可以把不同公司的环境或项目拆开。
- JSON 快照适合当前最多 12 组、240 个链接的读取模型；未来若需要跨空间统计、链接级审计或多人协作，再新增迁移拆分为关系表，而不修改已经执行的 migration。
- 工作台与外部应用注册表职责清晰：前者是成员私有的“打开链接”目录，后者是全局 WAO 菜单和 iframe 壳配置。
