# ADR-093：恢复窄范围 Windows 桌面伴侣

## 状态

已采纳。

## 背景

ADR-077 退役了复制项目、任务、AI 运行和自动化页面的 WPF 客户端。那次退役解决的是第二套完整 UI、登录、
更新和兼容性维护面过大的问题，不代表 WAO 永远不能拥有轻量桌面入口。

本次需求只需要一个始终可见的桌面宠物：汇总当前成员自己发起的 AI Run 状态、提醒需要处理的结果，并把用户
带回现有 WAO Web。它不承担任务编辑、知识库、自动化、Runner 管理或本地 AI 执行。

## 决策

- 新建独立 `wao-companion/`，使用 .NET 8 WPF。应用只有配对/设置窗口、透明桌宠、活动抽屉和系统托盘，
  不嵌入 WebView，也不复制 WAO 页面。
- 桌宠通过专用 HTTPS API 读取当前配对成员的 AI Run 聚合状态；不直连数据库，不获得 WAO Session、
  AI Runner 令牌或其他业务 API 权限。
- 首次连接使用十分钟有效的网页确认：客户端创建短码并打开 WAO 设置页，用户在现有登录态中明确批准设备。
  服务端只保存轮询密钥和设备令牌的 SHA-256；设备令牌由 Windows DPAPI CurrentUser 加密保存。
- 首版使用 5 秒轻量轮询，桌宠隐藏后降为 30 秒；不引入多节点 SSE 广播。状态优先级固定为
  `NEEDS_INPUT > BLOCKED > READY > RUNNING > IDLE`。
- 交付为自包含 `win-x64` 便携 ZIP 和 SHA-256 文件。用户级开机启动不请求管理员权限；首版不做安装器、
  自动更新或 Authenticode 签名。

## 影响

- ADR-077 仍然约束完整原生工作台；本 ADR 只恢复窄桌面伴侣，不恢复历史客户端协议或页面。
- main CD 增加 Windows 构建任务和公开下载制品，但客户端版本升级仍需用户重新下载。
- 当前只有 AI Run 能产生桌宠活动。未来接入提醒、审批或其他 WAO 事件时，必须扩展同一聚合接口，不能让
  客户端直接抓取多个业务表或获得通用凭据。
