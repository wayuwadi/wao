# ADR-175：每日提醒复用自动化调度与飞书通知执行器

## 状态

已采纳。

## 背景

WAO 已有 `automation_job` 的真实 Cron 调度、`feishu-notification` 飞书卡片执行器，以及统一群通知策略，但泛化“新建自动化”入口已经收起。用户要维护打卡、吃饭、午休等固定时刻消息时，既找不到专门入口，也不应该填写底层 Cron 表达式。另建提醒表和调度器会产生双份计划状态、抢占与失败记录，无法复用已有双节点幂等领取能力。

## 决策

1. 在“设置 → 通知设置”增加每日提醒面板，只暴露时间、标题、正文和启停状态；服务端把上海时间 `HH:mm` 确定性转换成六段 Spring Cron。
2. 每条提醒仍是 `handler = 'feishu-notification'` 的 `automation_job`，运行记录、下一计划点、双节点领取和飞书反馈继续复用现有链路。
3. 新增专用 `/api/notification-reminders` 接口，只允许管理员修改、删除和试发，并拒绝把其他自动化任务 id 当成提醒操作；普通成员只读。
4. 用新增 migration 预置四条已明确要求的提醒并默认启用；若真实飞书应用或目标群未配置，执行器明确记录失败，不降级、不伪造。
5. 每日提醒继续受群通知总开关、提醒分类开关和沉默时段门禁。试发同样遵守门禁，避免设置页绕过组织策略。

## 后果

- 用户在一个通知设置页面即可管理策略、项目通知和固定时刻提醒，不需要理解 Cron。
- 调度、外部发送和审计仍只有一套权威实现；回退界面不会丢失提醒任务，回退 migration 则需显式处理已产生的运行记录。
- 当前专用界面只支持每日固定时刻；周几、节假日或基于业务数据的提醒需要另行扩展规格，不能用静态消息伪装业务判断。

## 验收

- 服务端测试验证每日 Cron、权限、字段约束、启停与类型隔离，Flyway 测试验证版本唯一。
- 前端测试验证四条真实提醒的查看、草稿保存、失败保留和试发门禁，生产构建通过。
- 部署后核对通知设置页面与线上接口返回的四条持久化提醒，不主动向真实群发送验收消息。
