# ADR-173：通知设置回归系统设置内容区

## 状态

已采纳。

## 背景

ADR-163 将通知设置迁到独立 `/notification-settings` 页面，以便集中展示系统策略、成员偏好和项目通知。实现同时让“设置 →
通知设置”离开了设置页面：左侧设置分类消失，用户无法直接返回或切换到其他设置项，只能重新打开设置模块。集中展示通知
能力不要求脱离设置导航，两者被错误地绑定为同一个决策。

## 决策

1. 通知策略与项目通知面板嵌入 `SettingsView` 的 `notifications` 内容区，与菜单配置等设置项采用相同的页签结构。
2. 规范入口使用 `/settings?tab=notifications`；通知中心直接使用该地址，旧 `/notification-settings` 仅保留单向兼容跳转。
3. 保留通知面板现有加载、保存、错误重试、权限控制和真实数据源，不复制状态或新增演示数据。
4. 设置页统一接管通知草稿的页签切换、全局路由和退出登录保护，拒绝离开时不卸载面板。

本决策仅取代 ADR-163 第 5 条中的独立页面导航结构，不改变 ADR-163 的统一通知策略和项目级门禁。

## 后果

- 用户管理通知时始终看得到设置分类，可直接切换到菜单配置等相邻设置。
- 旧书签仍可使用，但浏览器最终地址统一为设置页签，避免维护两个页面壳层。
- 通知数据、API 和权限模型不变，回退时只需恢复前端路由与挂载位置。

## 验收

- 前端测试覆盖设置侧栏入口、旧地址跳转、通知中心入口和未保存草稿保护。
- 生产部署后从三个入口验证均落在选中的通知设置页，并确认可切换其他设置项。
