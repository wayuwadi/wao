# ADR-288：小记挖掘先创造可追溯内容，再由本人决定用途

状态：实施中（2026-09-27）。

## 背景

WAO 已能记录小记，但原文主要停留在时间线中。用户需要 AI 主动连接多篇小记里的重复主题、变化和张力，创造以后还能继续使用的内容；首页只应承担动态总览，不应变成又一个重操作页面。提醒是可能的用途之一，不是小记挖掘的全部价值。

## 决策

- 一次挖掘选择当前成员最近 12 篇、至少 2 篇有正文且非自动生成的小记，材料总量有界。只读 AI 同时生成 `INSIGHT`、`REMINDER`、`ARTICLE_SEED` 三类内容候选。
- 原小记不被改写。任务只保存来源文档 id、版本、标题和短摘录；每条产物保存生成理由及引用来源，使成员能核对本次实际引用的摘录，并打开当前小记继续阅读。
- 产物先是候选。成员可收藏、标记不准确，或把提醒类产物标记为“提醒草稿”；草稿不自动启用、定时或站外推送。真正的提醒规则、时间窗口和投递去重另行设计。
- 长时分析复用内部只读 AI 队列，浏览器以稳定请求 id 幂等启动并轮询。运行完成后物化内容；已经物化的结果不再依赖内部 AI 运行历史。
- 首页只显示最新洞察或运行状态，并跳转到小记页。启动、来源核对和反馈都在小记页完成。首页与“准则自留地”组成固定动态卡片区，为以后报表保留空间。
- 所有读取、启动与反馈都按当前浏览器成员隔离。本次不向既有工作区 MCP 令牌开放。

## 验收

1. 不足两篇有效小记时不启动 AI，并明确说明条件；重复 POST 复用同一任务。
2. 成功结果包含三类内容、生成理由和至少一个真实来源；原小记正文与版本不改变。
3. 反馈只更新本人产物，提醒草稿明确显示“尚未启用”。失败可重试，运行中可离开页面后继续查询。
4. 首页卡片不承担创建操作；宽屏为挖掘卡片与准则卡片的 2:1 区域，窄屏自动单列，减少动态效果设置下不做位移动画。

## 后续边界

当用户明确把草稿转为提醒时，再设计时间段、静默规则、完成交互、重复投递和通知渠道；不得根据这次产物反馈直接推断作息或健康结论。若以后需要批量导出或自动化挖掘，先设计独立授权、来源范围和审计，再评估 CLI/MCP。
