# ADR-170：托管页持久化来源类型并压缩 AI Run 卡片信息层级

## 状态

已采纳。

## 背景

AI Run 报告复用 `hosted_page` 的安全托管链路，但表中没有来源字段，文件汇总页无法可靠区分人工上传与自动报告。首页运行类型与结果已经是服务端正交筛选，却被渲染成两行；卡片又重复展示两个文字标签和单独的详情行，挤压标题空间。自主目标直接取最长 80 字的首行作为任务标题，也会把说明性长句带进运行卡片。

## 决策

- 为 `hosted_page` 增加 `source_type`：浏览器人工创建写 `MANUAL_UPLOAD`，Runner 报告与服务端生成报告写 `AI_RUN_REPORT`。存量默认保持人工类型，只按稳定的 `run-report-<run-id>` id 回填报告。
- 托管页元数据接口接受 `ALL / MANUAL_UPLOAD / AI_RUN_REPORT`，非法值直接拒绝；不把标题、文件名或创建人当成来源判断依据。
- 首页继续使用既有服务端类型与结果组合筛选，只调整为同一工具栏内的两个视觉分组。卡片保留类型和结果图标，移除重复文字标签和常驻详情行，悬浮与键盘聚焦显示整卡蒙层入口。
- 自主目标创建任务前，从首个有效 Markdown 文本提取标题：优先在说明性标点处收束，最长 36 字；完整目标继续存入描述。普通任务的显式标题保持原样。
- HTTP 性能巡检仍复用统一强制报告能力，不新增第二套报告生成器；巡检任务提示补充接口、根因、彻底性、遗留边界、规避与经验要求。

## 后果

- 文件汇总现在有可扩展的真实来源维度，未来项目文件入口可以继续在此类型之上叠加项目范围，而不靠展示文案猜测。
- AI Run 卡片更紧凑，类型和结果信息仍可通过图标、辅助文本、筛选及详情读取。
- 确定性短标题不依赖外部模型，任务创建不会因标题生成服务失败；它只做保守截取，不宣称替代人工命名。
