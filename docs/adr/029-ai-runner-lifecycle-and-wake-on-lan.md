# ADR-029：AI Runner 自启动守护与离线唤醒

## 状态

已采纳。

## 背景

Runner 进程退出或 Windows 重启后，后台只能看到设备离线，用户无法判断是进程停止还是电脑关机，也无法从 WAO 尝试恢复。把“已发送请求”伪装成“电脑已上线”会继续制造错误感知。

## 决策

- Windows 使用计划任务同时配置开机、用户登录和每 1 分钟重复触发，并开启异常重启、错过触发后补跑及禁止重复实例。Runner 必须用当前交互用户运行，以复用该用户的 Codex、Git 和 GitHub 登录态。
- 进程意外退出但 Windows 在线时，由计划任务守护自动恢复，不依赖 WAO 后台。
- 电脑睡眠或关机时，WAO 只提供标准 Wake-on-LAN Magic Packet：Runner 在线时自动上报本机 MAC，服务端自动记录心跳来源地址；离线卡片只保留一个唤醒按钮，不要求用户理解或填写网络参数。
- “唤醒包已发送”不等于“唤醒成功”。页面持续以 Runner 心跳作为上线的唯一依据，并显示最近请求时间。
- 服务端每分钟检查心跳：超过 2 分钟仅发送一次“设备离线”飞书通知；之后首次恢复心跳仅发送一次“设备上线”通知，稳定状态不重复打扰。
- 后台解除 Windows 节点接入时，Runner 在收到 401、删除本机令牌后主动禁用安装它的计划任务，再以退出码 78 退出；计划任务不能识别 systemd 的 `RestartPreventExitStatus`，否则会把已解除的节点反复拉起并制造无效重试。
- BIOS、网卡、操作系统电源管理和路由器 UDP 转发属于外部条件；条件不满足时系统必须明确说明，不能伪造上线状态。

## 后果

- 普通进程退出和登录后未启动可在最多 1 分钟内自动恢复。
- 远程物理唤醒需要目标硬件支持并完成网络配置；不支持 Wake-on-LAN 的网卡仍只能由现场开机或其他带外管理能力恢复。
- MAC 地址不是凭据，但唤醒目标属于环境配置，不写入代码或 Git，由后台持久化管理。
