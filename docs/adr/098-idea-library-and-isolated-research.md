# ADR-098：点子库独立聚合与隔离调研运行

- 状态：Accepted
- 日期：2026-08-23

## 背景

项目与任务适合承载已经决定要做的工作，却无法完整保存一个想法从模糊线索到证据、决策、MVP 和人工验证的过程。把历史任务自动转换、或用任务状态表达点子阶段，都会混淆执行完成与价值验证。

## 决策

1. 建立独立 `idea` 聚合及资产、任务关系、迭代、调研运行四个子表；不迁移或删除历史任务。
2. 阶段只由成员显式推进。任务和 AI Run 的终态是门禁输入，不是点子的自动状态机。
3. 自动资产进入固定内部 id 的系统知识库和固定点子文件夹；显示名称不承担身份判断。
4. 调研通过 `IDEA_RESEARCH` 复用 assistant-v2 的 claim/complete、安全账号隔离和超时收口，但使用独立队列表与临时目录。Runner 保持 Shell、多代理、本地文件和凭据隔离，仅为该模式开放 Web 搜索。
5. 点子团队可见且团队成员均可推进，负责人仅表达责任归属；第一版不提供公开分享和飞书录入。

## 后果

- 点子档案可跨越多个任务和 AI 迭代，并保留放弃知识，代价是新增一套阶段门禁与聚合查询。
- 固定内部 id 避免误复用同名用户知识库；自动调研永远新增版本，文档人工编辑不会被覆盖。
- 研究运行无法触达仓库或执行代码，降低不可信网页材料扩散执行面的风险；需要代码验证时必须另行创建 MVP 任务并进入现有开发型 AI Run。
