# ADR-095：以运行级能力清单治理 Skill、MCP 与插件

- 状态：提议
- 日期：2026-08-21

## 背景

WAO 已有不可变 Skill 审核包、个人记忆 MCP、项目工程记忆和多引擎 AI Runner，但尚未定义一个项目如何
启用 Skill/MCP、Runner 如何得到一致配置，以及运行后如何审计实际使用情况。让自动任务继承执行电脑的全局
插件和 MCP 会使不同节点结果漂移，也可能把个人能力和凭据带进组织任务。

同时，固定交付流程如果继续全部依赖自然语言提示，会重复消耗上下文并产生不必要的轮询；但把所有命令简单
包装成 MCP 也不会自动节省 Token，因为工具定义、参数、结果和后续判断仍需模型处理。

## 提议

- 在 `skill_version` 之外建立项目能力绑定；绑定固定审核版本，不自动跟随市场最新版。
- 每次 AI Run 把项目绑定解析成不可变 `capabilityManifest`，包含 Skill 版本与哈希、MCP 工具白名单、权限、
  平台兼容性和预算；历史运行保留实际加载与调用记录。
- Runner 为每次运行生成隔离能力目录并校验包哈希，不继承节点个人的全局插件或 MCP。不同 AI CLI 通过适配器
  显式报告支持或不兼容，不能伪造能力。
- Secret 只以服务端受控引用和短期运行凭据进入对应 MCP，不能出现在 Skill 包、浏览器响应、运行摘要或日志中。
- “WAO 方法论”采用短入口、按需参考和固定评测集；新方法先作为带证据候选，经人工评审后创建不可变版本，
  不由 AI Run 直接覆盖已发布内容。
- 任务获取、PR/部署状态、失败日志裁剪和验收证据等固定步骤优先下沉到 Runner 状态机或少量高层 WAO 工具；
  MCP 不取代现有领域权限与业务校验。
- 是否节省 Token 必须以固定模型、推理强度、代码基线和代表任务做 A/B 验证，同时满足质量基线；未记录或
  未验证时显示未知，不推算收益。

详细架构、分阶段范围和验收口径见
[WAO AI 能力治理与方法论 Skill 方案](../architecture/ai-capability-governance.md)。

## 影响

- Skill 市场的“审核与分发”和 Runner 的“项目启用与执行”保持解耦，公共发布不会自动获得执行权限。
- 项目成员能回答一次 Run 使用了哪些能力及版本，升级、撤销和跨节点复现都有明确边界。
- 首期需要新增能力绑定、运行快照和 Runner 适配；在这些能力完成前，不能把 Skill 市场宣传为已支持一键安装
  到 AI 工作流。
- 方法论、项目事实和个人记忆继续分域，降低陈旧经验或提示注入变成隐式系统指令的风险。
- 方案不承诺零 Token 的 MCP。优化收益以真实用量、时延、成功率和验收质量共同决定。
