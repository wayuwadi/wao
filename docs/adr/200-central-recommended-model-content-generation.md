# ADR-200：自媒体成稿复用 WAO 推荐模型并由主服务持有凭据

## 状态

已采纳。

## 背景

自媒体 Agent 已有话题、个人上下文、平台提示词和异步发布状态机，但文案生成只读取独立的
`AGENT_AI_*` 环境变量。生产环境没有重复配置该 API Key 时，页面会把成员勾选的“AI 生成”静默改成
手工草稿，点击“开始创作”后得到 0% 的空白内容。WAO 主服务已经有经过验证的推荐模型配置和加密凭据，
继续维护第二份 Agent 凭据既容易漂移，也会扩大凭据暴露面。

## 决策

- Agent 读取 `ai_account` 的供应商、模型、启用状态等非敏感元数据，判断 WAO 推荐模型是否可用；不读取
  `credential_json`，也不获得 `WAO_VAULT_KEY`。
- 创建 AI 图文任务时，Agent 在当前成员权限内完成有界上下文筛选，固化系统提示词、用户材料和来源快照，
  将任务写为 `GENERATING`。成员明确要求 AI 生成但没有模型时，接口直接失败并保留页面输入，不创建空白稿。
- `wao-server` 通过数据库队列领取 `WAO_RECOMMENDED` 任务，在主服务内调用
  `AiAccountService.defaultDocumentPolishAccount()` 解密凭据，再用受信 Chat Completions 客户端生成结构化内容。
  成功后写入标题、正文、标签、封面文字和分段，进入 `WAITING_REVIEW`；提示词随即清除，来源快照继续保留。
- 任务领取使用随机 claim token 和十分钟租约。多主服务节点靠条件更新互斥；进程中断后，租约到期可重新领取。
- 模型调用或结构解析失败时任务进入 `FAILED`，保留当时的提示词并展示真实错误。成员可一键重新入队；若改为
  手工保存，则清除生成请求，后续发布失败不会被误判成生成失败。
- 若 Agent 自身配置了可用的 `AGENT_AI_*`，继续由原本地生成器执行，供独立部署使用；生产默认复用 WAO 推荐模型。
- 页面直接提交成员选择的 `generateCopy`，生成中自动轮询并在完成后回填编辑器，不再根据一次能力探测静默改写意图。

## 后果

`agent_publish_task` 会短暂保存实际发给模型的提示词，其中可能含成员授权的个人摘录；它与既有来源快照使用同一
工作区访问边界，生成成功后立即清除，失败时仅为可重试而保留。主服务与 Agent 共同依赖这张队列表的字段契约，
因此接口、migration、本地 H2 投影和两端测试必须同步更新。推荐模型被停用时，新任务会明确失败，已有失败任务在
模型恢复后可沿用原始快照重试。
