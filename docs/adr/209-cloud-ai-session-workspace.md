# ADR-209：独立云端 AI 会话工作区

## 状态

已采纳（2026-09-08），扩展 ADR-208。

## 用户问题

AiRun 已能恢复精确 session，但必须进入项目、打开任务抽屉、找到执行记录才能阅读和追加输入。
云端持续使用需要以会话为入口，不能靠用户在任务列表里反复定位。

## 决策

- 新增 `/ai-sessions`，侧栏「AI 会话」、首页和已有运行详情均可直达。
  左侧展示全部可见 AiRun（包含未建立 session 的排队/旧运行），数据库每页 25 条摘要；
  支持名称 / 原任务名称 / session ID 搜索、工具和状态筛选，按置顶和最近活动排序。
- 选中一条运行后，右侧直接显示 Markdown 对话、初始任务要求、展开的执行过程和报告，底部固定续聊框。
  URL `?session=<runId>` 可刷新、收藏、前进后退；窄屏在列表和会话间切换。
- 新会话从此处填写目标、项目、执行节点和执行方式，复用既有 AiRun 入队接口逻辑并关联一条任务。
  执行仍在已配对的两台服务器上，默认自动分配或显式选择节点；续聊保留原节点、原 session。
- 会话命名、置顶、归档保存在新表 `ai_session_preference`，按成员与运行联合主键隔离。
  归档只整理列表，不停止任务，不删除会话，不修改项目任务标题；可以移回并继续。
- `/api/ai/sessions` 系列接口在读写前验证当前成员的项目可见性，列表先在数据库按项目过滤。
  会话记录和执行数据仍以原 `ai_task_run` 为权威来源，不复制历史、不创建第二套执行器。
- 续聊沿用已有按用户 / runId 隔离的本机草稿，新会话和名称草稿也持久化。
  发送中保持只读；失败保留输入；切换时拒绝过期响应，轮询不得覆盖草稿或抹掉已读历史。
  对话按游标补读，后台页签停止轮询；活动会话 5 秒、其它 15 秒检查，列表每三次同步一次。

## 参考与边界

参考 CC GUI 的会话列表、历史阅读与线程恢复的交互组织，使用 WAO 现有 Vue/Java/Runner 独立实现。
这里管理 WAO 已持久化的 AiRun 会话，不声称读取节点上所有私人 Codex 会话，也不通过浏览器另起执行进程。
早期未存储的 session 和被截断的旧消息不能凭空恢复，页面明确提示不可续接的历史运行。

## 验收

验证列表分页 / 搜索 / 权限隔离、续聊绑定、乱序请求、草稿恢复 / 失败重试、名称和归档的成员隔离，
以及真实发布后的「打开会话→查找历史→追加要求→原节点执行→收到回复」和新会话派发链路。
