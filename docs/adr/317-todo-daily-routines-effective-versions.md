# ADR-317：日常规则按生效日版本生成虚拟实例

状态：已采纳（2026-10-03）

## 背景

用户需要在现有待办日视图看到早晚固定事项，能跳过或完成，又不希望普通任务列表每天出现复制件或积压。规则可以编辑、暂停和归档，但昨天的标题、分组、排序和状态必须保留当时语义；今天编辑也不能悄悄改变尚未打开的今天。

## 决策

每条规则保留成员私有模板及按上海业务日生效的版本。创建当天生效；已有规则的编辑从次日生效，同日后续编辑只更新次日提案并递增模板版本。版本含标题、`MORNING`/`EVENING`、每周星期、排序、启用和归档状态。读日期范围时以版本及星期确定性生成尚未操作的虚拟 `OPEN` 实例，不因读取写数据库。只有今天发生状态操作时才持久化实例，并把版本、标题、时段、排序和状态一同固定；过去和未来禁止首次标记。`OPEN` 是可重置状态，`SKIPPED` 不计完成。规则不用普通任务表，亦不写第一阶段任务历史。

规则版本和实例版本分别作为条件写入前置条件；账号加 UUID 的第一阶段回执仍提供丢响应重试。状态操作的原请求即使第二天重放也能拿到已提交结果，避免把时钟推进误报为失败。回执只存资源引用，返回时依当前成员重新验权。暂停、归档都只阻止生效日起的新虚拟实例，已持久化实例和旧版本保留。

## 影响

V179 新增 `wao_todo_routine_template`、`wao_todo_routine_revision`、`wao_todo_routine_occurrence`，复用 V178 的账号范围回执表。新 `DailyRoutineController` 与 `DailyRoutineService` 保持独立，统一回执查询需要在第一阶段提交后接线。无定时批量建任务、无逾期实例清扫，也不改现有任务、小记和日历数据。迁移仅新增表，不修改既有已执行迁移。
