# ADR-116：子任务迭代运行继承主任务已完成上下文

## 状态

已采纳。扩展 ADR-027 的子任务级 AI 派工，不改变 ADR-013 的人工分享边界。

## 背景

主任务第一次 AI Run 会带上全部未完成子任务整体交付。后来在同一任务下新增一条子任务并单独运行时，
现有提示地址只返回这一条子任务的标题和描述；AI 看不到主任务背景与已经完成的子任务，容易丢失上一轮约束、
重复已有工作，无法真正基于首轮结果继续优化。

普通子任务分享链接又有明确的最小披露语义：展开子任务后复制链接，只分享当前子任务。不能为了运行上下文
直接扩大所有人工分享链接的范围。

## 决策

- 主任务运行继续使用 `?openOnly=true`，首次运行自然包含主任务与全部未完成、未单独派工的子任务。
- 子任务 AI Run 的固化提示地址增加 `?iteration=true`。该 Markdown 把当前子任务标成唯一待办，并带上：
  - 主任务标题、状态、优先级、截止日期、描述与图片；
  - 当前任务下已完成子任务的标题、描述与图片。
- 历史段落明确标注为“只读记忆”，要求 AI 不得重复执行；其它未完成子任务不进入上下文，避免扩大本次范围。
- 不带 `iteration=true` 的子任务 JSON、分享页和 Markdown 保持只含当前子任务，继续遵守 ADR-013。
- 上下文从任务当前持久化数据实时生成，不复制快照、不补演示数据；排队期间补充的真实描述和图片会在领取时读取。

## 后果

- 用户可以先运行主任务，后续只新建并运行一条迭代子任务，AI 仍能读到上一轮已完成工作的业务背景。
- 迭代上下文会比原来的单子任务提示更长，但只纳入已完成历史，不把所有未完成工作混入本次范围。
- 运行提示地址仍是公开只读地址，沿用 ADR-013 的“链接即凭据”风险；本次没有扩大普通分享链接的默认披露范围。
