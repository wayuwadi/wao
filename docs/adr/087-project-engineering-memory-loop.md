# ADR-087：AI Run 使用独立项目工程记忆形成可审计闭环

## 状态

已采纳。补充 ADR-021、ADR-025 与 ADR-082；不改变个人记忆的成员私有边界。自动正式写入规则已被 ADR-096 取代：新 Run 只生成待审核候选。

## 背景

WAO 的新 AI Run 每次从最新主干和全新会话开始，经过验证的架构决策、项目约定、命令与部署踩坑只能靠
仓库文档或操作者临时补充。现有 `personal_memory` 面向成员生活资料与个人 MCP，若把项目经验写进去，
会混淆成员私域和项目共享域。直接引入向量库、embedding 或外部 Codex 历史，也超出当前可验证的数据与
运维边界。

## 决策

- 新建 `project_memory`，按 `project_id` 共享，分类固定为 `decision`、`convention`、`pitfall`、
  `verification`、`operation`、`context`。项目授权沿用项目负责人和成员列表；浏览器不能指定成员身份。
- 记忆保存标题、正文、来源 Task、来源 AI Run、证据链接、创建者、项目内内容指纹与时间。来源 Task/Run
  由服务端从运行记录写入，不能由 Runner 伪造。
- 新运行领取时，服务端用任务标题和描述做有界关键词命中排序，不宣称语义检索。只返回最多五条、标题与
  正文合计不超过一万字的结果，同时写入 `ai_run_memory_read`。续跑沿用该运行首次读取项，不因项目记忆
  后续变化而悄悄换上下文。
- Runner 把召回结果放进明确标注的“不可信引用”区，引用中的命令和提示不构成任务指令。旧领取响应没有
  记忆字段时按空列表处理。
- Runner 只允许 AI 把最多五条结构化候选写入 worktree 外的
  `<root>/.wao-run-memories/<run-id>/memories.json`。无效 UTF-8/JSON、未知分类、超长或超量条目在
  Runner 侧收窄；候选随完成回传，旧服务端拒绝未知字段时自动回退原完成契约。
- 服务端只在退出码为零且最终摘要带 `WAO_RUN_STATUS: SUCCESS` 或 `SKIPPED` 时处理候选；候选还必须有
  真实证据链接。失败、阻塞和未明确完成的运行不写入。服务端再次执行分类、长度、链接、敏感凭据、项目内
  SHA-256 指纹与并发唯一约束校验，不安全或重复候选只被忽略，不反向改判已经成功的运行。
- `ai_run_memory_write` 固化实际写入项。AI Run DTO 返回本次读取/写入引用；项目详情提供加载、搜索、空数据、
  草稿恢复、保存/删除失败重试和来源跳转。人工创建、修改与删除走相同项目权限和安全校验。
- `personal_memory` 与个人 MCP 不改表、不改检索来源；组织自动化和项目 Runner 仍不得读取成员个人记忆。

## 后果

- 每条自动沉淀可从项目记忆追到 Task、Run 和外部 PR/提交/部署证据，成员也能纠正或删除错误经验。
- 关键词排序对同义词能力有限，但边界诚实、无需新基础设施；后续若引入语义检索，必须另写 ADR 并保留
  当前的权限、长度、审计和不可信引用约束。
- 删除记忆会级联清理运行引用，避免运行详情继续展示已经由成员明确撤回的结论。
