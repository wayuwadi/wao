# ADR-174：额度采样留存与真实使用轨迹建议

## 状态

已采纳。补充 ADR-026、ADR-031、ADR-032 与 ADR-164，不改变额度供应商、采样频率和 AI Run 用量口径。

## 背景

数据统计页已经能按日展示 AI Run 次数和 CLI 真实回传的 Token，但 AI 账号与 Runner 额度只保留最新快照；额度重置时虽可发群通知，
页面仍无法回看“何时刷新、刷新后剩多少、每天下降多少”。AI Run 已持久化模型、思考深度、状态、起止时间、Token 与活动类型，
却没有把这些轨迹整理成用户可执行的使用建议。

## 决策

- 新增 `ai_quota_snapshot`，复用现有真实采样：集中 Codex/Claude 账号成功同步与 Runner 本地 Codex 成功上报时，保存来源、窗口、
  剩余百分比、重置时间和采样时间；不保存供应商原始响应或任何凭据。历史写入失败不阻断当前额度和 Runner 心跳。
- 数据统计页近三十天按账号窗口、上海自然日取最后一条采样作为日末剩余值；相邻有记录日期只在剩余下降时记录下降幅度，
  剩余上升单独形成刷新事件并保留刷新前后比例。缺少真实采样时显示空状态，不从 Token 消耗估算额度。
- 使用建议是服务端确定性分析，不额外调用 AI。模型、思考深度和任务方向按已结束运行的成功率、样本数与真实 Token 比较；
  速度只比较有起止时间的成功运行；频率以活跃日真实次数为基线。每项都返回证据，少于三条有效运行或三个活跃日时明确标为
  “数据不足”，不把偶然一次结果称为最优。
- 服务档位目前没有可比较的 Fast 真实记录，因此本次不伪造速度档位建议；页面只报告已观测配置耗时。后续 Runner 真正回传服务档位后再扩展。

## 后果

- 用户可从数据统计页回看额度刷新、刷新后余额和每日下降，并把 Token 用量与额度消耗放在同一页面判断。
- 建议能覆盖模型、思考深度、速度、频率和后续任务方向，且每条结论都能追溯到真实 AI Run；早期样本不足时页面会诚实说明等待数据。
- 额度历史会持续增长；接口最多读取九十天，后续数据规模需要压缩时可按日归档，但不得修改既有采样语义。
