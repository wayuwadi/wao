# ADR-183：用消息撤回墓碑删除飞书快速收集任务

## 状态

已接受（2026-08-31）。

## 背景

快速收集已经用 `message_id` 持久关联飞书原消息与 WAO 任务，也支持原消息编辑；但事件入口只消费收到消息，
主动轮询又过滤 `deleted=true`，因此成员撤回原消息后任务仍永久存在。只在回调里直接删任务还会受到事件
乱序影响：撤回先到、收到消息后到时，任务会在撤回之后重新创建。

## 决策

1. 在既有回调地址消费飞书官方 `im.message.recalled_v1`，同时让近两分钟增量轮询和 24 小时编辑回看
   消费消息的真实 `deleted=true`，作为回调未配置或暂时失败时的恢复路径。
2. 删除目标只来自 `feishu_quick_collect_event` 的 `message_id → target_id`，并同时核对当前配置群与事件记录群；
   不从用户可编辑的标题或正文猜测。
3. 复用事件表的 `RECALLING → RECALLED` 作为持久墓碑。撤回先到时先插入处理中墓碑，后到的接收事件命中
   唯一消息键后不创建任务；创建与撤回并发时，创建完成使用条件更新，发现墓碑后立即删除刚创建的任务。
4. 任务删除保持幂等：任务已经被成员删除仍把事件收敛为 `RECALLED`。快速收集开关只控制新建，不阻断
   已有消息的撤回清理。

## 后果

飞书原消息与 WAO 任务保持同生命周期，并能在双节点、重复投递和事件乱序下收敛。代价是轮询现在还要处理
已撤回消息，但只按已有消息关系执行幂等删除，不增加无界扫描或演示数据。
