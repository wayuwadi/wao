# ADR-265：浏览器发布快路径与一分钟合并窗口

- 状态：已采纳
- 日期：2026-09-24
- 来源：用户要求缩短 Jenkins 发布耗时，延续 ADR-264 浏览器唯一维护范围

最近一次成功发布 #484 的运行耗时为 534 秒，其中前端测试构建 127 秒、镜像制品 23 秒、部署 356 秒，另有启动前 300 秒合并等待。对于仅改浏览器的提交，重复滚动重启后端是主要无效工作。

主站合并等待缩短为 60 秒，继续禁止并发、不打断旧构建、合并同参数待执行批次。仅当从已发布版本到目标提交的完整差异只包含前端和原有非运行文件白名单时使用浏览器快路径：仍执行相应前端测试与双前端生产构建，保留不可变源码和静态资源、三节点静态资源校验、入口最后切换以及完整公网版本/路由/健康验收；跳过后端镜像导出、数据库检查及后端重启。发布前后均确认双节点健康，失败即停止，不自动掩盖故障。

后端、数据库、基础设施、流水线和未知路径变化，缺失比较基线，以及显式从库重建或离线发布，均走完整流程。快路径执行前再次核对 Git 变更范围，不能通过环境变量绕过范围判定。后端版本允许保持前次已验证 SHA，前端版本独立推进，状态描述明确保留原后端。主站的后续变更范围仍以公网前端已发布版本计算。

首个引入流水线自身改动的批次必须完整发布；后续纯 Web 批次用于测量实际提速，不以估算冒充实测。

2026-09-24 起，ADR-267 调整主线 CD：浏览器快路径保留生产构建与验收，完整前端测试改在合并前执行。
