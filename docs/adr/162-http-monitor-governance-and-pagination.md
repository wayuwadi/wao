# ADR-162：请求监控治理入口与全站统一分页

## 状态

已采纳。

## 背景

ADR-115 与 ADR-131 已把 HTTP 性能巡检接入真实 AI Run、系统设置和自动化运行记录，但请求监控页只提供手动启动，
配置与历史藏在自动化页面。接口聚合固定按平均耗时排序，无法优先查看失败最多或 P95 最大的接口。现有五个页面又分别
手写上一页和下一页，用户不能直接查看页码或跳到指定页。

## 决策

- 请求监控页直接提供“巡检设置”和“巡检历史”入口。设置继续读写 `http.inspection.*` 与真实 Cron；历史继续读取
  `automation_run`，不复制运行结果，也不建立演示历史表。
- 未自定义时，HTTP 巡检按每日 06:30、Top 10 候选、最多治理 10 个接口执行。V116 只把仍等于旧默认 5/2 的现有配置
  升级到 10/10；管理员已保存的其他数量保持不变。
- 接口聚合表默认按失败数倒序，平均耗时、P95 和失败数表头都可切换为对应指标倒序；相同值依次按失败数、平均耗时、
  P95 和路径稳定排序。排序只作用于后端已经返回的最多 50 个真实接口聚合，不扩大数据采集范围。
- 新建共用 `WaoPagination`，替换自动化运行、网页托管、首页 AI 运行、完整 AI 历史、请求监控双表和系统报告三处
  现有分页。长列表展示首尾页、当前页附近页码和省略号，并统一提供指定页输入及“跳转”按钮。

## 后果

- 成员不用离开请求监控页即可调整真实巡检并核对每次自动或手动执行结果；加载、空历史与失败重试仍有明确状态。
- 所有现有分页获得一致的键盘回车和按钮跳页能力；页面继续使用原来的前端有界切片或服务端分页，不改变接口数据来源。
- 监控表排序只在当前返回的 50 个接口内生效。若真实接口规模使截断影响失败数排序，再以线上指标为依据增加服务端排序参数，
  不能把本次前端排序宣称为全量数据库排序。
