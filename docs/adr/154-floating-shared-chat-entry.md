# ADR-154：共享聊天收口为全局悬浮框

## 状态

已接受（2026-08-28）。本 ADR 调整 ADR-126 与 ADR-130 的页面入口和生命周期，不改变共享消息、飞书桥接与聊天复盘 API。

## 上下文

共享聊天当前注册为左侧“公共”菜单和 `/chat` 模块页，进入后还会生成普通 Tab。聊天是跨业务页面持续发生的轻交互：成员为了查看或发送一句话必须离开当前工作位置，收起聊天也等同于切换页面。页面组件被路由销毁后虽然能靠 `localStorage` 恢复文字草稿，但无法表达“最小化后继续收未读、再次展开回到原输入位置”的常驻聊天体验。

## 决策

- 从内置菜单注册表、完整工作台、手机底栏和持久化 Tab 中退休 `chat`；登录后的应用壳在通知按钮旁常驻聊天入口。既有 `/chat` 与 `/chat-reviews` 地址跳到首页并通过查询参数打开悬浮聊天或复盘，旧书签不变成死链。
- 聊天组件在受保护应用壳中常驻，桌面端使用右上角固定悬浮框，手机端使用全屏框。点击框外、最小化按钮或 Escape 只切换可见性，不销毁组件；未发送正文和引用继续按成员写入现有本机草稿键。
- 最小化后继续按既有频率读取真实消息，用右上角角标展示服务端返回的未读数量；隐藏状态禁止调用已读接口，只有悬浮框打开、页面可见且消息区到达底部时才提交已读事实。
- 聊天复盘仍从聊天框内打开。复盘自身 Teleport 到全局弹层，操作复盘不触发底层聊天的框外最小化。
- 内置菜单注册表升级到 V26，读取旧注册表时丢弃 `chat`，保留其它改名、分组、排序和显隐定制；旧浏览器保存的聊天 Tab 和手机底栏聊天项在读取时清理。

## 后果

成员可在任意业务页打开聊天并在收起后继续当前操作，未发送内容不会因最小化丢失；未读角标来自真实共享消息，不用静态提示。应用壳会常驻共享聊天的轻量轮询，这是获得跨页面未读和常驻草稿所需的固定请求；飞书群配置、发送、图片、引用、表情和复盘数据流均保持原实现。

## 回退

恢复 `chat` 内置菜单和路由组件即可重新使用模块页；共享消息、草稿键和后端 API 没有迁移或删除，回退不需要数据操作。
