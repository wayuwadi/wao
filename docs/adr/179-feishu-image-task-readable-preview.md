# ADR-179：飞书图片任务使用文字优先的描述与预览

## 状态

已接受（2026-08-31）。

## 背景

ADR-112 要求把飞书富文本图片按原位置写入任务描述。图片出现在文字之前或消息只有图片时，快速收集
会把图片 Markdown 第一行误当成任务标题，看板因此显示被截断的 `![飞书图片](/api/images/...)`，既不
可读也会让内部图床路径占据预览。图片本身已经可靠转存，问题位于描述编排和标题推导。

## 决策

1. 飞书富文本的文字继续保持段落顺序；图片仍逐张真实下载并保持图片间的先后顺序，但统一追加到文字
   正文之后。图片下载或转存失败仍使本次收集失败，不降级成缺图任务。
2. 新写入的图片 Markdown 使用「任务图片」作为替代文本，不再把来源渠道「飞书」暴露成内容描述。
3. 标题只从非图片文字行提取。纯图片消息没有可靠文字或图片识别数据源时，不伪造图片语义，使用稳定
   标题「图片待办」；全文与真实图片继续保存在描述中。
4. 数据迁移只修复由快速收集事件明确关联、且标题确实以旧图片 Markdown 开头的历史任务，并替换这些
   任务描述中的旧替代文本；不触碰用户手写标题，也不猜测图片内容。

## 后果

任务看板、列表和分享标题始终是可读文字，带文字的图片消息先展示说明再展示图片。图片原位置不再保留，
但多图顺序不变；纯图片标题只说明数据类型，用户仍可在 WAO 内按真实内容自行补充标题。
