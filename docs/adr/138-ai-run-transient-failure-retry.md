# ADR-138：AI Run 在最终失败前按项目配置自动恢复

## 状态

已采纳。

## 背景

开发任务可能因为 AI CLI 短暂网络错误、进程异常或 Runner 对新增事件形状处理不完整而结束。这些错误不代表
需求无法完成，但旧链路会立即把当次运行记为失败并发送飞书卡片，用户只能手工点击“基于报错重跑”，新的运行
还会产生另一条档案和通知。另一方面，AI 明确返回 `WAO_RUN_STATUS: BLOCKED` 往往代表真实权限或信息阻塞，
原样重跑既没有新增条件，也可能重复外部副作用。

## 决策

- 项目 AI Run 配置新增“失败自动重试次数”，默认 2 次，可在 0 到 5 次之间调整。领取任务时把配置固化到
  Runner 的本次执行参数，旧服务端缺字段时 Runner 仍按默认 2 次兼容。
- 自动重试覆盖 Git 工作区准备失败、AI CLI 非零退出和调用过程异常；人工暂停、运行中补充输入以及 AI 正常返回的
  `SUCCESS / SKIPPED / BLOCKED` 业务终态不触发。
- Git 工作区准备按项目串行，失败时先清理可恢复的半成品再按同一项目配置重试。Runner 每次准备前都会删除
  主克隆中不该存在的 `core.worktree`；这能原位修复 Windows worktree 被 WSL Git 写入 `/mnt/...` 后导致原生
  Git 全部失败的跨系统路径污染，不要求用户删除仓库重克隆。
- 重试保留同一运行、分支、worktree、已取得的会话 id、累计用量和已有外部状态；恢复提示要求先核对现场，
  不重复已经成功的外部副作用。中间失败只写运行进展和本机脱敏日志，不调用完成接口，因此不发送失败飞书卡片。
- 只有重试成功或次数耗尽后才向服务端回传一次最终结果。成功只发成功通知；连续失败耗尽后才定义为失败，
  保留最后一次完整错误供“基于报错重跑”。
- JSONL 中合法的字符串、数组等非对象事件直接忽略；进展解析回调异常只影响观测，不得终止 AI CLI 主进程。

## 后果

短暂故障不再要求用户充当重试按钮，且一次任务仍只有一条运行档案和一张最终通知。代价是故障运行可能占用
更长时间和更多模型额度，因此重试次数有上限且允许项目关闭。Git 准备与 AI CLI 分阶段计数，Git 恢复不会消耗
模型执行阶段的恢复次数；真正的业务阻塞仍会立刻交给用户，不用无意义重跑。
