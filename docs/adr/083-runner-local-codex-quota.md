# ADR-083：Runner 上报本地 Codex 脱敏额度

## 状态

已采纳。补充 ADR-030～034 与 ADR-065，不改变集中账号的 OAuth 登录、服务端额度刷新和按运行路由。

## 背景

首页原先只读取 `ai_account` 中已集中登录的账号。用户在 Windows、Linux 或 Codex Desktop 中登录同一个
ChatGPT 账号，并不等于这个账号已经保存到 WAO；Runner 心跳也只上报 CLI 能力，因此服务端无法识别本地
账号，更无法展示当前真实余额。机器是否相同不是额度差异的原因，缺失的是本地登录态到首页的安全观测链路。

Codex CLI 当前 app-server 协议提供 `account/read` 与 `account/rateLimits/read`：可从本机登录态返回邮箱、
套餐、点数余额、通用限额、模型专属限额、窗口周期和重置时间。这比直接读取 `auth.json` 或由 Token 用量估算
余额更安全、也更接近 Codex Desktop 自身展示。

## 决策

- Runner 每五分钟启动一次本机 `codex app-server --stdio`，通过协议读取账号与真实限额。只保留邮箱、套餐、
  点数和结构化限额窗口；OAuth Token、refresh token、Cookie、`auth.json` 和原始响应都不进入心跳、日志或数据库。
- 心跳把脱敏快照写入 `codex_runner_quota`。刷新失败只记录错误并保留上一次成功快照；额度观测失败不得阻断
  Runner 心跳、任务领取或已在执行的工作。
- 首页按规范化邮箱合并多台 Runner 的同一账号，使用最新成功快照，并展示来源电脑、同步时间和新鲜度。
  没有邮箱时按 Runner 隔离，不能猜测两个匿名账号相同。
- 首页展示通用和模型专属窗口，按 `100 - usedPercent` 显示剩余比例；只有 300 分钟窗口才标为本轮额度，
  只有 10080 分钟窗口才标为周额度。未知周期、余额或重置时间保持未知，不伪造成满额或零余额。
- 集中账号的既有额度仍保留，供自动进化调度与没有本地快照时使用。本地 Runner 快照只用于可见性，
  不替代自主调度“必须由服务端本次刷新成功”的安全门槛。
- 本次 migration 一次性为现有 Codex Runner 设置脚本更新请求，使旧节点在部署后通过既有自更新机制获得新探针；
  后续 Runner 更新仍沿用后台一键下发，不改成每次发布都自动升级。

## 后果

- 同一 Codex 账号登录在不同机器时，首页会合并显示同一份真实额度，不再要求为了看余额重复集中登录。
- 页面能看到 Codex 套餐、点数余额、通用周限额与模型专属周限额，信息来源与参考客户端一致。
- Codex app-server 协议随 CLI 演进时，旧快照仍可见并标为历史；Runner 日志记录脱敏错误，升级解析器即可恢复。
- 服务端只获得本来就用于页面展示的账号标识和额度，不获得使用该账号发起供应商请求的能力。
