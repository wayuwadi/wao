# ADR-007：密钥库密码采用服务端 AES-256-GCM 加密，而非零知识端到端加密

## 状态

已采纳。

## 上下文

密钥库此前是纯前端演示（`VaultView.vue` 明确标注「不存储真实密码」）。本轮要求把密钥库做成可用功能。密码类数据的存储方案有两条路线：

1. **零知识端到端加密**：客户端用独立主密码派生密钥，加解密只发生在浏览器，服务端全程只存密文、不掌握密钥，即便数据库和服务器同时失陷也无法还原明文。
2. **服务端静态加密（encryption at rest）**：密码在传输层（HTTPS）保护下到达服务端，由服务端加密后存库；服务端持有密钥，理论上可以解密。

WAO 当前没有真实的用户级鉴权体系（`session.ts` 明确写着「登录态存 localStorage、成员为静态演示数据，不接真实 OAuth」；后端没有 Spring Security，所有 `/api/*` 对任意请求方开放）。零知识端到端加密要求「谁能登录、主密码归属哪个用户」这套身份边界先存在，否则「客户端持有主密码」这件事本身就没有意义——现状下任何人都能调用 API。在鉴权体系补齐之前引入端到端加密，只会增加前端 WebCrypto 复杂度，不会带来真实的安全收益。

## 决策

- 密码字段以 **AES-256-GCM** 在服务端加密后存储（`vault_item.secret_ciphertext` + `secret_nonce`），密钥来自环境变量 `WAO_VAULT_KEY`（base64 编码的 32 字节），不落库、不出现在日志中；`VaultCryptoService` 是唯一加解密入口。
- 列表 / 详情接口（`GET /api/vault`）永不返回密码明文，只返回 `hasSecret` 布尔标记；明文只在显式调用 `POST /api/vault/items/{id}/reveal` 时解密返回一次。
- `local` / `dev` 环境使用 `application.yml` 中的内置默认密钥（明确标注「不是真实密钥」）；`prod` 必须通过 `deploy/.env` 或 GitHub Secrets 注入 `WAO_VAULT_KEY`，与 `DB_PASS` 同等对待。
- VaultView 的「本页仅为演示」提示改为如实说明当前信任边界：服务端加密，不是零知识端到端加密。

## 后果

- 数据库被单独拖库（不含应用服务器）时密码不会明文泄露；但服务器与密钥同时失陷时仍可解密——这是有意识接受的折中，不是零知识方案。
- 真正的端到端加密（客户端主密码派生、服务端不可解密、按用户隔离密钥）依赖尚不存在的用户级鉴权体系，留待鉴权补齐后单独立项，届时本 ADR 状态改为「被取代」。
- 在此之前，不应把 WAO 密钥库用于存放高敏感凭据（如银行密码、私钥），`VaultView` 与本文档需要保持这条提示同步更新。
