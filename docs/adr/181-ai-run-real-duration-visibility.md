# ADR-181：AI Run 区分端到端总耗时与 AI 实际执行耗时

## 状态

已采纳。

## 背景

AI Run 页面原先把领取到 Runner 最终回传之间统一显示为“执行时长”。这个区间同时包含 Git 工作区准备、AI CLI
执行、提交合并、批量部署等待、报告上传和线上验收，无法回答 AI 自身实际运行了多久；仅有目标模式会回传目标计时，
其它引擎和模式没有同口径数据。前端根据 Token 或进度时间推算会制造不可靠结果。

## 决策

1. `claimed_at` 作为首次有效领取时间，续跑同一 Run 时不覆盖；节点掉线并回收任务时仍清空，由下次有效领取重新计时。
2. Runner 用单调时钟包围每次真实 AI CLI / Codex app-server 调用，自动重试和同会话继续输入都累计到
   `ai_execution_duration_ms`；Git 准备、报告上传、部署排队与线上验收不计入。
3. 运行详情以 `claimed_at → finished_at`（活动态以当前时刻）展示端到端总耗时，并单独展示实测 AI 执行耗时。
   历史记录没有实测字段时显示“旧记录未记录”，不按时间线或 Token 猜测。
4. 完成回传字段保持滚动升级兼容：新 Runner 遇到旧 API 拒绝未知字段时回退旧契约；新 API 接受旧 Runner 缺省为空。

## 验收

- Runner 测试固定单调时钟，证明多轮 AI 调用累计且 Git 准备时间不计入，并覆盖旧 API 契约回退。
- 服务测试证明实测耗时随续跑累加、首次领取时间不被同 Run 续跑覆盖，DTO 同时返回领取时间与实测耗时。
- 前端测试覆盖任务详情和 AI Run 详情的两个独立时长，以及旧记录未记录状态。
