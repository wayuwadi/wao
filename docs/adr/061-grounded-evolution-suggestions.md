# ADR-061：自主进化建议从真实 WAO 资产中挖掘

## 状态

已采纳。补充 ADR-046、ADR-059；AI 助手的只读沙箱、资产白名单和 AI Run 派发边界保持不变。

## 背景

ADR-059 在服务端保存了四条固定的通用改进模板。它们能进入真实 AI Run，但不会读取用户知识库或飞书同步
聊天，反复打开首页也只能看到相同内容，无法承担“从已有信息中发现下一项需求”的产品目标。只在前端增加
刷新按钮仍会返回同一批模板，也会把没有真实资料支持的通用巡检伪装成用户需求。

WAO 已按 ADR-046 建立统一资产检索层，并按 ADR-044 由本地 Codex 在临时空仓库和只读沙箱中完成分析，
无需新增模型凭据、向量库或把生产资料交给开发 Runner。

## 决策

- 首页不再返回硬编码建议。首次没有已保存批次时，页面自动请求挖掘；之后展示最近一批最多五条建议，用户
  可以点“刷新换一批”。有一至五条可靠新建议就保存并立即换批，避免因凑不满五条而让有效候选整批作废；
  一条可靠候选也没有时才失败。生成期间保留上一批，失败时显示真实原因并允许重试，不用模板或演示数据兜底。
- 候选资料只取 ADR-046 白名单中的知识库文档和飞书同步归档，最多各四个、总计八个来源和 16,000 字；
  同时只向模型提供最多 100 个未完成任务标题用于查重，不读取密码库、凭据、系统配置或私人助手会话。
- 复用 `ai_assistant_run` 的本地 Codex 只读队列，但内部分析不写入成员聊天历史。提示词要求最多五条、逐条
  引用来源编号、避开未完成任务和上一批建议；只选择用户可感知的功能、操作提效或体验改善，排除纯测试、
  纯文档、纯重构和依赖升级；有可靠证据的候选不足五条时如数返回，一条也没有时才返回错误，不允许用纯技术优化凑数。
- 服务端校验 JSON 数量为一至五条、字段长度、批内重复、上一批重复和来源编号。通过后在一个事务中写入
  `ai_evolution_suggestion`；每条保存来源标题与站内地址，首页可回看原资料。
- 建议 id 使用不可猜测随机值。刷新后保留历史批次，因此已打开旧页面仍可派发；派发时只读取服务端保存的
  完整目标，客户端不能替换内容。生成和派发都确保目标带有用户价值验收契约，要求真实用户链路对比；因此
  升级期间已经保存的旧批次也不会绕过新规则。自动进化调度只轮换最近一批；尚未生成真实建议时明确跳过。
- `POST /api/ai/evolution/suggestions/refresh` 只访问共享数据库，继续走双 Gateway；云 Nginx 单独给它 330 秒
  读取超时并关闭写请求自动重放，与本地 Codex 五分钟等待窗口保持余量。

## 后果

- 首页建议来自当前系统已有真实资料，且可追溯、可换批、可进入既有任务—Runner—PR—部署闭环。
- 首次生成和换批会占用一个本地 Codex 问答槽位，最长等待时间与 AI 助手一致；本地 Codex 离线或真实资料
  没有任何可靠新线索时功能明确不可用，但不会伪造建议。
- 历史建议会随刷新增长。当前数据量很小；需要清理策略时必须保留正在展示或可能被旧页面派发的安全窗口。
