# ADR-127：共享聊天改用飞书自建应用完成双向消息桥接

## 状态

已接受（2026-08-26）。

## 上下文

ADR-126 的首版把 WAO 消息投递到系统默认 Webhook。Webhook 只有出站能力，目标隐含为系统通知群，
且消息只能表达成机器人卡片；调用结果没有可供引用、已读和表情关联的开放平台消息身份。因此继续在
Webhook 上叠加页面状态既不能选择真实群，也无法形成双向消息流。

仓库已经加密保存飞书自建应用凭据，并能列出机器人真实所在群、读取群消息、下载消息资源、发送消息和
添加表情。飞书官方事件还提供消息已读与表情新增/删除事实，具备不依赖演示数据的实现条件。

## 决策

- 共享聊天独立保存一个自建应用群目标，不改变群聊知识库归档的群。保存前必须用开放 API 验证该群确实在
  当前机器人所在群列表中；页面不再列 Webhook 或写死群名。
- WAO 消息仍先落 MySQL，再用自建应用发送普通 `post` 富文本；本地图片先上传为飞书消息图片。WAO 消息 id
  同时作为飞书发送 `uuid`，超时重试保持幂等，返回的 `message_id` 用于引用、已读和表情关联。
- 服务端每 15 秒读取目标群近两分钟消息作为事件订阅的兜底，并按飞书 `message_id` 唯一写入；每分钟回看
  近期消息同步编辑与撤回。应用自己发送的消息不作为新的入站成员消息，避免回声。
- 飞书未绑定 WAO 的真实成员仍以稳定外部 id 与飞书成员名称显示；不能安全换算身份时不猜测归属。
- WAO 页面阅读写入逐消息阅读事实。飞书只在收到官方 `im.message.message_read_v1` 回调时写入飞书阅读事实；
  未回调不推测已读人数。表情同理由官方 reaction 事件同步，WAO 主动表情先调用飞书成功再落本地。
- 回复保存 WAO 父消息 id；父消息已有飞书 id 时走飞书原生 reply API，飞书入站的 `parent_id` 反向关联 WAO。
  Markdown 原文仍是 WAO 权威正文，页面统一使用净化后的 Markdown 渲染。
- V99 起入站轮询间隔由共享聊天配置保存为秒，限制 5～3,600 秒；调度器每秒检查动态间隔。飞书 `post` 中多个图片节点按原顺序
  转存为同一条 WAO 消息正文，不再把首图拆进单图字段。界面密度与复盘入口由 ADR-129 增补。

## 后果

- 用户可以明确选择任一机器人真实所在群，WAO 与飞书普通聊天互相可见，并共享可验证的回复、已读和表情事实。
- 飞书已读与表情实时性依赖开放平台为 `/api/feishu/events` 订阅相应事件；普通消息即使未订阅事件也有 15 秒
  轮询兜底。事件 Verification Token / Encrypt Key 继续沿用现有加密配置和校验入口。
- Webhook 注册表继续服务系统通知，不再承担共享聊天消息投递；已保存但尚未选择群的 WAO 消息明确标记未同步。
