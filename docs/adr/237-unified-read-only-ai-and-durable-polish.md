# ADR-237：润色与卦象复用统一 AI 默认能力并持久化润色任务

## 状态

已采纳，补充 ADR-041、086、128。取代 ADR-041 中开发任务始终先于页面问答领取的规则。

## 问题

删除 API 配置后，文档和工作台润色虽然能回退 Codex，但同步 HTTP 最多等待五分钟；执行节点忙碌、登录失效或代理超时只能表现为失败，刷新也无法继续取结果。卦象默认仅选 Codex，与润色的 API 默认规则不一致。

## 决策

- 未显式指定能力的页面问答、卦象解读及后台只读分析共用润色现有默认规则：最新启用的模型网关 / DeepSeek API；没有 API 时使用 Codex 队列。显式选择保留，已入队任务冻结能力，不在供应商失败时静默切换。
- 新增 `POST /api/text-polish/jobs`，参数为 `requestId`（32 位小写十六进制幂等键）、`kind`（DOCUMENT / WORKSPACE）、`originalText`。响应立即返回 `id/status/message/polished/record`，统一使用 `ApiResponse`。文档上限 4000 字，工作台 12000 字。
- `GET /api/text-polish/jobs/{id}` 只查询当前成员的任务，状态为 QUEUED / RUNNING / SUCCEEDED / FAILED。入队与任务快照在同一事务落库；重试同一请求不生成第二次 AI 调用。工作台成功结果在查询时幂等写入既有历史。
- 新增 V156 表保存成员归属、原文、方法快照和 AI 运行引用；不保存认证信息。沿用只读队列的 60 分钟排队 / 30 分钟执行期限及清理，终态不会再交给 Runner。
- 前端轮询短请求。工作台按成员保存待查任务，编辑器按成员与来源保存冻结选区（24 小时有效）；刷新继续原任务。成员切换使旧请求失效；正文发生变化时仍禁止替换。网络错误继续查原任务；终态失败或主动重新润色才新建任务。
- Runner 在既有并发上限内优先分配一个只读槽位，不增加并发上限、不打断开发任务；单槽位时与开发任务交替领取，避免持续只读请求饿死开发任务。安全只读运行的执行节点心跳失联后可由其它节点重新领取，旧 claim token 不能覆盖新结果。
- 登录失效仅以确定错误信号识别，回传固定 `CODEX_AUTH_REQUIRED`；不回传 CLI 原始错误或凭据，不无效重试三次。

## 边界与验收

电脑在线不等于登录有效。本地登录文件只在对应机器使用；无可用登录或额度时不能承诺 AI 可用。验证覆盖幂等提交、成员隔离、网络中断恢复、终态重试、原文变更保护、默认路由和迟到回传。旧同步接口保留以兼容旧客户端；新前端不再调用。
