# Phase 1：复杂页面分区导航

对应任务：`t1788144689876`（页面体验优化）。

## 用户结果

1. 登录成员打开首页以外、包含至少三个明确功能区的页面时，桌面正文左侧展示悬浮“本页内容”清单。
2. 点击清单项平滑定位到对应真实功能区；滚动正文时，清单同步高亮当前所在分区。
3. 清单由页面显式提供稳定分区 id 与用户可读名称，不从任意标题猜测结构，避免把弹窗、卡片内小标题或隐藏内容误当作页面模块。
4. 分区随页面条件渲染或页内视图切换自动更新；少于三个分区时不占用正文宽度。
5. 1180px 及以下隐藏清单，保留原有紧凑正文与手机左栏，不让辅助导航遮挡主要操作。

## 首批范围

- 首页保留 AI 控制中心、自主目标、成长教练、AI 运行控制台及当前控制台内容的锚点数据，但不显示悬浮目录；首页顶部目录按钮会挤占主要内容空间。
- 应用壳统一承载分区发现、当前项计算和滚动行为；后续复杂 Tab 通过 `id` 与 `data-page-anchor` 接入，不复制交互代码。
- 不新增后端数据、演示模块或持久化状态。

## 验收

- 首页不显示悬浮目录；其他复杂页面展示六个锚点，点击“最近 AI 运行”后对应分区进入滚动区顶部附近。
- 滚动经过各分区时仅当前项带有 `aria-current="location"`；切换到执行电脑或项目工作流后，旧动态分区从清单消失，新分区出现。
- 只有两个分区的页面不显示清单；1180px、760px 与 390px 宽度不显示清单，原页面功能和内容宽度保持可用。
