# WAO 查询、调用与展示性能治理

## 目标与基线

在保持真实数据、现有权限、文档反链、草稿保护和统计口径的前提下，减少每次操作引发的数据库读取、写入往返、JSON 解析和浏览器更新。沿用现有技术栈与双节点部署，不以扩大硬件或长期缓存私有数据实现优化。

2026-09-19 基于 `61803f1a` 代码和既有线上数据库的只读检查：

- 未删除文档 173 篇，`blocks_json` 3,863,133 字节、`content_json` 239,577 字节、`content_markdown` 85,651 字节。文档心跳每 5 秒调用 `getDoc`，即使版本一致也先读取目标文档及全部未删除文档并构造反链。
- 请求监控表约 124 万行（`information_schema` 估算）；单批最多 100 条却逐条 INSERT。最近 24 小时聊天读取 31,477 次、任务读取 6,359 次；这些次数是用户端历史观测，不能直接等同于本次代码的服务器耗时。
- 首页 summary 读取全部运行、在线节点和本周完整任务/运行，在 Java 中计数；趋势和用量建议也读取无关正文、进度、提示词等宽字段。
- 全局任务/项目同步已经有隐藏暂停、串行执行及 15/30/60 秒退避，但合并列表逐项 `find`，未变化的嵌套数据仍重新赋值。统计页独立每 30 秒轮询，隐藏后仍请求六个接口，成功无变化或失败也重绘全部图表。
- 热路径已有文档删除/归档、任务项目/完成时间、运行状态/创建时间索引；本轮不增加未经执行计划验证的重复索引。

## Plan 与实施顺序

1. **文档协作与反链读取**：心跳仅查 `id/rev` 并校验未删除，版本变化才取完整 DTO；单篇读取与保存响应仅查询真正引用该文档的来源，排除自身和已删除来源。归档列表一次构建反链索引，目录操作仅查 id/文件夹。归档与活跃来源的原有可见范围不变。
2. **首页统计查询**：计数在 SQL 中完成；趋势、引擎计数、用量分析仅取所需字段。保留空日期桶、时区、未记账含义、任务创建时间历史估算与交付判定。不得将未回传 Token 计为已记账。
3. **高频写入**：浏览器监控先完整验证一批数据，再用一条参数化 INSERT 写入；空批无数据库调用，失败整批回滚。成员归属、原有监控字段、保留期和精确 P95 口径不变。
4. **浏览器同步与绘制**：列表按 id 建临时索引，实现线性匹配；仅赋值有变化字段，保持未变子对象引用和任务草稿保护。统计页复用可见性串行轮询，隐藏暂停、恢复立即更新；数据没变或请求失败时不重复绘图，主题变化继续重绘。工作区向保留的页面传递可见性，隐藏文档页签暂停心跳，返回时立即同步，可见悬浮窗口继续同步。
5. **证据与交付**：核心行为回归、前端完整测试/构建、服务端相称测试；同一真实数据库快照内比较结果、行数、字段字节与查询耗时，低并发执行，不向生产插入压测数据。尝试独立本地服务和真实浏览器链路，未完成项如实记录。检查最新 main 与 ADR/Flyway 语义冲突后，一个需求一个 PR 交付；合并后不等待发布。

## 设计边界与后续条件

- 此轮优先消除已证实的重复工作，不承诺每个接口都变快或整机 CPU 降低固定比例。
- 文档列表契约目前含完整正文；改成目录摘要、分页与按需正文会影响搜索、小记、关联与草稿恢复，需单独端到端迁移设计。当前优化单篇与心跳路径，不偷偷改变列表字段。
- 监控历史精确 P95 仍需读取窗口内样本；若管理页成为瓶颈，再依据真实执行计划设计保留精确分位数的分桶聚合。不能通过截断历史样本伪造性能改善。
- 不引入全局 GET 缓存或服务端业务缓存；失效与跨节点一致性未经验证时，先减少查询工作量。
- 索引、虚拟列表、资源拆包等候选仅在对应查询计划或浏览器剖析能证明瓶颈时推进，避免增加写入和维护成本。

## 验收标准

- 同版本心跳不读取文档正文、不查询反链；缺失/软删除文档保持 404，旧版本返回完整当前文档；协作者状态与本地草稿不被优化覆盖。
- 反链覆盖同源重复出链、自链、同 id 不同类型、归档来源与删除来源，真实数据与原实现结果一致。
- summary/趋势/引擎/用量结果与原逻辑一致，窄字段不包含正文、提示词、进度或能力 JSON。
- 监控 100 条上报仅一次 INSERT，校验失败无写入，空批无写入。
- 同步无变化时保留数组、项目/任务对象及嵌套数组引用；新建、删除、远端变化和未保存草稿语义保持；隐藏统计页不请求，返回可见只触发一轮，不堆叠慢请求。

测试维护补充：完整回归发现基线 `SkillConnectionsView.spec.ts` 仍断言旧文案，与已经采纳的“尚未开放授权”页面不符；只对齐两处断言，保留入口链接、没有输入框及没有授权按钮的检查，不改变功能页面。

技术依据：[MySQL JSON_CONTAINS 语义](https://dev.mysql.com/doc/refman/9.1/en/json-search-functions.html)、[Vue 更新稳定性建议](https://vuejs.org/guide/best-practices/performance)。实际收益以本项目测试与真实数据测量为准。
