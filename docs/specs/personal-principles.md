# 我的准则：浏览器版首期规格

设计参照：2026-09-26 高保真 Demo `wao-personal-principles-demo-20260926`。本规格以真实业务能力为准，演示数据不进入业务。

## 页面与交互

- 模块 id `personal-principles`，路由 `/personal-principles`，导航名“我的准则”。首页 `HomeDailyWorkspace` 前是一张约 136px 的“准则自留地”卡片，只放一条内容与入口。
- 独立页包含标题、真实统计、完整列表、全部/待关注/建议筛选和选中规则详情。新增或编辑从右侧抽屉完成；窄屏抽屉铺满宽度。卡片和按钮只做轻量 CSS 反馈，`prefers-reduced-motion` 取消位移。
- 类型：`RED_LINE` 红线、`MUST` 必做、`MORE` 多做、`LESS` 少做、`ALLOWED` 可以做、`AVOID` 暂不做、`ADVICE` 建议。建议只做参考。表单必填标题、类型、至少一位适用人、时机/场景、希望采取的动作。
- 成员来自 `/api/members`，多选和全选只取当前目录。发起人可为本人制定，也可邀请别人。被邀请者看到规则后自行接受或拒绝；撤回后不再记录。每人只读取自己的当日记录。
- 编辑草稿按当前成员和规则 id 保存在当前浏览器；失败保留内容。提交期间禁重复写入；版本过期返回 409，需刷新核对。加载、失败重试、筛选无结果与首次空状态都有明确反馈。

## API

前缀 `/api/personal-principles`，响应 `ApiResponse<T>`。

| 方法 | 路径 | 行为 |
|---|---|---|
| GET | `/` | 当前成员自建或受邀准则；`date` 可选，默认上海今天；只附自己的记录 |
| POST | `/` | 创建规则及适用成员邀请；本人目标自动接受 |
| PUT | `/{id}` | 发起人带 `version` 编辑；保留版本快照，冲突 409 |
| PUT | `/{id}/consent` | 适用成员本人接受或撤回 |
| PUT | `/{id}/checkins/{date}` | 已接受的本人记录：`DONE/NEEDS_WORK/EXCEPTION`，限最近 30 天 |
| GET | `/{id}/revisions` | 发起人或当前适用人查看规则历史文本，不包含他人的记录 |

规则来源 `MANUAL` 支持本人手动记录；`SCREEN_TIME` 仅表示希望将来接入，当前显示待数据，不触发自动判断。准则时间 `reminderTime` 是站内动态待记录提示依据；本期没有后台定时推送或外部消息发送。没到时间显示待判断，到了时间仍未记录显示待本人记录。本人提交 `DONE` 为已完成，`NEEDS_WORK` 为本人反馈需调整，`EXCEPTION` 为例外。暂停、未接受、建议有独立状态。

## 权限与隐私

- 成员身份由会话决定，不接受前端指定当前成员。所有规则读写操作以服务端身份校验；只有发起人修改规则，只有目标成员调整自己的确认和记录。
- 规则文本和目标确认状态为参与者可见；每日记录、备注仅记录者本人可见。移出目标后不再能读规则详情和历史，但历史事实保留。
- 不读取浏览内容、系统应用列表、设备在线时间、Runner 心跳或 AI 后台运行来推断个人行为。首页不会出现未被事实支持的违规结论。

## 验收重点

- 两个真实成员分别登录：创建多选规则、目标独立确认/撤回、本人记录和私有备注隔离。
- 全选后新增成员不自动加入；更新目标不覆盖既有确认。旧 `version` 编辑返回 409 且草稿仍在。
- 手动记录之前只显示待判断/待记录；选屏幕时间来源仍显示待数据。建议不计数为待记录或偏离。
- 检查 390px 页面、减少动态效果、加载和点击响应。
