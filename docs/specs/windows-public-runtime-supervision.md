# Windows 公网运行态独立守护

日期：2026-10-07。

## 问题与边界

当前公共入口的静态文件在云端，API 经云端 loopback 转发到 Windows 的网关与本机开发数据库。该实际运行态不能表述为 ADR-291 的 Linux2 生产数据库已经恢复。2026-10-06 的故障现场是云端 API 502、本机服务和守护进程缺失，主机没有重启记录。旧守护程序只能恢复子进程；守护本身没有任务计划或服务托管。

## 行为

- 使用当前用户、普通权限的 Windows 任务计划运行守护程序；不保存密码、不增加账号或网络权限。
- 登录时和每分钟触发，重复实例忽略；任务没有执行时限，失败后一分钟重试。关闭 Codex 不终止该任务。
- 本轮使用交互登录令牌。退出 Windows 登录、主机关机或网络中断仍可能中断 API；不能声称已解决无人登录启动或独立 Linux 部署。
- 守护采用独占文件锁，同一运行目录只有一个实例。仅接管记录的 PID、精确启动时间、预期进程名称和启动脚本均匹配的组件；不能因 PID 重用而接管其他进程。
- 保留存活组件，缺失组件才启动。端口被非已登记进程占用时记录阻塞，不结束该进程，不启动数据库副本。
- MySQL 只复用原 launcher 和已初始化目录；不初始化、重置、迁移、导入或删除数据库。
- 后端、网关或 relay 退出后自动重启；启动失败保留诊断并退避。健康失败只记录降级，不根据一次 HTTP 失败杀死服务。
- 生命周期以 JSONL 记录启动、接管、退出、失败及暂停，日志不包含命令参数、环境变量或响应正文。
- 暂停文件使任务退出且后续触发保持暂停；显式恢复移除暂停文件并启动原任务。暂停守护不结束业务进程。

## 验收

先在独立的临时目录用无业务连接的组件完成锁、PID 校验、已有进程接管、组件退出恢复、端口冲突与暂停验证。真实交接只停止旧守护 PID，保留数据库、后端、网关及转发，再由系统任务接管；核对组件 PID 不变、公网就绪、版本及已登录首页真实数据。故障恢复实验不终止生产数据库或中断用户输入。
