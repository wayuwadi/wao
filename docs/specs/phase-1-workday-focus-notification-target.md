# Phase 1：今日重点就地选择通知群

对应任务：`t1787673298214`。既有群承诺链路见 [ADR-117](../adr/117-workday-focus-commitment-loop.md)，本次交互决策见
[ADR-120](../adr/120-inline-workday-focus-notification-target.md)。

## 用户结果

1. 「今日三个重点」保存按钮左侧直接展示当前通知状态；成员无需进入完整节奏设置即可确认会发到哪个群。
2. 点击紧凑入口可选择系统设置中已启用的 Webhook、飞书应用真实所在群，或明确选择不发送群通知。
3. 选择后先保存到当前成员的跨设备偏好；保存完成前不可提交今日重点，避免界面显示新群但服务端仍向旧群发送。
4. 目标读取或保存失败时保留原配置并展示真实错误，不回落到系统默认群，也不伪造可用群。
5. 选择器作为独立组件保留，后续需要用户指定通知群的页面可复用同一交互和真实目标视图。

## 数据与安全边界

- 继续复用 `workday-rhythm-config-v1.energyNotification`，不新增目标副本、数据库字段或浏览器侧凭据。
- Webhook 只返回稳定配置 id、名称、脱敏地址状态；飞书应用群聊只返回机器人真实所在群。Webhook 明文和应用密钥仍只在服务端使用。
- 发送接口仍只接收日期，服务端按当前会话重读成员偏好和当日重点；前端选择结果不能直接指定一次发送的目标。
- “不发送群通知”关闭 `notifyFocus`，不影响成员已为精力补给项目配置的通知。

## 验收

- 未启用今日重点通知时入口明确显示“不发群”，保存重点只落库、不调用通知接口。
- 从入口选择任一真实群后，先保存包含稳定目标 id 的成员偏好，再允许保存三项重点并由服务端发送。
- 切换群、选择不发送、列表加载失败和偏好保存失败均不丢今日重点草稿，不静默改变既有通知目标。
- 390px 窄屏可打开选择器、浏览目标并完成选择和保存，业务区不产生横向滚动。
