# 小记 AI 伴读

用户确认「安静伴读」方案：左上记录、左下伴读、右侧小记空间。桌面保留分栏拖拽，手机按记录、伴读、小记顺序显示；成果区域独立滚动，不挤占正文。复用现有四项整理、原稿快照、私人会话和顺手发现，不恢复 Runner。

阅读模式中的 AI 伴读作为独立浮层打开，正文仍保持目录、文字、图片三列；返回不退出阅读。手机面板全屏打开，返回保留问题、记录草稿和当前位置。

## 状态和持久化

新增 note_ai_artifact 保存每次真实模型产物、不可变来源、结果、来源摘要、采用和阅读状态。执行来自 note_ai_stage_attempt / ai_assistant_run；生成成功不等于采用。当前、过期、取消与失败分别展示。只有打开对照才记录 seen_at。来源未知的历史任务只展示状态，不能伪造原稿或成果。默认保持自动采用，成员可显式选择「先看建议」，策略在创建 attempt 时固定。关闭页面后继续执行，不依赖浏览器计时器。

正文建议采用服务端来源校验、文档 CAS、资源引用保留检查；富文本只在可无损映射的段落上更新，不可无损映射时保留建议。标题、标签、图片独立应用；标签只能选择已有标签且合并人工标签。恢复只回退该产物改变的字段，其他修改保留；当前字段不再等于该成果时拒绝恢复。取消持久化后立即阻止发布，专属进程收到取消信号，实际停止后收尾，不终止共用 worker。

来源与真实成功任务均可验证的旧成果在读取时幂等归档，时间沿用实际完成时间；当前字段仍等于结果时才能恢复。已经改变的历史成果只读，缺少原稿或真实结果的历史任务不补造产物。恢复正文同时移除旧阅读润色投影并清理页面缓存，原稿和不可变成果仍在。无需修改为正常终态，不计未读；数字或富文本结构无法安全保持时转为需要对照采用，禁止丢弃原资源。

## HTTP

所有接口仅会话成员本人，历史不可随当前文档共享。GET /api/docs/notes/ai-companion 返回执行器真实就绪、队列与成员策略、未读数量；PUT /ai-companion/preference 使用版本 CAS。GET /{docId}/ai-results 使用游标分页；POST /ai-artifacts/{id}/{apply|restore|decline|seen} 采用 expectedRev；POST /{docId}/ai-cancel 取消当前篇尚未完成阶段；GET /ai-receipts 给出未读成果和需处理状态。

私人对话绑定成员、文档、版本与明确选择的来源。GET/POST /{docId}/ai-conversation 查询/发消息，每次从服务端读取真实来源、验证权限和版本，默认只有当前已保存小记，未保存草稿不自动进入。POST 请求携带 requestId，幂等且不得复用不同输入。回答不得扩展成全库检索，数字与引用需可追溯；仅接受返回的来源标记，正文变化后保留历史并提示来源更新。答案转新小记或任务草稿需要显式点击与确认，无默认提醒或日期。

对话最多额外绑定五篇本人小记，总材料限制 24000 字符。每个回答必须返回来源编号与连续逐字引文；服务端校验编号、引用文本、权限及修订号后才发表。逐字引用不能证明全部语义正确，仍提供原文定位供核对。每轮保存自己的来源集合，改变范围不混用旧会话材料；撤权、删除或归档来源后不能通过私人历史泄露内容。问题与待确认请求号在成员、文档隔离的本机草稿中保护，响应不明时沿用幂等号重试。

POST /ai-transfer 校验真实本人 assistant 消息，将用户确认并可继续编辑的回答草稿保存成新小记，或通过 expectedRev 写入原小记。派生身份随草稿恢复，服务端使用 AI_DERIVED 来源，初次派生记录不建立独立用户事实依据；不自动再次启动四项整理。待办只进入已有任务编辑草稿，保存由用户确认。仅持有普通文档令牌不能读取或调用私人伴读接口。

顺手发现复用 opt-in 偏好、来源校验和反馈；关闭、不可用、等待、分析、无合格结果、失败各自呈现，显示实际索引覆盖范围与数目。候选不足允许零结果，不把零结果当质量成功。不改变现有预算、稳定时间、去重及权限。

共享单执行器优先处理主动任务，等待超过十分钟的发现任务进入 FIFO 优先级，避免长期饥饿。执行记录显示真实排队、开始和完成时间；没有完成时间不估算进度。发现全局基础设施就绪不等于成员已开启，升级保留默认关闭及本人偏好。

新 API 不隐式扩展旧 MCP 令牌；CLI 能力台账记录这些交互接口由浏览器管理，现有创建小记/任务命令保持不变。合成验收内容明确标识，仅精确清理本轮记录，不修改已有用户输入。
