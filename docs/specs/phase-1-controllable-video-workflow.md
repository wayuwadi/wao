# Phase 1：可控的 WAO 功能介绍视频工作流

决策见 [ADR-125](../adr/125-browser-rendered-video-workflow.md)。视频生成供应商边界继续遵循
[ADR-074](../adr/074-retire-api-key-video-generation.md)。

## 用户结果

成员从 WAO 内嵌的“自媒体 Agent → 视频工作流”打开一份约三分钟的 WAO 功能介绍分镜，逐镜调整后，
在浏览器内真实合成、预览并下载 WebM。工作流不要求平台 API Key，不展示伪造的 AI 配音、生成画面或进度。

## 用户链路

1. 首次进入自动创建一份 180 秒、覆盖 WAO 当前主要能力的真实分镜；再次进入读取服务端草稿。
2. 页面把流程明确分为“整理分镜 → 逐镜审核 → 合成导出”，每个镜头可启停、排序、改标题/字幕/时长/主题色。
3. 编辑后显示未保存状态，并在短暂停顿后自动保存；保存中、已保存、失败重试和版本冲突都有反馈。
4. 预览只播放当前镜头，不产生文件；正式合成按启用镜头的真实总时长运行，页面展示当前镜头、剩余时间与进度，
   并允许取消。
5. 编码成功后先得到浏览器本地 Blob，再上传 Linux 主节点的 Agent 媒体卷；只有上传和项目关联均成功才显示
   “已导出”。
6. 刷新后可播放、下载上次真实导出的视频；修改分镜后旧成片仍保留为媒体资产，但项目回到“草稿待导出”。

## 数据与接口

- 新增 `agent_video_project`，按 Agent 工作区保存标题、分镜 JSON、版本、导出媒体标识和时间。
- 已执行的 `agent_video_generation` 历史表不修改、不复用。
- 所有 JSON 响应使用 `ApiResponse<T>`，且要求有效 `WAO_SESSION`。

| 方法 | 路径 | 行为 |
| --- | --- | --- |
| `GET` | `/api/agent/video-workflow` | 读取或初始化当前工作区的视频项目 |
| `POST` | `/api/agent/video-workflow` | 按版本保存标题与完整分镜 |
| `POST` | `/api/agent/video-workflow/media` | 上传浏览器真实合成的 WebM |
| `POST` | `/api/agent/video-workflow/export` | 校验媒体后关联项目并标记已导出 |
| `GET` | `/api/agent/video-workflow/output` | 按当前工作区鉴权播放或下载成片，支持单段 Range |

## 状态与约束

- 项目状态只有 `DRAFT`、`EXPORTED`；浏览器合成进度不伪装成服务端后台任务，刷新或关闭页面即中断。
- 分镜为 3 至 12 个；单镜 5 至 60 秒；启用分镜总时长为 30 至 600 秒。
- 标题、字幕和主题色由后端做长度与格式校验。旧版本保存返回 409，不能覆盖新稿。
- 只接受浏览器产生的 `video/webm` 输出；上传限制延续 Agent 媒体上限。
- `/api/agent/video-workflow/**` 固定到 Linux 主节点，上传请求关闭 Nginx 缓冲且不自动重放。
- 合成使用本地确定性信息图、字幕与原创程序化轻音乐；没有可靠来源时不增加 AI 配音或自动屏幕录制。

## 验收标准

- 未登录访问返回 401；不同工作区不能读写项目或成片。
- 默认分镜启用时精确为 180 秒，文案只陈述仓库已有的 WAO 功能。
- 启停、排序、编辑后保存并刷新不丢失；旧 version 被拒绝。
- 不支持 MediaRecorder 时禁用合成并说明原因；取消、编码失败和上传失败保留草稿并可重试。
- 成功合成后产生非空 `video/webm`，服务端关联真实媒体，站内播放和下载返回相同字节并支持 Range。
- 合并后 `/agent/` 出现“视频工作流”，API 响应带 `X-WAO-API-Route: linux-master-video-workflow`。
