# Phase 1：iOS 主屏幕应用壳

> 本规格已取消。任务 `t17866728549710` 明确要求原生 iOS，不接受主屏幕 Web App；后续验收以
> `phase-1-native-ios-client.md` 为准。

对应任务：`t17866681718350`（iOS 版本）。本规格在现有移动端页面和真实业务 API 上增加可随主站发布的
iOS 应用入口；页面布局继续遵循 `phase-1-mobile-navigation-resilience.md`、
`phase-1-task-groups-and-mobile.md` 与 `phase-1-task-links-and-mobile-polish.md`。

## 用户路径

1. 用户在 iPhone 或 iPad 浏览器登录 WAO 后看到一次轻量安装说明；展开后明确引导使用“分享 → 添加到主屏幕”。
2. 从主屏幕图标启动时，WAO 使用独立窗口、自己的名称与图标，并完整适配顶部和底部安全区。
3. 首期重点能力全部复用线上真实数据：项目与任务、AI 派发与运行控制台、自动化。手机底部导航提供稳定的
   “AI”直达入口，直接定位到自主目标输入区；应用清单也为这三处声明快捷入口。
4. 知识库、日历、文件等既有模块继续出现在移动端应用导航中，作为后续扩展入口；不新增空页面、样例数据
   或无法操作的原生占位能力。

## 规则

- 应用清单必须声明 `standalone`、WAO 品牌色、192 / 512 图标及中文名称；`index.html` 同步声明 Apple
  主屏幕应用元信息和 `viewport-fit=cover`。
- iPadOS 桌面 UA 需要通过触控能力识别。已经在独立窗口中运行时不再显示安装引导；用户关闭引导后，
  当前版本不重复打扰。
- 不缓存登录页、业务接口或私有数据。WAO 的项目和 AI 状态依赖服务端实时结果，断网时沿用现有明确失败与
  重试状态，不能用旧缓存伪装成最新数据。
- 本阶段不产出无法签名、无法安装验证的 IPA；原生分发条件与后续演进见 ADR-069。

## 验收

- iPhone / iPad 浏览器打开已登录 WAO，可以看到安装方法；展开后能看到“添加到主屏幕”的完整步骤。
- 添加后从主屏幕进入，浏览器地址栏不出现，应用名称为 WAO，图标和主题色正确。
- `/projects`、`/?console=runs#ai-launcher`、`/automation` 均可直接打开；项目、AI 运行和自动化数据来自
  现有生产接口，登录保护保持不变。
- 独立窗口内不再出现安装提示；项目新建、AI 派发、底部导航和安全区行为不回退。
