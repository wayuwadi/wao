# Phase 1：三端内容生成与手机预览

对应任务：`t1788825250718`（按标题和参考内容生成抖音、小红书、公众号成稿）。

## 用户结果

- 成员进入「自媒体 Agent → 内容工作台」，输入创作标题和可选内容参考后，一次创建抖音、小红书、公众号三份真实 AI 生成任务。
- 三份任务共享本次标题、参考内容和经过当前成员权限收窄的 WAO 上下文快照，但分别使用既有平台提示词，产出口播脚本、小红书笔记和公众号长文。
- 编辑区与右侧手机屏幕同时出现；手机上固定提供抖音、小红书、公众号标签，切换标签即切换同组草稿，当前编辑内容立即反映到对应预览。
- 历史单平台创建、人工草稿、审核、素材、导出和发布状态机继续可用，不把生成完成等同于发布成功。

## 数据与失败边界

- 三端创建由一个事务完成，共享服务端生成的 `contentGroupId`；任一任务无法落库时整组回滚，不留下半组内容。
- 创建前必须确认真实推荐模型可用；不可用时保留页面标题和参考内容并显示错误，不生成示例文案或空白三端草稿。
- 模型调用仍由既有生成队列逐条执行。某一平台失败不覆盖其他平台已完成内容，失败标签显示真实状态，并沿用该任务的一键重试。
- 小红书和公众号没有当前环境已接通的官方发布能力时，只支持成稿、导出和人工发布确认，不伪造平台回执。

## 验收

- 一次请求返回同一 `contentGroupId` 下的三条 `GENERATING` 任务，平台依次覆盖抖音、小红书和公众号，各自固化不同平台约束。
- 页面轮询完成后，右侧三个标签展示各自标题、正文、标签；抖音额外展示口播分段，切换标签后左侧进入对应审核稿。
- 修改当前标题或正文时手机预览即时变化；有未保存修改时切换平台仍触发既有防丢确认。
- Agent 后端测试、Agent 前端单元测试、类型检查和生产构建通过；线上真实推荐模型完成三份成稿且刷新后仍存在。
