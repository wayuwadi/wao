# 飞行中继续输入后的草稿版本持久化

## 问题

用户输入第一版并发出保存请求，在响应回来前继续输入第二版。第一版成功后，内存中的第二版草稿会采用服务器新版本号继续保存，但浏览器持久化草稿仍可能保留旧基础版本。若第二次保存失败后刷新，页面会误以为其他窗口修改了服务器，要求用户处理并不存在的协同冲突。

## 预期

- 第一版响应只能确认第一版已经保存，第二版正文保持完整。
- 第一版成功后，第二版草稿的新基础版本同步保存到 localStorage 和 IndexedDB，随后再安排补交。
- 补交失败后刷新，恢复第二版正文，并基于第一版已确认的版本重试；不显示虚假冲突。
- 如果其他窗口确实又更新了服务器，仍保持冲突保护，不自动覆盖。
- 不修改 API、数据表或实际版本冲突策略；本地存储失败沿用现有提示和草稿保护。

## 验收

用可控异步请求复现“第一版成功、第二版失败、刷新恢复”；分别验证 localStorage 与 IndexedDB 恢复路径，再验证真实的其他窗口更新仍被拦住。真实浏览器使用专用验收文档、延迟第一版响应并使补交失败，刷新后应保留最新输入且无虚假冲突。
