# 规格：移动端应用壳导航与安全区修复

> 状态说明：本规格的“底部导航”应用壳规则已由
> [手机高密度桌面同构应用壳](phase-1-mobile-dense-desktop-shell.md) 取代；完整菜单可见、当前入口跟随和安全区目标继续有效。

对应任务：`t1786662178915`（移动端显示有问题）。本规格收敛到跨页面的应用壳问题；各业务页既有的
移动端布局继续遵循 `phase-1-task-groups-and-mobile.md` 与

## 背景

桌面侧栏允许折叠「公共」「个人」「工具」分组，状态保存在浏览器本地。手机端把同一份导航改成底部横向栏，
但隐藏了分组标题和展开按钮：如果用户曾在桌面折叠分组，对应模块在手机上会直接消失，且没有恢复入口。
当可见模块超过一屏时，从地址、收藏或页面内跳到后半段模块，底部导航仍停在开头，当前入口也不可见。

应用壳已经使用 `safe-area-inset-bottom` 计算导航高度，但主页面没有声明 `viewport-fit=cover`，内容区也只预留
固定 64px，刘海屏和底部手势区的安全区计算没有形成完整链路。

## 规则

- 桌面端继续记忆并应用分组折叠状态；手机宽度（`max-width: 760px`）下忽略分组折叠状态，展示所有服务端
  配置为可见的模块。手机端不修改已保存的桌面偏好。
- 手机底部导航可横向浏览。路由或菜单配置变化后，当前模块入口自动滚动到导航可见区域的中间附近；用户
  仍可手动横向滚动，不强制回到导航开头。
- 主站 viewport 启用 `viewport-fit=cover`。手机内容区底部同时预留 64px 导航高度与
  `safe-area-inset-bottom`，最后一段内容不能被底部导航或系统手势区遮住。
- 桌面布局、菜单排序、隐藏配置与外部应用注册表行为不变。

## 验收

- 先在桌面折叠「个人」和「工具」，再以手机宽度打开，待办、日历、密码本、自动化、文件与游戏厅等可见
  模块仍全部出现在底部导航。
- 在 390px 宽度直接进入游戏厅或其它靠后的模块，当前入口自动进入可见区域并保持选中态。
- 在带底部安全区的移动设备上，底部导航、悬浮入口和页面最后一段内容均位于系统手势区上方。
- 桌面重新打开时，之前的分组折叠状态仍然生效。
