# 四象限按主任务层级展示

2026-10-20 用户纠正项目四象限展示方式，2026-11-02 将同一规则统一到项目、待办、原待办和按天工作区。本规格取代四象限按子项优先级独立分布的规则。

- 一个顶层主任务与所有可见后代组成连续层级，整个层级按顶层主任务优先级进入同一象限。普通子事项、嵌套子事项和完整下级任务一致处理。
- 子项紧跟父项并逐层缩进；项目与汇总待办的象限数量统计顶层主任务，按天工作区保留当天记录件数。保留显示子任务、显示已完成、完成与详情操作。
- 筛选仅命中后代、或已完成父项仍有可见后代时，补回祖先作为层级上下文。缺失父级按现有可见根节点处理。
- 只在根任务行提供移动象限和拖拽。根任务跨象限移动时后代跟随展示，不批量重写子项优先级、不更改父子关系；子项详情中的独立属性保留。
- 按天工作区只展示当天记录中的任务，沿授权任务的祖先确定象限；主任务不在当天记录时也不另造记录。历史标题、状态和进展沿用当日快照，归类使用现有主任务优先级。无 API、数据库、MCP 或 CLI 能力变更。

验收：两类子项及多层级连续顺序、根优先级分区、根移动、筛选祖先、完成过滤、显示开关、保存失败重试和既有待办四象限回归。

自定义项目、标签、日期或优先级条件同样保持父子连续：优先级条件按最上层主任务匹配，其他条件按工作项匹配；命中后展示当前候选范围内的整组父子项，并补回祖先上下文，数量按根任务组计。自定义规则可让整组出现在多个象限；启用后关闭跨象限拖动，恢复默认后可在根任务调整。详见 [任务标签与待办工作台](task-workspace-labels-2026-10-29.md)。
