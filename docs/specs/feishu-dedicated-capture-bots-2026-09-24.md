# 飞书群专用待办与小记机器人

## 用户路径

在已配置的目标飞书群里，成员 @ 群自定义机器人「任务待办」发送文字，WAO 将正文记为该成员的待办；默认项目沿用快速收集配置（未指定时为「Wa All in One」）。@「小记创作」发送文字，WAO 在该成员的小记文件夹创建小记，首行作为标题，全文作为正文。两者都保留原消息去重、编辑更新、撤回删除和原消息表情回执；未绑定飞书身份的发言人不创建内容。

这两个机器人是群自定义 Webhook 机器人，不能作为接收消息的应用。WAO 仍通过现有已授权飞书应用读取目标群消息，按飞书返回的结构化 @ 名称精确分流；普通聊天、@ 其他对象、机器人自己发出的消息均不创建内容。同一消息同时 @ 两个专用机器人时不猜落点，也不创建内容。旧 WAO 应用机器人的任务收集入口继续保留。

## 接入与验收

- 群消息轮询不依赖旧应用的 Bot Info 成功才能处理两个专用机器人。Bot Info 失败时一小时后再试，避免每分钟重复消耗调用量；读取群消息本身仍需要飞书 API 额度。
- 飞书事件订阅仍只适用于已有自建应用，群自定义 Webhook 机器人不能单独配置事件回调。相同消息由轮询和现有回调同时看到时以 `message_id` 去重。
- 小记使用原消息派生的稳定文档 ID，重试不会产生第二篇；消息编辑更新原篇，撤回只删除事件记录关联的小记。
- 接收表情是确认 WAO 收下消息，不表示小记进入任务 AI Run；小记记录不会被任务表情派工查询命中。
- 实机验收需用已绑定的娃哥账号分别 @ 两个机器人，核对 WAO 项目待办、小记作者和正文、重复轮询后的数量，以及原消息回执。若飞书返回 `429 / 99991403`（租户本月 API 调用额度耗尽），真实群消息读取与验收须待额度恢复；更换群自定义机器人不会增加租户 API 额度。

本次只扩展飞书群消息入口，WAO 既有任务与小记写入能力不改变。CLI/MCP 不增加“模拟飞书 @”命令：该操作必须来自飞书授权群的真实消息与身份，不能让普通工作区令牌伪造来源；普通任务创建已有 CLI 命令，小记入口仍按现有知识库权限边界评估。
