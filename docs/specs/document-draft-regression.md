# 文档草稿防丢回归包

## 目标与范围

把文档编辑器已有的保存、失败重试、刷新恢复、页签保留和版本冲突保护变成可以重复执行的验收资产。复用真实本地应用、现有登录会话及既有数据库，不伪造业务接口成功响应，不引入生产测试入口。

## 工具

- 独立 Vite 验收入口只监听 `127.0.0.1`，代理至明确指定的本地业务服务；关闭 Vue DevTools。
- 故障配置放在仓库外的临时目录。仅拦截明确文档 ID 的 PATCH 保存；GET、其他文档和业务接口正常透传。失败时返回明确的验收原因；延迟模式只延迟转发，用于观察保存中状态。
- 浏览器回归函数使用调用方提供的浏览器页签，不读取 Cookie、密码或应用内部状态。通过真实控件编辑和断言，通过刷新验证服务端持久化。
- 每轮新建带唯一验收前缀的文档。成功后只把本轮创建的文档移入回收站；失败时保留文档与现场，清除故障开关。绝不清空回收站或批量清理历史数据。
- 独立验收入口将文档删除的原生确认替换为页面内确认，只允许临时登记的两篇文档精确 ID / 标题，登记十分钟失效。仍调用既有应用软删除链路。适配器只在该 Vite 入口加载，普通开发与生产构建不加载；目标源码变化时停止，禁止广泛替换确认逻辑。
- 截图与报告存储在仓库外，避免把页面中的私有信息提交到 Git。报告区分自动化单测与真实链路结果。

## 验收场景

1. 新建专用文档，输入标题和正文，观察保存中、自动保存成功，刷新后内容保持。
2. 仅令该文档保存失败，保留错误原因和重试入口；刷新后仍保留草稿，恢复请求后重试成功，再刷新确认。
3. 保存失败期间切换应用页签，再返回原文档，正文保持。
4. 在另一个独立源页面保存另一版；原页面恢复后保留本机草稿并出现版本冲突，另存副本后两版均可刷新读取。
5. 单测补充覆盖请求未返回时继续输入、协同更新不得覆盖本地输入、成功后清理本机草稿及失败后保留。

本工具不接入 PR 或 Jenkins 重复门禁，不触发发布后验收。每次执行明确指定专用验收知识库；未配置或未登录时直接报告缺项。
