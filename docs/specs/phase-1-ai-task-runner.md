# Phase 1：任务驱动的 AI Run

## 用户路径

0. 用户也可在首页 AI 控制台只写一句目标，选择已启用的项目工作流和本次执行电脑；系统自动
   生成带自主执行约定的任务并立即入队，不要求用户先手工拆任务。
1. 项目管理员在首页 AI 控制台的「AI 工作流」视图（或项目设置 → AI Run）填写 Git 仓库、
   默认分支、本机工程文件夹、默认 AI 工具，设置项目并发数和固定电脑后开启开关。
2. 新电脑在控制台「执行电脑」视图点击“生成配对码”，按 `deploy/ai-runner/README.md` 启动
   Runner；配对码十分钟有效且只能使用一次。Runner 自己声明本机装了哪些 AI CLI。
3. 单个任务在详情页点击“AI run”，在弹出的面板里选 AI 工具、集中账号和执行电脑（默认取项目配置；
   账号留空时使用执行电脑本地登录态）后开始；
   多个任务在项目列表勾选后批量点击，走项目默认配置。
4. 首页立即显示排队/运行数量、每种 AI 工具的在线电脑数与槽位。运行卡片持续显示最近一条 AI
   反馈、使用的工具和更新时间，点击先查看实时执行记录，再按需进入对应任务。
5. Runner 自动准备 worktree、调用对应 AI CLI 并流式回传用户可读摘要；成功后任务进入“待验证”。
6. 每次运行的摘要时间线永久关联到任务详情，完成后仍可回看 AI 做了什么、结论和失败原因。
   分析、调研、方案、决策依据或验收证据还可产出持久化单文件 HTML 报告，任务档案与首页运行详情
   直接提供查看、分享入口；普通小改动不强制生成占位报告。
   数据仪表盘按运行创建日期展示每日使用频次，并汇总 CLI 真实回传的输入、输出、缓存与总 Token；
   未回传用量的运行单独计入运行频次和记账覆盖数，不得当作零消耗。
7. AI 因缺少信息而阻塞时，用户可在该次运行中补充输入；系统必须固定派回保存该 worktree 的原电脑，
   用原 AI CLI 会话继续执行，无法恢复时明确提示使用「基于报错重跑」。
8. 跑完但不符合预期时，同一个入口可以继续给提示词让 AI 基于这一版迭代（按钮显示「继续优化」），
   不必新建任务把需求重述一遍。
9. 子任务可以单独交给 AI：子任务行上的「AI run」只跑这一条，主任务派工时已完成和已单独派过工的
   子任务都不会再进入范围。
10. 不再使用的电脑由管理员在「执行电脑」视图的卡片上解除接入：确认后节点记录连同令牌一起删除，
    那台电脑上的 Runner 下一次心跳就会发现自己已被解除，删掉本机令牌后自行退出。
11. 全局 AI 助手把问答写入短期队列，由任一在线本地 Codex Runner 的空闲槽位以只读沙箱回答；
    开发任务优先领取。成员的会话和消息单独持久化，宽屏聊天工作台左侧提供历史搜索、切换和删除；页面明确
    显示节点在线、等待、失败与重试状态。回答可以统一检索群聊、知识库、项目和 Task 并提供可追溯来源；
    群聊支持按群、发言人和归档日期范围筛选，不再依赖单独的 Chat Completions Key。
12. 首页展示已启用 Codex 集中账号的真实五小时会话剩余值，以及 Codex / Claude 集中账号的真实七天
    额度剩余值，并从知识库与飞书同步归档中挖掘五条
    带来源的可执行任务建议；用户不满意时可刷新换一批，首次无批次时自动生成。
    用户可设置连续多少小时没有 AI 任务后触发检查（默认 12 小时、范围 1 到 168 小时），以及单次为
    WAO 自身工作流轮换派发多少项建议（默认 1 项、范围 1 到 5 项）；触发时仍要求真实周剩余额度高于 50%；
    候选和自动任务只选择用户可直接感知的功能、操作提效或体验改善，不把纯测试、纯文档或纯技术优化
    作为主要结果；与人工派工使用同一套任务、Runner、PR、部署和飞书通知链路。

## 验收标准

- 自主目标入口只列出已启用的项目工作流，执行电脑只列出支持该工作流默认 AI 工具的真实节点，
  默认选择项目首选电脑，也允许本次改选其它兼容电脑或自动分配；离线电脑仍可选择并明确提示任务会排队等待。
  提交后在一个事务内创建任务和 AI Run，
  项目未配置、无可用执行节点或入队失败时不留下半成品任务。任务保留用户原始目标，
  并明确要求 AI 先盘点现有资源、自行拆解、完成可安全执行的工作、只在关键阻塞时求助。
- 自主目标输入与任务描述使用同一套 Markdown 编辑器和图床：可粘贴、拖入或选择一张及多张图片，
  多图并行上传后按用户选择的原顺序内联；上传未结束时不得提前派发不完整目标。剪贴板只提供
  Base64 图片 HTML 时也必须转为真实图片上传，不得把数万字编码塞进目标正文。目标文字不设 4000 字
  人为上限，长 Markdown 完整保存到任务描述。
- 项目未开启或未填写仓库时，入队返回可理解的 400 错误，不生成半条运行记录。
- 选中的 AI 工具没有任何电脑接入，或指定的电脑没装这种工具时，入队返回可理解的 400，
  不生成半条运行记录。
- 节点只领取自己装了对应 CLI 的运行；单次指定了电脑时，只有那台电脑能领，它离线则继续排队。
- AI 助手来源选项来自真实配置和业务数据；日期范围必须在查询候选前生效，发言人筛选后不得把其他人的
  消息正文交给 Codex。知识库、项目和 Task 的引用可以回到对应 WAO 页面；密钥库和系统凭据不得进入资产层。
- 控制台三个视图（运行状态 / 执行电脑 / AI 工作流）覆盖原本分散在首页和项目设置里的信息：
  电脑卡片展示平台、接入的 AI 工具、槽位占用、心跳和正在跑的任务；工作流卡片可就地编辑
  仓库、分支、目录、默认 AI 工具、固定电脑与并发，并展示进行中/成功/失败统计。已保存的工作流
  可以在二次确认后删除配置，历史运行记录保留；项目已经删除的孤儿配置必须明确标记并允许清理，
  还有 queued/claimed/running 运行时拒绝删除。
- 电脑卡片可以解除接入：解除前有二次确认；这台电脑还有 claimed/running 的运行时拒绝解除并说明
  原因（先取消或等它跑完）。解除后排队中点名它的运行改回自动分配，把它设为首选电脑的项目配置
  一并清空，历史运行记录保留并显示为「已解除接入的电脑」；原会话在它上面的运行不再允许续跑，
  提示改用「基于报错重跑」。飞书发送一次解除通知。
- 同一个任务在 queued/claimed/running 状态下重复点击不会重复入队。
- 一台电脑同时运行数不超过 Runner 配置；同一项目不超过项目配置。
- 首选电脑离线时任务保持排队，不会错误派给其他电脑；自动分配模式可被任意在线节点领取。
- 每次运行的分支、worktree 和 AI CLI 会话独立。
- 选择集中账号时，账号必须启用且 provider 与 AI 工具一致；账号 id 固化到运行，重跑与续跑沿用。
  Runner 只在领取该运行时拿到对应明文，并用 `<root>/.wao-codex-homes/<run-id>` 隔离 Codex 配置。
- AI 账号卡片提供“查看额度”和“刷新额度”。查看额度展开真实套餐、凭据有效期、限额窗口和重置时间；
  刷新额度调用供应商同步接口并展示刷新中、成功或失败状态。供应商没有可靠额度接口时显示明确原因，
  不得把未知额度展示为 0%；自定义 API 只展示和刷新连接检测结果。
- 首页 Codex 会话额度只取真实主窗口，周额度只取供应商真实返回的七天窗口，两者均以
  `100 - 已用百分比` 展示剩余值；没有对应窗口、刷新失败
  或快照未知时不展示首页额度卡片，具体原因仍保留在账号设置和自主进化状态中。首页可以保存自主进化
  空闲间隔（1 到 168 小时）和单次任务数（1 到 5）；加载、保存中、已保存、失败重试与未保存草稿状态
  必须可见，后台轮询不得覆盖草稿。自主进化只有在本次
  额度刷新成功、周剩余高于 50%、最近一次 AI 活动已超过人工设置的间隔且
  没有活动运行时才可派发；真实周剩余额度低于 50% 时发送飞书提醒，同一账号的同一重置周期只提醒一次；
  一轮最多按设置数量派发最新真实建议且不超过建议总数；调度器只在具备受控额度出口的 Linux 主节点启用，
  双节点部署只能由一个节点执行该轮派发，派发失败或部分成功要保留可见原因并允许下轮重试。
- 首页改进建议必须来自真实知识库或飞书同步归档，恰好五条且可回看来源；刷新必须避开上一批与现有未完成
  任务。资料、本地 Codex 或可靠证据不足时显示错误并保留上一批，不得用固定模板或演示数据凑数。建议必须
  可一键进入现有自主目标链路；派发按钮覆盖派发中、成功、失败、无工作流状态，不得用仅展示的假按钮或
  不会进入 Runner 的演示逻辑。
- 建议挖掘必须排除以纯测试补齐、纯文档修订、纯重构或依赖升级为主要结果的候选；生成和派发时都追加
  用户价值验收契约，要求交付可直接使用的新能力、操作提效或体验改善，并以真实链路验证改动前后的差异。
- Codex 集中账号使用官方设备码登录：页面打开 OpenAI 官方确认页、展示一次性短码并自动轮询完成状态；
  不得跳转用户电脑的 `localhost:1455`，也不得要求用户复制失败页地址、授权码或令牌回填。
- Codex 设备码、令牌刷新和额度查询等服务端请求固定由配置 VPN 的 Linux 主节点发出；云端只做代理，
  不要求阿里云 VM 配置 VPN。AI 账号、集中凭据下发与 Runner 领取凭据不得回退到无可用出口的 Windows
  从节点；目标创建、运行入队、状态轮询、心跳和结果回传只访问共享数据，必须保留双节点容错。部署时
  必须从 Linux 的 `wao-server` 容器经主机网络内部代理真实探测 OpenAI 设备码端点并取得 HTTP 200。
  该代理只能供主机回环与 Docker 私网使用，且只注入 Codex OAuth 客户端，不能改变其他供应商和自定义 API
  的出站路径。
- Codex OAuth 额度使用同一 ChatGPT 登录态读取 `backend-api/wham/usage` 的主次窗口；该非稳定公开契约
  调用失败时保留账号与上一次快照，页面显示失败原因并允许重试，凭据不得写入响应或日志。
- 选择集中账号而未显式指定执行电脑时，默认固定到支持对应 CLI 的 Linux 主节点；Linux 尚未接入该
  工具时前后端都给出明确提示，不得自动落到 Windows 个人电脑。选择“使用执行电脑本地登录态”时
  继续沿用项目首选电脑或自动分配，用户也始终可以明确改选其他执行电脑。
- 自定义 API 以 OpenAI Responses 协议配置 Codex provider；API Key 只通过子进程环境变量注入，
  不写入 `config.toml`、日志或全局认证文件。隔离目录与 worktree 同保留七天后回收。
- 节点离线超过三分钟后任务重新排队；成功/失败均有结果摘要和结束时间。
- 前端每五秒刷新运行控制台；运行卡片展示最近反馈及新鲜度，点击先打开进展时间线，详情按钮
  可准确跳转到 `/projects/{projectId}?task={taskId}`。
- AI Run 派工面板的执行电脑查询不得使用缓存，面板打开期间每五秒刷新一次在线状态，首次打开不能先把
  实际在线电脑显示成全部离线。
- 任务详情按运行批次展示最近 30 次 AI 档案，每次最多保留最近 50 条摘要；活动运行持续轮询，
  历史运行可展开查看最终结果。
- Runner 在 worktree 外提供运行级报告路径；存在 UTF-8、10MB 以内的单文件 HTML 时自动上传到
  隔离托管并用稳定地址关联运行。继续优化更新同一页面，上传成功后清理本机文件，上传失败明确
  回传错误；没有报告文件时不影响运行结果（见 ADR-055）。
- 最近完成列表直接展示失败摘要；点击运行记录可查看失败阶段、完整错误、退出码、执行电脑和
  工作目录，再从详情进入对应任务。
- Runner 将不含凭据的诊断写入本机 `~/.wao/ai-runner.log`，并在启动时校验 Git 与本机声明的
  AI CLI 命令，任务计划程序环境异常时可通过完整命令路径修复。心跳只上报二次脱敏后的最近
  200 行、最多 30,000 字符；AI 控制台在执行电脑卡片按需读取，必须提供加载、空数据、失败重试、
  手动刷新和复制状态，不得把日志正文塞进执行电脑列表轮询。
- Windows Runner 必须通过标准输入传递完整多行提示，保证任务 Markdown 地址不会经过
  `.cmd` 转发脚本时被截断；Codex 仅退出码为 0 仍不足以判成功，还必须返回明确完成标记。
- Windows Runner 启动 Git、AI CLI、取消命令和自身更新进程时必须使用系统无窗口创建标志；连续执行
  成功、失败和取消三类任务都不得闪现控制台，同时必须保留输出管道、失败摘要、Runner 文件日志和
  整棵进程树取消语义，退出 Runner 后不得遗留脱管的 AI CLI 子进程。
- 续跑对失败和成功的运行都开放：失败是补充信息接着修，成功是基于这一版继续优化，两者都恢复
  原会话与原 worktree，并固定派回原执行电脑（见 ADR-027）。
- 子任务级运行与主任务运行互不去重：主任务在跑时仍可单独派某条子任务，同一条子任务重复派工会被拦下。
- 主任务的提示词地址一律带 `openOnly=true`；该参数同时过滤已完成和已单独派过工的子任务。
- AI 跑完（成功或失败）必须往飞书群发一张带跳转按钮的卡片；通知失败只记日志，不影响运行结果落库。
- AI 判断某项非必要功能缺少真实数据源或可靠接口时，不得以 mock/演示数据伪造实现；取消该功能并完成其余交付后返回 `WAO_RUN_STATUS: SKIPPED`，运行按成功进入待验证，不显示失败或“基于报错重跑”。
- Runner 使用 `codex exec --json` 的 JSONL 事件流，只保存 agent message、公开的 reasoning summary、
  plan update 与阶段/结果；command execution、file change、MCP tool call、web search 不进入 WAO。
- Claude Code 侧使用 `claude -p --output-format stream-json --verbose`：只保存 assistant 文本、
  TodoWrite 计划与阶段/结果；thinking 正文和其余工具调用细节不上传。最终答复取 `result` 事件，
  `is_error` 为真时即使退出码为 0 也判失败。
- Qoder 侧使用 `qodercli -p --output-format stream-json`：事件与 Claude Code 同构，进展过滤、
  最终答复与会话恢复（`-r <session-id>`）复用 Claude 口径；Qoder 按 Credits 计费，结束事件
  没有按次用量字段时只记模型不记账（见 ADR-028）。
- 项目只配置一个 HTTPS 仓库地址；Runner 按本机认证方式解析实际克隆地址（`--git-protocol auto`
  时没有 HTTPS 凭据就改用 SSH），已克隆的仓库同步纠正 `origin`，同一份配置在 HTTPS 与 SSH
  两种机器上都能拉起工作区。
- Runner 从本机 Git credential helper 读取现有 GitHub HTTPS 凭据，仅通过子进程 `GH_TOKEN`
  提供给 AI CLI，并自动补齐 Windows GitHub CLI 路径；不持久化或记录令牌。AI 应优先使用
  `gh` 完成 PR、合并和部署跟踪，连接器不可用不能直接判定任务阻塞。
- 新建且尚无任何提交的 Git 仓库同样可以派发任务：Runner 创建不基于 `origin/<默认分支>` 的
  孤儿任务分支和独立 worktree，AI 的首个提交即为该仓库的首版内容；不得因远端默认分支不存在
  而报“无效引用”。
- Linux 主节点的 Codex CLI 和 Runner 能力由管理员作为主机级依赖独立维护；CD 不下载、上传、安装、升级或重启
  Codex CLI/Runner。已配对 Runner 需主动上报 `codex` 能力并同步集中账号。页面问答允许任一在线的本地 Codex
  Runner 领取，不限 Windows 或 Linux；在临时空仓库中用 `read-only` 沙箱执行，完成后清除问题正文和临时目录；每位成员同时
  只允许一条问答。

## 安全边界

- Windows Runner 通过 `install-windows-task.ps1` 安装开机、登录和 1 分钟守护触发器，并优先用
  `pythonw.exe` 无窗口运行；没有 `pythonw.exe` 时才回退到 `python.exe`。Runner 首次在线时自动准备
  Wake-on-LAN 信息，离线卡片只需点击一次即可发送真实唤醒包。页面只在心跳恢复后显示在线，
  不把 UDP 包发送成功伪装成电脑启动成功（见 ADR-029）。
- Runner 心跳超过 2 分钟时飞书发送一次离线通知，后续心跳恢复时发送一次上线通知；同一状态不得重复通知。
- 解除接入即作废该电脑的节点令牌：Runner 收到 401 后删除 `~/.wao/ai-runner.json` 并以退出码 78
  退出（systemd 用 `RestartPreventExitStatus=78` 不再拉起），重新接入必须走新的一次性配对码。

- 配对码和节点令牌不写日志、不进 Git；节点令牌只保存于 `~/.wao/ai-runner.json`。
- WAO 可按 ADR-030～032 加密保存用户主动添加的 Codex、Claude Code、OpenAI 兼容 API 凭据；
  列表和浏览器接口不回传明文。GitHub 凭据仍只留 Runner 本机。
- Runner 协议仅开放配对、心跳（含受限日志尾部）、领取、进展、完成五类接口；业务配置、任务档案与运行列表仍要求
  WAO 会话。单条进展最多 1000 字，服务端校验运行归属并拒绝未知类型。
