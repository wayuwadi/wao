# Phase 1：任务驱动的 AI Run

## 用户路径

0. 用户也可在首页 AI 控制台只写一句目标，选择已启用的项目工作流和本次执行电脑；Codex 工作流还可在
   Plan、目标和直接执行三种互斥模式中选择，默认选中 Plan。系统自动生成带自主执行约定的任务并立即入队，
   不要求用户先手工拆任务。
1. 项目管理员在首页 AI 控制台的「AI 工作流」视图（或项目设置 → AI Run）填写 Git 仓库、
   默认分支、本机工程文件夹、默认 AI 工具，设置项目并发数、失败自动重试次数和固定电脑后开启开关。
   同一配置页还提供项目级「AI 执行提示词」：默认把原始需求整理为事实保真的用户结果与验收清单，管理员
   可自行修改；Runner 固定的安全、权限、提交、部署和最终状态约束不可被项目提示词覆盖，详见
   [AI Run 执行提示词配置](phase-1-ai-run-execution-prompt.md)。
2. 新电脑在控制台「执行电脑」视图点击“生成配对码”，按 `deploy/ai-runner/README.md` 启动
   Runner；配对码十分钟有效且只能使用一次。Runner 自己声明本机装了哪些 AI CLI。
3. 单个任务在详情页点击“AI run”，在弹出的面板里选 AI 工具、集中账号和执行电脑（默认取项目配置；
   账号留空时使用执行电脑本地登录态）；选择 Codex 时还可按本次运行选择后台允许的模型与推理强度，
   默认 `gpt-5.6-sol + high`，也可选择 `medium / low`，Fast 固定关闭；Codex 执行模式默认使用 Plan，也可在派工面板把直接执行、Plan 或目标模式设为后续默认值，设置由服务端持久化并同时作用于自主目标入口。自定义 API 账号继续使用账号自身模型；
   多个任务在项目列表逐条主动勾选后，可选择“单独给 AI”为每条任务建立独立运行，或选择“合并给 AI”创建
   一次 AI Run；页面初始不选中任何任务，也不提供一键全选，避免误把整个项目交给 AI。合并运行走项目默认配置；
   所选任务共用一个上下文、分支、worktree 和 AI CLI 会话，不再逐条创建线程。首页自主目标在 Codex 工作流下
   同样读取后台允许列表，提供高、中、低思考深度并固化本次选择。
4. 首页立即显示排队/运行数量、每种 AI 工具的在线电脑数与槽位。运行卡片持续显示最近一条 AI
   反馈、使用的工具和更新时间，点击先查看实时执行记录，再按需进入对应任务。
5. Runner 自动准备 worktree、调用对应 AI CLI 并流式回传用户可读摘要；成功后任务进入“待验证”。
   项目显式绑定审核 Skill 时，入队固化版本与哈希，Runner 在本次隔离 `CODEX_HOME` 校验并加载；详情永久展示
   计划与实际装配结果。运行中形成且已验收的通用方法还可产出市场草稿，但绝不自动确认授权或发布。
6. 每次运行的摘要时间线永久关联到任务详情，完成后仍可回看 AI 做了什么、结论和失败原因。
   任务详情与 AI Run 详情同时展示从首次有效领取到运行终态的总耗时，以及 Runner 用单调时钟累计的
   AI CLI / app-server 实际执行耗时；后者不混入 Git 准备、报告上传和部署等待，旧运行缺值时明确显示未记录。
   每次开发型运行都产出持久化单文件 HTML 报告，任务档案与首页运行详情直接提供查看、分享入口；
   报告聚焦公开 AI Plan、关键决定、功能入口与人工验收，不重复系统级检查（见 ADR-165）。
   「工具 → 使用统计」在 WAO 页签中打开数据仪表盘，按运行创建日期展示每日使用频次，并汇总 CLI
   真实回传的输入、输出、缓存与总 Token；未回传用量的运行单独计入运行频次和记账覆盖数，不得当作零消耗。
7. AI 因缺少信息而阻塞时，用户可在该次运行中补充输入；系统必须固定派回保存该 worktree 的原电脑，
   用原 AI CLI 会话继续执行，无法恢复时明确提示使用「基于报错重跑」。
8. 跑完但不符合预期时，同一个入口可以继续给提示词让 AI 基于这一版迭代（按钮显示「继续优化」），
   不必新建任务把需求重述一遍。
   AI 仍在排队或执行时也可从运行卡片继续输入；执行电脑必须把输入加入同一会话并调整后续方向，
   不能只记录成评论或等整次运行结束后才让用户重述。
9. 子任务可以单独交给 AI：子任务行上的「AI run」只跑这一条，主任务派工时已完成和已单独派过工的
   子任务都不会再进入范围。
10. 不再使用的电脑由管理员在「执行电脑」视图的卡片上解除接入：确认后节点记录连同令牌一起删除，
    那台电脑上的 Runner 下一次心跳就会发现自己已被解除，删掉本机令牌后自行退出。
11. 全局 AI 助手把问答写入短期队列，由任一在线本地 Codex Runner 的空闲槽位以只读沙箱回答；
    开发任务优先领取。成员的会话和消息单独持久化，宽屏聊天工作台左侧提供历史搜索、切换和删除；页面明确
    显示节点在线、等待、失败与重试状态。回答可以统一检索群聊、知识库、项目和 Task，并在涉及最新外部事实或
    现有材料不足时由隔离 Codex Runner 按需联网，WAO 资产和网页事实分别提供可追溯来源；
    群聊支持按群、发言人和归档日期范围筛选，不再依赖单独的 Chat Completions Key。
    服务端内部只读分析另外支持“非阻塞入队→按运行 id 查询终态”：首个使用者是共享聊天复盘（见
    [ADR-088](../adr/088-shared-chat-review-workflow.md)）。该能力仅为 Java 服务内部接口，不提供通用工作流 HTTP API；现有同步
    `runReadOnlyJob` 继续作为旧调用方的兼容包装。
12. 首页展示已启用 Codex 集中账号的真实五小时会话剩余值，以及 Codex / Claude 集中账号的真实七天
    额度剩余值；已接入 Runner 还通过 Codex 本地接口上报脱敏的套餐、点数、通用与模型专属限额，
    同一账号跨电脑合并展示。首页同时从知识库与飞书同步归档中挖掘最多五条
    带来源的可执行任务建议；用户不满意时可刷新换一批，首次无批次时自动生成。
    用户可设置连续多少小时没有 AI 任务后触发检查（默认 12 小时、范围 1 到 168 小时），以及单次为
    WAO 自身工作流轮换派发多少项建议（默认 1 项、范围 1 到 5 项）；触发时仍要求真实周剩余额度高于 50%；
    候选和自动任务只选择用户可直接感知的功能、操作提效或体验改善，不把纯测试、纯文档或纯技术优化
    作为主要结果；与人工派工使用同一套任务、Runner、PR、部署和飞书通知链路。
13. 点子库的 `IDEA_RESEARCH` 通过同一 assistant-v2 领取协议运行，但使用独立研究记录和临时目录；它继续禁用 Shell、多代理、图片与本地读取，仅开放 Web 搜索。研究报告写入固定内部点子资产库，不创建任务、不改变点子阶段，详见 [点子库规格](phase-1-idea-library.md) 与 [ADR-098](../adr/098-idea-library-and-isolated-research.md)。
14. 首页“最近完成”上方可开启“空闲后执行最早待办”，默认 2 小时、项目“Wa All in One”和状态“待办”；
    空闲时长、单次推进数、单个项目、任务状态（可多选待办 / 收集中 / 进行中）与通用 Webhook 通知群均可在功能旁配置。
    没有活动 AI Run 且达到空闲阈值时，从所选项目与状态里按录入时间选择最早一批，为每条任务创建独立的 Plan 模式
    AI Run；单次推进数范围 1 到 10，升级时取项目当前并发上限，以后不得保存为高于该上限的值。Runner 暂无槽位时
    已入队运行安全排队。每条入队通知都明确写明由闲置时间自动触发，并发到所选通知群。AI 进行中、待验证和已完成不提供为自动候选状态。
    系统设置中启用的每日断网时段内不抢占检查窗口、不自动派发，窗口结束后继续检查。
15. 首页“正在运行”标题旁提供“可 AI Run 的任务”清单；没有活动运行时，空态直接推荐最多三条任务并提供
    “开始运行”按钮。候选只来自已启用且配置 Git 仓库的真实工作流，限定待办 / 收集中 / 进行中，排除已有
    活动运行、AI 进行中、待验证和已完成；按 P0–P3 优先级、同级录入时间最早优先。快捷按钮一次点击即沿用
    项目默认 AI 工具、首选电脑与 Codex Plan 默认入队，服务端仍执行重复运行、Runner 能力和配置完整性校验。

## 验收标准

- 自主目标入口只列出已启用的项目工作流，执行电脑只列出支持该工作流默认 AI 工具的真实节点，
  默认选择项目首选电脑，也允许本次改选其它兼容电脑或自动分配；离线电脑仍可选择并明确提示任务会排队等待。
  Codex 工作流展示 Plan、目标和直接执行三种互斥选择；目标模式通过 Codex app-server 建立真实持久目标，
  不能只向 `codex exec` 注入目标提示词；其他 AI 工具不展示无效选项。
  提交后在一个事务内创建任务和 AI Run，
  项目未配置、无可用执行节点或入队失败时不留下半成品任务。任务保留用户原始目标，
  并明确要求 AI 先盘点现有资源、自行拆解、完成可安全执行的工作、只在关键阻塞时求助。
- Codex 自主目标的思考深度选择包含后台下发的高、中、低三档，默认高；所选值必须写入运行记录并由领取协议
  下发，Claude、Qoder 和自定义 Responses API 不提交无效思考深度。允许列表读取失败时入口明确提示重试，
  不用前端硬编码选项冒充可用能力。
- 项目任务列表选择两条及以上任务后同时显示“单独给 AI”和“合并给 AI”；前者创建与任务数一致的独立运行，
  后者只创建一条关联全部所选任务的运行。任一模式失败都保留当前选择并给出错误，成功后才清空选择并同步状态。
- 自主目标输入与任务描述使用同一套 Markdown 编辑器和图床：可粘贴、拖入或选择一张及多张图片，
  多图并行上传后按用户选择的原顺序内联；上传未结束时不得提前派发不完整目标。剪贴板只提供
  Base64 图片 HTML 时也必须转为真实图片上传，不得把数万字编码塞进目标正文。目标文字不设 4000 字
  人为上限，长 Markdown 完整保存到任务描述。
- 自主目标派发后，运行中卡片、最近完成列表与运行详情必须展示目标里的图片预览（最多四张），
  任务标题跳过 Markdown 图片语法且绝不显示 Base64 编码；历史遗留的内联图片通过受控图片接口兼容预览，
  不得把完整编码重复塞进每 5 秒刷新的运行列表响应。
- 项目未开启或未填写仓库时，入队返回可理解的 400 错误，不生成半条运行记录。
- 选中的 AI 工具没有任何电脑接入，或指定的电脑没装这种工具时，入队返回可理解的 400，
  不生成半条运行记录。
- 节点只领取自己装了对应 CLI 的运行；单次指定了电脑时，只有那台电脑能领，它离线则继续排队。
- AI 助手来源选项来自真实配置和业务数据；日期范围必须在查询候选前生效，发言人筛选后不得把其他人的
  消息正文交给 Codex。知识库、项目和 Task 的引用可以回到对应 WAO 页面；密钥库和系统凭据不得进入资产层。
- 非阻塞内部只读任务入队后立即返回 `ai_assistant_run.id`，其活动状态专用 `secure_queued / secure_running`，查询只允许调用方按该 id 读取状态和结果；
  不创建 `ai_assistant_conversation` 或 `ai_assistant_message`。成员页面助手以及保留五分钟等待的 `runReadOnlyJob / executeReadOnlyJob` 同步兼容包装使用 `queued / running`；它们与 durable `secure_*` 共用一张表，但超时恢复语义不同。AI 运行进入成功、失败或超时终态时都必须立即将 `prompt_text` 显式置空，
  开发任务队列仍优先于页面问答和内部分析。
- 内部 secure enqueue 要求当前 API 构建中的 bundled Runner 脚本可读，并验证提示非空和同一操作没有活动运行；提示的业务上限由调用方在入队前执行。它不依赖当下兼容 Runner 在线或哈希匹配。节点哈希 / Codex 能力只在 assistant-v2 claim 时检查；无兼容节点时 `secure_queued` 可等待到后续节点上线，但默认 60 分钟后由 DB 硬超时失败并清空 prompt。
- 内部只读运行的入队 `created_at / updated_at`、领取 `claimed_at / updated_at`、成功 / 失败 / 超时终态 `finished_at / updated_at` 均由 MySQL
  `CURRENT_TIMESTAMP(6)` 直接写入；超时 SQL 用 `DATE_SUB(CURRENT_TIMESTAMP(6), ...)` 比较。API 节点和 Runner 本地时钟不参与这些时间戳及过期判断。
- 内部只读任务的过期不能依赖调用方继续查询。服务端后台周期扫描并以活动状态条件更新清理超时运行：`secure_queued` 从 `created_at` 起超过
  `wao.ai.read-only.queued-timeout`（环境变量 `WAO_AI_READ_ONLY_QUEUED_TIMEOUT`，默认 60 分钟），或 `secure_running` 从 `claimed_at` 起超过
  `wao.ai.read-only.running-timeout`（环境变量 `WAO_AI_READ_ONLY_RUNNING_TIMEOUT`，默认 30 分钟）时转为 `failed`，只保存有界稳定超时错误并清空
  `prompt_text / claim_token`。`secure_running` 不进入成员页面助手使用 JVM 墙上时钟的 3 分钟 stale requeue；它只会正常完成，或由 MySQL 时钟的 30 分钟执行硬超时终止为失败，不重排同份敏感材料。
  清理与 Runner 完成并发时只能有一个终态 CAS 成功；即使没有页面轮询或上层 worker 已停止，敏感提示正文也会按时释放。
- 页面助手和内部安全只读运行只通过独立协议 `POST /api/ai/runner/assistant-v2/claim` 与
  `POST /api/ai/runner/assistant-v2/{runId}/complete` 流转。新 API 不映射旧 `assistant` 路由；新 Runner 命中旧 API 的 v2 404 时只重试 v2，不降级到旧 claim / complete。
- 能力门禁不信任 Runner 自报的布尔标志：心跳上报的 `scriptHash` 必须与当前 API 构建中打包的 Runner 脚本原始字节 SHA-256 完全相同，节点也必须上报 Codex 能力，才能领取。服务端未打包脚本、节点未上报或哈希不匹配时均返回无任务。
  滚动发布时，旧 Runner 不调用 v2 且哈希不匹配，旧 API 不识别 v2；两端均 fail-closed，安全任务等待兼容节点或 DB 硬超时，不能落入旧协议或带工具执行。
- 每次 v2 claim 生成新的 32 字符随机 `claimToken`，与 `runnerId` 一起写入 `ai_assistant_run`，并返回从安全执行硬超时扣除保护余量得到的 `maxRuntimeSeconds`（默认 1,740 秒）。Runner 必须用本地单调时钟计算截止时间；
  到期后终止 Codex 子进程，不使用可回拨的墙上时钟也不回传部分结果。complete 必须原样带回 token；服务端只在 `id + runner_id + claim_token + 当前执行中状态` 全部匹配时 CAS 接受成功或失败，终态清空 token，旧 attempt 迟到完成无法覆盖终态。
- 页面助手和内部只读分析（包括聊天复盘）每次都在临时空 Git 仓库、独立临时 `CODEX_HOME` 与 `read-only` sandbox 中运行。Runner 调用 Codex 时必须同时使用
  `--ephemeral`、`--ignore-rules`、`--disable shell_tool`、`--disable multi_agent`、`tools.view_image=false`，并在子进程环境中剥离
  `GH_TOKEN`、`GITHUB_TOKEN` 及同类 GitHub Token。只有普通页面问答和点子调研使用顶层 `--search`；内部只读分析、聊天复盘、文档润色和天人解读继续强制
  `web_search=disabled`。这些进程级约束才是阻断不可信正文读取本机、扩散工具、调用子代理或触达 GitHub 凭据的安全边界；提示中的“不可信引用”标签只是纵深防御。
- 页面选择 DeepSeek 或受信模型网关时，assistant-v2 Runner 先以 `ASSISTANT_WEB_SEARCH` 生成最多 20,000 字、带公开 URL 的有界联网材料，再 CAS 转入
  `provider_queued`，由用户选定的 Provider 生成最终答复；不能把最终回答偷偷换成本地 Codex。联网材料在终态与完整提示一起清除，任一阶段失败不静默降级。
- 任一强制开关不被当前 Codex CLI 识别时，该只读任务必须失败关闭；Runner 不得删去开关后重试、切换到可用工具的旧模式或继承开发任务权限。Codex 非零退出时不得回传
  stdout 或最后消息中的部分答案，只回传稳定失败类别与退出码；服务端只保存有界稳定错误，不保存部分 `response_text`。Runner 在尝试 v2 完成回传后进入 `finally`，无论成功、非零、单调超时或回传失败都清理临时仓库与 `CODEX_HOME`。
- Runner / 服务端验收覆盖 `secure_queued / secure_running`、无兼容 Runner 在线时仍可入队并由 60 分钟 DB 超时收口、精确 bundled-script hash 能力门禁、旧 Runner / 旧 API 滚动发布 fail-closed、旧 v1 路由 404 且不回退、v2 `claimToken / maxRuntimeSeconds`、单调截止和全路径临时目录清理。
  另需验证旧 `claimToken` 迟到完成更新 0 行，后台在没有任何结果查询时仍会清理安全排队 / 执行超时、清空提示与 token，安全执行不会被 3 分钟 JVM stale requeue，且 DB 硬超时与正常完成竞争时不覆盖先到终态。

  本次范围。人工复制的普通子任务分享仍只含当前子任务（见 ADR-116）。
- AI 跑完成功时不发群卡片：快速收集来源在原消息添加完成勾，其余来源保持静默；失败或未报告终态时发送带真实原因和
  任务入口的短卡片。完整摘要留在任务详情；表情或通知失败只记日志，不影响运行结果落库（见 ADR-152）。
- AI CLI 非零退出或调用异常时，Runner 必须先在同一运行、分支、worktree 与可恢复会话中按项目配置自动重试
  0 到 5 次（默认 2 次）。中间失败只显示“正在自动重试”的运行进展，不回传终态、不发送飞书失败卡片；
  任一次恢复成功只反馈最终完成表情且不发成功卡片，连续失败耗尽后才回传最后错误并定义为失败。人工暂停、运行中补充输入和
  AI 正常返回的 `SUCCESS / SKIPPED / BLOCKED` 不进入该重试链路（见 ADR-138）。
- Codex 同会话恢复只使用 `codex exec resume` 自身支持的参数；工作目录由 Runner 子进程固定，沙箱与审批策略通过
  `-c` 明确下发，不得把普通 `exec` 专属的 `--color`、`--sandbox` 或 `-C` 传给 `resume`。升级 Codex CLI 后必须
  由命令构造回归测试保证首次执行和恢复执行各自使用合法参数，避免任务完成前在重试或续跑阶段集中失败。
- PR 合并后 Runner 接收 AI 文字事件中的结构化等待部署标记，把交付阶段切到 waiting_deployment；首页和任务档案
  分开展示代码完成、等待部署与部署终态。Jenkins 以五分钟 quiet period 合并相邻 main push，按线上真实版本计算
  整个未部署范围并把同一次构建状态回写到每个提交；旧构建失败不能让仍等待后继批次的运行提前失败（见 ADR-144）。
- AI 判断某项非必要功能缺少真实数据源或可靠接口时，不得以 mock/演示数据伪造实现；取消该功能并完成其余交付后返回 `WAO_RUN_STATUS: SKIPPED`，运行按成功进入待验证，不显示失败或“基于报错重跑”。
- Runner 使用 `codex exec --json` 的 JSONL 事件流，只保存 agent message、公开的 reasoning summary、
  plan update 与阶段/结果；command execution、file change、MCP tool call、web search 不进入 WAO。
  合法 JSON 但不是对象的事件必须忽略，进展解析异常不能中断仍在运行的 AI CLI。
- Claude Code 侧使用 `claude -p --output-format stream-json --verbose`：只保存 assistant 文本、
  TodoWrite 计划与阶段/结果；thinking 正文和其余工具调用细节不上传。最终答复取 `result` 事件，
  `is_error` 为真时即使退出码为 0 也判失败。
- Qoder 侧使用 `qodercli -p --output-format stream-json`：事件与 Claude Code 同构，进展过滤、
  最终答复与会话恢复（`-r <session-id>`）复用 Claude 口径；Qoder 按 Credits 计费，结束事件
  没有按次用量字段时只记模型不记账（见 ADR-028）。
- 项目只配置一个 HTTPS 仓库地址；Runner 按本机认证方式解析实际克隆地址（`--git-protocol auto`
  时没有 HTTPS 凭据就改用 SSH），已克隆的仓库同步纠正 `origin`，同一份配置在 HTTPS 与 SSH
  两种机器上都能拉起工作区。
- Runner 从本机 Git credential helper 读取现有 GitHub HTTPS 凭据，仅通过子进程环境提供给
  工作区 `git clone/fetch` 与 AI CLI，并自动补齐 Windows GitHub CLI 路径；后台 Git 禁止
  交互式凭据询问，凭据不进入命令行、Git 配置、持久化状态或日志。AI 应优先使用 `gh` 完成
  PR、合并和部署跟踪，连接器不可用不能直接判定任务阻塞。
- 工作区远端 Git 操作必须有硬截止时间：首次克隆最多 5 分钟，日常 `fetch` 最多 60 秒；超时后
  Runner 必须终止 Git 及其后代进程并进入现有自动重试，不能让失联的 SSH/HTTPS 链路长期占用
  项目 Git 锁或阻塞节点脚本更新。
- 新建且尚无任何提交的 Git 仓库同样可以派发任务：Runner 创建不基于 `origin/<默认分支>` 的
  孤儿任务分支和独立 worktree，AI 的首个提交即为该仓库的首版内容；不得因远端默认分支不存在
  而报“无效引用”。
- Linux 主节点的 Codex CLI 和 Runner 能力由管理员作为主机级依赖独立维护；CD 不下载、上传、安装、升级或重启
  Codex CLI/Runner。已配对 Runner 需主动上报 `codex` 能力、与服务端打包脚本精确匹配的 `scriptHash`，并同步集中账号。页面问答允许任一满足这些门禁的在线本地 Codex
  Runner 领取，不限 Windows 或 Linux；按上述强制隔离档位执行，普通页面问答仅额外开放 Web Search，完成后清除问题正文、联网材料、临时仓库和运行级 `CODEX_HOME`；每位成员同时只允许一条问答。

## 安全边界

- Windows Runner 通过 `install-windows-task.ps1` 安装开机、登录和 1 分钟守护触发器，并优先用
  `pythonw.exe` 无窗口运行；没有 `pythonw.exe` 时才回退到 `python.exe`。Runner 首次在线时自动准备
  Wake-on-LAN 信息，离线卡片只需点击一次即可发送真实唤醒包。页面只在心跳恢复后显示在线，
  不把 UDP 包发送成功伪装成电脑启动成功（见 ADR-029）。
- Runner 心跳超过 2 分钟时只更新后台在线状态，后续心跳恢复时再恢复为在线；自动离线和恢复均不发送飞书群通知（见 ADR-108）。
- 解除接入即作废该电脑的节点令牌：Runner 收到 401 后删除 `~/.wao/ai-runner.json` 并以退出码 78
  退出（systemd 用 `RestartPreventExitStatus=78` 不再拉起），重新接入必须走新的一次性配对码。

- 配对码和节点令牌不写日志、不进 Git；节点令牌只保存于 `~/.wao/ai-runner.json`。
- WAO 可按 ADR-030～032 加密保存用户主动添加的 Codex、Claude Code、OpenAI 兼容 API 凭据；
  列表和浏览器接口不回传明文。GitHub 凭据仍只留 Runner 本机。
- GitHub 凭据仅可注入需要提交代码的开发任务。页面助手和内部只读分析必须从继承环境移除 `GH_TOKEN`、`GITHUB_TOKEN` 及同类 GitHub Token；
  无工具开关与 `read-only`、空仓库共同限制提示注入，不能以自然语言规则替代进程隔离。旧 CLI 缺少安全开关时失败关闭，不提供兼容降级。
- Runner 协议仅开放配对、心跳（含受限日志尾部）、领取、进展、完成五类接口；业务配置、任务档案与运行列表仍要求
  WAO 会话。单条进展最多 1000 字，服务端校验运行归属并拒绝未知类型。
