# Phase 1：任务驱动的 AI Run

## 用户路径

1. 项目管理员在首页 AI 控制台的「AI 工作流」视图（或项目设置 → AI Run）填写 Git 仓库、
   默认分支、本机工程文件夹、默认 AI 工具，设置项目并发数和固定电脑后开启开关。
2. 新电脑在控制台「执行电脑」视图点击“生成配对码”，按 `deploy/ai-runner/README.md` 启动
   Runner；配对码十分钟有效且只能使用一次。Runner 自己声明本机装了哪些 AI CLI。
3. 单个任务在详情页点击“AI run”，在弹出的面板里选 AI 工具、集中账号和执行电脑（默认取项目配置；
   账号留空时使用执行电脑本地登录态）后开始；
   多个任务在项目列表勾选后批量点击，走项目默认配置。
4. 首页立即显示排队/运行数量、每种 AI 工具的在线电脑数与槽位。运行卡片持续显示最近一条 AI
   反馈、使用的工具和更新时间，点击先查看实时执行记录，再按需进入对应任务。
5. Runner 自动准备 worktree、调用对应 AI CLI 并流式回传用户可读摘要；成功后任务进入“待验证”。
6. 每次运行的摘要时间线永久关联到任务详情，完成后仍可回看 AI 做了什么、结论和失败原因。
7. AI 因缺少信息而阻塞时，用户可在该次运行中补充输入；系统必须固定派回保存该 worktree 的原电脑，
   用原 AI CLI 会话继续执行，无法恢复时明确提示使用「基于报错重跑」。
8. 跑完但不符合预期时，同一个入口可以继续给提示词让 AI 基于这一版迭代（按钮显示「继续优化」），
   不必新建任务把需求重述一遍。
9. 子任务可以单独交给 AI：子任务行上的「AI run」只跑这一条，主任务派工时已完成和已单独派过工的
   子任务都不会再进入范围。

## 验收标准

- 项目未开启或未填写仓库时，入队返回可理解的 400 错误，不生成半条运行记录。
- 选中的 AI 工具没有任何电脑接入，或指定的电脑没装这种工具时，入队返回可理解的 400，
  不生成半条运行记录。
- 节点只领取自己装了对应 CLI 的运行；单次指定了电脑时，只有那台电脑能领，它离线则继续排队。
- 控制台三个视图（运行状态 / 执行电脑 / AI 工作流）覆盖原本分散在首页和项目设置里的信息：
  电脑卡片展示平台、接入的 AI 工具、槽位占用、心跳和正在跑的任务；工作流卡片可就地编辑
  仓库、分支、目录、默认 AI 工具、固定电脑与并发，并展示进行中/成功/失败统计。
- 同一个任务在 queued/claimed/running 状态下重复点击不会重复入队。
- 一台电脑同时运行数不超过 Runner 配置；同一项目不超过项目配置。
- 首选电脑离线时任务保持排队，不会错误派给其他电脑；自动分配模式可被任意在线节点领取。
- 每次运行的分支、worktree 和 AI CLI 会话独立。
- 选择集中账号时，账号必须启用且 provider 与 AI 工具一致；账号 id 固化到运行，重跑与续跑沿用。
  Runner 只在领取该运行时拿到对应明文，并用 `<root>/.wao-codex-homes/<run-id>` 隔离 Codex 配置。
- 选择集中账号而未显式指定执行电脑时，默认固定到支持对应 CLI 的 Linux 主节点；Linux 尚未接入该
  工具时前后端都给出明确提示，不得自动落到 Windows 个人电脑。选择“使用执行电脑本地登录态”时
  继续沿用项目首选电脑或自动分配，用户也始终可以明确改选其他执行电脑。
- 自定义 API 以 OpenAI Responses 协议配置 Codex provider；API Key 只通过子进程环境变量注入，
  不写入 `config.toml`、日志或全局认证文件。隔离目录与 worktree 同保留七天后回收。
- 节点离线超过三分钟后任务重新排队；成功/失败均有结果摘要和结束时间。
- 前端每五秒刷新运行控制台；运行卡片展示最近反馈及新鲜度，点击先打开进展时间线，详情按钮
  可准确跳转到 `/projects/{projectId}?task={taskId}`。
- 任务详情按运行批次展示最近 30 次 AI 档案，每次最多保留最近 50 条摘要；活动运行持续轮询，
  历史运行可展开查看最终结果。
- 最近完成列表直接展示失败摘要；点击运行记录可查看失败阶段、完整错误、退出码、执行电脑和
  工作目录，再从详情进入对应任务。
- Runner 将不含凭据的诊断写入本机 `~/.wao/ai-runner.log`，并在启动时校验 Git 与本机声明的
  AI CLI 命令，任务计划程序环境异常时可通过完整命令路径修复。
- Windows Runner 必须通过标准输入传递完整多行提示，保证任务 Markdown 地址不会经过
  `.cmd` 转发脚本时被截断；Codex 仅退出码为 0 仍不足以判成功，还必须返回明确完成标记。
- 续跑对失败和成功的运行都开放：失败是补充信息接着修，成功是基于这一版继续优化，两者都恢复
  原会话与原 worktree，并固定派回原执行电脑（见 ADR-027）。
- 子任务级运行与主任务运行互不去重：主任务在跑时仍可单独派某条子任务，同一条子任务重复派工会被拦下。
- 主任务的提示词地址一律带 `openOnly=true`；该参数同时过滤已完成和已单独派过工的子任务。
- AI 跑完（成功或失败）必须往飞书群发一张带跳转按钮的卡片；通知失败只记日志，不影响运行结果落库。
- AI 判断某项非必要功能缺少真实数据源或可靠接口时，不得以 mock/演示数据伪造实现；取消该功能并完成其余交付后返回 `WAO_RUN_STATUS: SKIPPED`，运行按成功进入待验证，不显示失败或“基于报错重跑”。
- Runner 使用 `codex exec --json` 的 JSONL 事件流，只保存 agent message、公开的 reasoning summary、
  plan update 与阶段/结果；command execution、file change、MCP tool call、web search 不进入 WAO。
- Claude Code 侧使用 `claude -p --output-format stream-json --verbose`：只保存 assistant 文本、
  TodoWrite 计划与阶段/结果；thinking 正文和其余工具调用细节不上传。最终答复取 `result` 事件，
  `is_error` 为真时即使退出码为 0 也判失败。
- Qoder 侧使用 `qodercli -p --output-format stream-json`：事件与 Claude Code 同构，进展过滤、
  最终答复与会话恢复（`-r <session-id>`）复用 Claude 口径；Qoder 按 Credits 计费，结束事件
  没有按次用量字段时只记模型不记账（见 ADR-028）。
- 项目只配置一个 HTTPS 仓库地址；Runner 按本机认证方式解析实际克隆地址（`--git-protocol auto`
  时没有 HTTPS 凭据就改用 SSH），已克隆的仓库同步纠正 `origin`，同一份配置在 HTTPS 与 SSH
  两种机器上都能拉起工作区。
- Runner 从本机 Git credential helper 读取现有 GitHub HTTPS 凭据，仅通过子进程 `GH_TOKEN`
  提供给 AI CLI，并自动补齐 Windows GitHub CLI 路径；不持久化或记录令牌。AI 应优先使用
  `gh` 完成 PR、合并和部署跟踪，连接器不可用不能直接判定任务阻塞。
- 新建且尚无任何提交的 Git 仓库同样可以派发任务：Runner 创建不基于 `origin/<默认分支>` 的
  孤儿任务分支和独立 worktree，AI 的首个提交即为该仓库的首版内容；不得因远端默认分支不存在
  而报“无效引用”。

## 安全边界

- Windows Runner 通过 `install-windows-task.ps1` 安装开机、登录和 1 分钟守护触发器；Runner 首次在线时自动准备 Wake-on-LAN 信息，离线卡片只需点击一次即可发送真实唤醒包。页面只在心跳恢复后显示在线，不把 UDP 包发送成功伪装成电脑启动成功（见 ADR-029）。
- Runner 心跳超过 2 分钟时飞书发送一次离线通知，后续心跳恢复时发送一次上线通知；同一状态不得重复通知。

- 配对码和节点令牌不写日志、不进 Git；节点令牌只保存于 `~/.wao/ai-runner.json`。
- WAO 可按 ADR-030～032 加密保存用户主动添加的 Codex、Claude Code、OpenAI 兼容 API 凭据；
  列表和浏览器接口不回传明文。GitHub 凭据仍只留 Runner 本机。
- Runner 协议仅开放配对、心跳、领取、进展、完成五类接口；业务配置、任务档案与运行列表仍要求
  WAO 会话。单条进展最多 1000 字，服务端校验运行归属并拒绝未知类型。
