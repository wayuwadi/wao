# 规格：长驻页面发布后检测版本并恢复懒加载

对应任务：

- `t1787792487889`（页面长时间未刷新后，部分功能加载失败）；
- `t1787820550918`（部署成功后提示版本升级）。

## 背景

WAO Web 的业务页面按路由懒加载。新版本发布时，云端会替换带内容哈希的静态分包；已经打开的旧页面仍持有
旧分包地址，之后首次进入尚未加载的项目详情、聊天复盘等页面时会请求已不存在的 `/assets/*.js`，得到 404 并
停留在当前页面。`index.html` 已禁止缓存，但只有整页重新加载后浏览器才会读取它。

仅在分包加载失败后恢复仍然太晚。对于一直停留在已加载页面上的用户，新版本已经发布也没有可见反馈，仍会继续
使用旧前端。因此发布产物还需要提供真实构建版本，让长驻页面可以在故障发生前检测到升级。

## 规则

- Vue 应用挂载前监听 Vite 的 `vite:preloadError`。首次遇到动态分包加载失败时阻止未处理异常，并在保持当前
  地址的前提下自动刷新，让浏览器读取最新且禁止缓存的 `index.html`。
- 自动刷新按浏览器标签页限流。同一标签页在 60 秒内再次遇到分包加载失败时不得循环刷新；页面顶部显示明确
  的版本加载失败提示和手动刷新入口。
- 手动刷新入口由用户显式触发，并清除本次自动刷新限流记录；提示不得伪装业务数据，也不得清除登录状态、
  已保存内容或现有本地草稿。
- 普通 API 失败、业务校验失败和非动态分包异常继续走原有错误处理，不触发版本刷新。
- 生产构建以 Git 提交 SHA 作为前端版本，并发布同源版本 JSON。旧页面每 60 秒以及标签页重新可见或重新获得
  焦点时读取最新版本；版本不同才显示升级提示，不用静态文案、随机数或业务接口伪造部署状态。
- 升级提示使用 WAO 自有居中弹窗，说明刷新会取得最新内容，并提醒用户先保存或复制尚未保存的编辑内容。用户
  可以立即刷新，也可以关闭并在 5 分钟后再次收到同一版本提醒；提示不得擅自刷新或清除草稿。
- 版本 JSON 明确禁止缓存并附带请求时间戳；第三方检测器不再监听脚本加载错误，避免与现有
  `vite:preloadError` 故障恢复重复处理。
- `index.html` 继续使用 `no-cache, no-store, must-revalidate`；带哈希的 `/assets/` 继续使用长期不可变缓存。

## 验收

- 首次派发可取消的 `vite:preloadError` 后，只调用一次整页刷新，事件不再作为未处理异常抛出。
- 60 秒内再次派发同一事件时不自动刷新，页面只出现一个带“立即刷新”按钮的恢复提示；点击后再次刷新。
- 无法访问 `sessionStorage` 时不冒险自动循环刷新，直接显示同一恢复提示。
- 生产构建生成 Git SHA 版本 JSON 并注入检测脚本；模拟不同版本事件后，只出现一个可访问的升级弹窗，焦点落在
  “立即刷新”，点击后保持当前地址整页刷新；选择“稍后提醒”后 5 分钟内同一版本不重复打扰。
- 线上版本 JSON 返回 `no-cache, no-store, must-revalidate`，其版本与本次部署提交一致；保留旧版本页面完成一次
  新部署后，60 秒内或重新聚焦时出现升级提示，刷新后提示消失且原路由可以继续使用。
- 前端单元测试、类型检查和生产构建通过；部署后线上 `index.html` 仍返回禁止缓存头，现有懒加载业务路由可正常打开。
