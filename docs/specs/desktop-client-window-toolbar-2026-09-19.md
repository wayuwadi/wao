# Mac 客户端非全屏窗口顶栏遮挡修复

## 现象与根因

普通窗口中原生顶栏仅露出上沿，网页覆盖工具栏；进入全屏后恢复。客户端由本地外壳和业务子 WebView 组成，工具栏占内容区顶部 40 个逻辑点。

Tauri 的 macOS 可见标题栏模式启用了全尺寸内容视图。该视图及缩放事件的高度包含系统标题栏，但本地外壳排在系统标题栏下方；业务子 WebView 仅从全尺寸视图顶部扣除 40 个逻辑点，导致被系统标题栏占用的部分侵入客户端工具栏。本机窗口化实测标题栏占 28 个逻辑点，工具栏只剩 12 个逻辑点可见；全屏时此差值消失。

## 行为

- 首次挂载用实际外壳 WebView 的尺寸与起点创建业务区域。
- macOS 在 AppKit 主线程读取窗口不被系统标题栏遮挡的 `contentLayoutRect`，转换为业务 WebView 父视图坐标，再从其顶部预留 40 个逻辑点；适配上下翻转坐标，不硬编码系统标题栏高度。
- 普通缩放、全屏进出和屏幕缩放比例变化重新定位同一个业务 WebView；最小化和无有效内容区保留最后可用尺寸。
- 不刷新或重建业务页面，不改变会话、草稿、快捷键和窗口恢复策略；Windows 保留现有逻辑尺寸定位。

## 验收

对比修复前后真实 Mac 原生宿主，检查 1100×760、800×560、1500×900、全屏和退出全屏，业务区域顶边距均应为 40 个逻辑点，底边应与内容区对齐。原生几何回归覆盖父视图坐标方向、非零坐标原点、最小化和无效尺寸。前端测试和构建需要通过。

本次为客户端原生修复，合并 Web 发布不能更新已安装的客户端，需要后续客户端安装包更新。
