# 复制页签的小记草稿身份

补充 `notes-tab-draft-isolation.md`。不改变 `notes-single-latest-content.md` 的显式保存、自动重新读取版本及有限 CAS 重试规则。

## 问题与决定

浏览器通过 opener 创建窗口时会复制 sessionStorage。原来的页签身份也随之复制，两边写入同一个持久草稿键，刷新后可能恢复成另一边的输入。回归测试已复现。

- 应用挂载前通过同源 Web Locks 独占自己的草稿身份。已有身份无人使用时原样沿用，刷新不迁移草稿、不留下过期副本。
- 继承身份已被另一份文档持有时，分配新身份，先复制该身份下的小记编辑及新建草稿，再切换当前会话身份。原页签内容不删除。
- 锁只保护页签身份，不锁正文或数据库；文档销毁后由浏览器释放。不同页签正常独立编辑和保存。
- 复制或会话写入失败时清理新副本并保留来源，草稿操作明确报错；无法使用 Web Locks 时同样不能显示保护成功。应用其他页面仍可使用。
- 验收辅助入口只存在于本地 `dev:acceptance` 服务，不进入生产静态目录，不提供业务 API。

## 边界

已实测 Edge 的 opener 复制会话存储路径；浏览器原生“复制页签”菜单及浏览器崩溃恢复不列为本次实测通过。已打开的旧代码页签不参与锁，发布后需要刷新相关页签才具备新保护。

没有业务 API、CLI、MCP、数据库或旧 Runner 变化。
