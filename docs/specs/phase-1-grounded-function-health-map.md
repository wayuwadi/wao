# Phase 1：真实功能健康地图与持续评分

对应任务：`t1788162743582`。

## 用户结果

1. 登录成员在每个 WAO 主壳页面右上角看到该功能的 1–100 分，并可用 `+1 / -1` 做一分校准。
2. 工作台的原生功能卡展示当前成员最近 30 天真实打开次数、使用占比、当前分数和可执行提示；没有数据时明确未知。
3. 功能默认 1 分。最终完成代码、PR、部署和线上验收的 Runner 运行，按本次 Conventional Commit 的稳定功能 scope
   自动加分；重复回传同一提交不重复计分，平台或未知 scope 不猜测归属。
4. AI 巡检在接口性能之外读取同一份真实功能快照，检查低频、常用路径和功能重叠；结论必须回到仓库页面与业务边界核对。

## 数据与边界

- `function_usage_event` 保存成员、稳定功能 id、入口来源和打开时间；聚合查询始终按当前登录成员隔离。
- `function_product` 保存全局人工校准与自动迭代次数；显示分数钳制在 1–100。
- `function_iteration_event` 以功能 id 与提交 SHA 唯一，Runner 只上报基线后的新提交，服务端负责 scope 白名单。
- 外部应用和快捷链接没有 WAO 页面实现与可靠提交映射，本期不评分；不能用路由点击或硬编码数据冒充其真实使用。

## 失败与验收

- 统计写入失败不能阻断当前页面；工作台读取失败保留目录并提供重试，评分保存中禁用重复操作，失败后允许原地重试。
- 打开两个不同功能后，工作台相应 30 天次数增加；另一成员看不到这些成员级次数。
- 同一成功运行的同一提交重复完成回传只增加一次；失败、`BLOCKED`、未知 scope 和非功能 scope 均不加分。
- 首次没有任何记录时所有功能仍显示 1 分和“暂无真实使用记录”，AI 巡检不生成演示结论。
