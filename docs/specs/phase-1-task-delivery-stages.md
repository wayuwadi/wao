# Phase 1：任务交付分层与验收记录

对应任务：`t1787799558009`（后续建议：WAO 产品优化）。

## 目标与边界

- 项目任务可以按“方向探索、待开发、待验收、已验证”查看，避免把聊天中仍在征集的想法、已经产出但没有验收的结果或人工完成项混为一谈。
- 交付阶段从现有任务状态派生，不新增第二份可编辑字段，不迁移历史数据：`收集中 → 方向探索`，`待办 / 进行中 / AI 进行中 → 待开发`，`待验证 → 待验收`，`已完成 → 已验证`。
- “已验证”只表示成员已经把任务人工置为“已完成”；AI Run 成功仍只进入“待验证”，不能自行获得已验证标签。
- 本次不复制已经存在的共享聊天、空闲任务派工、基于报错重跑、系统报告、文件配置和视频生成入口，也不为尚未定义内容类型、平台与风控边界的视频实验制造演示数据。

## 项目任务页

- 列表、看板和分组视图上方共用交付阶段筛选；每项展示当前创建人范围内的真实数量。
- 筛选写入 URL 查询参数，刷新和分享项目地址后仍能恢复；未知参数回退为“全部”。
- 看板只展示所选交付阶段覆盖的原始状态列；切换筛选时清空隐藏的 AI 批量选择，避免对不可见任务发起运行。
- “已验证”筛选自动展示已完成任务，不要求再展开一次归档；没有结果时说明是当前筛选为空，不伪装成项目没有任务。
- 手机端筛选横向滚动，按钮保留足够点击高度。

## 验收记录

- 任务详情复用现有服务端持久化的自定义属性，可一键补齐“成功条件、验收证据、端到端耗时、异常与恢复、通知结果”。
- 已存在的同名字段不重复创建；部分缺失时只补缺项。新字段保持空白并提示填写真实结果，不写示例或猜测值。
- 阻塞点继续使用任务已有的“等待”字段，任务状态继续表达执行和验收进度，不增加重复概念。
- 自定义属性值允许清空后重新填写，加载、保存中、已保存和失败重试继续复用任务抽屉既有保存链路。

## 验收

- 六个任务状态分别且唯一映射到四个交付阶段，现有状态顺序和保存行为不变。
- 项目任务页可按四阶段筛选真实任务，筛选 URL、计数、看板列、已完成展开和空结果文案一致。
- 同一任务连续点击“补齐验收记录”不会产生重复字段；已有两项时只新增其余三项，值均为空。
- 前端单元测试、类型检查和生产构建通过；合并部署后使用真实登录账号验证项目任务筛选和任务详情保存。
