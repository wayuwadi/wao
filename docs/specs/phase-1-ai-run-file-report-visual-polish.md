# Phase 1：AI Run 文件归类、巡检报告与运行卡片优化

对应任务：`t1788147229324`。数据分类决策见 [ADR-170](../adr/170-hosted-page-source-and-ai-run-card-polish.md)。

## 用户结果

1. “文件与图床”的“网页托管”汇总页明确标出“人工上传”或“AI Run 报告”，并可按类型筛选；旧报告也能正确归类。
2. HTTP 性能 AI 巡检继续使用每次 AI Run 的真实 HTML 报告链路，报告额外说明实际优化接口、根因、是否彻底解决、遗留边界、规避方式和可复用经验；没有可靠优化时如实记录跳过证据。
3. 首页“最近 AI 运行”和完整历史把类型与结果筛选合并在同一行，并以分组标题和分隔线保持两个维度清晰。
4. 最近运行卡片去掉重复的类型/结果文字标签和底部详情行，以类型图标、结果图标和悬浮/键盘聚焦蒙层保留辨识与打开入口。
5. 从自主目标创建任务时，先从首个有效文本短语生成不超过 36 个字符的任务标题，再创建 AI Run；完整目标仍原样保存在任务描述中。

## 数据与兼容边界

- `hosted_page.source_type` 是稳定来源枚举，当前只接受 `MANUAL_UPLOAD`、`AI_RUN_REPORT`；默认值保持存量人工页兼容，`run-report-` 稳定 id 只用于一次性迁移回填。
- 列表接口可以用 `sourceType` 服务端筛选；文件汇总页一次读取元数据后在本地组合分页，不读取 HTML 或 icon 正文。
- 滚动发布期间旧接口缺少 `sourceType` 时，前端只用既有 `run-report-` id 做展示兜底；新建和更新均由服务端写入正式枚举。
- 短标题只改变自主目标创建出的任务标题；用户明确填写的普通任务标题不被后台擅自改写，完整自主目标不丢失。

## 验收

- 人工页和 AI Run 报告同时存在时，两者显示不同类型；切换任一类型后总数、列表、分页和空态都只对应当前筛选。
- 巡检派工收到的公开任务原文明确包含报告六项内容和“不伪造已解决结论”的约束。
- 类型和结果筛选在一条工具栏内可任意组合，仍请求服务端真实计数与分页；卡片悬浮或键盘聚焦时出现蒙层入口，点击行为不变。
- 输入带冒号和长解释的自主目标时，任务标题只保存冒号前的短语，任务描述仍含完整解释。
