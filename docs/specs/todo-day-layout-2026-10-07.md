# 待办按天页面：主清单与日常区

2026-10-07，用户确认交互 Demo 中的「主清单＋日常区」。此规格补充日视图融合与日常规则规格，仅调整浏览器的信息层级和布局，不改变接口、任务状态、排期或历史记录契约。

- 页头合并待办标题、按天／全部待办和新建入口；当天摘要缩为日期下的一行文字。新建全局入口采用轻操作，清单内添加仍为当前主操作。
- 桌面以约 2:1 划分主清单和日常区。主清单先显示当日已安排且未真正收尾的任务；未安排但当天有进展、以及已真正收尾的任务归入「当天进展与已完成」。主状态完成但子项未收尾仍留在安排区；不把待验证算作完成。
- 进展分组今天和未来默认收起，历史默认展开；用户主动展开。正在保存、保存失败或正在记进展的条目保持可见，避免保存反馈与编辑器被折叠。日期或成员切换重置展开选择，仍使用原有隔离草稿。
- 固定事项在右侧独立线框分区，保留真实早晚清单、完成／跳过／恢复、只读日期和规则管理。随手记使用原有正文与提交链，默认呈现前三条，明确提供展开全部与收起；不静默截断数据。
- 按可用容器宽度重排，800px 以下依次呈现主清单、进展、固定事项、小记。各区不设置固定高度与独立滚动，继续由既有页面主容器滚动。长标题自然换行，320／390px 的输入与常用操作保留触控空间。
- 排时浮层、精确输入、撤销、任务详情、历史快照、补记、保存回执、错误重试与草稿机制沿用现有实现。读取失败仍显示失败与重试，不能冒充空数据。全部待办的列表、看板、四象限与筛选保留。
- 复用 `WaoCard`、`WaoButton` 与主题 token。`TodoDayLayout` 在业务页面与 `/design` 的布局示例中复用；不复制生产数据到设计参考，不引入演示任务或 AI 调用。

验收覆盖实际成员数据、当日无安排但有进展、历史、长文本、明暗主题、窄屏、键盘、固定事项管理、排时、进展草稿与失败，以及原有日视图和全部待办回归。实体设备最终体验交用户确认。
