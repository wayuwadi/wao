# 小记自动标题、配图、润色和图片复制

## 用户结果

- 新小记首次保存时先可靠保存正文，再依次生成简短标题、总览图、润色阅读版；后续编辑保存不自动重生成。可在保存前关闭自动润色。AI 暂不可用时保留已保存的小记和可恢复任务，不把正文保存失败说成生成失败。
- 原文始终是可编辑事实源；润色版按成员保存为阅读版本，卡片悬浮或获得键盘焦点时可在“润色 / 原文”间切换。原文变化后旧润色版失效，不能覆盖新正文。
- 卡片更新时间后展示标题、配图、润色三个语义图标；成功的三个阶段默认收起，正在执行或失败时展示进度，失败可重试。总览图在正文旁作为小封面，置顶与分享操作在悬浮时出现。右上角集中筛选标签、有无图片、今天 / 昨天 / 以前，并选择排序。
- 手动点击小记编辑器的“总览配图”时，同时提炼标题。已有总览图时先展示新图，用户明确选择“保留原图”或“替换为新图”；选择前正文和原图保持不变。
- 小记清单缩略图、打开后的大图，以及文档正文中的图片和预览图，右键提供“复制图片”“复制图片地址”。复制失败显示可操作提示。

## 状态与冲突

- `NOTE_TITLE` 使用现有持久只读 AI 队列和 `/api/text-polish/jobs` 的幂等任务接口，返回单行标题，最多取 30 字；只对当前成员可见，不写入润色历史或聊天历史。润色任务表只存正文哈希用于幂等核对，不另存正文副本。标题成功后才启动配图；配图成功后才启动 `NOTE_BODY`，按成员已保存的润色偏好清理口语和重复内容，保留事实、数字、原意和 Markdown 结构。
- `GET /api/docs/notes/polish-versions` 读取当前成员的对照版本；`PUT /api/docs/notes/polish-versions/{docId}` 保存 AI 结果时校验源 Markdown 与当前文档一致。持久化表 `note_polish_version` 不改写 `doc`，每成员每篇保留最近一次原文与润色版。
- 保存后自动生成任务只保留成员、文档、任务 id、完成阶段和版本号在浏览器本地；正文由服务器已保存文档读取。刷新后继续查询原任务，不重复提交。原标题和正文在后台生成时仍可正常阅读、编辑。
- 自动写回标题和图片使用 `expectedRev`。如果用户在等待时修改了小记，生成结果不会覆盖新版本；页面明确提示。AI 错误保留重试入口。自动图片只对新小记首次生成；已有小记可手动重生成并决定是否替换。
- 手动生成的新图先预览，确认后插入正文，并沿用编辑器原有保存机制。图片复制采用图床原图；地址复制为可打开的绝对 URL。

## CLI 与权限

`NOTE_TITLE` 与 `NOTE_BODY` 是小记页面的自动编辑辅助动作，结果需结合文档版本条件写回或保存为对照版本，不新增独立 `wao` CLI 命令，也不自动向工作区 MCP 旧令牌暴露。若以后需要终端批量整理小记，应设计带版本条件和明确权限的独立业务命令后重审。

## 本次本地验收（2026-09-25）

- 浏览器使用本地前后端与既有线上数据库，实测标签、有无图片、今天筛选和窄屏封面布局；新建验收小记后，标题任务失败并展示重试入口，验收小记已移入可恢复回收站。本地服务未配置与线上一致的加密密钥，无法解密已配置的 AI 账号，因此标题成功后的实际配图、润色链路此次未能走完；页面显示的“系统繁忙”是通用错误提示，不代表 AI 服务端繁忙。
- 自动顺序、旧正文冲突、润色对照和删除后的任务取消由针对性测试覆盖；前端类型检查和生产构建通过，服务端润色任务、对照保存与 Flyway 编号测试通过。V164 新表迁移在本地服务连接的既有数据库上成功执行。
