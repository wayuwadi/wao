# 恢复 Codex 额度刷新与重置卡增加通知

依据 2026-10-11 小记 `ba58e9b01177444c962faedd08db0a69`。原文与一张配图均已读取。本规格接续 ADR-164、ADR-307，并取代 `reset-card-feishu-restore.md` 中「其他额度刷新仍仅走站内」对 Codex 的限制；其他通知保持既有渠道。

## 行为

- 现有本机只读采集器成功保存真实快照后，交给额度通知观察器；维持一分钟节流，不恢复旧 Runner 或自主开发调度。
- 同一规范化邮箱的本机与兼容 Runner 共用持久化基线。首次采样只建基线；未知值不当成零，持平或减少不发送；多个额度窗口增加合并为一张卡。
- Codex 剩余额度增加与可用重置卡数量增加通过既有默认飞书机器人发群卡片。集中 OAuth 的 Codex 额度走同一渠道，其他供应商沿用站内通知。
- 卡片显示账号、窗口及前后真实值；重置卡使用张数、不限制为百分比。额度窗口缺失时仍可独立观察已知重置卡数量。
- 遵守全局通知、沉默时段和自动化通知策略，以及默认机器人启停。关闭或沉默时消费事件，不补发旧消息。
- 只有飞书明确返回成功才推进增加事件的基线；失败保留基线，下一轮真实采样重试。通知异常不把成功的额度快照标成失败。
- 不兑换重置卡、不修改会员日期、不增加数据库结构、不重新开启其他群通知。

## 验收

覆盖本机保存后观察、节流、失败采样/保存不通知、通知异常隔离、首次采样、增加/下降、发送失败重试、多来源去重、无额度窗口的重置卡、集中 Codex 与其他供应商渠道、默认机器人和沉默策略、飞书显式成功响应。

本机连接既有线上数据库运行真实额度采样与会员读取链路，检查基线落库和默认通知配置，并发送明确标注的恢复验证卡。自然额度重置和重置卡增加无需人为制造，最终体验由用户在实际发生时验收。

## CLI / MCP

本次改变已有采样的通知副作用，不新增 HTTP API、MCP 工具或 CLI 命令。通知应由真实采样触发，不开放伪造增加事件或兑换重置卡的命令，不扩大旧令牌权限。
