# 小记标签请求内容变化后的重试

补充 `notes-ai-tags-and-editor-efficiency.md` 的失败恢复规则，保持单份最新正文。

## 已确认的问题

标签推荐已提交后，正文被用户或其他整理阶段更新；其他阶段又推进了浏览器任务记录的文档版本。此时恢复标签任务仍携带旧请求号和新正文，服务端正确拒绝“请求内容已改变，请创建新的润色任务”。因为版本号已经一致且这不是模型终态失败，原重试逻辑再次使用同一请求号，无法恢复。

## 行为

- 用户点击重试时，若标签阶段曾被服务器明确拒绝为请求内容变化，只为未完成标签换一个请求号，用当前已保存正文重新提交。
- 普通网络错误仍续接原请求；不因未知提交结果重复调用模型。
- 已完成标题、配图和润色不重做。保留文档版本条件、本地未保存草稿保护、已有标签合并与当前字典过滤；不创建新标签，不覆盖正文或图片。
- 兼容修复前持久在浏览器的失败记录；无需清除浏览器存储或重建小记。

## 验收

`npm run test:unit -- --run src/__tests__/autoNoteEnrichment.spec.ts src/__tests__/NotesView.spec.ts --maxWorkers=2` 覆盖版本已推进时换号、网络错误保留原号、只调用标签阶段及合并已有标签。真实浏览器使用登记的合成小记，从既有失败记录点击重试，核对实际 Astra 任务与刷新后的结果；模型和发布证据单独记录。

仅修改浏览器恢复逻辑，HTTP、MCP、CLI 权限与服务端幂等校验不变。
