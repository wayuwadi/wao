# Web 聊天阅读位置与已读事实

补充现行原生聊天规格；沿用最近消息范围，不新增无限历史查询。

- 请求发起时在底部，但等待期间上滑阅读历史，响应到达不得强制拉回最新消息。
- 离开底部时显示“回到最新消息”，点击后定位到底部；隐藏聊天及不可见消息区域不得提交已读。
- 已读要求页面和聊天可见、消息区域有实际高度且已经到达底部（只容忍 2px 布局误差）。旧的 120px 跟随阈值不能作为用户已看到末条消息的依据。
- 首次/重新打开聊天时，在完成定位前隐藏消息区域，避免从历史位置跳到底部；加载失败仍展示可重试状态。
- 图片加载及消息区域尺寸变化时，仅在原本跟随最新消息时保持底部，阅读历史时不改变位置。
- 低高度桌面窗口的悬浮聊天最小高度受可用视口限制，保持输入区可访问。

验收覆盖慢请求期间上滑、距底部 60px 不标已读、回到底部后同步、零高度区域不标已读，以及真实历史消息的滚动操作和窄屏布局。
