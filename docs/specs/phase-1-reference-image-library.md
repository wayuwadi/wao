# Phase 1：参考图库与带图提问

## 用户结果

成员看到值得借鉴的界面、图标、架构图或流程图时，粘贴/拖入截图即可保存；之后可从个人图库选最多四张原图，附一句当前需求发送给本地 Codex 页面助手。收图时不要求填写标题、类型或用途。

## 首版范围

- `参考图库`是个人图片墙。上传只接受真实 PNG、JPEG、GIF、WebP，单张不超过 10MB；服务端按字节特征识别格式，不信任请求中的 MIME。单成员同内容 SHA-256 去重，超时后重试不会制造第二条图片。
- 列表仅返回当前成员元数据，按创建时间倒序，最多 500 张；原图 `GET /api/reference-images/{id}/raw` 需要当前成员会话，不使用既有公开图床地址。首版只按原始文件名过滤；自然语言、OCR 和 AI 自动整理属于后续阶段，不把文字匹配称作语义检索。
- 上传逐张反馈结果，失败保留当前页面的原始 `File` 供重试。刷新后的上传失败文件不能自动恢复，用户须重新选择。空数据、加载中、读取失败、发送失败分别展示。
- 选中一至四张图后可以输入一句需求；留空时采用可见的默认提示。发送成功的用户消息在 AI 会话历史中包含私有原图链接。输入草稿按成员保存在本机；失败时选择与文字不清空。
- `POST /api/assistant/chat/stream` 增加可选 `referenceImageIds`。服务端先验证成员拥有每张图，带图请求固定使用 `local-codex`，跳过不必要的联网检索。运行记录保存选图 ID，Runner 持精确 `runId + claimToken` 在运行期间拉取对应字节，把原图作为 `codex exec --image` 输入附件；既不传公开 URL，也不开放本机文件读取工具。领取结束后临时图片随运行目录删除。
- 已有 AI 会话历史继续存文字与安全的站内图片 Markdown；未改其它业务问答的请求行为。

## 状态与失败收口

- 图片保存成功与 AI 整理是两件事。首版尚未实现 AI 自动标题/标签，即使它不存在也不影响原图入库和带图提问。
- 本地 Codex Runner 不在线或不支持最新只读脚本时，按现有助手状态返回明确错误；用户选择的图和本机文字草稿保留。
- 精确领取令牌错误、成员不匹配、图片不存在时拒绝取图；Runner 不把部分答复伪装成成功。模型/网络失败后可重试，但可能产生新的 AI 会话，前端保留历史入口。
- 参考图不提供公开分享或删除。项目关联、相似图、浏览器快捷收藏、OCR、AI 自动标题及自然语言检索按已对齐方案后续迭代，不能在首版 UI 中伪称可用。

## 本地验收

1. 登录成员 A 粘贴真实截图，刷新仍可看到并选中；同图再传只出现一条。
2. 成员 B 列表看不到 A 的图，直接访问 A 的原图地址得到拒绝或不存在。
3. 选择两张真实图片附一句需求，确认 Runner 领取时得到两张原图附件，Codex 回答能指出图中的可核对视觉信息；刷新 AI 对话历史可看见原图与回复。
4. 上传无效格式/超过上限、断网重试、Runner 不在线及发送失败时，页面保留输入并给恢复入口。
5. 手机宽度下收图、找图、选图和提问可完成，弹窗/浮层无首次跳位。
