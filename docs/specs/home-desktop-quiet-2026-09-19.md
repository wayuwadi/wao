# 首页、桌面空间与交付反馈优化

来源：任务 `t17897276079220` 的四个子任务，以及用户补充“Mac 找不到更新升级入口”。

## 用户结果

- 首页以待办、文件和项目为起点。AI Run 保留为实验功能，默认收成一行，点击后显示原有额度、目标输入和控制台；有活动运行时在入口提示真实数量。控制台直达链接仍自动展开。折叠使用隐藏而非卸载，已有草稿、上传、执行和弹窗状态保留。
- 旧版原生壳仍通过既有固定动作桥接运行，网页隐藏重复的六个快捷操作，保留 32px 的当前功能与自定义顶部菜单；新版桥接客户端沿用单层原生顶栏。普通浏览器保留网页完整操作。
- 网页安装图标采用独立版本化透明资源，可见图形横向约占 82%，不替换页面品牌标识。Apple touch icon 与 manifest 同步引用新资源。原生专用 PNG 与 ICNS 已有 9% 四周边距，本次核对一致并保留。系统已缓存的旧图标需要浏览器刷新安装信息或重新安装网页应用；原生图标通过客户端更新生效。
- 原生顶栏始终显示“版本与更新”，更新页展示当前版本、检查更新、失败重试、下载进度和安装入口。发现新版本显示提示点，点击入口先看版本信息；下载后仍需用户确认安装。关闭更新页回到原有工作区，不刷新业务 WebView。Mac 系统菜单及托盘检查更新入口继续保留。
- Jenkins 每批成功后发送一张简短飞书卡片，包含提交标题摘要和详情链接。只有生产发布且从节点、主节点、云端和最终检查全部成功时称为发布成功；无需部署或影子构建明确标注未部署。失败卡片原行为保持。
- 成功通知遵守群通知总开关和沉默时段，独立于失败通知开关。成功策略读取失败时静默；失败告警沿用故障兜底。成功通知的失败不改变已完成发布结论。

## 本地验收与交付边界

首页连接既有本地后端和真实线上数据库，验证默认折叠、展开真实运行、草稿保留、项目入口及直达链接。前端和客户端进行针对性回归、类型检查与构建；服务测试覆盖成功通知门禁，Shell 测试检查成功/失败卡片、策略拒绝和未完成部署不发送。

原生应用 UI 自动化在本次环境不可用；更新页浏览器预览与自动测试不能替代真实 DMG 升级、签名安装和 Dock 实机比较。客户端变更须经独立客户端发布流程构建新安装包，合并主站 PR 不等于旧安装包已更新。Jenkins 的线上发送回执由用户在发布后验收，本地不伪造成功群通知。

## 本次验证记录

- Web 相关 65 项测试通过，类型检查与生产构建通过；客户端 24 项测试通过，另有 1 项原生场景测试按原规则跳过，类型检查与构建通过。
- 通知策略与 Flyway 检查共 41 项通过；通知 Shell 用例通过，覆盖正常成功、失败、总策略拒绝、策略不可读、生产验证不完整和无需部署。
- 本地页面复用真实已登录会话，查看真实额度、运行及执行电脑，验证默认收起、展开/收起、`?console=runners` 直达与打开项目列表。客户端预览确认常驻入口、当前版本、检查更新按钮和返回工作区。
- 新服务以 `local-cloud` 连接既有数据库，成功/失败通知公共门禁均返回真实允许结论；未向飞书发送模拟成功消息。
- 本机安装版本为 1.1.5。原生专用 PNG 和 ICNS 均为 1024px，主要不透明区域为 `(92,92)-(932,932)`；新 PWA 资产可见宽度约为画布 82%。原生安装升级、Dock 实际显示及 390px 浏览器视口未完成实机验收，不以源码或浏览器预览替代。
