# Phase 1：原生 Windows 客户端飞书扫码登录

> 已退役：该规格不再实施，仅保留历史背景；现行决策见 ADR-077。

对应任务：`t17869405414760`。技术与安全边界见 ADR-076，并继续遵循 ADR-007、ADR-016 与 ADR-075。

## 用户路径

1. 未登录用户在原生登录页优先看到“飞书扫码登录”，邮箱密码保留为次级入口。
2. 点击后，WAO 打开系统默认浏览器中的飞书官方扫码授权页；客户端明确显示等待状态，并允许取消。
3. 用户在飞书扫码并确认后，浏览器显示“可以返回 WAO”，客户端自动交换授权码、保存受 DPAPI 保护的 WAO
   会话并进入真实项目页面，无需复制验证码或再次输入账号。
4. 飞书身份首次出现且无法唯一匹配成员时，客户端展示服务端返回的候选成员；用户确认后永久绑定并登录。
5. 授权被拒绝、超过五分钟、浏览器无法打开、本机回调失败或服务端交换失败时，客户端停留在登录页，显示错误并
   可重试，不能展示虚假成功。

## 规则

- 飞书授权必须走生产 `/api/auth/feishu/**` 与飞书官方页面；不生成演示二维码，不嵌入 WebView，不读取系统
  浏览器 Cookie。
- 回调只允许签名 `state` 内的 `http://127.0.0.1:<高位端口>/wao-auth/callback`，监听一次后立即关闭。
- 授权码只存在于本次内存流程；飞书应用 Secret 和 access token 始终留在服务端。
- 飞书成功后的 WAO Cookie 与邮箱登录使用同一 Cookie 容器和 DPAPI 存储，退出、401 与无法解密时继续清理。

## 验收

- 服务端单元测试覆盖 Windows 授权地址、本机回调返回和非 loopback/错误路径拒绝。
- Core 单元测试覆盖随机 loopback 端口接收授权码与浏览器完成页。
- Windows WPF 可交叉编译，真实发布后线上授权入口接受安全 callback，并拒绝公网 callback。
- Windows 实机从按钮打开飞书官方页面，扫码后自动回到客户端；已绑定身份直接登录，未绑定身份可完成成员认领。
