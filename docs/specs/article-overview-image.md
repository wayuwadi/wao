# 小记与文档的文章总览配图

## 用户结果

- 小记和知识库文档的正文编辑区，在现有“图片”按钮左边显示“总览配图”。点击后根据当前全文生成一张概括主题与核心观点的 PNG，并作为正文第一张图片插入。编辑期间不冻结正文，也不把生成过程中的旧正文写回编辑器；新生成的总览图替换最前面已标记的总览图。
- 默认画面要求：16:9 横版、一个主题、最多 3–5 个重点、简洁中文关键词、手机可读、不得编造事实或加水印。每个成员可在按钮旁的设置中修改提示词，保存到已有成员偏好接口；空偏好使用全局默认。该偏好同时用于小记和文档，不影响其他成员。
- 生成任务入队后可离开页面。浏览器按成员、内容类型和内容 ID 记住任务 ID，返回编辑器后继续查询。失败显示原因并允许重新生成。生成成功但插入失败时保留任务 ID，供用户继续插入；插入后仍沿用页面原有保存机制。
- 小记保存后自动生成标题和配图、手动重生成前的预览确认、图片复制，见 [小记自动标题、配图和图片复制](notes-auto-title-image.md)。
- 正文下方使用独立操作行，左侧放“总览配图”“提示词设置”“图片”，右侧放全文/选中字数。小记标签接在同一行；窄屏和标签较多时自然换行。操作、错误提示和字数均不覆盖正文，标签选择器与保存区仍在其下方。

## 执行与数据边界

- `POST /api/assistant/article-images` 接收 1–60000 字当前正文和 1–4000 字画面提示词，返回任务 ID；小记自动整理携带稳定请求标识，网络响应丢失后的重试复用同一任务。`GET /api/assistant/article-images/{id}` 仅允许任务成员查询，返回排队、执行、成功图片地址或失败状态。成员同一时间只允许一张总览图任务；小记自动整理遇到占用会等待，不重复排队或终止后续润色。
- 复用 `ai_assistant_run` 的 `secure_queued / secure_running`、assistant-v2 领取令牌与 60/30 分钟数据库超时清理。只有脚本哈希匹配的在线 Linux Codex Runner 可领取 `ARTICLE_IMAGE` 模式。正文只在任务提示中暂存，终态即清除；不进入 AI 聊天历史。
- Runner 在空仓库、隔离 `CODEX_HOME`、只读沙箱中运行已有 ChatGPT 登录态的 Codex 内置 `image_gen`。禁用 shell、多代理、本地看图和 Web 搜索，不使用额外 API Key。只接受本次隔离目录生成的唯一 PNG，不信任模型返回的路径。Runner 以节点令牌与本次 claim token 上传到既有图床；服务端验证格式、尺寸、大小及任务所有权后登记图床 URL。完成请求只有与已登记 URL 一致才可成功。
- 旧 Runner、Windows Runner、登录失效或图像工具不可用时不能冒充成功；页面给出可重试状态。滚动发布期间新上传接口的 404 不应使图片错归属，旧 claim token 不能上传。

## 验收

1. 两台 Linux 节点的真实登录态可调用内置 `image_gen` 并生成 PNG；未额外配置 API Key。
2. 小记和文档按钮均在“图片”左侧；默认与个人提示词可用，成员间隔离。
   正文写满编辑区、窄屏和多标签时，底部操作行与文字没有重叠，字数仍可见。
3. 成功图片在原文最前面，原文和用户编辑保留；重复生成只替换已标记的首图。
   小记从第一行可读正文提取标题，不能把首图地址或替代文字当成标题。
4. 旧领取令牌、伪 PNG、越权查询、重复上传、超时和重进页面均有确定结果。

## 发布顺序

先发布包含新接口的服务端与前端，再在首页 AI Run 的“执行电脑”里点击“更新 Runner 脚本”，等待 Linux1 与 Linux2 上报最新脚本哈希。更新前按钮会明确提示缺少兼容节点，不会让旧 Runner 错领配图任务。
