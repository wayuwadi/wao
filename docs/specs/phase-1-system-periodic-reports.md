# Phase 1：系统日报、周报与月报

对应任务：`t17874472792432`、`t1787743764227`。决策见
[ADR-109](../adr/109-grounded-system-periodic-reports.md)。

## 用户链路

1. 成员从首页理念卡片上与“查看 AI 详情”并列的“查看系统报告”进入；侧栏不再重复展示低频入口，原路由继续兼容已有页签和书签。
2. 日报、周报、月报可直接切换，并可浏览前后自然周期。
3. 页面展示生成时的项目、任务、未完成任务和 AI Run 存量，以及周期内新建任务、完成任务、AI Run 数、
   成功数、失败数和真实 Token 合计。
4. 周期活动清单可回到原任务；AI Run 保留引擎、状态、时间、真实用量和有界结果摘要。
5. 报告未生成或读取失败时提供明确的补齐/重试入口，已有报告不会因一次失败消失。
6. 日报、周报、月报标签各有独立重新统计按钮；任务的新建/完成清单分别每页 20 条，AI Run 按快照中的最新顺序每页 20 条，长标题和结果不得撑出业务区。
7. 页面内可编辑团队共享设置：自动刷新开关、上海时间起始点、1/3/6/12/24 小时频率、自动刷新的报告类型和汇总项；保存中、已保存、失败重试均有明确状态，后台读取不覆盖未保存草稿。

## 周期与产出

- 全部边界使用 `Asia/Shanghai`。
- 日报覆盖 00:00（含）至次日 00:00（不含），周报覆盖周一至周日，月报覆盖自然月。
- 默认从每日 00:00 起每 24 小时刷新一次最近完整日报、周报和月报；成员保存的起始时间、频率和报告类型由 Linux 主节点下一次分钟探测读取，无需重启。
- Linux 主节点启动时按已启用设置补齐最近结束的周期；同一周期重复生成只更新一份快照。

## 数据与真实性

- 新建任务按 `task.created_at` 归属周期，完成任务按 `task.completed_at` 归属周期；同一任务可同时具有两类事件。
- AI Run 按 `ai_task_run.created_at` 归属周期。`succeeded`、`failed` 分别统计，其它真实状态仍进入运行总数和清单。
- Token 只累加数据库中非空的 `total_tokens`；未回传用量的运行单独计数，不当作零消耗已记账。
- 快照保存必要标题、状态和链接元数据，不读取密码本、个人记忆、任务描述或运行提示词。
- 汇总项支持“新建任务”“完成任务”“AI Run 与 Token”；重新统计只查询并保存当时选择的真实数据，并把选择写入快照，旧报告不随全局设置变化。
- 没有真实记录时显示 0 和空数据说明，禁止静态示例、随机数或模型补写。

## 状态与验收

- 后端测试覆盖日/周/月边界、未来或未结束周期拒绝、任务双事件、AI Run 状态与 Token 统计、设置校验、调度命中和汇总项裁剪。
- 前端测试覆盖三类切换、加载、空数据、失败重试、逐类手动重算、设置保存、20 条分页、前后周期和任务跳转。
- 窄屏下统计、任务和运行清单改为单列，长标题和结果摘要不产生业务区水平滚动。
- 部署后确认主节点调度开关启用、接口返回数据库真实快照、页面可切换，并确认本次 main 发布成功且没有成功飞书卡片。
