# 小记同源页签草稿隔离

补充 `notes-single-latest-content.md`，不改变单份最新正文和服务端 CAS 保存规则。

## 已复现问题

两个同源页签在同一小记中分别输入 A、B 后，刷新 A 恢复成 B。旧存储键只有成员与小记，没有编辑页签，最后一次浏览器写入覆盖另一份尚未提交的输入。

## 决定

- 同一成员、同一小记的每个独立页签使用各自持久草稿键；sessionStorage 只保存页签身份和恢复标记，正文仍保存在 localStorage。
- 当前页签刷新、收起、重新编辑优先恢复自己的草稿。新页签首次打开时自动恢复最近一份已有草稿并复制为自己的独立副本，继续只有一个编辑正文，不增加版本选择界面。
- 保存成功只清理本页签副本；同一页签后续打开读取服务器，不能自动接管其他页签未保存的输入。其他页签的独立草稿保留。
- 兼容旧共享键：首次恢复先写入自己的持久键，成功后才条件移除相同旧值；旧客户端后来写入共享键不得覆盖本页签已恢复的内容。
- 新建区、全局新建弹窗、卡片预览、失败任务重试判断与删除后的本地清理统一使用上述存储边界。
- 存储失败继续明确提示，不宣称草稿已保护。清理不得通过删除所有成员或全部 localStorage 实现。

## 验收与边界

验证两页签不同草稿的刷新恢复、一方成功/失败不清除另一方、收起与卡片预览一致、成员隔离、旧键迁移、持久写入失败和新页签恢复。使用两个独立打开的同源页签；浏览器“复制页签”可能复制 sessionStorage 身份，需另验，不把本次结果扩展为浏览器崩溃或所有标签复制行为的保证。

本变更仅调整浏览器本地草稿；不新增业务 API、CLI、MCP 权限或数据库 migration。
