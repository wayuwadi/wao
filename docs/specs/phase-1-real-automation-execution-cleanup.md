# Phase 1：自动化真实执行收口

需求来源：WAO 任务 `t1787800163678` 的生产 Mock 补漏。

## 问题

设置偏好与前端演示入口退役后，自动化服务仍保留 V8 写入的四条描述性任务及十二条演示运行记录。更严重的是，任务没有真实 `handler` 时，手动或定时触发仍会写入“成功”以及按步骤数推算的耗时，用户无法分辨真实执行与模拟结果。

## 用户结果

- 自动化页面只展示已接入服务端 `JobHandler` 的真实任务和真实运行结果。
- 已知的手机相册 / NAS、账单邮箱、证件台账等演示任务没有可靠接口或生产配置，因此直接移除，不伪造接入。
- 任务缺少执行器或执行器名称未登记时写入明确失败记录，不再产生成功假象。
- 新运行的 `durationMs` 使用服务端单调时钟测量真实执行耗时，不再按描述性步骤数量推算。
- 浏览器只在服务端确认成功后更新任务和运行记录；离线或请求失败时显示真实错误，不再回落为本地“成功”。

## 数据与兼容

- 新增 migration 只删除仍无 `handler` 的 V8 固定种子 id `j1`～`j4` 及其演示运行记录；若固定种子曾被接入真实执行器则完整保留，不按名称或内容猜测。
- 飞书群聊同步、HTTP 性能 AI 巡检、共享聊天夜间核对及飞书通知等已登记真实执行器保持不变。
- 历史真实运行记录可能没有绝对时间，旧的估算耗时也不回写；新记录从本次变更起保存实测值。

## 验收

- migration 版本唯一，且 SQL 只命中四个固定演示 id。
- 无执行器任务手动触发后保存“失败 · 未配置真实执行器”和零耗时。
- 已登记执行器继续保存其真实返回结果，执行异常继续保存真实失败原因。
- 前端断网、接口失败时保持原任务状态，不生成本地任务或运行记录，并提供可见失败提示。
- 完整后端测试与 Flyway migration 测试通过；合并后部署成功并确认线上健康、提交状态和飞书通知。
