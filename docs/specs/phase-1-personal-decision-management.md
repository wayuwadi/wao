# Phase 1：个人决策管理

对应任务：`t1788167995900`。数据与交互决策见 [ADR-182](../adr/182-personal-decision-management.md)，个人权限、
版本和检索边界沿用 [统一记忆中心规格](phase-1-unified-memory-center.md)。

## 用户结果

1. 登录成员从“个人 → 决策管理”新增一条选择原则，写明适用情境、具体决定和原因。
2. 列表只显示当前账号有效的确认决策，可按标题或正文搜索；无数据、加载中和失败均有明确状态。
3. 成员可编辑并发布新版本；另一设备已先更新时，本机表单和草稿不丢失，可比较后重试。
4. 成员可明确废止不再适用的决策；历史版本仍可从记忆中心核对，但不再进入默认列表和 AI 检索。
5. 新建与编辑输入在本机自动保存草稿，保存中禁止重复提交，失败后保留内容和重试入口，窄屏可完成全链路。

## 数据与接口

- 权威数据源是 `memory_document / memory_revision` 的 `scope_type=personal`、`category=decision` 记录；范围 id
  必须等于当前登录成员，页面不能指定其他成员。
- 列表、新建、修订和废止分别复用 `GET/POST /api/memories`、
  `POST /api/memories/{id}/revisions`、`POST /api/memories/{id}/archive`。
- “适用情境 / 决定 / 原因”以普通 Markdown 小节保存。不存在这些小节的历史正文仍完整显示为具体决定，不改写存量。
- 页面不自动生成决策，不把任务描述或示例写成用户的真实决策。

## 验收

- 以两个账号分别新建决策，双方列表只能看到自己的记录；个人 MCP 可检索本账号刚发布的决策。
- 用“去武汉的出行方式”录入情境、决定和原因，刷新后内容一致；在记忆中心能看到相同记录和正式版本。
- 两个浏览器同时编辑同一条记录，后提交者得到 409，输入仍在；刷新并重新编辑后可发布下一版本。
- 废止后决策从默认列表和 MCP 搜索消失，记忆中心显式筛选已废止状态仍可查看历史。
- 模拟列表和保存请求失败，页面分别提供重新加载与原表单重试；手机宽度下按钮、字段和长文本均可见。
