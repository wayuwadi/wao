# 小记正文润色独立模型设置

用户确认日常润色优先速度，并要求保留可调整入口。本规格补充 [保存后自动整理](notes-save-ai-settings.md)、[选区可靠替换](notes-selection-polish-reliable-apply-2026-10-10.md) 和 [设置规范](../design/settings-ui-pattern.md)。

## 入口和默认

小记设置与全局小记 AI 设置共用「正文润色」分项，顶部独立选择处理模型和思考深度，下方保留原有正文提示词。未配置专用字段时默认 `gpt-6-luna` / `low`；复杂改写可明确选择 Astra 等当前目录中的模型。标题、标签、配图保留原有公共模型与深度，不随润色选择改变。

目录来自实际服务主机 Codex。刷新不替换已有模型或不兼容档位；不可用时显示恢复提示、保留草稿并阻止保存。默认标签正确对应本分项的低思考档位。复用既有设置外壳、分项布局、模型控件、成员隔离草稿与固定保存栏。

## 契约与执行

既有 `GET/PUT /api/docs/notes/ai-settings` 的 `settings` 增加可选字符串 `polishModel`、`polishReasoningEffort`，保存在 `note-ai-defaults-v1` JSON 中，不新建表或修改已执行迁移。GET 返回真实有效默认；配置读取不写回或改变原始配置指纹。老客户端 PUT 省略新增字段时保留账号当前专用选择。

聚合保存继续采用 `expectedVersion` CAS；服务端核对精确模型标识及目录支持的思考深度。关闭开关、提示词、其他配置和原有代次语义保持不变。旧本机草稿补足专用默认但保留原 CAS 基准，读取、保存失败与冲突不能清空草稿。

`DOCUMENT` 选区与 `NOTE_BODY` 整篇润色统一从已认证成员读取专用设置，不能使用内部 AI 操作标识读取用户偏好。新提交时将模型与深度写入持久 AI 任务，之后改设置不改变已入队任务；相同请求号返回旧任务，不重新执行。旧整篇请求的公共 `model` 不覆盖账号专用润色选择。工作台与获准 API 路由保持原准入，本配置仅作用于本机 Codex 润色，不擅自增加付费通道。

已有结果对照、原稿留存、确认替换、事实和图片保护保持原样。速度以同输入真实执行结果为准，不宣称固定秒数或未经测量的倍数。

## 能力与验收

成员 AI 偏好仍仅由浏览器会话管理，不扩展 CLI/MCP 旧令牌，不新增工具。服务、参数、配置隔离、旧客户端兼容、CAS、任务幂等和界面草稿均有回归；真实链路在既有数据库完成配置保存重开、实际模型生成和结果替换。补充明暗主题、390/320px、键盘与真实目录验证；实体手机体验由用户验收。
