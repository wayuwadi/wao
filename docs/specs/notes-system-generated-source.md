# 小记系统文章来源与展示

2026-10-06 用户要求交付 Skill 生成的功能介绍显示“系统”、整张卡片有颜色区别，并能在筛选里开关显示。

- `Doc.systemGenerated` 是持久化展示来源，默认 false。真实 `author`、成员目录、编辑和共享权限保持原业务规则，不创建系统账号，也不把客户端的来源标记当成特权。
- 系统文章在卡片、阅读目录、阅读元信息和知识库文档详情中显示“系统”。整张卡片使用主题兼容的蓝紫浅底、强调边框和系统徽标；普通小记经过 AI 润色、配图或带“新功能介绍”标签不会自动变为系统文章。
- 筛选第一项提供“显示系统文章”滑动开关，默认打开；关闭仅隐藏这类文章，保留个人记录、未保存草稿及其他筛选。按成员持久化偏好，清除筛选恢复打开。作者选项将系统来源独立列为“系统”，个人作者只对应个人记录。搜索、标签、图片、时间、分页和阅读目录在来源筛选后继续工作。
- 系统文章不计入本人“今日写字”统计。历史文章默认个人来源，仅对已确认由 Skill 生成且用户要求调整的本人文章补标，不按名称、作者或标签批量猜测。

## 写入与并发

新增 V185 的 `doc.system_generated TINYINT(1) NOT NULL DEFAULT 0`。创建与正文同事务保存，目录与详情返回一致；普通编辑和标签更新省略来源时保留已有值。

Web 创建小记支持 `systemGenerated`；局部文档更新同字段只用于小记且必须传 `expectedRev`，存在实际操作成员时只能更改本人的来源。版本冲突保持原内容和输入。

MCP `create_note.system_generated` 默认 false；`update_document.system_generated` 在已有操作权限与知识库范围内更新本人小记，必须携带 `expected_rev`，不替换正文或标签。只读连接拒绝，错误类型拒绝。不新增工具、AI 执行权限或扩大旧令牌；旧文档创建流程可创建后用受版本保护的更新补标。`list_notes.include_system` 默认 true，false 在分页前排除系统文章，摘要仍返回真实所有者与 `systemGenerated`。

CLI 通过实时 schema 支持 `notes create --system-generated true`、`notes update ID --system-generated true --expected-rev REV` 和 `notes list --include-system false`；旧服务不声明参数时拒绝，不能以作者改名或标签代替来源。

本机 wao-delivery-story 在创建或兼容补标时显式提交系统来源，并保留既定“新功能介绍”标签。保存回读必须验证来源、真实所有者、正文、标签及修订号；公开 Skill 包更新仍遵循用户实际发布授权。

## 验收

覆盖创建持久化与真实所有权、同 id 重试、普通编辑保留来源、目录与详情、元数据 CAS、本人/只读/类型拒绝、分页排除、卡片和阅读作者、开关持久化、草稿防丢、窄屏与两种主题。实际用户文章补标仅修改来源，回读比对正文及其他元数据。
