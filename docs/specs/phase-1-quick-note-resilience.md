# 规格：小记草稿防丢与幂等创建

2026-10-04 扩展：`PUT /api/docs/notes/{id}` 可携带 `createOnly: true`。已有同作者、未删除的小记原样返回，不更新正文、标签、rev，不触发新的保存信号；ID 被其他作者、知识库或回收站占用仍拒绝。不传时保持原重试更新语义。移动端首次创建使用此标记，后续编辑使用 PATCH 的 `expectedRev`；见 [iOS 采集规格](ios-notes-system-capture.md)。

对应任务：`t1786855008126`（从高频记录入口自主寻找提效空间）。

## 问题

全局「新建小记」虽然已经会按创建人自动归档，但输入内容只存在于弹窗内。误触关闭、刷新页面或服务端写入
失败都会让用户失去当前上下文；更严重的是，真实 API 写入失败时前端会回落成仅存在内存里的本地小记并提示成功，
刷新后才发现内容没有落库。若服务端已经写入、只是成功响应在弱网中丢失，重新提交还可能生成重复小记。

## 规则

- 小记正文按当前成员保存到浏览器本地草稿；关闭弹窗或刷新页面后再次打开可以继续输入，成员之间不共用草稿。
- 弹窗明确显示真实归档目标「小记 / 当前成员」，与服务端按创建人文件夹归档的规则一致。
- 真实后端在线时，小记只在服务端确认后显示成功；失败不回落为内存假数据，弹窗保留正文并提供原地重试。
- 客户端为一份草稿生成稳定的 32 位文档 ID，使用 `PUT /api/docs/notes/{id}` 创建或重试；同一成员用同一 ID
  重试时更新同一篇小记，不重复插入，也不重复发送飞书创建通知。
- 提交期间禁用编辑、关闭与重复提交；成功后才清理草稿。明确标注的离线演示态仍可沿用本地创建。
- 已有 `POST /api/docs/notes` 保留兼容；Web 端使用新的幂等 `PUT` 接口。

## 验收

- 输入正文后关闭并重新打开弹窗，正文仍在且显示“草稿已保存”；保存成功后再次打开为空白。
- 模拟服务端失败时，弹窗不关闭，显示“未保存到服务器，草稿仍在”，按钮变为“重试保存”。
- 同一 ID 首次写入与再次重试只保留一篇文档；第二次正文有变化时更新原文档，不再次发送飞书创建通知。
- 娃哥与娃弟在同一浏览器分别输入草稿时互不覆盖，归档提示与最终 `folderId` 对应各自成员文件夹。
