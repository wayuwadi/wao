# 规格：新建任务落库反馈与失败重试

对应任务：`t1786605779378`（真实用户链路小范围体验走查）。

## 问题

新建任务表单和项目分组的快速新增此前都会先插入本地任务，随即关闭或清空输入并提示“已创建”；
服务端请求在后台失败时，用户仍会看到成功反馈，刷新后才发现任务没有落库。弱网重试若重新走服务端生成
ID 的创建接口，还可能产生两条内容相同的任务。

## 规则

- 提交后任务仍即时出现在本地列表，但入口进入“正在创建 / 提交中”，成功提示必须等待服务端确认。
- 新建使用服务端支持新增的 `PUT /api/tasks/{id}`，重试沿用同一个本地任务 ID，避免响应丢失后重复创建。
- 失败时不关闭表单、不清空快速新增输入，也不显示成功；明确提示“未保存到服务器”。
- 完整表单的既有草稿继续保留；失败后修改字段再重试时，把最新内容写入同一条本地任务。
- 提交期间禁用重复提交和关闭按钮；手机底部操作区继续固定在安全区上方，失败提示与重试按钮可见。
- 离线原型状态不伪装成服务端写入，但保留既有本地交互，供单元测试和明确标注的演示环境使用。

## 验收

- 延迟任务写入响应时，列表即时出现任务，表单显示“正在创建”且不能重复提交；收到成功响应后才关闭并提示成功。
- 任务写入失败时，完整表单的标题、描述和草稿仍在，并提供“重试创建”；重试成功后不产生第二条本地任务。
- 分组快速新增失败时，输入内容和分组归属仍在，行内出现失败提示与“重试”；成功后才清空输入。
- 在 390px 宽度下，提交中和失败状态均位于贴底操作区，按钮不被安全区遮挡，页面无新增横向滚动。
