# Phase 1：飞书三阶段任务表情工作流

本规格修正 `phase-1-feishu-task-reaction-workflow.md` 中把“已收下”和“人工派工”合并的部分；身份、项目、
Runner、幂等和失败恢复边界保持不变。决策见 [ADR-176](../adr/176-feishu-three-stage-reaction-and-polling.md)。

## 用户结果

1. 群聊 `@机器人` 成功保存任务后，原消息显示 Get，含义只是不丢想法、WAO 已了解。
2. 已绑定的任务创建者给原消息添加飞机后，系统自动创建一次 Plan AI Run；执行期间原消息显示飞机。
3. AI Run 成功并进入待验收后，原消息显示 Done；失败仍有 Error，不伪装成完成。
4. 管理员可以分别修改“已收下”“人工派工 / AI Run 中”“完成待验收”三个表情，草稿与保存失败行为沿用
设置页统一交互。

## 触发与安全边界

- 默认值为 `GET` / `StatusInFlight` / `DONE`，可选值为 `GET`、`DONE`、`StatusInFlight`、`CheckMark`。
- 新消息每 15 秒主动读取；近 24 小时消息每分钟回看编辑与指定表情。事件回调配置完整时可更快触发，
  但两条入口必须复用同一身份校验和持久幂等记录。
- 非创建者、未绑定账号、非快速收集原消息、非 user 操作人和非当前 trigger 表情均不得派工。
- 已消费的消息不重复读取表情；重复 reaction_id、重复事件或双节点竞争只允许产生一条 AI Run。

## 验收

- 新建任务只新增 Get，不因机器人自己的 Get 自动派工。
- 给原消息添加飞机后在一分钟内出现一条 Plan AI Run，重复轮询不产生第二条。
- 网页派工和人工表情派工进入运行后均添加飞机；成功待验收后新增 Done。
- 修改三个配置后，创建回执、触发条件、执行中与完成回执全部使用保存后的值。
