# 知识库权限

知识库新建时由服务端记录当前会话或工作区令牌成员为 `ownerId`，默认 `仅自己`；请求体不能指定所有者或隐式公开新库。所有者在知识库设置中选择 `成员可编辑`，才允许组织内已登录成员查看和编辑。只有所有者可以修改知识库设置、共享范围或删除整库。普通协作者可管理库内文档和目录。

HTTP 知识库、文档列表/目录/正文/归档、协同心跳、模板来源、回收站、反向链接、收藏、项目动态、AI 资产引用及工作区 MCP 使用相同的知识库范围。不可访问的对象统一返回 404；空的成员身份不能回落为系统身份。工作区令牌仍需通过既有能力与资源范围校验，不增加旧令牌的能力。可信进程内归档任务保留系统调用能力，用户发起的 HTTP 请求不能使用该能力。

库内图片和附件受来源文档的知识库权限约束，包括资源库列表和直接 URL。相同资源被多篇文档引用时，有权访问至少一篇未删除来源文档的成员可以读取。已存在的限时公开快照继续通过令牌和快照内图片清单授权，普通文档 ID 不能兑换公开访问权限。小记容器继续使用已有的小记行为，不将个人知识库所有权强加到系统小记容器。

撤销共享后，后续服务端读取、修改与心跳立即拒绝；界面重新打开文档会校验权限，知识库刷新清理不可访问的正文缓存。本机未保存草稿仍保留在成员隔离的草稿存储，不能自动重新提交到无权访问的库。已被授权用户读到或自行复制的内容无法追溯收回。

## 历史安装迁移

历史库未记录创建者，不能从首篇文档作者推断归属。部署 V201 前，维护者根据用户明确指定的成员，在私有数据库设置 `system_setting.cfg_key = 'knowledge.legacy-owner-member-id'`，其值必须为真实成员 ID。迁移仅为已有非小记库补充所有者，保留原有共享设置及全部正文和目录。不配置时旧私有库保持未认领并拒绝普通访问，不能自动选第一个管理员或默认公开。

发布前备份数据库，核对成员 ID 与账号对应关系、旧库数量和共享值；发布后核对 V201 成功、所有者分配、新建私有/共享/撤销以及无关成员直链访问。此迁移仅增加可空列和索引，旧版本代码可以回退，但回退旧代码也会恢复旧权限缺陷，因此应优先修复前滚。不得通过 Flyway repair、修改旧迁移或重建数据绕过问题。

## API 与 CLI

- `GET /api/kbs`、`GET /api/kbs/{id}` 新增只读 `ownerId`。
- `POST /api/kbs` 始终创建当前成员的私有库。
- `PATCH /api/kbs/{id}` 的 `perm` 仅接受 `仅自己`、`成员可编辑`，仅所有者可修改。
- 既有工作区 MCP/CLI 知识库、文档和搜索操作沿用原协议，使用令牌成员重新校验上述权限。
