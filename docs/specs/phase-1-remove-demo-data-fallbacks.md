# 规格：移除业务数据 Demo 回退

对应任务：`t1787651573278`（数据未加载时不展示 Demo 数据）。

## 问题

领域数据 store 在应用启动时注入整套原型 fixtures。虽然真实接口成功后会替换对应列表，但慢请求期间页面会把虚构项目、知识库、自动化、密码库、日程、建议和目标展示成当前用户的数据；部分接口失败时，这些内容还会长期保留，用户无法及时发现读取异常。

任务域已在 `phase-1-task-real-data-loading.md` 中单独禁止 fixtures，本规格把同一约束扩展到全部业务域。

## 规则

- 生产 store 的项目、任务、知识库、文档、自动化、文件、图片、密码库、日程、建议和目标均以空值初始化，只接受真实 API 返回结果。
- 首次请求未完成时展示明确的“正在加载业务数据”提示；项目页在项目接口返回前不得渲染项目卡片或真实空状态。
- 各业务域独立记录加载结果。一个接口失败不得阻止其他成功结果接管页面，也不得回退到原型数据。
- 任一业务域失败时显示可见错误和“重新加载”入口；真实空数组仍是成功结果，应显示该页面已有的空状态。
- 测试夹具只能由测试代码显式注入，不能进入生产加载链路。
- 本次不删除既有 Flyway migration，也不根据内容猜测并删除可能已被用户继续使用的数据库记录；数据库返回的数据视为真实持久化结果。

## 验收

- 延迟项目接口时，项目页只显示加载提示，页面中找不到原型项目标题。
- 项目接口失败时，项目列表保持为空并显示错误与重新加载入口。
- 其他业务域失败时，全局提示列出真实错误；成功域仍能展示接口返回的数据。
- 接口返回空数组时结束加载，进入既有空状态，不展示 Demo 数据。
- 生产构建产物中不包含 `src/data/fixtures.ts` 的原型项目标题。
