# 规格：阴阳历日历提醒、群通知与事项搜索

对应任务：`t1787793034587`（日历功能优化）。决策见
[ADR-136](../adr/136-calendar-lunar-group-reminders.md)。

## 用户结果

- 从日历日期格或日/周时间轴创建事项时，先选择“任务”或“提醒事项”；任务继续进入个人事项，提醒事项独立持久化，不伪装成待办。
- 提醒事项可切换公历或农历录入。每次修改日期后由服务端权威换算并同时显示另一种历法；农历事项以后按农历月日逐年展开。
- 日历显示全部二十四节气，并继续显示中国法定休息日、调休上班日和成员主动选择的国际节日。
- 提醒事项可在当天或提前 1 至 30 天、指定上海时区时间通知；通知可私聊配置人，也可发送到机器人真实所在的所选飞书群并只 `@` 配置人。
- 日历顶部可显示或隐藏已完成任务；关键词搜索覆盖当前日期窗内的任务、提醒事项、节气、节假日、里程碑和 CalDAV 事件，点击结果切到当日并打开已有详情或只读预览。

## 真实数据与安全边界

- 阴阳历转换、农历年度展开和二十四节气均使用仓库锁定的 `cn.6tail:lunar:1.7.7`，不在前端维护易漂移的静态日期表。
- 法定放假、调休仍遵循既有节假日规格：只展示依赖已收录国务院安排可确认的“休/班”，未收录年份不推测。
- 飞书群列表来自 `/api/feishu/chat-sync/chats` 的官方接口结果。群通知复用已配置自建应用，不接受手填群 id。
- 飞书 Open ID 按应用隔离。服务端使用登录身份已保存的 Union ID，在目标群两种 id_type 的成员列表中按唯一昵称配对；重名、退群或缺少 Union ID 时拒绝保存/发送，不能猜测要 `@` 的成员。
- `family_important_date` 表名为兼容已上线数据而保留，产品语义扩展为“日历提醒事项”；既有公历私聊记录默认行为不变。

## 状态与失败恢复

- 日期转换、群列表和事项列表都有加载、失败提示与重试；转换失败时禁止保存，不把无效农历日期落库。
- 编辑草稿按成员和事项 id 存在浏览器本地，包含历法、农历年/月/日、提醒天数、通知方式和目标群；保存成功或主动取消后清理。
- 提醒投递继续按“事项 + 实际发生日期”唯一，多节点不能重复发送；失败五分钟后重试，最多六次。
- 群投递时重新校验 Union ID 到目标群 Open ID 的唯一映射；不能唯一映射则记录失败，不降级成不带 `@` 的群消息。

## 验收

- 录入 2026 农历正月初一时显示对应公历 2026-02-17，保存后在 2026 年日历的该日出现，详情同时显示两种历法。
- 2026 年自然年能找到 24 个“节气 · …”节点，包括立春、春分、夏至、冬至。
- 选择真实飞书群、提前 1 天 09:00 后，投递卡片只 `@` 配置人；相同事项和发生日期不重复投递。
- 已完成任务可一键隐藏并恢复；搜索命中提醒事项后切换到日视图并打开该事项编辑预览，CalDAV 搜索命中后显示只读预览。
