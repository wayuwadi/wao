# 更新说明：发布区间、具体入口与分层开箱

日期：2026-10-06。沿用 `update-unboxing-2026-10-04.md` 的卡片内开箱与按需大图演示，替代其仅取 HEAD 及双份手填说明的规则；保留旧档案兼容。

## 用户目标

一次更新说明本批次实际变化、用途和使用步骤。标题只出现一次，变化点和步骤同时存在。先展示三个重点，每项默认两个变化点及两个步骤；其余内容通过明确的展开按钮访问。复杂演示由用户主动打开，不恢复固定三页欢迎流程。

## 发布边界

- `WAO_CHANGE_BASE` 必须为上次实际交付的完整 SHA，且位于构建 HEAD 的首父链。区间为 `(base, HEAD]`；边界本身不重复展示。
- 容器无 Git 时，主机导出 `WAO_GIT_RELEASE_RANGE` 首父链 TSV（SHA、完整父节点），与完整提交档案交叉校验端点、父链与覆盖。
- 缺少可靠边界时只说明 HEAD，`rangeVerified:false`，不宣称汇总完整发布批次；base 等于 HEAD 时没有新增变化。
- 全部可达提交仍进入制品提交档案。文档、测试、CI 等维护变化不生成功能亮点。缺少人工说明的功能提交展示真实标题及说明缺项，不生成虚构教程。
- 同功能不同变化独立保留，按稳定变化身份去重；不按功能 id 删除其他改动，不截断整个批次。

## 单一说明来源

每项用户可感知改动在 `wao-web/src/data/releaseChanges/` 增加一个 JSON。`sourceSubject` 精确对应最终 Squash 标题，忽略末尾 PR 编号；`id` 稳定，保留 `publishedOn/title/intro/highlights`。历史文件兼容但新内容不再重复编辑 `currentRelease.json` 和 `releaseHistory.json`。历史介绍仅在构建 HEAD 的提交中找到匹配来源后显示，按提交顺序排序。

亮点包含用途 `summary`、变化 `points`、操作 `steps`，以及可选登记动作 `action` 和专用 `demo`。构建校验身份、格式、动作关联、演示类型及制品图片存在性；冲突说明或缺失图片阻止构建。操作图必须对应功能，无法维护的示意不冒充真实截图。

## 精确体验入口

`releaseActions.json` 是允许入口的登记表，清单仅引用 `target` 与按钮文案，不提供任意 URL：

| target | 实际行为 |
| --- | --- |
| notes-compose | 原地打开快捷记录 |
| notes-settings | 小记页打开小记设置 |
| notes-reading | 等真实数据加载后进入已有小记阅读 |
| notes-ai | 等真实数据加载后查看本人小记 AI 成果 |
| workspace-connections | 能力中心的我的连接 |
| release-updates | 功能页最近更新锚点 |

同页保留筛选；重复体验生成独立请求，消费完成移除意图参数。空数据给出引导，不生成测试小记。打开已有内容不自动写入正文、运行 AI 或修改设置。有快捷编辑弹层时拒绝替换；页面记录草稿沿用既有保护。专用阅读示意展示双击编辑与返回阅读，连接示意对应实际能力中心。

## 提醒等级与保护

仅明确 `prominence:major` 的用户新能力自动展开和播放登场；普通改进与修复为 `minor`，仅显示更新提示；维护更新安静保留手动入口。未声明等级默认 minor。编辑、安静模式、后台或保存屏障期间延后重大提醒。保留版本匹配、请求失效、同标签页版本去重、错误重试、焦点、减少动态效果及窄屏首次定位保护。

## MCP / CLI 评估

本次为浏览器更新说明与既有页面入口，未新增业务操作或后端 API。MCP 与 CLI 的业务工具不扩权、不需要新命令；连接说明指向已存在的能力中心。构建元数据可在公开制品中读取，不把 UI 演示注册成业务工具。

## 验收

Git 真实夹具验证区间、侧分支、未知边界、相同版本、无 Git 导入、稳定去重与校验失败。组件及路由测试验证变化与步骤共存、全部展开、精确入口、重复请求、草稿保护、空数据、等级提醒和异步请求。类型检查与生产构建完成后，仍须在连接真实数据的浏览器中验收，再按 ADR-325 交付公网；编译和模拟数据测试不能替代真实体验验收。
