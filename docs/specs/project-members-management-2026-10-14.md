# 项目成员管理

- 项目设置直接展示成员；负责人可从真实组织目录添加成员，也可移除共享成员；负责人始终保留，普通成员只读。
- 点击「保存并关闭」后生效，关闭沿用现有自动保存；加载失败可重读，保存失败保留选择并允许重试，保存期间禁止重复提交。界面分项见 [项目设置重设计](project-settings-redesign-2026-10-14.md)。
- 未编辑成员不回写旧成员快照，后台刷新不覆盖当前选择；修改提交 `members` 和编辑前 `expectedMembers`。后端先校验可见性、负责人身份和组织成员，再核对原成员集合，用原 `detail_json` 做条件更新；并发变化返回 409，窗口提供读取最新成员入口，按原快照计算本次添加和移除并合入最新列表，保留其他窗口新增成员，用户确认后再保存。
- 项目负责人、任务、文档和其他详情保持；移除后既有项目可见性规则拒绝被移除成员读取项目，显示的可见范围人数同步更新。
- 复用 `PATCH /api/projects/{id}` 和 `detail_json`，没有数据库迁移；省略 members 保持历史兼容。members 空数组仅保留负责人，expectedMembers 修改时必填。
- 工作区 MCP 与 CLI 的旧令牌没有共享管理授权，本次仅提供浏览器会话操作，不扩大令牌权限。创建时的组织可见开关保持现有行为。
- 验收：私人项目添加、共享项目移除、负责人保留、非负责人拒绝、未知成员拒绝、失败重试、旧快照冲突与真实数据库条件写入。

实际数据库验收注意：detail_json 是 MySQL 原生 JSON，条件更新使用 CAST(参数 AS JSON) 做结构比较，不能直接拿 JSON 对象与 SQL 字符串比较。
