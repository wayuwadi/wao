# Phase 1：飞书定时通知与反馈报表

决策见 `docs/adr/035-feishu-scheduled-notification-feedback.md`。

## 用户路径

1. 管理员在「自动化 / 定时任务」新建任务，填写 Cron、标题和正文，并勾选「飞书群提醒 / 公告」。
2. 到点或手动运行时，WAO 使用「飞书群聊同步」里已配置的自建应用向已选群发送卡片；卡片有「做到了」「没做到」两个回传按钮。
3. 飞书通过独立的卡片回传交互 `card.action.trigger` 回调到既有 `/api/feishu/events`，WAO 从官方回调的操作者 `open_id` 记录真实点击人、通知时间、事件与反馈，并在群里的原卡片消息上用勾选 / 叉号表情标记结果。未点击不写反馈，报表中就是空，绝不补造结果。
4. 自动化页的「反馈报表」可查看日、周、月、总统计与明细；例如「喝水提醒」按日可看到做到人数与没做到人数。

## 验收标准

- 未配置自建应用凭据或目标群时，通知任务运行记录为明确失败，不回退到普通 webhook（普通 webhook 无法可靠取得点击人）。
- 每位用户对同一张通知卡片只保留一条最新反馈；同一用户重选会更新结果。
- 点击“做到了”后原卡片消息出现勾选表情，点击“没做到”后出现叉号表情；表情添加失败时明确提示重试，已保存的反馈不丢失。
- 服务重启后已发送卡片的回调仍能归属，因为通知发送事件与反馈独立持久化。
- 只有飞书回调产生的数据进入报表；没有反馈时显示空状态。

## 飞书侧配置

在飞书开放平台打开现有应用的「事件与回调 → 回调配置」，为「卡片回传交互」配置
`card.action.trigger`，请求地址填写 `https://wao.wayuwa.cn/api/feishu/events`。这与同页的「事件配置」是
两个独立入口，不能只在事件订阅中配置群消息事件；应用还需要机器人能力和以应用身份发送群消息权限。
