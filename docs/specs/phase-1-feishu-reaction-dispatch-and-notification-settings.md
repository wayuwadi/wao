# Phase 1：飞书表情派工与通知设置

对应任务：`t1787907975092`。决策见 [ADR-155](../adr/155-feishu-reaction-dispatch-and-notification-policies.md)。

## 用户链路

1. 已绑定 WAO 的成员在自己 `@机器人` 创建任务的飞书原消息上添加飞机，任务按项目默认工作流立即进入一次 Plan AI Run；
   重复回调或双节点只产生一条运行，他人添加飞机不越权派工。
2. 入队成功后机器人在同一消息添加飞机确认，完成后添加完成勾；入队失败尽力添加错误表情，不发噪音卡片。
3. 通知中心标题栏可进入“设置 → 通知设置”。管理员编辑共享的群通知策略，普通成员只读系统策略；每个成员独立编辑
   自己的站内事件类型。
4. 默认不发送任务完成、AI Run 成功或普通任务动态；AI Run 失败、人工通知和无人值守启动说明保持开启。
5. 任务详情提供人工通知按钮，点击后只有真实发出 Webhook 卡片才显示成功。
6. 通知中心最新动态每条压为一行，点击进入详情；三个统计入口使用固定短摘要，不再以省略号截断描述。

## 状态与边界

- 设置页面覆盖加载、未保存、保存中、已保存、失败重试和离开草稿确认；后台刷新不覆盖本地草稿。
- 系统策略、项目通知开关和 Webhook 开关同时生效；任一关闭都不伪装为发送成功。
- 飞书表情派工要求事件订阅配置 Verification Token 或 Encrypt Key；无可信回调时不接受可伪造的派工请求。
- 没有快速收集消息关系、绑定身份、项目 AI 工作流或可用 Runner 时不创建占位运行。

## 验收

- 后端单元测试、Flyway migration 测试与完整 `mvn test` 通过。
- 前端通知设置、通知中心和任务人工通知组件测试与生产构建通过。
- main 部署后完成真实飞书 reaction → AI Run → 部署终态链路并核对线上页面。
