# 任务详情分区布局

2026-10-08 用户确认「分区页签」方案。适用于项目内及其他入口打开的任务、子任务详情。

## 布局与交互

- 面包屑、标题、常用状态摘要与「概览 / 描述 / 子任务数量」导航保持可达。首次打开显示概览。
- 概览只展示描述原文的前三行预览，图片用提示代替实际高度，子任务紧接其后。预览不调用 AI、不改写正文；空描述可直接进入描述分区补充。
- 描述分区承载现有编辑器、历史图片、步骤及附件；保留自动保存、失败重试、冲突提示和本机草稿语义。切换分区不卸载编辑器。
- 概览和子任务分区复用同一个子任务列表，不重置尚未提交的新增输入、个人顺序、已完成筛选。完整任务的父子关系保留导航，完整子任务入口移入子任务区。
- 在详情中打开下级再返回时，恢复该对象先前的分区与滚动位置。新打开另一对象默认概览，关闭详情后不持久化浏览位置。
- 标题下保留真实状态、优先级、负责人及保存反馈；属性、关联和评论按需展开。桌面显示辅助侧栏，760px 以下显示单独的内容区域，通过「收起」或 Esc 返回正文；输入不因收起销毁。
- 页签支持方向键、Home、End 和键盘焦点，显示选中态与子任务数量；长标题限制在可滚动的标题区，不将导航挤出窗口。

## 边界与验证

只调整 Web 展示和浏览状态，不新增 API、MCP、CLI、数据库字段或迁移。现有任务保存、权限、分享和子任务四态保持原语义。

同一公共布局用于 `/design` 的明确标注演示。验收覆盖长描述与长图、任务及多级子任务、分区切换草稿保留、返回位置、属性评论、空数据、保存失败和冲突，以及明暗主题、320/390px、键盘与触屏；正式验收使用本地服务连接既有线上数据库。
