# Phase 1：团队共享点子库

## 目标与边界

点子库是独立于项目和任务的团队共享域。它承载从低成本记录，到调研、判断、对齐、MVP、验证和人工结案的完整证据链；负责人只是责任归属，所有已登录团队成员都可以编辑和推进。第一版仅提供登录后 WAO 页面手工录入，不改变飞书机器人创建任务、任务分享或 AI Run 成功进入「待验证」的现有行为。

阶段固定为：`收集箱 → 看明白 → 想明白 → 说明白 → 干明白 → 验证中 → 已达成 / 已放弃`。点子总数和同时推进数不设限制，只提供阶段、负责人、创建人、优先级和项目筛选及进行中统计。

## 数据与接口

- `idea` 保存标题、原始想法、问题、目标、P0–P2、阶段、创建人、负责人、可选项目、当前阶段表单和活动时间线。
- `idea_artifact` 关联调研、方案、会议、验证与放弃文档；`idea_task_link` 只建立关系，解除关联不删除任务。
- `idea_iteration` 永久保留认可和未认可的迭代；`idea_research_run` 保存专用调研排队、领取、成功与失败状态。
- `/api/ideas` 提供 CRUD、阶段推进、调研、资产、任务与迭代子资源。没有公开分享端点。
- 历史任务不回填为点子，迁移只新增表和索引。

## 阶段门禁

1. 收集箱仅要求标题；进入看明白后可启动调研，调研不会自动改变阶段。
2. 进入想明白要求至少一份成功调研报告且成员确认已读。
3. 进入说明白要求 MVP 假设与验收指标；会议超过 20 分钟只提示。
4. 进入干明白要求会议结论及已有项目；页面可用点子标题和目标一键创建项目。
5. 进入验证中要求至少一个必做 MVP 任务处于待验证或已完成，且这些任务没有活动 AI Run。
6. 已达成要求人工填写验证结论和证据；启动后的点子进入已放弃要求原因。两条终态均自动沉淀原生知识文档。
7. 任务完成、AI Run 成功或继续优化只更新任务，不自动推进或关闭点子。

## 知识资产

系统使用稳定内部 id `kb-idea-assets` 创建团队可编辑的「点子资产库」，绝不按显示名称复用用户知识库。每个点子使用稳定文件夹 id；自动文档采用 WAO 原生块格式。重复调研创建带版本号的新文档，不覆盖已被成员修改的旧报告。

## IDEA_RESEARCH 安全模式

专用调研复用 assistant-v2 安全队列和 Codex 集中账号，但使用独立临时目录。Runner 强制 `read-only`、`--ephemeral`、`--ignore-rules`，禁用 Shell、多代理和图片工具，剥离 GitHub Token；唯一相对普通页面只读问答开放的能力是联网搜索。它不克隆业务仓库、不创建分支、PR 或部署，也不注入项目凭据与个人对话。来源不足必须明确说明，失败保留稳定原因并允许重新调研。

## 前端与验收

左侧公共导航通过内置菜单注册表提供默认可见的点子库入口，旧注册表升级时自动补齐该菜单。点子库沿用项目管理页的标题、工具栏、筛选标签和卡片视觉，看板按阶段分组展示，列表与看板共用筛选。详情区提供横向阶段导航、阶段表单、知识资产、MVP 任务、迭代和活动时间线；编辑具备本地草稿、保存中、已保存、失败重试状态，后台轮询不覆盖未保存草稿。手机端为单列卡片与详情，并可横向滚动阶段。

端到端至少走通达成路径和带调研报告的放弃路径，并回归飞书建任务、任务公开分享及 AI 成功进入待验证。
