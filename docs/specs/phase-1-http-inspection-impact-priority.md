# Phase 1：HTTP 巡检按用户影响选择候选

对应任务：`t1788391813017`。

## 用户结果

1. HTTP 夜间巡检的“优先接口”先展示失败次数更多的接口，再比较慢请求次数、P95、平均耗时与请求次数。
2. 即使失败响应很快，只要它真实影响了用户，也不会因为平均耗时较低而在截取 Top N 前消失。
3. 请求监控页面的既有总览、明细、成员隔离与平均耗时排序保持不变；本次只收紧自动巡检的候选选择。

## 根因与边界

- 2026-09-03 的 24 小时快照共有 433 次失败，但按平均耗时截取的 10 个候选失败数全部为 0，AI 无法看到需要优先定位的失败接口。
- 巡检专用快照复用同一成员、同一时间窗口和同一批浏览器实测记录，不新增采集数据，也不读取其他成员的指标。
- 排序只决定交给 AI 检查的候选，不改变接口成功或失败口径，不宣称本次已降低线上请求耗时或失败数。

## 验收

- 同一窗口同时存在快速失败与慢速成功请求时，Top 1 巡检候选必须是失败接口。
- 候选数继续受配置的 Top N 限制；非法数量被服务端拒绝。
- 普通请求监控总览仍按平均耗时返回最多 50 个接口，现有页面结果和权限隔离不变。
