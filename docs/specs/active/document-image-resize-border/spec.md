# 文档图片缩放与边框

## Problem Statement

正文图片目前可以通过右键菜单设置比例和像素尺寸，但选中图片后没有四边或四角拖动入口，也不能配置持久化边框。用户难以直接调整截图在正文中的展示大小。知识库、小记与任务描述共用编辑能力，需要保持操作和保存结果一致。

## Solution

选中可编辑图片时展示八个缩放柄及轻量工具条。四边和四角均保持图片比例缩放，显示当前尺寸，限制在正文可用宽度内；松手提交本次修改，Esc 取消，一次撤销恢复拖动前状态。工具条提供尺寸、边框、对齐和恢复原尺寸入口，保留已有菜单能力。

图片默认无边框，可选颜色、1–8px 粗细、实线或虚线。尺寸和边框属于文档展示属性，随正文保存并在阅读时呈现，不修改原图片文件。能力覆盖知识库、小记和任务描述；只读页面不提供编辑控件。

## User Stories / Acceptance Criteria

- AC-01 — 在知识库、小记或任务描述中选中可编辑图片后，可见四边中点和四角共八个缩放柄；每个拖动柄都能等比例改变图片展示大小，尺寸反馈随预览更新，图片不超出当前正文可用宽度。
- AC-02 — 一次拖动松手后提交尺寸修改；一次撤销恢复拖动前尺寸，重做恢复修改。Esc 取消当前拖动且不保存预览尺寸；拖动不误触图片块移动、全屏查看或正文选区操作。
- AC-03 — 图片工具条可设置无边框或有边框；有边框时可选颜色、1–8px 粗细、实线或虚线，结果立即可见。尺寸和边框操作不重新上传或改写原图，不改变图片来源和替代文本。
- AC-04 — 工具条提供尺寸、边框、对齐和恢复原尺寸入口；恢复原尺寸清除显式尺寸但仍遵守正文宽度限制，其他图片属性保留。已有比例、精确尺寸和对齐能力继续可用。
- AC-05 — 三类编辑入口保存并重新打开后，尺寸、边框与对齐效果保持；现有富文本结构及 Markdown 往返兼容，旧图片未操作时保留原有展示。阅读及只读页面显示已保存的样式，不显示工具条或缩放柄。
- AC-06 — 键盘与触屏用户能够完成等价的尺寸和边框操作；焦点可见、Esc 行为明确。桌面、320px/390px 窄屏及明暗主题中控件可达，图片、工具条与边框不造成正文横向溢出。
- AC-07 — 图片编辑沿用现有自动保存、离线草稿、失败重试及版本冲突保护；保存失败时修改仍可恢复，后台更新和并发修改不静默覆盖未保存内容，账号间草稿保持隔离。

## Implementation Decisions

- D-01 — 在已有共享编辑器内扩展图片交互，知识库、小记、任务描述保持一致；不替换编辑器或增加独立图片处理服务。
- D-02 — 八个拖动点始终等比例缩放，不提供自由拉伸。拖动预览与最终提交分离，松手形成单次可撤销修改，Esc 回到拖动前状态。
- D-03 — 尺寸与边框作为正文图片展示属性持久化，兼容现有结构与 Markdown 投影；不修改原图文件、图片地址或历史文档，不执行批量迁移。
- D-04 — 边框默认关闭；启用后提供颜色、1–8px 粗细及实线/虚线设置。内容边框与编辑选中轮廓分离，取消选中后仍显示已保存边框。
- D-05 — 复用现有菜单、工具条能力和主题语义变量；只读及引用展示保持既有权限语义，不向只读状态提供修改入口。
- D-06 — 保留现有草稿、自动保存、失败和冲突处理；本次不改变账号、文档权限或生产发布流程。

## Testing Decisions

- 用户已确认以共享编辑器的公共交互、内容变更输出及保存后重新加载作为主要测试边界。使用现有组件行为测试覆盖八方向缩放、比例与宽度限制、取消、撤销/重做、边框设置、只读、旧内容及富文本/Markdown 往返，不以内部函数调用次数作为验收依据。
- 浏览器验收覆盖知识库、小记、任务描述的实际拖动和工具条操作、保存重开、撤销、键盘与触屏、320px/390px 窄屏及明暗主题。组件模拟不代替真实业务持久化验收。
- 通过已有保存与草稿测试边界验证失败、重试和冲突保护；真实账号保存验收需使用明确的测试文档并报告环境及结果，不以界面保存提示代替服务端回读。
- 执行与改动相称的类型检查、UI 规范检查、构建及相关回归测试。用户截图仅说明问题，不作为像素级设计还原目标。

## Out of Scope

- 图片裁剪、滤镜、自由拉伸、原图重编码或替换上传。
- 批量修改历史图片样式、全站布局重做或更换编辑器。
- 当前 Propose 阶段的代码实现、Git 提交或推送、生产部署。
