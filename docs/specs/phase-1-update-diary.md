# Phase 1：WAO 更新日记

对应任务：`t1788831246685`。

## 用户结果

1. 登录成员从公共导航进入“更新日记”，按时间线查看 WAO 每个有交付结果的日期更新了什么。
2. 日记只展示已经成功结束的 Git 新增、修复和性能提交，不展示任务正文、失败运行、部署维护或测试流水。
3. 没有功能更新的日期不生成空条目；首次没有真实记录时明确显示空状态，不填充示例更新。
4. 日记按有更新的日期倒序分页，窄屏仍能顺序阅读；读取失败时保留上一次结果并提供原地重试。

## 真实数据与边界

- Runner 直接读取本次基线后的 Git 提交 SHA、Conventional Commit scope、标题和提交时间；一次开发运行以成功状态结束后，服务端才按提交 SHA 幂等写入 `product_update_event`。
- 新采集记录的更新日期取 Git 提交日期，不使用任务创建时间或模型摘要；既有 `function_iteration_event` 中已经验证成功的提交会作为真实起始记录迁入，并沿用其原事件记录时间作为历史交付日期。
- 对用户展示时移除 Conventional Commit 前缀和 GitHub 合并编号，只保留功能名、更新类型和可读结果标题。
- 当前可展示类型为 `feat`、`fix`、`perf`；`docs`、`test`、`chore` 以及 `deploy`、`ci`、`jenkins` 等工程 scope 不进入日记，其他具体 scope 原样保留，避免遗漏 Agent、编辑器或通用交互等真实产品变化。
- 本期从功能交付追踪启用后开始积累，不根据 Git 历史猜测或伪造过去的日记。

## 接口与入口

- `GET /api/update-diary?page=1&size=12` 按有更新的日期分页返回 `days`、`totalDays`、`page` 与 `size`。
- 页面路由为 `/updates`，稳定功能 id 与提交 scope 均为 `updates`；默认显示在“公共”导航，也可由菜单配置调整。

## 验收

- 同一天的多个已成功功能提交显示在同一个日期节点，不同日期按倒序排列。
- 页面不显示 `feat(scope):`、任务正文或没有更新的日期；`feat`、`fix`、`perf` 分别显示为新功能、问题修复、体验优化。
- 接口真实空结果显示空状态；初次读取失败可重试，已有结果刷新失败时旧时间线不会消失。
- 桌面和手机均可从公共菜单进入 `/updates` 并完成分页浏览。
