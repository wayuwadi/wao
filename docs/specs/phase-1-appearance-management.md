# Phase 1：电子衣库与形象管理

对应任务：

- `t1788006765769`：以整体协调、舒适和主动改变为核心，建立个人形象管理闭环。
- `t1788246796512`：建立成员私有电子衣库，整理单品、个人形象与真实穿搭照片；本期不做 AI 换装。

## 用户结果

- 登录成员从「个人 → 电子衣库」维护上衣、裤子、鞋子、外套和配饰；品类允许自由填写，床单、被罩等床品及未来新增物品不需要改接口即可纳入同一个衣库。
- 每件物品可保存私有实拍图、季节、风格、颜色、场合、材质和当前状态；首页按常用品类与自定义品类显示真实数量并支持筛选。
- 成员可保存一张私有个人形象照，把物品组合成穿搭，并为固定穿搭或每次实际穿着分别上传实拍；系统只根据真实穿着记录统计低频单品和近期重复频率。
- 成员可维护身材数据、肤色、脸型、发质、风格偏好、避雷项以及头部、服饰、鞋履、配件、体态、仪态六项自评。
- 成员可登记未来场合、清洗、换季收纳和采购事项；页面根据真实截止日期显示待办、今日到期和逾期，不伪造已经送达的外部通知。
- 颜色搭配参考是固定方法提示；穿搭笔记和实际感受由成员自己录入，不由系统臆测身体或审美结论。

## 数据与接口

- `appearance_workspace` 按 `member_id` 保存一份结构化 JSON 快照；衣物、穿搭、个人形象照引用、计划、带照片的穿着记录和笔记均随当前成员隔离。
- `appearance_photo` 保存实拍图原件；`GET /api/appearance/photos/{id}` 每次按当前会话校验所有权，响应使用 `private, no-store`，不复用公开图床。
- `GET /api/appearance` 读取当前成员工作区；`PUT /api/appearance` 全量保存并由服务端校验 id 唯一性和跨对象引用。
- `POST /api/appearance/photos` 接受最大 10 MiB 的 JPEG、PNG、WebP 或 GIF；`DELETE /api/appearance/photos/{id}` 只删除当前成员自己的照片。
- 衣物穿着次数和最后穿着日期由服务端从穿着记录及其关联组合重新计算，请求中的派生统计不会被信任。

## 交互与失败恢复

- 页面覆盖首次加载、空数据、编辑后保存中、已保存、保存失败和手动重试；失败时完整工作区写入当前成员专属的本机草稿，刷新后只恢复同一成员的草稿。
- 新增和编辑表单在窄屏保持可滚动，关闭前未提交的表单内容留在当前页面；保存中的重复操作被禁用。品类提供上衣、裤子、鞋子、外套、配饰和床品建议，但不限制成员填写其它真实品类。
- 照片上传失败不会提交空图片占位；工作区保存失败时已上传照片 id 保留在本机草稿，可继续重试。
- 物品被穿搭或穿着记录引用时不允许直接删除，避免历史统计失真；先调整引用后才能删除。

## 验收

- 新增带实拍图的物品、个人形象、穿搭、带当次照片的实际穿着、档案、到期事项和笔记，刷新后全部存在；低频与最近穿着统计和记录一致。
- 切换成员后不能读取工作区或照片；知道另一成员的照片 id 也只能得到 404。
- 模拟保存失败后页面保留输入、显示失败与重试，刷新仍可从本机草稿恢复；重试成功后清理草稿并显示已保存。
- 今日到期与逾期事项按本地日期真实变化；不存在推送渠道配置时页面只声称站内提醒。
- 工作台完整目录和个人侧栏注册表均能找到「电子衣库」，窄屏可完成上述操作；既有稳定 id `appearance` 与 `/appearance` 路由保持兼容。
- 页面不提供 AI 换装、身材推断或硬编码搭配结果；这些能力没有可靠实现条件时不得用演示数据替代。
