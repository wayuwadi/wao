# Phase 1：AI Run 执行提示词配置

对应任务：`t1788170818071`（AI Run 前把提示词整理成更适合 AI 阅读的版本）。本规格扩展
[任务驱动的 AI Run](phase-1-ai-task-runner.md)，不改变任务原文、Git 权限和部署终态要求。

## 用户结果

- 项目管理员在「首页 → AI 控制台 → AI 工作流 → 编辑」或「项目设置 → AI Run」看到一版可直接使用的
  「AI 执行提示词」，可以按项目修改并保存。
- Runner 在每次领取开发任务时，先把该提示词作为任务理解方法，再依次提供任务原文地址、工作区边界、
  实现与合并、部署验收、真实性边界和最终答复格式；初次、续跑、运行中追加与失败恢复均使用清晰分段。
- 提示词只指导 AI 如何阅读和执行，不改写公开任务 Markdown。用户原文、数字、链接、图片和清单层级仍是
  权威需求来源。

## 数据与兼容边界

- `ai_project_config.execution_prompt` 保存项目级提示词，最大 4,000 字且不能为空；旧工作流没有存量值时，
  服务端和 Runner 都回落到内置默认版本。
- 旧页面在滚动发布期间未提交该字段时保留现有值；新 Runner 从旧 API 领取不到该字段时使用相同默认版本。
- 项目配置不能覆盖 Runner 固定的仓库隔离、凭据边界、提交与 PR、部署等待、线上验收、真实数据和
  `WAO_RUN_STATUS` 约束。

## 验收标准

- 两个项目工作流配置入口均能读取、编辑并保存相同的真实服务端提示词，显示 4,000 字计数和用途说明；
  保存失败时保留当前输入并允许原地重试。
- 新建和旧项目都能看到非空默认提示词；空白或超长值由服务端返回可读错误，不写入配置。
- 领取协议包含最终生效的提示词；Runner 生成的初始提示中，该内容出现在任务地址之前，任务地址与所有固定
  交付约束仍完整存在。
- 自定义提示词保存后发起真实 AI Run，执行档案正常进入部署与验收链路；没有存量自定义值的项目继续读取默认值。
