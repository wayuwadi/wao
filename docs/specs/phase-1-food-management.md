# Phase 1：饮食管理

对应任务：`t1788008145731`（延续形象管理的个人闭环，以《黄帝内经》的节律与自我观察视角改善一日三餐）。

## 用户结果

- 登录成员从「个人 → 饮食管理」分别维护工作日与休息日的早餐、午餐、晚餐模板，提前记录时间、食物组合和预计准备时长。
- 成员记录实际吃过的食物、用餐时间、准备耗时、主观质量与餐后感受；页面只根据这些真实记录汇总最近完成度、平均准备时长，以及同一种食物的舒服或不舒服记录。
- 成员维护口味偏好、主动避开的食物、本人已经观察到的餐后反应和效率目标，并可登记采购、预处理和备餐事项。
- 《黄帝内经》只作为“饮食有节、顺应日常节律、持续自我观察”的文化框架，不引用未经核验的篇章，不判断体质，不生成药膳、方剂、热量目标或治疗建议；能力边界见 ADR-159。

## 数据与接口

- `food_workspace` 按 `member_id` 保存一份结构化 JSON 快照；餐次模板、实际记录、个人档案与备餐事项均按当前成员隔离。
- `GET /api/food` 读取当前成员工作区；`PUT /api/food` 全量保存，并由服务端校验记录 id 唯一、同一天同一餐唯一、枚举值、日期、分值、准备时长和文本上限。
- 首次使用返回空业务集合和固定文化边界，不写入演示餐单；统计在前端由服务端返回的真实记录即时重算，不接受或持久化浏览器提交的派生结论。

## 交互与失败恢复

- 页面覆盖首次加载、空数据、保存中、已保存、保存失败和手动重试；编辑后先写本机草稿，刷新时优先恢复未同步内容。
- 新增餐次模板、实际记录和备餐事项的表单在窄屏可滚动；关闭前的未提交表单保存为本机草稿，保存中的重复操作被禁用。
- 今日三餐只显示成员实际记录或可执行模板，不把模板冒充已经吃过；逾期事项只提供站内提醒，不声称已经外部推送。
- 不舒服记录只显示“本人记录的观察”，持续或严重不适明确建议咨询合格医务人员。

## 验收

- 分别新增工作日与休息日餐次模板，记录三餐、准备时长、质量与餐后感受，刷新后全部存在且汇总与原始记录一致。
- 同一种食物出现舒服和不舒服记录时，观察页展示实际次数并允许继续记录，不给出“适合体质”或医疗结论。
- 模拟保存失败后页面保留完整输入并提供重试，刷新可从本机草稿恢复；重试成功后清理草稿并显示跨设备可读取。
- 工作台完整目录和个人侧栏注册表都能找到「饮食管理」，窄屏可完成模板、记录与待办操作。
