# Phase 1：原生 Windows 客户端与桌面宠物

> 已退役：该规格不再实施，仅保留历史背景；现行决策见 ADR-077。

对应任务：`t17869345652730`。原生技术与更新交付边界见 ADR-075。

## 用户路径

1. 用户首次从 `https://wao.wayuwa.cn/downloads/windows/WAO-win-x64.zip` 下载并解压 WAO，运行
   `WAO.exe`；在原生登录页使用已绑定的邮箱密码登录。密码只进入当前 HTTPS 请求，会话 Cookie 由 Windows
   当前用户的 DPAPI 加密保存，重新打开应用可恢复登录。
2. “项目与任务”从真实 `/api/projects` 和 `/api/tasks` 加载数据。选择项目查看任务，并在明确的保存中状态下
   切换完成/重新打开；失败不覆盖当前服务端结果，可再次操作或刷新。
3. “AI 运行”读取真实运行与项目，可向项目派发目标；“自动化”读取真实任务，可立即运行、暂停、恢复，待修复
   时可重新授权。加载、空数据、保存和失败均显示明确状态。
4. 登录后默认出现独立透明置顶的桌面宠物。宠物可拖动、隐藏或唤回主窗口，并根据真实 AI 队列显示当前工作；
   没有运行时只显示中性陪伴文案，不制造业务状态。
5. 客户端启动后及每 30 分钟读取公开更新清单。发现更高版本时标题栏更新图标出现红点；用户点击后下载更新包、
   校验 SHA-256、退出主程序、由独立更新器替换文件并重新启动。替换失败时恢复上一版并写入本机错误日志。

## 规则

- 客户端使用 .NET 8 WPF、`HttpClient` 与 Windows DPAPI，不使用 WebView、Electron、Tauri 或远程页面壳。
- 首期原生覆盖已有可靠接口支撑的项目/任务、AI 运行和自动化，不为知识库、日历、文件等模块设置空入口。
- API 与更新基址固定为 `https://wao.wayuwa.cn`；业务响应继续使用 `ApiResponse<T>`，更新包必须使用 HTTPS
  且与清单里的 SHA-256 完全匹配。
- main 流水线在 Windows runner 上测试并生成自包含 `win-x64` 包，再由同一次云端部署发布固定下载地址与
  禁止缓存的版本清单。版本号使用 `1.0.<GitHub run number>.0`，每次成功 main 构建单调递增。
- 更新器只更新当前解压目录，使用当前用户权限，不请求管理员权限。用户首次应解压到自己可写目录；安装在
  `Program Files` 等不可写目录不承诺原地更新。
- 仓库没有 Windows Authenticode 证书，因而不伪造“已签名安装器”。首次手动下载可能触发 SmartScreen
  提示；取得代码签名证书后另开任务接入签名，内置更新仍以 WAO HTTPS 与 SHA-256 保证传输和包完整性。

## 验收

- Windows CI 通过 API 信封、登录、401、业务错误、更新版本、HTTPS 地址、哈希校验、版本替换和废弃文件
  清理测试，并成功构建 WPF 主程序及独立单文件更新器。
- 发布包包含 `WAO.exe` 与 `Wao.Updater.exe`，不包含密码、会话 Cookie、部署 Secret 或演示业务数据。
- 登录、项目/任务状态切换、AI 目标派发、自动化操作均命中生产真实接口；断网、401 和保存失败不展示虚假成功。
- main CD 后，`latest.json` 与 ZIP 均可公开访问，清单哈希为 64 位十六进制，ZIP 支持下载；客户端从旧版本
  发现红点后可一次点击完成下载、校验、替换和重启。
- 桌面宠物首次渲染位置稳定，可拖动、隐藏、唤回 WAO，并且其运行文案来自已读取的真实 AI 状态。
