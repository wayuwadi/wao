# 润色：成员草稿隔离与异步结果保护

来源：产品体验审计 A04。补充独立润色工作台规格，不修改 AI 模型路由、成员权限、数据表或接口。

## 用户结果

- 原文与未保存提示词按当前成员保存本机草稿；退出或切换成员时立即清空页面上的提示词、原文、结果和历史，再加载新成员数据。
- 旧成员的加载、提示词保存或润色请求晚返回，不得更新当前页面、清理新成员草稿，或继续以新会话发送后续润色请求。
- 保存期间继续修改提示词，旧回包只更新已保存快照，不覆盖新输入；“保存并润色”从第一步即禁止重复提交，新提示词尚未保存时明确提示重新确认。
- 本机存储失败可见地提示保持页面或复制备份，并允许重试保存草稿。恢复时说明本机草稿不等于跨设备同步。

## 旧版草稿

旧 `v1` 键不含成员身份，无法可靠确认归属。新版本不读取、不自动迁移、不删除这些旧值，避免把前一成员内容分配给后来登录者。新草稿使用含成员 id 的 `v2` 键；云端提示词和历史仍按既有成员权限读取。无身份时不创建共享兜底草稿。

## 验收

- 组件级两成员切换：两人的原文/提示词草稿互不覆盖，切回恢复本人输入，结果与历史立即清空。
- 分别延迟旧成员的加载、保存、润色回包，确认新成员内容不受影响。
- 覆盖无身份、旧版键保留、保存失败重试、保存中继续编辑、防重复提交与存储失败恢复。
- 本地连接既有数据库，验证当前成员输入、刷新恢复及真实润色；不冒用其他真实成员账号验证隔离。

## 当前验证记录

- 早期基线全量 184 个文件、1072 项测试通过；同步 2026-09-19 最新主分支后，润色针对性测试 13 项、完整类型检查与生产构建通过，保留现有大包提示。
- 本地真实页面：原文与未保存提示词刷新恢复成功；提示词保存到数据库后刷新读回成功，原有提示词已恢复保存。
- 真实 AI 请求失败时原文保留、未生成成功占位。本地服务缺少部署使用的解密密钥，因此成功链路采用本地前端与已授权登录的线上润色 API，沿用真实模型和成员数据，无模型配置修改。
- 真实成功链路已验证：输入标注验收的原文、刷新恢复、开始润色、复制成功、刷新历史后展开原文与结果；保留一条“【验收记录】润色草稿恢复 2026-09-19”。
- 两成员切换及旧请求回包由组件测试验证，没有冒用其他真实成员账号。
