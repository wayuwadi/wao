# 决策版本冲突恢复

补充决策保存草稿保护规格。不改变统一记忆的 409 并发检查、发布权限、版本持久化或业务逻辑。

- 保存已有决策收到 HTTP 409 时进入核对状态，保留包括请求期间追加的全部输入及本机草稿，暂停再次提交旧版本。
- 通过既有单条读取接口获取最新版本；读取失败在原处给出重试，不将原输入替换为远端内容。
- 展示最新版本号、更新时间和四个字段。逐字段标注是否与当前输入相同；用户可明确采用某个最新字段，或自行在原表单合并。
- 必须点击“已核对，继续编辑当前内容”才采用该最新版本作为提交基线，并同步本机草稿。此动作不发送保存请求，不自动合并或覆盖服务端。
- 用户再点击保存新版本后仍受服务端并发检查；期间再次更新时重新进入核对。
- 最新记录不匹配对象、成员、范围、分类或缺少版本时不得推进；已废止或其他非有效状态保留比较但不能继续保存。
- 关闭后重开、切换编辑对象、切换成员、卸载后旧读取回包不得污染当前编辑。

验收覆盖真实双页面冲突、输入保留、按字段采用、确认前禁止保存、最终版本读回；自动化覆盖读取失败重试、再次冲突、成员切换和已废止保护。
