# Phase 1：HTTP 请求体验监控

对应任务：`t1787573087536`。

## 用户链路

1. 登录成员访问 WAO 时，统一 Axios 客户端自动记录每次 `/api/` 请求从浏览器发出到收到结果的端到端耗时。
2. 成员从“工具 → 请求监控”打开独立 Tab，查看最近 24 小时总请求数、平均耗时、P95、慢请求、失败请求、接口聚合和最近明细。
3. 页面支持手动刷新，也可在明确确认后清空当前成员的全部历史记录，便于修复后重新采样；首次进入覆盖
   加载中、空数据和失败重试，窄屏下统计与表格保持可浏览。
4. 采集失败不会阻塞业务请求；指标留在有界内存队列中退避重试，页面卸载时使用 `sendBeacon` 尽力补报。
5. 系统每天上海时间 06:30（默认断网窗口结束后）读取「Wa All in One」项目负责人的最近 24 小时真实指标；有数据时创建一条
   包含本次指标快照的任务并立即进入该项目的 AI Run，交由开发 Runner 判断和治理新的性能瓶颈。
6. 页面可手动启动同一真实巡检；自动化页面可配置频率、时间、指标窗口、Top N 候选、单次治理上限与启动通知群，
   详细约束见 `phase-1-automation-and-file-controls.md` 与 ADR-131。

## 数据与权限

- 耗时由浏览器单调时钟测量，包含用户网络、云 Nginx、Gateway 和服务端的完整链路，能够反映公司网络下的真实等待。
- 只采集 WAO 统一客户端发起的 `/api/` 请求；采集与查询接口 `/api/request-metrics` 自身排除，避免递归和监控流量污染。
- 只保存 HTTP 方法、去除 query/hash 后的接口路径、状态码、耗时、浏览器网络类型、重试序号和开始时间；不保存请求体、响应体、Cookie、查询参数或凭据。
- 数据由服务端会话绑定当前成员，成员只能写入和读取自己的指标；客户端不能提交成员 id。
- 主动清空同样只按服务端会话删除当前成员记录，不接受客户端成员 id，也不影响其他成员。
- 单批最多 100 条，方法、路径、耗时、状态码和时间均由服务端再次校验；全局定时清理超过 30 天的记录。

## 指标口径

- 默认窗口为最近 24 小时，允许查询 1～168 小时。
- 慢请求定义为浏览器端耗时不低于 1,000 ms；失败请求包括 HTTP 4xx/5xx 和没有状态码的网络错误。
- P95 使用窗口内实际记录排序后向上取整的第 95 百分位；接口聚合按平均耗时降序，最多展示 50 项。
- Gateway 自动重试的每一次真实网络尝试分别记录，明细中的“重试”序号用于识别 502/503/504 自愈带来的额外等待。
- 每日巡检只在「Wa All in One」已启用真实 AI 工作流、已配置公网分享地址且指标窗口非空时派工；条件不足时
  自动化运行记录明确失败或跳过原因，不创建没有证据的占位任务。双节点通过既有 Cron 到期时间条件更新只领取一次。
- 夜间任务正文固定记录窗口生成时间、请求数、平均耗时、P95、慢请求、失败请求和最慢接口聚合；不附请求明细，
  不扩大成员级监控数据的敏感字段范围。AI 必须从仓库与实测指标定位根因，没有可靠优化时不得伪造收益。

## 性能治理

- 任务列表读取先一次性取得当前成员可见项目集合，再过滤并转换任务；禁止按任务逐条查询项目权限。
- 文档列表读取先单次解析各文档出链并建立反向链接索引，再转换全部文档；禁止为每篇文档重复扫描、解析全库出链。
- 文档列表组装时每篇文档的正文与出链 JSON 各解析一次，反链摘要复用已解析正文，禁止在同一请求内重复解析。
- 应用壳层不预取包含全部正文的文档列表；只有知识库、项目文档、任务关联或全局搜索真正需要时才读取，多个入口同时
  打开时复用同一个在途请求，失败保留明确重试状态。
- 应用壳层不预取图床列表；文件 / 图床页首次打开时只发起一次读取，失败可原地重试，上传仍直接使用真实上传结果，
  不依赖预先加载历史图片。
- 共享聊天已读上报继续覆盖页面真正展示到的最后一条及此前最近 100 条消息，但必须用一次幂等批量写入完成，
  禁止按消息串行产生最多 100 次数据库写入。
- 文档树拖拽保存必须先完整校验知识库、文件夹和文档集合，再用一次窄批量更新写入所有文档的文件夹与序号；
  禁止按文档串行写入，也不得覆盖正文、链接或自动归档版本。
- AI Run 首页只读取全部活动运行与最近 8 条已结束运行；完整结束历史继续由分页接口按需读取，禁止先组装百条运行及其
  进度、任务、项目、记忆和报告元数据后再在前端截断。
- 可见页面的项目与任务后台同步首次及发现变化后保持 15 秒；连续无变化时依次退避到 30 秒、60 秒，重新聚焦立即同步，
  请求失败回到 15 秒重试。同步仍返回完整真实数据并保护未落库草稿，不用静态缓存换取虚假的低延迟。
- 任务详情的 AI 档案只在活动运行期间保持 5 秒刷新；无活动运行时依次退避到 15 秒、30 秒、60 秒，页面隐藏时暂停，
  重新聚焦立即同步。下一轮必须在上一请求结束后安排，禁止慢请求跨轮重叠；仍完整返回最近 30 条真实档案。
- 优化必须保持现有权限过滤、任务完整 DTO 与文档反向链接结果不变；查询次数和聚合结果由单元测试约束。

## 验收

- 成功、HTTP 错误、网络错误和 Gateway 重试均形成准确的单次记录，业务响应行为不因采集失败而改变。
- 查询按当前成员隔离，空窗口返回零值与空数组，不填充演示数据。
- 页面可从工具菜单以 Tab 打开，并覆盖加载、空、失败重试、刷新、长路径和移动端横向浏览。
- 清空前明确提示不可恢复；确认后先暂停采集并丢弃待发旧样本，再删除当前成员的全部历史并刷新为空状态；
  完成后恢复新请求采集，取消或失败时保留已有结果和恢复入口。
- 同一批任务无论数量多少，列表权限判断只读取一次项目集合；同一批文档的出链只解析一次，反向链接结果与优化前一致。
- 文档列表每篇正文与出链各解析一次；共享聊天已读范围、成员隔离和幂等结果不变，单次上报最多执行一次批量写入。
- 普通首页启动不请求 `GET /api/docs` 与 `GET /api/images`；进入知识库或打开文档关联入口后才读取完整文档，进入图床页
  只读取一次图片列表，并覆盖加载中、失败重试与真实空数据状态。
- 文档树保存的完整性校验、跨文件夹移动与并发冲突反馈不变；同一请求无论文档数多少最多执行一次顺序更新。
- AI Run 首页始终包含全部活动运行和最多 8 条已结束运行；历史分页仍能访问上限之外的完整档案。
- 项目与任务同步退避档位有单元测试约束；下一次真实监控窗口应比较 `/api/tasks` 的请求次数、慢请求数与失败数，
  不以本地计时或理论比例替代浏览器端到端实测。
- 任务 AI 档案的活动、空闲、失败退避档位及慢请求不重叠由前端测试约束；下一次真实监控窗口应比较
  `/api/ai/tasks/{taskId}/runs` 的请求次数、慢请求数与失败数，未经下一窗口实测不宣称线上提速比例。
- 夜间真实指标非空时自动化创建一条可被 Runner 领取的 AI Run；指标为空、工作流不可用或分享地址缺失时不留半成品任务，
  自动化历史保留可执行的原因。
- 下一次真实监控窗口分别比较 `GET /api/docs` 与 `POST /api/chat/messages/read` 的请求数、P95、慢请求数和失败数；
  本地解析次数与数据库写入次数只证明代码路径收敛，不替代浏览器端到端提速结论。
- 下一次真实监控窗口比较 `PUT /api/kbs/{id}/document-order` 的 P95、慢请求数与失败数；批量 SQL 测试只证明
  数据库往返次数收敛，不替代浏览器端到端提速结论。
