# Phase 1：HTTP 请求体验监控

对应任务：`t1787573087536`。

## 用户链路

1. 登录成员访问 WAO 时，统一 Axios 客户端自动记录每次 `/api/` 请求从浏览器发出到收到结果的端到端耗时。
2. 成员从“工具 → 请求监控”打开独立 Tab，查看最近 24 小时总请求数、平均耗时、P95、慢请求、失败请求、接口聚合和最近明细。
3. 页面支持手动刷新；首次进入覆盖加载中、空数据和失败重试，窄屏下统计与表格保持可浏览。
4. 采集失败不会阻塞业务请求；指标留在有界内存队列中退避重试，页面卸载时使用 `sendBeacon` 尽力补报。
5. Linux 主节点每天 23:30（Asia/Shanghai）读取最近 24 小时的去身份化真实指标；有数据时在
   「Wa All in One」已启用工作流中创建一条带指标快照的 AI Run，由 AI 判断是否仍有优化必要并在有证据时直接治理。

## 数据与权限

- 耗时由浏览器单调时钟测量，包含用户网络、云 Nginx、Gateway 和服务端的完整链路，能够反映公司网络下的真实等待。
- 只采集 WAO 统一客户端发起的 `/api/` 请求；采集与查询接口 `/api/request-metrics` 自身排除，避免递归和监控流量污染。
- 只保存 HTTP 方法、去除 query/hash 后的接口路径、状态码、耗时、浏览器网络类型、重试序号和开始时间；不保存请求体、响应体、Cookie、查询参数或凭据。
- 数据由服务端会话绑定当前成员，成员只能写入和读取自己的指标；客户端不能提交成员 id。
- 单批最多 100 条，方法、路径、耗时、状态码和时间均由服务端再次校验；全局定时清理超过 30 天的记录。
- 夜间任务只包含方法、路径、次数、状态与耗时聚合，不包含成员 id；没有真实指标时不创建空任务，
  同一天已存在同标题巡检任务时幂等跳过。

## 指标口径

- 默认窗口为最近 24 小时，允许查询 1～168 小时。
- 慢请求定义为浏览器端耗时不低于 1,000 ms；失败请求包括 HTTP 4xx/5xx 和没有状态码的网络错误。
- P95 使用窗口内实际记录排序后向上取整的第 95 百分位；接口聚合按平均耗时降序，最多展示 50 项。
- Gateway 自动重试的每一次真实网络尝试分别记录，明细中的“重试”序号用于识别 502/503/504 自愈带来的额外等待。

## 验收

- 成功、HTTP 错误、网络错误和 Gateway 重试均形成准确的单次记录，业务响应行为不因采集失败而改变。
- 查询按当前成员隔离，空窗口返回零值与空数组，不填充演示数据。
- 页面可从工具菜单以 Tab 打开，并覆盖加载、空、失败重试、刷新、长路径和移动端横向浏览。
- 夜间巡检只在 Linux 主节点启用；生成目标使用真实聚合值和现有项目工作流、负责人及首选执行电脑，
  指标健康或证据不足时允许据实结束，不为产生提交而伪造优化。
