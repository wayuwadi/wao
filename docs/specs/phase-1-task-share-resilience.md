# 规格：公开任务分享页弱网与窄屏可用性

对应任务：`t1786619361385`（真实用户链路小范围体验走查）。公开范围和双形态链接继续遵循
[ADR-013](../adr/013-public-task-share-links.md)，本规格只补齐分享页的读取反馈和手机布局，不改变公开字段。

## 问题

公开任务分享页是把任务交给协作者或 AI 的入口。此前接口失败后只显示“链接无效或任务已删除”，
没有重试入口；短暂断网或滚动部署期间读取失败时，访问者只能手动刷新整页。页面也没有窄屏规则，
“回到原任务”的浮动按钮会和长标题争抢宽度，正文、子任务标题或底部复制操作可能难以浏览。

同一分享页在前端路由间快速切换时还会并发读取；旧地址的慢响应可能晚于新地址返回，并覆盖当前内容。

## 规则

- 首次读取期间展示明确的加载状态，不提前显示空内容或上一条分享内容。
- 读取失败时展示可理解的失败说明和原位“重新加载”入口；重试期间恢复加载状态，成功后展示真实任务。
- 每次读取绑定当前任务、子任务和 `openOnly` 参数；只允许最新一次请求更新页面，旧请求的迟到结果不得覆盖新地址。
- 在不超过 600px 的窄屏上，品牌、返回入口和标题顺序排列；长标题、描述与子任务可换行，不产生整页横向滚动。
- 窄屏复制按钮至少 40px 高并占满内容宽度；页面底部避开安全区。
- 加载动画尊重系统的“减少动态效果”设置。

## 验收

- 延迟分享接口时，页面显示“正在读取任务”，且尚未出现任务标题；接口返回后出现真实标题和子任务。
- 首次请求失败后出现“重新加载”；点击时先回到加载状态，第二次成功后错误消失且内容可见。
- 让旧地址请求晚于新地址返回，最终仍展示新地址对应的任务。
- 在 390px 宽度检查长标题、描述、子任务和复制入口：内容均可见，页面无业务区横向溢出。
