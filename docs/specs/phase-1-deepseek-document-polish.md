# Phase 1：DeepSeek 文档快速润色与 Token 管理

对应任务：`t17870249341564`。补充 `phase-1-document-selection-polish.md`，不改变选区冻结、候选对照、
用户确认后替换和文档自动保存的既有交互。

## 用户链路

1. 设置页「AI 账号」可以新增 DeepSeek 官方 API 配置，选择 `DeepSeek V4 Flash`（快速）或
   `DeepSeek V4 Pro`（质量优先），并录入 Token。
2. Token 只在新建或轮换时输入；保存后页面不回显明文，编辑时留空表示沿用原 Token。用户可以测试连接、
   停用、重新启用或删除配置，所有状态均来自真实服务端结果。
3. 最新创建且仍启用的 DeepSeek 配置标记为「文档润色」，知识库选区润色直接使用该配置。若没有启用的
   DeepSeek 配置，保留既有本地 Codex 润色链路；如果已经选择 DeepSeek 但上游调用失败，展示真实错误并允许
   重试，不静默切换供应商。
4. DeepSeek 处理期间原文不变；返回候选后仍由用户选择保留原文、重新润色或替换选区。协作者或本地输入在
   等待期间改变文档时，旧候选仍禁止覆盖新内容。

## 安全与真实数据边界

- DeepSeek Token 复用 `ai_account.credential_json` 与 `VaultCryptoService`，以 AES-256-GCM 加密落库；列表、
  连接状态、异常响应和日志均不包含明文。
- DeepSeek 类型的 Token 只允许由服务端发送到 `https://api.deepseek.com`，不开放自定义主机，避免把集中凭据
  误发到伪装端点。
- 连接测试调用官方 `/models`；所选模型不在真实响应中时标记失败。文档润色调用官方
  `/chat/completions`，关闭思考模式以缩短等待时间，并拒绝把被截断或空的上游结果作为候选。
- 任务分享原文中出现的凭据不进入 Git、migration、默认配置或前端构建产物；生产配置必须由有权限的用户
  在设置页录入，避免把公开泄露值扩散到部署历史。

## 验收

- 新建 DeepSeek 配置时可选择两个当前官方 V4 模型，Token 输入框为密码类型；接口返回不含 Token。
- 编辑配置并留空 Token 时保留原密文；轮换 Token 后旧值不可再由服务端取用。
- 「测试连接」使用真实 Token 拉取模型；鉴权失败、模型不可用与响应异常均显示失败原因。
- 有启用配置时润色不依赖 Runner，成功候选仍需确认后才写入文档；DeepSeek 失败时正文不变并可重试。
- 无启用配置时既有本地 Codex 润色继续可用。
