# Phase 1：飞书群聊快速收集与协作提醒

决策背景见 `docs/adr/027-feishu-quick-collect-and-subtask-runs.md`。

## 用户路径

1. 管理员在「自动化 → 飞书群聊同步」弹窗底部打开「群聊快速收集」，复制事件订阅地址
   （`https://wao.wayuwa.cn/api/feishu/events`）填到飞书开放平台的事件订阅里，订阅
   `im.message.receive_v1`；按需填 Verification Token / Encrypt Key，并选好落点项目。
2. 想法冒出来时在群里 @机器人 说一句话（手机上可以直接用飞书的语音输入说完发文字）。
   机器人回一张卡片：任务已建好，点「打开任务」进去补细节。
3. 任务需要同伴一起补充时，把状态改成「收集中」。系统自动把它分享到群里、@ 上勾选的协作成员，
   卡片按钮直接落到这条任务。
4. AI 跑完这条任务后，群里再收到一张卡片：成功是「去验收任务」，失败是「查看失败原因」。

## 验收标准

### 快速收集

- 飞书的 URL 校验（`url_verification`）能通过：原样回 `challenge`，配了 Verification Token 时
  校验不过要拒绝。
- 配了 Encrypt Key 时能解开加密事件体；解不开时返回可理解的 400，并提示去核对 Encrypt Key。
- @机器人 的**文本**与**富文本**消息建成任务：第一行（超过 40 字截断）是标题，全文是描述，
  `@_user_x` 占位符不残留在正文里，`custom` 里带一条「来源 = 群聊快速收集」。
- 落点项目按「配置值 → 名为 Wa All in One 的项目 → 第一个项目」依次回落；一个项目都没有时
  回一句提示而不是静默丢弃。
- 发言人绑过飞书登录时，任务负责人就是他；没绑过回落到默认负责人。
- **语音条不做转写**：回一句提示让对方改用飞书的语音转文字，不建空任务。
- 同一个 `event_id` 重复推送只建一条任务。
- 未开启开关时，事件收下但不建任务；配置了目标群时，其他群的消息一律忽略。
- 处理过程中的任何异常都不返回 5xx —— 否则飞书会无限重推同一条失败消息。

### 收集中自动分享

- 任务状态从别的状态变成「收集中」时发一次卡片；已经是「收集中」时再保存任何字段都不再发。
- @ 名单来自设置里勾选的成员，且永远排除当前操作人；名单为空时只发通知不 @ 人。
- 通知发送失败不影响状态落库。

### 安全边界

- `/api/feishu/events` 是免登录端点，真实性只由飞书的 Verification Token / Encrypt Key 与
  目标群限制保证；它不读写任何用户会话，能做的事只有在配置好的项目里建一条任务。
- Verification Token 与 Encrypt Key 与 App Secret 一样加密存 `system_setting`，接口只回脱敏形态。
