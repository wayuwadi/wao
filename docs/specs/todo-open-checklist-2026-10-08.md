# 待办按天视图：展开清单

2026-10-08，用户确认「展开清单」交互预览。本规格在 `todo-day-layout-2026-10-07.md` 的主清单与日常区布局上调整任务阅读密度，取代该规格将未排期进展与已完成合并折叠的规则。不改变服务端、数据库、CLI 或 MCP 契约。

- 主清单使用留白与分隔线。今日安排、今天推进过、已完成分开呈现：已安排且未收尾的任务留在安排区；未安排但当天有真实进展、仍未收尾的任务直接显示；只有真正收尾的任务进入已完成区。空的推进区不占位。收尾仍复用 `isTaskFinished`，待验证子事项不能作为完成。
- 所有任务默认展开未完成子事项，不根据任务数量或屏幕宽度自动收起。已完成子事项可单独展开；已完成上级仍有未完成下级时保留上级，避免丢失层级。手动收起放在任务更多菜单，收起后在原位置保留明确的展开入口；日期或成员切换恢复默认。
- `TodoTaskChecklist` 复用稳定子事项键、`subtaskRows`、`subtaskState`，保留当日个人顺序及顺序读取失败的重试；历史合成键不随展示顺序改变。当日勾选沿用 `setSubState` 与 `flushTask`，保存中禁用重复操作，错误仍在任务原位提供处理入口。历史与未来子事项只读，历史内容读取当天快照，不读取当前子事项代替历史。
- 任务标题仍打开既有任务详情。常驻的「记进展」「拆分与详情」按钮移到复用 `ContextActionMenu` 的更多菜单；未来日期不显示记进展。进展编辑器打开后保留原有 `NoteComposer`、日期与成员隔离草稿、保存回执、失败重试与跨设备冲突处理。保存中、保存失败或编辑中的已完成条目保持可见。
- 项目、当前优先级、排时为次要元信息，不另造优先级或重点字段。最新当天事件摘要直接可见，历史明细按需展开。摘要只使用服务端实际事件，不推断或生成进展。历史不补造当日优先级。
- 保留右侧固定事项与随手记、全部待办的筛选及列表／看板／四象限；保持原有容器断点和统一页面滚动。明暗主题、320／390px、长标题、键盘菜单与只读日期均需验收。

设计参考复用 `TodoDayLayout` 与 `TodoTaskChecklist`，示例明确标注且不调用业务保存。验收分别记录自动检查、本地真实数据链路、PR、合并和公网版本，未具备的环境条件不得用演示数据替代。
