# 执行安排与截止分离

当前 `start` 为可空开始日期，任务创建并不自动填它；`due` 为截止日期，`startAt/endAt` 为无时区的本地 ISO 执行时段。现有任务开始日期编辑已使用「留空表示未排期」语义。复用这些字段，无新增字段或迁移。

- 无时间的执行安排写 `start`，不捏造时刻。有时段以 `startAt/endAt` 为准，移动同时同步 `start`，保留本地时钟持续长度及跨日范围。
- 日历拖动仅调整执行安排。原来只有截止的任务拖动后增加开始日期，保留截止。截止在任务详情的「截止」独立修改。时段编辑及新建不再连带填写截止。
- 日历按日拆分跨日时段，区分「执行」「截止」。同一天合并为「执行 · 当天截止」，午夜结束不额外生成次日零时长事件。
- 新建时间安排支持不安排、日期、时段；截止独立选填。日历进入新建只预填执行安排。历史日期原样读写，不猜测清空。
- 拖动显示保存中、已保存或失败保留本机安排并重试/打开详情。撤销只在任务版本及安排与本次保存一致时允许；服务器仍用现有 `editVersion` 防止远端并发覆盖。冲突保留草稿并由任务详情处理，不能盲重试覆盖。

沿用现有登录会话 PUT 和幂等回执，无 API schema 变化。MCP/CLI 的既有 `update_task` 仅公开截止等原字段，本轮不自动扩展旧令牌或增加时段操作；以后单独开放脚本排程时必须提供同等版本条件。浏览器安排不需要新权限。
