# 更新卡片内开箱与按需功能演示

2026-10-04，用户确认「卡片内开箱」为默认，复杂功能采用「卡片与演示窗」。本规格取代 `release-highlights-feature-explorer.md` 的刷新后自动欢迎 / 亮点 / 完成三页介绍，以及 `product-release-notes.md` 中仅从提交标题生成通用介绍的表现；既有版本检测、动画与草稿保存屏障保持。

- 更新前与更新后复用顶栏卡片。保留笑脸伙伴、紫蓝横幅及十秒到达动画；每个变化只展示一次功能标题，随后展示用途与「怎么用」步骤。多项更新按条展示，不在抬头再复制单项标题。
- 安全刷新标记只在当前页面实际版本与目标一致时显示「已更新」轻提示，不自动打开大窗口或抢焦点。普通刷新不重复提示，设置页「查看本次更新」也打开顶栏卡片。移动端隐藏锚点继续使用视口定位。
- 保存成功后才刷新；正在保存禁用收起、体验与演示入口。失败保留原页、目标版本与草稿，提供重试。未更新时可以查看演示，但不能进入新版功能。
- 演示按功能制作，可以使用明确标注「操作示意」的专用交互图或随制品保存的截图。默认卡片内按需展开；复杂图主动打开深色渐变大图窗，一屏呈现，无欢迎和结束页。大图支持 Esc、焦点循环、关闭恢复、窄屏与短屏滚动，尊重减少动态效果。
- 新增可选 `steps` 和 `demo` 静态元数据。截图只接受 `assets/release-guides/<安全文件名>.(png|jpg|webp)`，构建检查图片存在。图片读取失败保留说明与步骤，可重试。功能入口仍由 MODULES 解析，元数据不能指定任意路由、HTML 或外部 URL。
- 评审说明保存在 `currentRelease.json`，通过 `sourceSubject` 与规范化后的构建 HEAD 提交标题精确绑定；不匹配时自动 Git 档案仍更新，但明确提示本次未附带使用说明，不复用旧精选。`releaseHistory.json` 保留旧说明；生产清单、页面常量和档案继续绑定同一个 SHA。每项用户可感知改动在同一 PR 维护对应用途 / 步骤；演示只在有必要时附带，不强制所有修复配图。
- 当前仍介绍构建 HEAD 的变化，不把历史五条或所有祖先包装为这次新增。Jenkins 合批的全部提交保留在全部记录；本期不新增发布区间接口。

仅静态制品元数据与浏览器交互变化，无业务 API、数据库、CLI 或 MCP 权限变化。
