# Phase 1：AI Run 强制 HTML 报告

对应任务：`t1788143318109`。

## 用户结果

1. 每次开发型 AI Run 结束后，任务详情的执行档案和首页 AI Run 详情都提供同一份“HTML 报告”入口。
2. 报告包含本次公开 AI Plan 原文、关键判断与决定、改动功能在 WAO 中的入口，以及用户可直接执行的验收步骤和结果。
3. 报告不披露模型隐藏思维链、凭据或工具参数，也不重复单元测试、自动化测试、构建和部署等系统级验证。
4. 运行在生成报告前失败时仍产出最小报告；没有可靠信息的字段明确说明未取得，不用演示文案或猜测补齐。

## 实现边界

- 沿用既有运行级报告目录、`POST /api/ai/runner/runs/{runId}/report`、隔离网页托管和 `reportUrl`，不新增数据表或第二套文件链路。
- AI 自行生成的合规 HTML 优先；仅在文件不存在时由 Runner 使用已经允许进入进展时间线的公开计划和消息生成兜底页。
- 已存在但不合法的报告继续导致运行失败，Runner 不覆盖原文件，以便准确暴露生成或上传错误。
- 历史 AI Run 不批量生成报告；规则只适用于更新后的 Runner 新领取和续跑的开发任务。

## 验收标准

- 新运行提示明确要求每次写报告，并明确四类必含内容和系统级验证排除项；续跑提示保持同一约束。
- AI 没有写报告、CLI 正常完成或在工作区准备阶段失败时，Runner 都能上传 UTF-8、10MB 以内的兜底 HTML，随后再回传终态。
- 兜底页可看到公开 Plan 和关键进展，但看不到 thinking、命令、工具调用、单测、自动化、构建和部署检查。
- AI 写出的空文件、非 UTF-8、超限文件或报告上传失败仍让原本成功的运行转为失败，并显示准确错误。
- 打开任务详情的执行档案或首页 AI Run 详情，存在 `reportUrl` 时都能在新窗口打开标为“HTML 报告”的稳定公开地址。
