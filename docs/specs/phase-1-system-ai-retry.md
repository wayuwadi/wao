# Phase 1：系统 AI 瞬时失败自动恢复

对应任务：`t1787897474502`。

## 用户结果

1. 开发型 AI Run 的 Git 工作区准备与 AI CLI、本地 Codex 只读分析和服务端模型 API 都在一次瞬时故障后自动继续，
   每阶段最多三次总尝试后才显示失败。
2. 聊天复盘、人生复盘、周报、每日建议、定时预热、网页助手、文档润色和点子调研复用同一恢复机制，不要求用户
   为一次偶发 CLI、网络或网关错误点击重试。
3. 中间失败不产生新的业务运行、不保存部分模型输出，也不提前显示终态失败；恢复成功时只展示最终结果。

## 稳定性与安全边界

- 本地只读运行的三次尝试共用同一运行 id、提示、临时空仓库、安全只读参数和硬截止时间；每次结束后仍清理运行级
  临时仓库与 `CODEX_HOME`。
- 模型 API 仅重试网络异常、HTTP 408 / 425 / 429 / 5xx、空响应和空答复；其他 4xx、内容截断、非法模型与输入
  校验错误立即返回真实原因。
- 重试固定使用原账号、原模型和原供应商。不能静默切换供应商、降低只读安全开关或把静态内容当作模型结果。
- 通用自动化执行器不做外层重放。创建任务、发送通知、同步外部数据等写操作只有具备幂等键时才能自行恢复；当前
  定时 AI Run 使用项目 AI Run 的既有恢复，定时只读生成使用本规格的只读恢复。
- AI Run 的项目级失败自动重试次数继续按 ADR-138 配置；默认首次加两次恢复，与本规格的三次总尝试口径一致。
- 同一项目并发运行时 Git 准备串行执行；主克隆若残留 Windows 无法识别的 WSL `core.worktree=/mnt/...`，领取时先
  原位清除并继续，不能要求用户手工删除整个克隆。Git 准备与 AI CLI 分阶段计算重试次数。

## 状态与验收

- 模拟本地 Codex 首次非零退出、第二次成功，只向服务端完成一次并保存第二次完整答复；连续三次失败只回传最后错误，
  三次产生的部分输出均不持久化。
- 模拟 Git fetch 首次锁冲突、第二次成功，只创建一个任务 worktree 并继续 AI；模拟 Windows 主克隆残留
  `core.worktree=/mnt/...` 时首轮自动修复，不产生终态失败；同一项目并发准备不会互相 prune 或删除任务分支。
- 模拟模型 API 连续两次 503、第三次成功，调用方取得最终答复；连续三次 502 后才失败；401 只请求一次并直接显示
  鉴权错误。
- 回归聊天复盘、周报、人生复盘、每日建议与点子调研仍使用真实持久化材料和现有安全协议；重试不新增业务档案，
  不重复发送通知或创建任务。
