# 项目空间优化：2026-09-18

来源：分享任务 t17897136382720（项目空间优化）的未完成清单，外加用户口头反馈「子任务下再建子任务时经常出现保存失败，草稿已保留重试保存」。一个 PR。清单里的「123」没有可执行描述，视为测试条目未处理。

- 保存失败：任务全文保存带 `subtaskVersion`，服务端版本不一致时返回 409。三种情况会让本地版本落后且重试永远失败：请求超时但服务端已落库、其它窗口改过子任务、刷新后回放的本地草稿带着旧版本（请求期间又有新改动时，草稿没有记录刚确认的版本）。现在：
  - 前端记住每个任务最近一次与服务端一致的子任务快照作为基线；遇到 409 时读取最新任务，按子任务 id 三方合并（本地改动优先，服务端新增保留，未冲突的删除生效，父节点丢失或成环时挂回根），采用服务端版本后自动重试，每轮最多两次。
  - 请求期间又有改动时，草稿同步记录刚确认的版本。
  - 仍然失败时在「保存失败」后面显示服务端给出的原因。
  - 服务端校验与接口不变。
- 表格里添加子任务的输入行不再常驻：鼠标移到任务行，标题格末尾出现「+」，点了才展开输入行并自动聚焦；子任务行的「+」把新子任务挂到这条下面；Esc 或空内容失焦收起。
- 「已完成」判定：主任务已完成但仍有未完成子任务时仍按进行中展示（表格与分组视图）。原「显示已完成子任务」开关改为「显示已完成的任务」，同时控制已完成的任务与子任务，旁边显示已隐藏的任务数；按交付阶段「已验证」筛选时始终显示。
- 表格字段行内可改：标题（铅笔）、分组、优先级、状态、负责人、计划开始、截止日期；子任务的标题、状态、负责人、截止日期。创建者由服务端记录，只读。
- 任务弹框里打开子任务后按一次 Esc 直接关闭（有弹出菜单时先关菜单）。
