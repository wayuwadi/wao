# Phase 1：Windows/macOS 跨平台桌面宠物

技术与安全边界见 [ADR-096](../adr/096-cross-platform-desktop-pet-and-signed-updates.md)。

## 用户路径

1. 用户在 WAO 侧边栏快捷链接或直接访问 `/desktop`，页面根据浏览器平台推荐 Windows x64 或 macOS Universal 安装包，也能手动选择另一平台。
2. Windows 用户运行每用户 NSIS 安装器；macOS 用户打开 DMG 并把 WAO 桌面宠物拖入 Applications。首次启动后出现透明置顶宠物，不打开第二套 WAO 主窗口。
3. 用户拖动宠物到合适位置；点击“打开 WAO”交给默认浏览器，点击隐藏后可从系统托盘/菜单栏再次显示。
4. 宠物启动后安静检查更新。没有更新时不打扰；发现新版本时显示版本与说明，用户点击后完成签名校验、下载、安装与重启，不需要卸载旧版。
5. 网络失败、清单损坏、签名不匹配或安装失败时明确显示错误并保留当前可运行版本，用户可原位重试。

## 规则

- 桌宠必须透明、无系统边框、置顶、可拖动；首次位置靠近当前工作区右下角，之后恢复用户移动后的窗口位置。
- 桌宠与托盘都提供“打开 WAO”“检查更新”“显示/隐藏”和“退出”。退出必须是真正结束进程，隐藏不能误报为退出。
- 更新端点只接受 HTTPS，安装前必须通过 Tauri updater 公钥签名校验；签名校验不可关闭。
- `latest.json` 使用 SemVer，并同时包含 `windows-x86_64`、`darwin-x86_64` 与 `darwin-aarch64` 平台；两个 macOS 架构指向同一个 Universal 更新包。客户端下载页使用稳定安装链接，更新器使用版本化链接。
- 下载页面为公开页面，不要求登录，不展示不存在的安装包为可用；清单读取失败时保留下载按钮并明确提示版本信息暂不可用。
- 当前没有系统级代码签名证书，下载页必须如实提示首次安装可能出现的 Windows SmartScreen 或 macOS Gatekeeper 操作。

## 验收

- Web 类型检查、单元测试和生产构建通过；`/desktop` 在 Windows、macOS 与未知平台 UA 下推荐正确且始终能看到两个平台入口。
- Tauri 前端单元测试和生产构建通过，Rust `cargo check` 通过；Windows x64 与 macOS Universal CI 能生成首次安装包、更新包及 `.sig`。
- 发布任务先上传所有版本化文件，再原子替换稳定下载文件和 `latest.json`；Nginx 对清单禁用缓存，对版本化文件允许长期缓存。
- 从旧版本点击更新后无需卸载即可重启到新版本；篡改更新包或签名时拒绝安装，当前版本仍能启动。
