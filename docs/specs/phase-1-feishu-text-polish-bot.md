# Phase 1：飞书 @润色机器人接入独立润色工作台

本规格扩展 `phase-1-text-polish-workbench.md`，不新增另一套提示词、模型选择或历史数据。
编排决策见 [ADR-191](../adr/191-feishu-text-polish-bot.md)。

## 用户结果

- 管理员在飞书群聊配置中启用群聊润色并填写精确触发名称；默认由现有 WAO 飞书应用直接回复原消息，
  需要独立发件机器人时才选择已启用的自定义机器人 Webhook。
- 已绑定成员在目标群发送 `@润色机器人 原文` 后，WAO 最迟在一个消息轮询周期内收下请求；普通聊天、
  @其他机器人、机器人消息、撤回消息和非文字消息均不触发。
- 润色使用发言人自己在 WAO「润色」页面保存的方法和现有模型路由。结果默认由 WAO 应用以
  `润色结果：` 加正文回复原消息；选择自定义机器人时则由该 Webhook 发回群聊。
- 飞书真实发送成功后，同一份原文、提示词快照和润色结果写入发言人的现有个人历史；其他成员不可见。
- 未绑定、空内容、超过 12,000 字、AI 终态失败或 Webhook 不可用时不写成功历史，并通过错误表情及可用时的
  简短群消息说明原因。

## 一致性与安全

- 现有飞书自建应用负责主动读取目标群并默认回复；可选的群自定义机器人 Webhook 只负责出站发送，地址复用通用注册表加密值。
- 以飞书 `message_id` 持久去重。原消息成功处理后再编辑不会重新润色；需要重跑时重新发送一条消息。
- 飞书润色使用持久 AI 队列和同一条运行 id，复用只读 AI 的三次有界瞬时故障恢复；多 API 节点通过数据库状态
  CAS 分别认领入队、发送和历史收口阶段。
- 提示词在收下消息时冻结；原文是不可议信息，不能覆盖事实保真、只返回润色正文和只读安全约束。
- 飞书发送成功后才保存成员历史。应用回复使用稳定 uuid 去重；Webhook 发送状态不确定时停止自动重放，避免在群里制造重复结果。

## 验收

- 单元测试覆盖精确机器人名称、文本/富文本、保留其他 @成员、成员归属、未绑定拒绝、消息去重和长结果分段。
- 模型 API 与本地 Codex 均进入现有安全执行边界；失败不新增 `text_polish_record`。
- 双节点只创建一项 AI 运行、只认领一次飞书发送，并用稳定记录 id 幂等收口历史。
- 实机发送一条真实 `@润色机器人` 消息，确认群结果、完成表情及网页个人历史三处内容一致。
