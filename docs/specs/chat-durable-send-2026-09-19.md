# Web 聊天发送确认与草稿恢复

承接原生聊天、客户端聊天发送规格及移动端发送去重约定，不改变服务端接口与消息权限。

## 用户行为

- 每个待确认请求单独按成员和发送标识持久化，避免另一窗口保存草稿时覆盖发送记录。恢复时展示待确认内容，用户确认后重试；清理只删除对应请求，不能清除另一窗口的新草稿。
- 服务端明确拒绝的消息允许修改后重新发送；超时和结果不明的请求保持原标识。
- 发送前把原文、引用 id 与去重标识一起保存到当前成员的本机草稿。刷新后仍可确认同一次发送。
- 网络失败后，按钮显示“重试确认上一条”。即使输入了新内容，也先用原标识和原文确认上一条；确认成功保留新内容，下一次操作才发送新内容。
- 消息确认成功后，仅清除仍与原请求相同的输入。若本机清理失败，保留原请求及草稿；恢复存储后重试不会新增重复消息。
- 草稿保存失败或内容损坏时明确提示，并阻止网络发送；保存失败可重试。损坏数据不自动覆盖，保留数据后刷新重读。
- 草稿保留引用对象快照；即使对象已经离开最近 100 条消息，刷新也不会静默取消引用。旧版草稿仍兼容读取。

## 验收

回归测试覆盖响应丢失后重新挂载、改写草稿后重试、发送成功后存储清理失败、损坏草稿保护、引用对象离开最新列表、中文输入法及发送中继续输入。

真实链路需验证本地连接现有数据库后的收发与刷新恢复；测试结果和未验证项在交付记录单独说明，不把组件模拟请求作为真实收发验收。
