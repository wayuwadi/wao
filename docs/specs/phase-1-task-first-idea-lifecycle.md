# Phase 1：任务优先的点子与项目升级闭环

对应任务：`t1787660094494`（把点子库融合进任务与项目）。

## 目标与边界

- 一句话或临时想法直接记录为现有项目中的任务，不再先创建独立点子或空项目。
- 一轮执行进入人工验收后，用户可以把值得持续迭代的任务升级为长期项目；原任务就是项目第一轮，不复制正文。
- 后续想法继续在新项目下创建新任务。任务完成不自动完成项目，项目仍由人工达成或搁置。
- 不恢复 PDCA 前端，不删除历史 `pdcaCycles`；“待验证/已完成”是本次使用的真实验收门禁。

## 服务端契约

- `POST /api/tasks/{id}/promote-to-project` 不接收客户端拼装的项目数据，名称、目标、负责人和可见范围来自当前真实任务
  及原项目权限。
- 仅主任务状态为“待验证”或“已完成”时允许升级；其它状态返回 `400`，任务和项目均不改变。
- 项目 id 由任务 id 确定性生成。首次调用在一个事务中创建“进行中”项目、移动任务并写入活动；响应丢失后重试
  返回同一项目和任务，不产生重复项目。
- 升级保留任务标题、描述、图片、子任务、评论、关联、历史 AI Run 与完成状态；任务分组清空，避免把原项目的
  分组 id 带入新项目。

## 前端与失败恢复

- 任务详情只在“待验证/已完成”时展示“升级为项目”，点击前说明任务会从当前项目移动。
- 请求期间按钮显示处理中并禁止重复提交；成功后同步项目与任务真实响应并进入新项目。
- 失败时任务抽屉保持打开、原数据不变，展示服务端原因并允许原地重试。
- 默认导航不再展示点子库；旧 `/ideas` 地址只显示历史点子归并，不提供快速记录或规划中项目副本。

## 验收

- 待办或进行中任务升级被拒绝且不创建项目。
- 待验证任务升级后，新项目为“进行中”，原任务 id、描述和状态不变但所属项目更新。
- 对同一任务重复请求返回同一项目，项目和任务均只有一份。
- 页面请求失败保留重试入口；成功后打开新项目且项目列表、任务抽屉数据一致。
- 默认菜单没有独立点子库，历史归并接口和兼容页仍可访问。
