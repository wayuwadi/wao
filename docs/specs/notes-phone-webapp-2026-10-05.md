# 小记手机 Web App 视口与内容布局补充

补充 `mobile-web-notes-first.md` 和 ADR-324。范围是 Safari 添加到主屏幕后的浏览器应用，不新增独立客户端。

## 问题与边界

用户确认从 iPhone 主屏幕 WAO 图标打开。截图出现桌面侧栏、页签和整体缩小的文字。当前公网入口已有 `width=device-width, initial-scale=1.0, viewport-fit=cover`，本地 390px 视口可进入手机布局，因此不能断言缺少 meta、缓存或 Safari 设置是根因，也不能把桌面模拟当成实体 iPhone 验收。

现有断点完全依赖布局视口；手机独立应用若以大于 760px 的桌面视口启动，脚本和 CSS 都不会进入手机布局。增加这一异常状态的定向兜底，不用 UA 猜测设备，也不对普通浏览器强制改版。

## 视口兜底

- 在应用挂载前检查：独立应用模式（包括 iOS `navigator.standalone`）、支持触控、屏幕短边 320–600 CSS px、竖屏布局宽度大于 760px 且大于屏幕宽度的 1.25 倍。
- 仅命中异常条件时，将 viewport 宽度显式设为屏幕 CSS 宽度，初始比例为 1，保留安全区；旧入口缺少声明时补齐。
- 仅启动、页面恢复和转屏时检查，不监听普通 resize、滚动或可见视口变化来强制复位。正在放大阅读时不改写，不增加禁止缩放或缩放上限。
- 已命中校正的手机转屏后跟随屏幕长边/短边。正常手机、平板、桌面和普通浏览器不受影响。
- 不刷新页面、不重建编辑器、不读取或覆盖任何草稿。

## 小记手机布局（不超过 760px）

- 沿用现有底部导航与完整菜单。空白输入区最低 300px、正文最低 120px；标题与全屏按钮保持同一行。
- 没有图片时，手机不显示图片模式开关；出现图片后恢复开关。全屏编辑、图片模式和桌面入口保留。
- 卡片保留作者、时间和“…”操作入口。点击后展开原有 AI、预览、编辑和次要操作，同一时间只展开一张卡片；不会因展开操作触发 AI 或进入编辑。
- 展开操作按钮至少 44px，窄屏可换行。错误信息、草稿和后台进度继续显示。
- 正文占满卡片宽度，图片清单在正文下方横向浏览；正文图号、查看大图与返回正文保持可用。
- 手机卡片通过正文预览高度限制长文，而非固定整个卡片高度，避免操作展开或图片清单遮挡内容。触屏保留展开全文入口。
- 不改变桌面悬停显隐、阅读展开状态、已保存内容或 AI 处理规则。

## 验收

自动测试覆盖异常独立视口、iOS 标记、旧入口缺少声明、桌面/平板/浏览器隔离、缩放保护、后台恢复和横竖屏。手机操作展开覆盖单卡独立状态及无 AI 副作用。

浏览器验收与实体 iPhone 验收分别记录；本机无法连接实体 iPhone，真实主屏幕启动、Safari 视口重算和系统键盘仍需用户设备验收，不以模拟通过宣称原截图问题已在真机消失。

2026-10-05 本地验收结果：107 项相关测试、33 项草稿回归、类型检查和生产构建通过。连接既有真实业务服务，320/390/760px 下页面无横向溢出，手机正文为 16px；320px 操作按钮实际尺寸均不小于 44px，次要操作正常换行。390px 全屏保存按钮位于可见区域（787–831px / 844px），输入验收草稿后刷新可恢复，退出确认可丢弃该验收草稿，未创建测试文章。图片引用可定位并高亮对应缩略图，阅读模式可进入退出。1024px 恢复桌面侧栏（236px）及正文/图片双列，手机专用操作入口隐藏。实体 iPhone 限制如上。
