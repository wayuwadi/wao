# 任务重复与提醒

任务详情通过共用 `TaskTimeSettings` 轻量入口打开 `SettingsDialogShell`。输入、正文和原有任务日期字段沿用既有保存链路。这里只保存独立的时间规则，不以全文任务保存覆盖新属性。

## 日期与重复

- 负责人选择执行日期/开始时间或截止日期作为基准。无日期时必须先设置，不把未排期任务自动放到今天。
- 支持每天、每周、每月、每年、周一至周五，间隔 1–365，可设结束日期。周一至周五不是法定工作日；农历与法定调休重复不包含在本次任务重复内。
- 计划重复按原计划周期推进，跳过已过去的周期，只创建下一条未来任务。完成重复按实际完成日加间隔。月末与闰年保留原始日号；成员手动改期后使用新日号。
- 主任务与未放弃的内嵌子任务全部完成后自动创建下一次，原历史保留。下一次复制正文、附件引用、文档、标签及内嵌层级；分配新编号，清空评论、活动、复盘和完成标记。独立父子任务关系须先解除，不隐式复制整个共享项目树。
- 跳过本次先确认，将当前任务放到已放弃并创建下一次。完成重复在跳过时从今天与本次日期的较晚者推进，避免跳过未来任务却生成更早日期。版本检查和下一次编号回执防止重复点击或网络重试产生多个副本。笔记不支持重复、提醒或跳过。
- 同一原任务最多生成一个后继；重新打开历史任务不会再次产生副本，也不会自动删除已经生成的后继。需要继续编辑重复规则时进入下一次任务。

## 个人站内提醒

提醒写入 WAO 通知中心，只对启用规则的负责人可见。支持准时、提前 10/30/60 分钟及一天，底层上限 5 个槽位；有精确开始时间按其计算，无精确时间和截止日期提醒使用选定当天时间。均使用 Asia/Shanghai。

不发送飞书消息、不请求浏览器系统通知权限。关闭页面后服务端仍记录提醒，回来可查看；界面明确说明不是系统弹窗。`wao.scheduling.enabled` 或 `wao.routines.scheduling-enabled` 至少一项开启才运行一分钟扫描；均关闭时界面明确提示且不能新启用提醒。完成后的重复生成使用提交后事件，在独立事务内执行；定时扫描兜底重试。

日期变化重新计算待提醒时刻，清除基准日期暂停提醒并显示原因；完成、放弃或转换为笔记后不再提醒。已完成且不重复的提醒任务重新开始后，需重新保存时间规则以恢复后台提醒；原设置仍可读取。负责人变化不会把原设置隐式授予新负责人；新负责人需主动设置，提醒回执按成员隔离。试发和自动投递都在通知写入与回执的同一事务内，失败可重试而不报假成功。

## 持久化与接口

V207 新增 `task_time_rule`、`task_time_delivery`；不修改已交付迁移或任务全文结构。规则独立 revision，冲突保留浏览器草稿，并读取当前账号设置供比较；只能明确采用账号设置或保留草稿后基于最新版本保存。账号切换丢弃迟到回执，草稿按账号、成员、任务隔离。

浏览器会话接口：

| 方法 | 路径 | 语义 |
| --- | --- | --- |
| GET | `/api/task-time/{id}` | 规则、可编辑性、下一次、待提醒与最近投递；非负责人不读取个人规则 |
| PUT | `/api/task-time/{id}` | CAS 保存当前负责人的规则，重复相同请求幂等 |
| POST | `/api/task-time/{id}/skip` | `{revision,editVersion}`，显式跳过并保留下一次回执 |
| POST | `/api/task-time/{id}/retry` | 本人明确要求重试已保存的到期提醒/重复，不修改规则 |
| POST | `/api/task-time/{id}/test/{uuid}` | 本人主动试发私人站内提醒；同 UUID 重试不重复投递 |

新增 HTTP 能力不新增工作区 MCP 工具或 CLI 命令，不扩展旧令牌权限。既有任务完成写入会执行负责人此前主动保存的重复规则。

## 验收

覆盖日/月/年/工作日、月末/闰年、计划/完成基准、截止结束、手动改期、无日期、内嵌未完成项、历史副本、关联父子拒绝、标签/图片复制、幂等跳过、负责人切换、提醒事务回滚、关闭调度和提交后新事务。浏览器回归覆盖读取失败、保存失败后重开草稿、CAS 冲突显式比较、账号切换忽略旧回执、跳过确认。真实页面与线上版本由整合发布验收补记。
