# Phase 1：今日节奏精力补给群通知

对应任务：`t1787018526668`。基础今日节奏见 [个人工作日节奏规格](phase-1-workday-rhythm.md)，新增决策见
[ADR-081](../adr/081-workday-rhythm-member-energy-notifications.md)。

## 用户结果

1. 精力补给卡片右上角有设置入口，首次打开弹窗即在正确位置展示，不跳动。
2. 成员可启停今日行动通知，并选择系统设置中维护的 Webhook 或机器人真实所在群作为目标；今日三个重点与每个补给项目可独立决定是否通知。
3. 页面顶部“调整节奏”打开的同一个配置弹窗同时包含精力补给与时间线，不再只有时间线配置。
4. 每次“喝水 +1”成功保存后向本人选择的群发送卡片；当天首次记录冥想成功后发送一次，撤销冥想不发送完成通知。
5. 通知卡片展示真实成员、日期和已保存结果，并可回到 WAO 今日节奏。
6. 通知失败不丢当天记录，页面明确区分“记录已保存”和“群通知未发出”，可原位重试。
7. 设置中可维护 1—8 个精力补给项目；每项可选择“累计次数”或“每天一次”，并独立决定是否发送群通知。
8. 累计项目每次点击都保存新的次数；每天一次项目成功后当天不可重复点击。增加、删除或修改项目后跨设备生效。

## 数据与安全边界

- 通知配置复用成员偏好 `workday-rhythm-config-v1.energyNotification`，其中保存通道及 Webhook 稳定配置 id 或群 `chat_id`；补给项目保存到同一配置的 `energyItems`，沿用会话级成员隔离；旧配置自动识别为群聊通道并补两个默认项目及原通知开关。
- 当天动作按项目标识写入 `workday-rhythm-day-YYYY-MM-DD.energyRecords`。服务端发送前重新读取当前成员的项目配置和当天记录，不采用客户端提交的名称、次数或成员身份。
- Webhook 地址来自系统设置的通用机器人注册表，只把稳定 id 与显示名写入成员偏好；地址仍加密留在服务端。群聊通道的 App ID / App Secret 继续来自系统级飞书群聊配置，App Secret 加密落库且不返回浏览器。
- 本功能是成员主动点击后的即时通知，不是定时健康提醒，不设置医学饮水目标，也不推断健康效果。
- 没有已启用 Webhook，或没有可用飞书应用、目标群时不展示伪造选项、不模拟成功；保存记录照常工作，配置区和通知状态显示真实错误。

## 验收

- 两个成员保存不同目标群后，服务端分别读取各自配置和当天记录，不能由请求体冒充其他成员、次数或完成状态。
- 通知关闭或关闭某一动作时，该动作只保存记录而不调用飞书；开启后，喝水每次 `+1`、冥想首次完成分别发送对应卡片。
- 当天记录保存失败时不发送通知；记录成功但飞书失败时保留可重试状态，重试不再次增加喝水次数。
- 旧版只有 `version + blocks` 的节奏配置仍可读取，保存后补齐通知默认值。
- 旧版 `waterCount`、`meditated` 与 `notifyWater`、`notifyMeditation` 自动映射为新项目结构，不丢已有当天记录和通知选择。
- 新增累计项目连续点击两次显示并保存 2；新增每天一次项目完成后当天禁用，刷新仍保持完成且不产生第二次通知。
- 390px 窄屏可完整选择目标群、配置各项目的通知开关、保存配置和重试通知，不产生业务区横向滚动。
- 选择已启用 Webhook 后不依赖飞书应用凭据即可发送；配置被停用或删除时保留当天记录并明确提示改选，不回落系统默认项。
