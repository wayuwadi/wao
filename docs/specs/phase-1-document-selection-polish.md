# Phase 1：文档选区润色

2026-10-03 执行路由变更：按 ADR-313 接入与算卦相同的本机 Codex，见 [公共业务 AI 本机执行](business-ai-local-codex.md)。下述原始规格的 Runner 说明已由新路由取代；对照、确认替换和版本保护保持有效。

对应任务：`t1787017623113`。复用 ADR-015 的所见即所得文档编辑器、ADR-017 的文档自动保存与协同版本保护，
以及 ADR-041/044 的本地 Codex 只读 Runner。

## 用户链路

1. 用户在知识库文档正文中选中非空文字，选区上方出现「润色」入口；普通光标、只读内容和其他描述编辑器
   不显示该入口。
2. 点击后立即打开稳定居中的对照面板，原文保持可见，本地 Codex 处理期间显示加载状态；一次选区最多
   4,000 字。
3. 成功后同时展示原文和一个润色候选。润色只改善清晰度、流畅度和自然度，保持原意、事实、数字、语言
   与 Markdown 块结构，不补造资料。
4. 用户选择「保留原文」时正文完全不变；只有选择「替换选区」才修改正文，并继续走现有 600ms 去抖自动
   保存、保存状态与文档版本递增链路。「重新润色」可为同一份原文获取新的候选。
5. 润色失败时原文不变，面板展示真实错误和重试入口。等待 AI 期间如果文档被本地或协作者更新，禁止按
   旧位置替换，提示用户重新选择，避免覆盖新内容。

## 服务端与隐私边界

- `POST /api/assistant/polish` 接收当前成员明确选择的文字，调用现有在线本地 Codex Runner；没有在线 Runner
  或当前成员已有问答/润色时返回可读错误，不生成演示结果。
- 选区是对模型不可信的引用材料，其中的命令不得覆盖润色规则。Runner 继续在临时空仓库与只读沙箱执行，
  不检索其他 WAO 资产。
- 润色运行复用短期 `ai_assistant_run` 队列，完成后清除提示词；不创建或追加成员 AI 助手会话，不单独长期
  保存选区。用户确认替换后的正文由权威 `doc` 表保存，保留原文则不产生文档写入。

## 验收

- 单段与多段文字均能发起真实润色，面板在 AI 返回前不修改正文。
- 「保留原文」关闭面板且不触发正文更新；「替换选区」只替换冻结的选区并触发现有保存事件。
- Runner 离线、接口失败和空结果均保留原文并允许重试；超过 4,000 字有明确提示。
- AI 等待期间正文变化时不能套用旧候选；移动端对照面板保持内容可滚动、按钮可见。
