# Phase 1：通用飞书 Webhook 配置

对应任务：`t17871887864620`。决策与兼容边界见
[ADR-089](../adr/089-generic-feishu-webhook-registry.md)。

## 用户结果

1. 系统设置入口显示“Webhook配置”，不再把能力表达成一条匿名的“通知 · 飞书 Webhook”。
2. 用户可新增、查看、编辑、删除多项飞书自定义机器人配置，并维护可辨识的名称、用途、启用状态和系统默认目标。
3. 每项配置可独立发送测试消息；测试期间有明确忙碌态，失败保留本地表单并允许重试。
4. 第一项自动接管现有系统通知；切换或删除默认项后，任务、评论、AI 运行与按项目通知继续指向一个明确目标。
5. 编辑名称、用途或开关时不需要重新粘贴地址；页面、列表接口和保存响应都只显示脱敏地址。
6. 原设置页“日历账户 · CalDAV”演示入口删除；真实 CalDAV 账户仍在日历页按当前成员维护。

## 数据与安全边界

- `feishu_webhook_config` 是全局机器人注册表，不伪装成成员私有配置。地址使用 AES-256-GCM 随机 nonce 加密，
  明文只在服务端真正发送或测试时短暂解密，不进入响应、Git 或应用日志。
- 仅允许飞书 / Lark 官方 HTTPS 自定义机器人地址；不接受任意 URL、账号密码、自建应用 App Secret 或群 `chat_id`。
- “WAO”群选择来自飞书群聊同步的自建应用与开放平台群列表，不来自 Webhook 注册表。本期保留两条真实通道，
  不用同名占位数据把它们强行合并。
- 旧单例配置自动迁移为“系统通知（原配置）”。旧接口与配置键只承担滚动发布兼容，不再作为新功能的数据模型。
- 新建、加载、保存、测试和删除均有加载中 / 保存中 / 失败重试；切换编辑项或删除前保护未保存草稿。

## 验收

- 创建两项配置后刷新仍存在；可把第二项设为系统默认，列表只出现一个“系统默认”标记。
- URL 明文不会出现在 GET/POST/PUT 响应，编辑时密码输入框为空，留空保存后旧地址仍可测试。
- 非官方域名、HTTP、带用户信息或查询参数的地址被拒绝，错误消息不回显密钥。
- 删除默认项后剩余项自动接管；删空后通知停用且不会回落到已废弃环境变量。
- V17 单例密文升级到 V78 后无需重新粘贴即可继续发送；滚动发布旧节点读取兼容镜像时目标一致。
- 设置导航和内容中不再出现演示 CalDAV；日历页真实账户的新增、同步、订阅和删除能力不受影响。
