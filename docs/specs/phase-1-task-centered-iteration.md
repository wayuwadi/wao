# Phase 1：任务中心化迭代

对应任务：`t17877079592820`（去掉项目顶部空间与任务升级项目功能）。

## 目标与边界

- 一次具体改进始终作为任务持续补充、执行和验收，不因进入待验证或完成状态而建议升级为项目。
- 项目继续组织任务、文档、文件、记忆和动态，但不单独展示“当前迭代”或复制最新任务状态。
- 已有项目和任务数据不迁移、不删除；普通新建项目、项目设置、新建任务和任务 AI Run 不受影响。

## 前端行为

- 项目详情的项目头部之后直接展示页签和当前任务视图，不出现“项目最终目标”“当前迭代”“开始下一轮”等概览操作。
- 任务详情在所有状态下都不出现“继续长期迭代”或“升级为项目”。
- 历史点子兼容页只引导用户创建并持续维护任务，不再提示任务可升级为项目。

## 服务端契约

- 删除 `POST /api/tasks/{id}/promote-to-project`；公开 OpenAPI 契约同步移除该路径及 `TaskPromotion` 响应结构。
- 删除任务移动、新项目派生 id 和任务行锁等仅由升级功能使用的代码。
- 不新增 migration；历史业务数据保持原所属关系。

## 验收

- 进入任意项目时，项目头部下方直接可见任务页签和任务视图。
- 打开待验证或已完成任务时，属性栏不包含升级项目入口。
- 前端代码不再引用升级 API，服务端不再暴露升级端点，API 契约中也不存在该路径。
- 前后端相关测试、类型检查和生产构建通过。
