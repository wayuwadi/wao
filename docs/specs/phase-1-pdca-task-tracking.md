# Phase 1：PDCA 事情跟踪

对应任务：`t1786440722814`（适合 PDCA 方法论的事情跟踪系统）。

## 目标

在既有任务、日历和待办链路上补齐“检查—改进—再计划”，让个人日常事项不仅能被完成，
还可以保留实际结果、偏差原因和下一轮行动。PDCA 是任务的可选增强，不强迫一次性事项填写复盘。

## 用户链路

1. 新建任务时可打开“使用 PDCA 跟踪”，并填写本轮计划与判定标准；已有任务可从详情启用。
2. P（计划）保存期望结果，D（执行）直接使用任务真实状态、步骤和子任务进度，不另造一套进度。
3. 任务进入“待验证”或“已完成”后处于 C（检查）；用户选择达成结果，并填写事实复盘和改进行动。
4. 结果、复盘和改进行动完整时才能完成本轮复盘。闭环会保留时间并把任务设为“已完成”。
5. 已闭环任务可把上一轮改进行动原样带入下一轮计划，同时重新打开为“待办”；历史轮次只读保留。
6. 待办页的 PDCA 视图只展示明确启用了 PDCA 的任务，并按 P/D/C/A 四阶段汇总真实数据。
7. 公开任务分享页和 Markdown 地址包含 PDCA 记录，便于协作者或 AI 按既定目标与历史经验处理任务。

## 数据与状态

- `task.detail_json.pdcaCycles[]` 按时间顺序保存轮次，不新增数据库列或 migration。
- 每轮包含稳定 `id`、`plan`、`check`、`act`、`outcome`、`startedAt`、`reviewedAt`。
- `outcome` 只取“达成 / 部分达成 / 未达成”；`reviewedAt` 为空表示本轮尚未闭环。
- 阶段由当前轮与任务状态投影：待办/收集中为 P，进行中/AI 进行中为 D，待验证/已完成且未复盘为 C，已复盘为 A。
- 没有 `pdcaCycles` 的历史任务仍是普通任务，不会被伪装进 PDCA 统计。

## 体验与失败处理

- P/C/A 编辑复用任务草稿和串行自动保存，展示保存中、已保存和失败重试状态；后台同步不能覆盖本地输入。
- 复盘按钮在结果、检查、改进行动任一缺失时禁用，并明确提示缺什么。
- 历史轮次折叠展示；移动端 PDCA 看板横向逐列浏览，任务详情保持单列可读。
- 服务端读写和公开分享必须保留 PDCA 轮次；未知旧 JSON 字段仍兼容读取。

## 验收

- 普通任务可启用 PDCA，编辑计划后刷新仍存在。
- 选择结果并填写 C/A 后完成闭环，任务进入已完成，轮次带 `reviewedAt`。
- 点击“开启下一轮”后历史不丢，新轮计划等于上一轮改进行动，任务回到待办。
- 待办页四阶段视图的数量和任务阶段与真实任务状态一致；未启用任务不计入。
- 公开 JSON、分享页和 Markdown 均包含任务 PDCA 记录，子任务单独分享不携带主任务 PDCA。
