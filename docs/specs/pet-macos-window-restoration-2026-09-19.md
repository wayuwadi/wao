# macOS 宠物与工作区跨屏恢复

## 实机缺陷

macOS 13.7.8 Intel，内建 Retina 屏幕 2× 与外接屏幕 1×，客户端当前 1.1.9 本地开发宿主：工作区在外接屏幕的位置为 `(2300, 200)`、尺寸 `1000×700`；正常退出并重启后变为 `(1150, 100)`、`500×350`。宠物在外接屏幕拖动后，重启回到主屏默认位置。

窗口状态插件保存的是物理像素，恢复时可能使用启动屏幕的缩放比例。宠物还有第二个问题：窗口构建完成后，无条件定位到默认位置，覆盖恢复结果。Tao 的初始定位通过主线程队列异步执行，恢复必须排在它之后，才能避免正确位置被稍后覆盖。

## 行为

- macOS 使用 AppKit 原生窗口 frame 自动保存；读取其 frame 描述中的全局逻辑坐标，在仍可用的屏幕内恢复，避免随启动时的活动屏幕重新映射位置。以应用标识和窗口标签区分正式版、开发宿主、工作区和宠物。
- macOS 不再通过跨平台插件重复恢复物理位置和尺寸；其余窗口状态与 Windows 既有路径保留。
- 宠物在完成恢复或默认定位后再显示，避免首次出现在错误位置。已有有效原生位置时不重新定位到默认角落。
- macOS 气泡缩放在同一个主线程操作中读取窗口 frame 与屏幕可用区，统一按逻辑坐标保留右下角位置并约束到屏幕内，避免跨屏恢复过程中混合不同缩放比例的物理坐标。
- 首次采用此机制没有原生 frame 记录时使用默认布局。旧记录缺少屏幕缩放信息，不猜测转换，不删除旧记录或任何业务数据。
- 保存位置与所有当前屏幕都不相交时回到可见的默认布局；部分越界和过大尺寸约束到相交面积最大的可用屏幕内。格式错误和非有限坐标不作为有效恢复数据；断屏场景未实测前不得声称验收通过。

## 验收

在本地真实开发宿主上分别验证主屏与副屏的工作区和宠物拖动、正常退出、重启后的坐标及尺寸；验证隐藏恢复仍可用，开发宿主不改变正式版窗口记录。无登录不影响窗口状态验收；设置及草稿刷新仍须独立验证。

依据：[Apple NSWindow frame 自动保存](https://developer.apple.com/documentation/appkit/nswindow/setframeautosavename(_:)) 与 [frame 恢复](https://developer.apple.com/documentation/appkit/nswindow/setframeusingname(_:force:))。
