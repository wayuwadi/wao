# 图片复制可靠性

日期：2026-10-13。用户反馈：图片已经显示，点击复制仍经常弹出失败 Toast。

## 原因

公共 `ImageCopyMenu` 原来先关闭菜单、请求原图并等待格式转换，最后才调用剪贴板写入。慢请求和异步等待可能使点击授权失效；关闭菜单也让失败只能通过短暂 Toast 显示。小记分步复制已经使用 Promise 图片项，但公共图片菜单没有复用。

## 行为

- 所有公共图片菜单与小记分步复制使用同一个完整图片复制流程。点击时立即调用 `clipboard.write`，异步读取与转换作为 `ClipboardItem` 的 Promise 内容。
- 页面已加载**同一完整原图地址**时，从其自然像素尺寸生成 PNG，不再次请求。CSS 显示尺寸不影响复制尺寸，透明通道保留。
- 只加载预览时仍读取原图，不按 `data-full-src` 将缩略图当原图；原图无法读取必须报告失败。跨域画布不可读取时尝试原地址，沿用浏览器 CORS 与登录权限，不新增图片代理或扩大权限。
- 图片请求位于前端 `src/api/`。PNG 直接使用读取的图片 Blob；其他格式转为 PNG，位图解码不支持的格式用图片元素解码；临时对象 URL 与位图及时释放。
- 复制期间显示「正在复制…」并阻止重复操作；成功才关闭菜单。失败原因保留在菜单中，可点击「重试复制图片」或使用原有图片链接入口，不再只弹出黑色失败提示。
- 不把复制链接、空 Blob、预览图或单纯图片可见标记为原图复制成功。浏览器权限拒绝仍明确显示，实体设备最终验收由用户完成。

## 验证

覆盖网络未完成时已发起写入、已加载原图无重复请求、预览不代替原图、完整像素与透明背景、格式转换回退、失败留在菜单和重试、成功关闭及重复点击拦截。真实浏览器连接既有数据库，用本次创建的合成小记及图片验证剪贴板图片结果，不向第三方发送内容；完成后回收本次验收数据。

无后端接口、数据结构、MCP 或 CLI 能力变化。沿用界面设计系统的浮层、颜色、文字和原位错误规范。

浏览器点击授权参考：[WebKit Clipboard API](https://webkit.org/blog/10855/async-clipboard-api/)、[MDN Clipboard API](https://developer.mozilla.org/en-US/docs/Web/API/Clipboard_API)。
