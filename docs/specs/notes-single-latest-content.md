# 小记始终显示一份最新内容

2026-09-30 用户确认交互原型。本规格取代 `notes-ai-draft-coexistence.md`、`notes-draft-conflict-recovery.md` 中双版本预览及人工核对选择规则；删除确认沿用 `notes-delete-confirmation-anchor.md`。

## 界面与自动选择

- 小记列表、阅读模式及重新打开的编辑器使用同一份最新内容，不提供原文 / 润色切换、独立已保存预览或另存冲突选择。
- 当前编辑有续写时保持输入和光标，后台刷新不会改写草稿。无本地修改时可同步最新 AI 成果；收起的未保存草稿恢复后继续编辑。
- 保存当前输入即明确更新本篇：自动读取最新版本、保留未手动修改的标题和标签、合入安全的自动总览图；正文和手动修改字段以本次输入为准。历史无基线草稿也可原地保存。
- 保留服务端 CAS 校验；竞争写入时自动重新读取并有限重试，连续变化或网络失败仍保留草稿，提供同一个重试保存按钮。
- 状态收在编辑器底部，涵盖加载、草稿保护、保存中、已保存、AI 整理中及失败。成功保存回到同一张卡片，再次编辑使用最新正文，可重复保存。

## 后台正文与续写

- 新的工作流润色结果在源正文仍有效时按版本条件写入文档正文；保留总览图。历史润色记录兼容显示，但不向用户提供版本选择。
- 小记通过既有文档 PATCH 保存新正文后，已选择的润色自动重新入队，旧任务 id 失效；完成的标题及配图不重复生成，未完成阶段改用最新正文，手动修改标题时取消旧自动标题。
- 只有已有作者本人工作流的自动选择续跑；未选择的阶段、不属于作者的文档及普通知识库文档不静默开启 AI。
- 浏览器关闭后仍由既有服务端调度器续跑，重试失败不能误报正文未保存。旧正文结果不能覆盖已经落库的新输入。

## 验收与能力边界

覆盖历史草稿、续写期间 AI 标题 / 配图 / 正文到达、连续保存、CAS 竞争与网络失败、单份正文进入再次编辑、来源失效后重新入队、保留图片和成员隔离。API 路径和请求结构不变；不新增 CLI / MCP 操作或扩大令牌权限，此次自动续跑仅是已有浏览器保存行为。

本次本地验证：前端相关 65 项、服务端相关 50 项测试通过；类型检查与生产构建通过。实际富文本编辑器通过模拟接口验证迟到 AI、收起草稿、失败重试、再次保存和 390px 窄屏。本地没有可用真实后端连接，未验证真实账户 AI 生成与线上数据链路；按用户“直接发布，我自己去线上测”的安排交付合并，由用户在线上验收。
