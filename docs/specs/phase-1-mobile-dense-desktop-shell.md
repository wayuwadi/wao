# Phase 1：手机高密度桌面同构应用壳

对应任务：`t1787973598097`（手机上 WAO 信息密度过低、难以使用）。本规格取代
`phase-1-h5-app-workbench.md` 中“手机底栏作为主导航”的界面规则；可安装 H5、30 天持久会话和各业务页
既有手机交互继续有效。

## 用户结果

1. 手机进入登录后的 WAO 时，和 PC 一样从左侧纵向菜单浏览真实功能，不再把导航压成只含少数入口的底栏。
2. 左侧菜单使用约四分之一屏宽的紧凑样式：品牌、搜索、分组、完整可见菜单和成员设置仍能辨认，菜单自身
   纵向滚动，不挤占正文滚动位置。
3. 顶栏和多页签条继续显示，但使用只保留图标或短标题的紧凑尺寸；页签过多时横向浏览，当前页签自动可见。
4. 首页首屏缩小留白、标题、卡片和控件间距，尽量同时显示运行状态、自主目标等真实信息；不增加演示数据。

## 兼容边界

- 手机断点继续使用 `max-width: 760px`。任务整页详情、密码查看、输入框防 iOS 聚焦放大等业务页手机规则
  继续生效；不得通过伪造 980px viewport 或整体缩放绕过这些规则。
- 手机左栏忽略桌面保存的分组折叠状态，始终展示全部服务端配置为可见的菜单；桌面折叠、拖拽、右键和停靠
  行为保持不变。
- 原成员偏好 `mobile-bottom-nav-v1` 不删除，便于回退，但当前界面不再读取、保存或展示“编辑手机底栏”，
  避免让用户维护一个已经不生效的配置。
- 手机悬浮新建任务入口继续保留在安全区上方；页面不再为已移除的底栏预留 64px，备案区只避让悬浮入口。

## 验收

- 在 390px 与 320px 视口进入首页：左侧可看到分组和所有可见菜单，右侧同时可见紧凑顶栏、页签与首页正文，
  应用壳不产生整页横向滚动。
- 桌面先折叠“个人”和“工具”，手机打开时两组菜单仍完整出现；返回桌面后原折叠偏好仍生效。
- 手机直接进入靠后的模块时，左栏当前入口自动滚入可见区域并保持选中；菜单自身和正文分别纵向滚动。
- 手机可从顶栏打开 AI、任务、小记、主题、聊天和通知，可从悬浮按钮新建任务；最后一段内容及备案信息不被
  系统安全区或悬浮入口遮挡。
- 桌面侧栏、顶栏、多页签、菜单拖拽与设置页功能没有布局或行为回归。

> 2026-10-03 后续调整：手机常驻左栏、顶栏和页签的规则由 [窄屏内容优先应用壳](mobile-content-first-shell.md) 取代，完整导航改为从底部“更多”按需打开；桌面偏好保留。
