# 规格：待办真实数据加载

对应任务：`t1786596551162`（待办不展示默认兜底假数据）。

## 问题

领域数据 store 启动时带有原型 fixtures，且初始化要等待所有业务域请求结束后才统一写入结果。即使任务接口已经返回，待办页也可能继续展示演示任务；任务接口失败时则会一直保留演示任务，用户无法判断这些任务是否属于自己。

## 规则

- 待办页只展示 `GET /api/tasks` 返回的真实任务，不把 fixtures 当成用户任务。
- 任务请求未完成时展示“正在加载中”，不提前展示空状态或演示任务。
- 任务请求失败时清空演示任务，展示真实错误和“重新加载”入口。
- 任务结果一旦返回就立即接管 store，不等待知识库、文件、密码库等无关业务域请求完成。
- 真实空数组是有效结果，显示既有的空任务状态。

## 验收

- 人为延迟其他业务域接口、让任务接口先返回，待办页应立即出现真实任务。
- 人为延迟任务接口，待办页只显示“正在加载中”，页面上找不到 fixtures 中的任务标题。
- 任务接口失败时页面不显示任何 fixtures 任务，并可点击“重新加载”再次请求。
