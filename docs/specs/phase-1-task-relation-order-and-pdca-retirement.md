# Phase 1：任务关联检索与 PDCA 前端退役

对应任务：`t17871887864620`（系统功能优化&问题修复）中的“任务功能优化”1–4 项；第 5 项为空，
不推断额外需求。

本规格在产品输出口径上取代 `phase-1-pdca-task-tracking.md` 的新建、详情、TODO 与公开分享展示条款；
ADR-048 定义的历史存储结构继续作为兼容契约保留。

## 目标

让任务关联选择器优先呈现刚创建且仍值得关联的真实内容，强化子任务危险操作的视觉辨识度，并从
产品界面下线当前使用率较低的 PDCA 模块，同时不破坏已经持久化的历史数据。

## 关联候选

- 知识文档、未完成任务和真实文件统一按各自的真实创建时间倒序；“全部”页签也使用同一排序，
  输入关键词筛选后不改变先后顺序。
- 任务新增 `createdAt` 契约，对应 `task.created_at`。V79 按现有稳定 id 中 `t` 后的 13 位 Unix 毫秒前缀回填能
  确认时间的存量任务；更早且没有可靠来源的数据保持空值并稳定排在有时间的数据之后，禁止用
  页面加载时间伪造。
- 文件接口除面向人的 `time` 文案外返回 ISO `createdAt`；文档沿用已有 `created` 真实时间。
- 关联任务候选排除当前任务与状态为“已完成”的任务。既有 `linkTasks` 数据不做破坏性清理，
  仍在任务详情的已关联区域正常展示和打开。

## 子任务操作

- “复制该子任务分享链接”和“删除子任务”使用有边框、有底色、完整点击区域的按钮，不再表现为
  灰色文字链接。
- 删除按钮使用明确的危险色；两个按钮均保留图标、键盘焦点与完整中文标签，在窄栏中不截断。

## PDCA 退役边界

- 移除任务详情的 PDCA 卡片与编辑逻辑、新建任务的 PDCA 开关、TODO 的 PDCA 视图，以及公开分享
  页和 Markdown 地址的 PDCA 展示。
- `pdcaCycles` 数据结构、后端读写校验和既有持久化数据继续兼容；本次不删除 JSON 字段、不迁移或
  改写历史轮次，避免一次界面退役演变成不可恢复的数据销毁。

## 验收

- 构造不同创建时间的知识、任务、文件，三类页签与“全部”搜索结果均为最新在前；无可靠时间的
  历史数据在末尾且相对顺序稳定。
- 已完成任务不出现在关联任务候选中，未完成任务仍可关联和解除关联。
- 打开子任务详情时，两项操作呈现为清晰按钮，其中删除按钮有危险色区分。
- 带历史 `pdcaCycles` 的任务仍能正常读取和保存，但任务详情、新建任务、TODO、公开分享页和
  Markdown 输出均不再出现 PDCA 入口或模块。
