# 小记自动整理的阶段异常恢复

补充 `notes-passive-ai-visual-triad.md`、`notes-single-latest-content.md` 与本机执行约定，不改变单份正文或已选模型。

## 复现

本机工作流在提交阶段被拒绝时只记录日志，标题仍为 PENDING，下一轮再次提交。既有通用调度器虽然保存失败，但按当前状态猜测阶段，可能将正在运行的标题误记成后来润色阶段的失败。

## 行为

- 推进阶段发生异常时，携带实际阶段及事务开始时的工作流快照向外抛出；原事务先回滚。已入队记录、阶段状态和正文写回不应部分提交。
- 调度器在独立事务中再次锁定工作流。仅当当前状态仍等于失败时的快照，才将实际失败阶段置为 FAILED；其余阶段保持原状态。
- 用户已重试、保存了新内容、删除或其他推进已改变工作流时，不采用迟到失败。来源失效和删除保护沿用现有规则。
- 数据库访问异常与版本冲突保留原状态，由之后的正常推进恢复；失败状态暂时无法写入也不阻断其他小记。
- 已知业务拒绝保留可操作原因，其他异常给出对应阶段、原文保留和重试说明，不将原始内部错误或 SQL 写进页面。
- 重试沿用现有接口，仅复位失败阶段。失败终态不表示已经终止其他仍在运行的模型调用。

## 边界

仅修改服务内部恢复路径，HTTP API 字段、CLI、MCP、权限和 migration 不变。当前单 worker 执行并发不因本修复改变。数据库整体不可用时无法持久化失败状态，不声称已写入失败。
