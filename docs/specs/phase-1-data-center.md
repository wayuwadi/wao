# Phase 1：WAO 数据中心

## 用户结果

1. 登录成员可从 WAO 一级导航进入「数据中心」，一次看清系统当前真实保存了哪些数据、记录量和最近写入时间。
2. 空数据、缺少可靠时间戳和仅完成数据源登记的状态必须明确区分，页面不得用演示统计填空。
3. 后续报告与功能可以先检查数据目录再选择真实数据源，不再依赖对数据库表或现有模块的口头猜测。

## 一期范围

- `GET /api/data-center/overview` 只读聚合 WAO 当前 MySQL 中的项目、任务、AI Run、知识文档、记忆版本、共享聊天、HTTP 请求指标、产品更新与项目 Git 源登记。
- 每项返回稳定 id、分类、用途、记录量、最近写入时间、覆盖级别和状态。状态只有：
  - `READY`：存在记录且能给出最近写入时间；
  - `TIME_UNKNOWN`：存在真实记录，但历史模型没有可靠时间戳；
  - `EMPTY`：当前没有记录；
  - `REGISTERED_ONLY`：只登记了来源元数据，没有采集来源内容。
- 数据中心只暴露目录与聚合元数据，不返回任务正文、聊天内容、记忆正文、请求明细或仓库凭据；原始数据继续由各领域 API 和既有权限边界负责。
- 页面覆盖加载、失败原地重试、全空状态、分类筛选、窄屏和手动刷新。

## Git 数据边界

项目 AI 工作流已经保存真实 `repo_url` 与默认分支，因此数据中心可以展示已登记仓库数量和最近配置时间。更新日记上线后，Runner 只在运行成功时把本次 Git 提交的 SHA、scope、标题和提交时间送入 `product_update_event`；GitHub/Git 凭据仍只保留在 Runner 本机，WAO 不镜像作者、diff、分支历史或完整提交历史，也不生成提交频率、贡献排行等伪报告。

后续接入 Git 明细时应单独设计 Runner 采集契约、增量游标、作者身份归并、敏感信息过滤、删除/重写历史处理和成员可见范围，并用真实仓库完成端到端验收。

## 能力选择

本期不引入 Airbyte、Debezium 或 OpenMetadata。它们适合多外部系统同步、变更数据捕获或企业元数据治理，但会新增独立服务、连接器凭据、运维与许可评估；当前真实数据都已在 WAO MySQL，使用现有 Spring Boot、MyBatis 和 Vue 能以更小边界交付完整只读闭环。达到多外部来源、持续增量同步或字段级血缘需求后再通过 ADR 评估。

## 验收

- 后端测试覆盖数据源稳定排序、四种状态、总量聚合与缺失行安全回落。
- 前端测试覆盖真实聚合展示、Git 仅登记边界、筛选、空数据与失败重试。
- 线上使用真实登录会话打开 `/data-center`，刷新后记录量与 API 一致；任何数据源为空时展示空状态而非示例数字。
