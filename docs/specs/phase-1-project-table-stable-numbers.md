# 项目表格、固定编号与紧凑工作区

来源：t17895256858940，全部五项；延续既有任务编辑、批量操作和桌面桥协议。

- 项目列表改为有列头、列分隔线、固定行高的真实表格；包含编号、标题、优先级、状态、负责人、创建人、计划开始、截止。标题展开子任务，保留快捷添加、完成勾选和保存失败重试。
- 所有任务及子任务共享服务端递增编号，从 0 开始；编号只读，删除不回收、排序不变，并发分配允许空号。旧数据按任务 ID 和子任务顺序回填；无 id 的历史子任务读取时获得确定性 id，下一次保存写入 JSON。
- 数据库 work_item_number 独立保留编号与身份映射，避免任务删除导致复用。列表批量解析编号，禁止逐行数据库查询。API Task.number 和 Task.subs[].number 为服务端输出字段，忽略客户端传入的编号。
- 项目正文使用可用宽度、缩小段落与工具栏间距；表格横向滚动适配窄屏，长标题截断但提供完整提示并可打开详情。
- 侧栏始终提供展开/收起按钮，沿用已有本地持久化偏好，桌面顶栏隐藏时仍可操作。
- Windows 托盘在聊天或通知存在未读时闪烁；右键勾选“新消息闪烁”控制开关并本机保存，默认开启。未读清零或关闭立即恢复图标。消息内容不通过原生桥传输。

验证：固定编号在新增、重排、删除、伪造编号及并发重试后的稳定性；真实表格结构、层级展开及原有状态操作；侧栏状态；托盘开关及未读判定。本次用户负责上线 UI 验收。客户端发布受现有 GitHub 计费状态约束。

## 任务加载与草稿冲突恢复

- 任务加载中、加载失败与成功返回空列表分别展示。请求失败不能显示“还没有任务”，也不能清空已有任务或本机草稿；项目页提供重新加载入口。
- 子任务保存发生版本冲突时，表格与详情列表都提供“查看并处理冲突”，打开既有任务详情中的服务器版本查看、复制本机内容与显式放弃入口。只有非冲突的保存失败继续提供“重试保存”。
- 不自动丢弃旧草稿，不替草稿补写服务器版本绕过冲突保护。此处只改善错误恢复入口，不能作为线上接口超时已经解决的证据。
