# 浏览器登录可靠性与原地恢复

## 范围

补充 `phase-1-feishu-login.md`、`phase-1-unified-account-auth.md` 与 ADR-007。仅调整浏览器客户端的加载、呈现与会话恢复，不改变服务端身份解析、权限、Cookie 或五分钟签名 state 的校验契约。

## 登录入口

- 桌面浏览器首次突出官方二维码；移动浏览器优先显示飞书授权，并提供扫码切换。飞书端内继续优先免登。
- 同一浏览器只记住最后一次成功登录的方式（飞书或邮箱）；点击切换及失败均不更新。不得存储邮箱、密码、授权码或 Token。首次身份认领成功才记住飞书。
- 邮箱密码可临时显示或隐藏，切换和关闭时恢复隐藏；原有本页输入保留，成功后清除密码。

## 可恢复状态

- 官方二维码/H5 SDK 共用有上限的加载器：八秒超时，错误后移除脚本及缓存，下次重试重新加载。端内请求本身也有八秒上限，超时后不再触发迟到的授权请求。
- 二维码按授权 state 中的服务端有效期提示过期；前台恢复时再次检查。过期后移除旧 iframe，明确提供刷新入口，并申请全新的授权 URL。前端有效期只作提示，真实性由服务端验证。
- 仅处理当前 iframe、匹配官方来源和数据格式的消息；旧二维码、已关闭弹窗及旧请求不能导航。

## 会话过期恢复

- 已登录页面的受保护请求收到 HTTP 401 后，在原页面弹出重新登录窗口；保留组件、路由参数、成员身份和未保存内容。401 不自动跳转或刷新页面，不将 403 当作会话过期。
- 暂停后续受保护请求（含 SSE），认证请求继续可用；失败写入不通过 HTTP 层重放。恢复后由用户检查保存状态并重试。
- 邮箱在弹窗内完成；飞书使用用户点击时打开的独立窗口。原页面只接受同源、该窗口、同一 state 的完成信号，再读取后端真实会话。
- 后端返回的 accountId 和 memberId 必须都与原账号一致；错误账号或首次认领仍保持暂停及原草稿，不切换当前页面身份。取消窗口、弹窗拦截和授权超时都可重试；也可检查在其他窗口恢复的真实会话。
- 全局恢复窗口不能通过 Escape 或关闭按钮绕过；恢复期间没有保存与退出等自动业务写入。所有凭据仍由已有服务端处理。

## 验收与边界

覆盖 SDK 卡住/错误/重试、二维码过期及来源、桌面/移动入口、成功方式记忆、密码开关、401 请求暂停与不重放、认证错误不触发全局恢复、错误账号拒绝、同账号原地恢复及草稿组件保留。浏览器真实数据验收与公网资源检查单独记录，实体手机扫码确认仍由用户验收。

本次无新增业务服务、HTTP 接口、MCP 工具或 CLI 操作；CLI 继续使用既有设备登录契约，浏览器 SDK 与同页草稿恢复不适合增加 CLI 命令或扩大旧令牌权限。
