# Phase 1：组织共享轻量聊天

对应任务：`t1787717313337`。技术与数据边界见
[ADR-126](../adr/126-shared-lightweight-chat.md)。

## 用户结果

1. 左侧“公共”分组增加“聊天”入口；已登录成员看到同一个共享消息流。
2. 可以输入文字，也可以粘贴、拖入或选择一张不超过 10MB 的截图；发送后刷新页面仍能看到消息和图片。
3. 消息先保存到 WAO，再同步到“Webhook配置”的系统默认飞书机器人；群里能看到发送者、正文、截图链接和
   返回 WAO 聊天的入口。
4. 飞书未配置、停用或临时失败时不丢 WAO 消息。页面逐条显示同步结果，失败项可以重试，未配置项提示去设置。
5. 输入草稿跨刷新保留；加载、发送、上传、空消息、读取失败和重试均有明确状态。后台刷新只追加消息，不覆盖草稿。

## 数据与权限边界

- `shared_chat_message` 是组织共享数据；接口受现有 WAO 会话保护，作者由服务端当前成员推导。
- `client_token` 只用于同一成员发送去重，不包含正文或身份凭据。
- 图片正文继续存 `image_blob`，聊天只保存图片 id 和发送时文件名；飞书只收到公开原图 URL，不收到 Webhook 地址。
- 本期只实现 WAO → 飞书。没有经过验证的飞书入站聊天室协议，因此不把群历史或静态样例冒充实时入站消息。

## 验收

- 两个成员分别发送消息后，双方刷新都按相同顺序看到真实作者、文字和时间。
- 粘贴截图并发送后，WAO 缩略图和飞书卡片中的原图链接都能打开同一份持久化图片。
- 模拟 POST 响应丢失后用相同 `clientToken` 重试，只产生一条数据库消息。
- 禁用系统默认 Webhook 后发送仍成功，消息标记“未同步”；恢复配置后失败消息可手动重试。
- 保留未发送草稿时发生轮询、读取失败或页面刷新，草稿不被服务端内容覆盖。
