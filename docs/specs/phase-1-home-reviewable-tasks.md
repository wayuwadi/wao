# Phase 1：首页可验收任务入口

对应任务：`t1788148628210`（首页“最近 AI 运行”附近增加可验收任务入口）。

## 用户结果

- 首页“最近 AI 运行”标题旁展示“可验收的任务”按钮和当前真实数量，点击后不用逐页翻运行历史即可看到需要人工处理的任务。
- 清单明确分成“需重试”和“待验收”：需重试项先展示最近一次失败摘要，再进入既有运行详情决定是否“基于报错重跑”；待验收项直接打开任务详情核对结果。
- 读取中、读取失败重试、空清单和窄屏状态均保持操作可见，不使用静态示例或前端猜测数据。

## 派生规则

- “待验收”以任务真实状态 `待验证` 为准；即使任务由人工置为待验证且没有 AI Run，也进入清单，但不伪造运行时间和结果。
- “需重试”仅包含尚未完成、且该任务最近一次 AI Run 为 `failed` 的任务。最近一次运行处于排队、领取或执行中时，不继续暴露更早的失败记录。
- 合并 AI Run 按 `ai_task_run_task` 的真实任务关系分别判断；清单只返回当前成员有权查看的项目任务。
- 任务状态 `待验证` 优先于运行失败派生，避免同一任务同时出现在两组；已完成任务不再进入需重试组。

## 验收

- 首页按钮数量与弹层条目一致；同时存在失败和待验证任务时分别出现在“需重试”“待验收”组。
- 点击待验收项打开对应项目的任务详情；点击需重试项先看到真实失败详情与既有“基于报错重跑”按钮。
- 新运行已开始、任务已完成、项目对当前成员不可见三种情况均不会残留为需重试项。
- 前后端单元测试、类型检查和生产构建通过；合并部署后用真实登录账号验证入口、分组与操作链路。
