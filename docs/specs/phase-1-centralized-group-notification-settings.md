# Phase 1：群聊通知统一设置

对应任务：`t1788089101854`。决策见 [ADR-163](../adr/163-centralized-group-notification-policy.md)。

## 用户链路

1. 通知中心和「设置 → 通知设置」都进入独立的 `/notification-settings` 页面；页面集中展示系统群通知、每日沉默时段、
   事件类型、项目静音与当前成员站内偏好。
2. 管理员可关闭全部群通知，或分别控制任务动态、任务/AI 终态、人工任务、群聊提醒、Jenkins 失败与自动触发说明；普通
   成员只读系统策略，仍可编辑自己的站内偏好。
3. 每日沉默时段固定按上海时间（UTC+8）判断，开始时间包含、结束时间不包含，支持跨午夜；命中的群通知直接跳过，
   不在时段结束后集中补发。
4. 飞书私聊提醒、站内记录、飞书原消息表情和群聊桥接的用户消息不属于“群通知”，不被系统总开关误伤。

## 真实门禁

- 任务与 AI 通知继续叠加系统事件类型、项目静音和 Webhook 启用状态。
- 日历群提醒、今日节奏群聊/Webhook 提醒和自动化飞书群提醒统一受 `reminders` 与总开关、沉默时段控制；跳过不伪装成
  已发送。
- WAO 内所有通用 Webhook 业务通知至少经过总开关和沉默时段；“发送测试消息”仍直接验证目标，不受业务门禁影响。
- Jenkins 失败脚本只读取公开接口返回的最终 `allowed` 结论；接口暂不可用时失败开放，避免应用故障导致关键部署告警丢失。

## 验收

- 旧 `notification.policy.v1` JSON 缺少新字段时使用安全默认值，不要求 migration。
- 后端测试覆盖普通与跨午夜沉默窗口、提醒门禁、无权修改和旧配置兼容。
- 前端测试覆盖独立入口、管理员编辑、普通成员只读、沉默时间草稿、失败重试与离开防丢。
- Jenkins shell 测试覆盖允许、策略拒绝和策略接口不可用时的失败开放。
