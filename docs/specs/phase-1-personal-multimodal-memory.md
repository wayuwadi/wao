# Phase 1：按账号隔离的个人多模态记忆

## 用户结果

1. 登录成员从“个人 → 个人记忆”收集文字、图片、音频、视频或普通文件，原件与说明真实持久化。
2. 每条记忆有生活经历、偏好习惯、长期职责、长期规划、确认决策或背景资料分类，并标明人工采集或 AI 采集。
3. 列表、关键词搜索、编辑、删除与附件下载全部按当前成员隔离；知道另一成员的记忆 id 也只能得到 404。
4. 成员自己的 Codex MCP 令牌可以检索同一份个人记忆，并用 `save_memory` 沉淀稳定文字；AI 写入记录明确标为 AI 采集。
5. WAO 页面内 AI 助手把“个人记忆”作为默认可选资料源，并由后端按当前对话成员过滤；组织级自动化不读取个人域。
6. 编辑器覆盖加载中、保存中、成功、失败重试、空数据和本机草稿恢复；窄屏仍可完成上传与编辑。

## 数据与接口

- `personal_memory.member_id` 是强制归属，浏览器请求从会话推导，MCP 请求从设备令牌推导；请求体不能指定。
- `POST /api/memory/entries` 保存人工文字；`POST /api/memory/entries/upload` 保存一份不超过 50MB 的真实原件。
- `GET /api/memory/entries` 只返回当前成员的元数据与正文，不把 BLOB 放进列表响应；附件通过
  `GET /api/memory/entries/{id}/attachment` 单独读取并再次校验成员。
- 附件的媒体类型只用于界面分类，不声称已经完成 OCR、语音转写或视频理解。
- MCP `search_memory` 只查询令牌所属成员的 `personal_memory`，不再把组织知识库、群聊、项目或 Task 当作个人记忆。
- MCP `save_memory` 写入 `personal_memory`，`capture_mode=ai`；人工页面写入为 `manual`。

## 真实能力边界

- 本期是“可追溯资料库 + 关键词检索”，不是模型微调，也不伪造向量召回。
- 图片、音频、视频和文件保存真实原件及人工说明；没有可靠的 OCR、ASR、视觉模型凭据时，不自动生成内容摘要。
- 不导入外部 ChatGPT/Codex 历史：目前没有项目可依赖的官方批量历史接口。值得长期复用的结论由用户明确保存。
- 组织知识库仍可用于协作，但它与个人记忆是两个权限域；个人 AI 上下文不得从组织资料推断个人偏好。

## 验收

- 两个成员各建一条记忆，双方列表和 MCP 搜索只能看到自己的记录。
- 上传图片、音频、视频和普通文件后，数据库保存真实字节，当前成员可下载，另一成员访问相同 id 得到 404。
- 人工文字和 MCP 写入分别显示“人工采集”“AI 采集”；刷新后数据仍在。
- 新建输入中途关闭后再次打开可恢复文字草稿；保存失败不清空表单。
- 没有匹配结果、接口失败和 50MB 超限均提供明确状态与重试/修正入口。
