# Phase 1：自动巡检与文件管理控制

对应任务：`t1787743279583`。

> 此处 50MB 是原需求验收基线。2026-09-30 起普通文件改为 200MB、请求体部署基线改为 1GB，见 [ADR-296](../adr/296-increase-file-upload-limit-and-deployment-baseline.md)。

## 用户结果

1. “请求监控”页面可直接手动启动内置的“HTTP 请求性能夜间 AI 巡检”，按钮覆盖启动中、成功、跳过与失败反馈，实际复用自动化任务的真实 `JobHandler`，不创建演示任务。
2. 自动化任务列表和详情都为该巡检提供设置入口，可配置启停、频率、执行时间、指标窗口、Top N 候选接口、单次最多治理接口数和启动通知群。保存后 Cron 与下次触发时间立即生效；通知群必须来自已启用的真实 Webhook。
3. 自动化“运行记录”默认展示按真实开始时间倒序的最新 10 条，并可前后翻页；旧记录缺少绝对时间时保持既有稳定顺序。
4. 请求监控的“优先关注的接口”和“最近请求明细”在宽屏左右并列、窄屏上下排列，两边独立分页，默认每页 20 条。
5. “文件与图床”提供设置入口，可配置普通文件上限（1–50MB）、用户主动上传图床的单图上限（1–10MB）以及公开下载算术验证码开关。服务端是最终约束，前端同步展示当前上限。
6. 网页托管列表默认展示最新 10 条并可翻页；列表仍只读取元数据，不加载 HTML 或 icon 正文。

## 真实数据与安全边界

- 巡检继续读取“Wa All in One”项目负责人的真实浏览器聚合指标；窗口为空、工作流或公网分享地址不可用时只留下明确运行结果，不创建占位 Task。
- Top N 是写入 AI 任务上下文的最慢接口候选数；“单次最多治理”是一个 AI Run 最多实际改动的接口数，必须小于等于 Top N，避免两个参数语义重复或永远遗漏轮转项。
- 选择启动通知群时，额外向该 Webhook 发送本次指标窗口与治理上限；AI Run 的开始、完成等既有生命周期通知仍遵循系统默认规则。
- 关闭算术验证码只省略答题步骤。公开下载仍必须打开下载页、人工点击、换取 120 秒内有效且用完即废的一次性票据；未登录请求不能恢复为公开直链。
- 文件与图片上限不能超过 Nginx / Spring multipart 与服务端既有 50MB / 10MB 基线。服务端内部抓取并转存的图片继续受 10MB 固定安全上限，不因用户上传设置降低而破坏飞书同步链路。
- 三处分页只切分已由现有接口返回的有界元数据：请求监控最多 50 个接口和 100 条明细，网页托管不加载正文；不复制或伪造分页数据。

## 状态与验收

- 配置弹窗覆盖加载中、加载失败重试、保存中、保存成功和保存失败保留输入。
- 手动巡检按钮在请求未结束时不可重复点击；后端仍通过现有 AI Run 与自动化运行记录提供最终审计。
- 运行记录跨任务按 `runAt` 倒序，时长优先展示服务端 `durationMs`；超过 10 条后第二页可访问。
- 两张请求表各自超过 20 条后出现独立页码，翻动一张不改变另一张；移动端保持横向表格滚动。
- 文件设置保存后，新上传立即由服务端按新上限拒绝或放行；关闭验证码后下载页不显示算术题，但取得的票据仍只能成功消费一次。
- 网页托管超过 10 条后第二页可访问，新增页面回到第一页，删除导致页数减少时自动回到有效页。
