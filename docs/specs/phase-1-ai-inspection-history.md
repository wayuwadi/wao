# Phase 1：AI 巡检历史与运行筛选

对应任务：`t1788138543068`。决策见 [ADR-166](../adr/166-ai-inspection-activity-classification.md)。

## 用户结果

1. HTTP 请求性能巡检历史展示真实总次数、成功、失败、跳过与平均启动耗时；每条记录可点开，查看触发方式、开始时间、
   实测耗时、执行结果及其创建的 AI Run 详情和用量统计。
2. 首页“最近 AI 运行”与“全部运行历史”都增加“AI 巡检”类型，并继续按服务端真实总数分页。
3. 最近运行与完整历史都可以快速筛选全部结果、成功和失败；类型与结果组合后仍由服务端筛选和分页，不在当前页内假过滤。

## 数据与兼容边界

- `ai_task_run.activity_type` 是运行来源的稳定分类：普通任务默认 `FEATURE_DEVELOPMENT`，HTTP 性能巡检创建时明确写入
  `AI_INSPECTION`。聊天复盘继续来自独立的 `chat_review_run`，不复制成 AI Run。
- `automation_run.ai_run_id` 保存巡检触发记录与其创建的真实 AI Run 的关联。未创建 AI Run 的跳过和启动失败记录保持为空，
  详情明确说明原因，不构造运行或统计。
- V118 只从固定任务 `job-http-performance-ai-run` 的既有标准成功结果中回填关联，并据此回填巡检来源；不能确定关联的旧记录
  保持普通开发类型和空关联。
- 结果筛选只接受 `ALL / SUCCEEDED / FAILED`。取消的开发运行只在“全部结果”中保留，不伪装成成功或失败。

## 验收

- 自动或手动巡检创建 AI Run 后，自动化记录持久化其 id；首页“AI 巡检”只返回该分类，且不会在“功能开发”重复出现。
- 巡检历史用真实记录计算总数、成功、失败、跳过和有值耗时的平均值；点击成功记录会读取关联 AI Run，展示终态摘要与已记录用量；
  点击失败或跳过记录仍能查看执行详情，并明确未创建 AI Run。
- 类型与成功/失败任意组合后均回到第一页，请求参数、总数、页码和空状态一致；读取失败保留原筛选并可重试。
