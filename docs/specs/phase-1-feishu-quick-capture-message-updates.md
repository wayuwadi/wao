# Phase 1：飞书快速收集原消息更新与图片

本规格扩展 `phase-1-feishu-personal-quick-capture.md` 与
`phase-1-feishu-personal-quick-capture-polling.md`。决策依据见
`docs/adr/112-feishu-quick-capture-message-updates.md`。

## 用户结果

- 成员第一次在目标群 @ WAO 机器人后，系统仍创建一条真实个人任务。
- 成员随后在飞书客户端编辑这条原消息时，WAO 更新第一次创建的同一条任务，不另建重复任务。
- 编辑同步只覆盖由飞书原消息维护的标题和描述；任务状态、负责人、排期、子任务、评论等在 WAO
  内继续维护的内容不被覆盖。
- 富文本消息中 @ 机器人的图片通过飞书消息资源接口下载并转存 WAO 图床，在任务描述中直接展示；
  不保存飞书访问令牌或临时资源地址。
- 富文本中的文字保持段落顺序并排在图片之前，图片按原有先后顺序集中追加到描述末尾；任务标题只取
  非图片文字，纯图片消息显示「图片待办」，列表预览不暴露 Markdown 路径或「飞书图片」占位文字。
- 图片下载或转存失败时记录真实失败并给原消息错误表情，不能创建一条缺图却声称完整收集的任务；
  后续轮询可重试尚未创建成功的瞬时失败。

## 一致性与边界

- `message_id` 是飞书消息与 WAO 任务的一对一稳定身份；数据库保存最近一次成功同步的原始内容
  SHA-256 指纹，内容不变的回调重推和轮询不写任务。
- Linux / Windows 双节点用数据库条件更新原子认领变化，同一次编辑只由一个节点落库。
- 新消息继续每 15 秒读取近两分钟；另一路每分钟回看近 24 小时的当前消息正文，覆盖飞书客户端的
  实际消息编辑窗口。超过该窗口的历史内容不做无界轮询。
- 只有用户消息、未撤回且仍精确 @ 当前机器人时才进入创建或更新链路。

## 验收

- 单元测试覆盖：同一 `message_id` 内容不变不重复创建、内容改变更新原任务、富文本图片转存并写入
  Markdown、图片前置与纯图片消息的标题和描述、更新时保留其它任务字段、编辑回看仍执行精确 @ 过滤。
- 线上使用真实已绑定成员发送一条带图片的富文本 @ 消息，确认任务内图片可见；随后编辑原消息，
  确认原任务标题和描述变化、任务总数不增加，并核对原消息成功表情。
