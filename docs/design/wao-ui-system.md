# WAO 界面设计系统

版本：1.0 · 2026-10-07 用户确认。适用于浏览器中的 WAO，新开发和修改均以本文件为总入口。

## 已确认的共同语言

轻盈、有秩序、阅读优先。**留白线框为主，浅底分区为辅，阴影集中在浮层。** 蓝紫色用于品牌识别、选中和关键操作；普通页面不使用大面积高饱和底色。四位伙伴用于适当的陪伴场景，不为每个表单新增插画或品牌口号。

保留清楚的文字和空白，避免卡片套卡片、多层背景和同时高亮多个操作。主操作由当前业务决定，不把“新建任务”等全局快捷入口默认做成有底色主按钮。次要编辑操作可以在桌面 hover / focus 时出现，键盘和触屏始终可达。

## 基础样式

倒数日使用自适应日期卡片，样式为简洁/浅底/彩色边框，颜色复用人生领域 token，不默认创建示例数据。习惯页采用清单与月历详情两栏，1000px 以下纵向叠放；打卡同时使用文字/勾选表达状态，不能只靠颜色。表单复用 SettingsDialogShell/WaoField，明确草稿、并发冲突、可恢复删除与个人提醒。设计参考复用 DateCounterCard 的静态示例，业务行为见 [倒数日与习惯打卡](../specs/countdowns-habits.md)。

番茄专注使用两栏：左侧计时和任务关联，右侧专注笔记与统计，下方为私有历史；页面实际内容区不超过 800px 时顺序叠放，随导航侧栏和悬浮窗口空间自动重排。准备阶段表盘收至 240px，减少开始按钮前的留白；计时中保留大表盘。`FocusDial` 复用主题 token，数字使用等宽计数，不以颜色区分暂停和错误。设计参考仅展示静态计时，真实行为见 [番茄专注规范](../specs/pomodoro-focus.md)。

待办工作台的「所有」、日期、标签和已完成入口只汇总当前用户负责的任务；未指派的内嵌子项沿父链归属，显式指派给他人的子项不混入，无负责人主任务按创建者归属。移除「指派给我」，旧已保存入口回到个人所有。显式项目清单仍展示后端授权的共享任务；清单与四象限保持同一范围，不改变项目权限。标签编辑使用紧凑浮层和可切换选中项，不挤动正文。

- 品牌色由 `brandIdentity.json` 提供。操作色用 `--wao-primary`，强调文字用 `--wao-primary-text`，选中浅底用 `--wao-primary-soft`。不要把品牌色、操作色混为一个硬编码值。
- 页面、卡片、辅助分区分别用 `--wao-bg-page`、`--wao-bg-card`、`--wao-bg-sub`。内容线用 `--wao-line`，控件线用 `--wao-line-control`；默认 1px 细线。
- 正文用 `--wao-text`，说明用 `--wao-text-3`。弱色仅用于非关键元信息，不用于正文、错误或必须阅读的说明。成功、待处理、失败使用各自语义色对，同时保留文字和图标，不只靠颜色。
- 默认内容卡片圆角 `--wao-radius-card`（12px），控件 `--wao-radius-control`（8px），弹窗 `--wao-radius-modal`（16px）。胶囊只用于标签等已有用途。
- 常用间距 `--wao-space-1/2/3/4`（8/16/24/32px）。页面标题 `--wao-font-title` 22px（手机 20px）、小节 `--wao-font-section` 18px、卡片标题 `--wao-font-card-title` 16px、正文 `--wao-font-body` 14px、说明 `--wao-font-help` 13px、元信息 `--wao-font-caption` 12px。标题字重 600、行高 1.4，正文行高 1.7；窄屏重排而不缩小正文和说明。
- 阅读正文使用 `--wao-font-reading` 16px；富文本 h1/h2/h3/h4 分别按正文的 1.5/1.25/1.125/1 倍缩放，编辑和预览复用同一规则，正文变大时小节不能变得比正文小。代码继续使用等宽字体，计时与统计数字使用等宽数字，统计单位使用说明字号。
- 内容卡片默认无阴影。浅底分区不同时叠加强阴影；菜单和弹窗使用 `--wao-shadow-pop`、`--wao-shadow-modal`。
- 传送到 body 的右键菜单显式使用正文基线：`--wao-font`、14px（`--wao-font-body`）、1.5 行高和 400 字重，不能继承浏览器默认 16px；辅助标题使用说明字号。
- 图标沿用 Remix Icon 的线性图标，通常 16–20px；图标按钮有明确可访问名称，图标不能替代保存失败等状态文字。
- 页面宽度按内容选择，设置普通内容上限 1000px，管理表格可保留 1420px；小记、编辑器与沉浸场景保留已批准的布局。不要强制所有页面相同宽度。

## 组件与布局规则

- `WaoCard` 的默认线框用于独立内容，`soft` 用于弱说明。不要为了“有设计感”给所有区域增加卡片。可点击整卡只能使用语义链接或按钮，不让普通 div 冒充操作。
- `WaoButton` 使用 primary / secondary / ghost / danger。一个当前操作区域通常只有一个主操作；危险操作有明确动词。加载时阻止重复提交，禁用说明由业务页面提供。
- `WaoField` 提供标签、说明、错误与关联关系，业务仍负责校验和草稿。输入不能只靠 placeholder 命名；错误在原字段位置显示，输入仍保留。
- 弹窗复用 `SettingsDialogShell`，复杂设置复用 `AiSettingsLayout` 等已确认组件。短确认约 420–480px，普通表单约 640–760px，复杂设置约 1000px / 最高 760px。按内容决定高度，不为短表单制造大片空白。
- 确认弹窗保持两个明确选择；普通表单保持焦点、Esc、关闭后焦点恢复、固定保存栏。关闭是否保存由原业务决定。320 / 390px 下弹窗全屏，分项导航换行或可浏览，正文独立滚动，底栏始终可达。
- 浮层首次渲染到位，不先出现在错误位置再跳动。长标题、长选项、大量标签都要有明确浏览方式。

## 必须覆盖的状态与体验

可编辑功能逐项覆盖：读取中、读取失败、空数据、草稿、保存中、已保存、失败重试、跨设备冲突。读取失败不能假装空数据；服务端和定时同步不得覆盖未落库输入。成员切换隔离草稿，冲突不静默覆盖。设计参考只演示这些状态，不把演示保存称为账号保存。

同时检查浅色 / 深色、320 / 390px 与桌面、长文本、键盘顺序与焦点、触屏操作、减少动画偏好。触屏控件尽量至少 44px 点击区域；输入字号避免手机自动放大。动画不得阻碍阅读和主要操作。

## Agent 与开发者执行约束

1. 修改界面前读取本文件和对应专门规范，定位已有 tokens / 组件；提交说明写明复用了什么。设计已确认时直接实现，不重新发明组件风格。
2. 新增和修改的通用界面不得增加硬编码颜色、圆角或阴影；优先复用变量和公共组件。新增语义值放到 tokens，并维护两种主题与设计参考。
3. 特殊图表、第三方画布、品牌插画等确需字面值时，先记录 `wao-web/scripts/ui-style-exceptions.json` 中的具体文件、规则、声明及理由；例外不是通用界面免检。旧页面问题不自动批准为新标准。
4. 执行 `npm run ui:check -- --base origin/main`、相称测试、类型检查及构建，并浏览器对比已批准的方向。样式检查只能发现字面值漂移，不代替视觉和用户链路验收。
5. 同一需求修改组件或规则时，同步规范、参考和必要测试；新规范修改须有确认依据。产品界面不展示内部开发清单或工程术语。
