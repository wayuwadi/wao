# WAO 本地开发与批量发布

一个需求一个 PR；多个 PR 共用发布批次。按 ADR-202，代码任务必须走到 PR 合并、发布上线与真实链路验收，不能以“发布待确认”作为正常结束条件。

## 开发线程

1. 读取当前项目 AGENTS、相关规格和 ADR。遵循当前用户授权；分享本 Skill 不向其他项目授予自动合并或生产部署权限。
2. 核对已有改动归属，基于最新 main 的功能分支开发；并行工作使用独立工作区，避免切换别人的分支或停止其服务。
3. 完成相称本地测试，优先在本机验证真实用户链路。数据库、登录与环境按用户指定；WAO 默认复用既有服务器数据库，不自建数据库，不输出凭据。本地连接受阻时记录证据与未验证项，继续已授权的合并发布，在可用真实环境补齐页面操作验收；编译或接口 200 不能代替最终验收。
4. 按一个需求或一个分享任务一个 PR 交付；合并前检查普通冲突及 ADR / Flyway 编号冲突。已有自动合并授权时直接提交、推送、创建和合并 PR，PR 没有 Jenkins checks 是预期行为。
5. 跟进相关 SHA 被成功批次覆盖，并验证线上版本、健康与真实用户链路。交付 PR 链接、合并 SHA、构建链接和验收结果。已有协调者时明确登记并确认接手；没有明确接手者时由当前任务负责。等待中可继续其他已授权工作，但不能把“已合并、发布待确认”当作已完成，不另建逐 PR 监控。

提交使用中文 Conventional Commit，功能 scope 使用项目路由或功能地图的稳定 id，正文包含“改动：”“原因：”“验收：”。平台与部署 scope 不冒充功能加分。

## 唯一发布协调者

- 以 Jenkins 控制器和 job 的组合为键。先查询已有协调任务、自动化或用户指定负责人，复用而非复制。协调者明确领取所有待发布 SHA；其他线程不竞争创建协调任务。
- 跨机器若无法确认共享负责人或去重记录，不能声称已实现全局互斥；当前任务继续跟进现有批次。不要创建 GitHub issue、聊天消息或新线程来冒充协调设施，除非用户授权。
- WAO 已有 300 秒静默窗口、禁止并发且不中断旧构建、最多一个同参数待执行批次。保留这些行为，不手动按功能重复 Build，不靠反复取消重启凑批。
- 运行批次检出 SHA 已固定，新合并若不被它覆盖，则进入下一批。排队批次尚未检出，不能提前声称已经包含某 SHA；启动后以实际检出提交的祖先关系核对。
- 只使用已授权的 Jenkins API、连接器、CLI 或已登录页面读取历史和队列，不绕过访问控制、不将会话或令牌放入 Skill。

## 安排检查时间

读取历史时只保留构建号、结果、开始时间、耗时、是否真实生产部署、检出 SHA；读取队列的可执行时间和当前构建开始时间。保留时间单位与时区。

- 取最近 5–10 次**已确认成功的生产部署**总耗时中位数 D，排除失败、中止、运行中及纯文档/仅测试构建；不是将并行阶段时间相加。样本不足时说明数量和不确定性。
- 余量 B = max(2 分钟, D × 20%)；当前运行预计剩余 R = max(0, D − 已运行时间)。静默窗口剩余 Q 取 Jenkins 实际值，不默认每次又加五分钟。
- 本次 SHA 已被运行批次检出：下一次检查安排在现在 + R + B。
- 本次 SHA 需下一排队批次：安排在现在 + max(R, Q) + D + B；如果 Jenkins 实际另有阻塞，以其队列原因修正。静默期通常与当前构建并行，不将 R 和 Q 简单相加。
- 空闲且已经排队：安排在现在 + Q + D + B。空闲且无队列：一次核对 webhook / 提交状态，不自行连点 Build；确认漏触发且授权允许后才由协调者补一次。
- 无可靠历史：明确“预计时间未知”，暂定 15 分钟后检查，不把截图平均值或失败耗时包装成成功构建样本。

示例仅用于推演：成功耗时 10、11、12、12、14 分钟，D=12，B=2.4；当前已运行 8 分钟、静默期剩余 3 分钟。已被运行批次覆盖的提交约 6.4 分钟后检查；新提交约 18.4 分钟后检查。两个新 PR 共用同一次检查。

## 非阻塞回访与收口

- 有调度工具且用户已要求自动跟进时，实际创建或更新**该 job 唯一一个**回访任务，登记协调者、待发布 SHA、估时依据与下一检查时刻；创建前检查现有任务去重。不要给每个开发线程创建 heartbeat。
- 调度器只支持固定周期时，取不早于预计时刻的下一次调度，并在提示中写明时间门槛；门槛前不查 Jenkins。未来加入的提交更新同一个任务，不能覆盖丢失旧 SHA。
- 未到检查时刻可继续其他已授权工作；不承诺工具没有安排的后台等待。需要跨回合跟进时必须实际安排唯一回访任务并保留未完成状态；没有后台调度能力或明确接手者时，当前任务继续跟进，不把等待移交给用户作为默认收口。
- 到时读取一次状态；仍运行则仅由协调者按 5 分钟、10 分钟、最多 15 分钟退避再检查。连续两次超预期则检查一次卡住阶段，报告原因或证据缺口，交还用户，不无限监控或自动重跑。
- 旧批次失败但新批次已排队，不重复修复、重跑或为每个 PR 报一次失败。确认最终相关批次失败且没有后继批次时，汇总影响 SHA 和失败阶段，只通知一次；修复须走对应授权和独立 PR。
- 成功以实际部署 SHA 覆盖待发布 SHA、Jenkins / 提交状态终态和线上版本及健康证据为准。将一次批次结果关联回所有覆盖的 PR。待发布集合清空后暂停该回访任务，下一批复用；失败交还后也暂停，避免空转。

正常交付须确认“PR 已合并、相关版本已上线、真实链路已验收”，并给出证据。等待和环境问题只报告过程状态；真实失败或确需用户输入时说明具体阻塞，不冒充完成。无变化不发重复状态通知，完成、失败或需用户处理时合并通知一次。
