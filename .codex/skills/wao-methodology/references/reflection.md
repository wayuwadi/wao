# 复盘与方法论维护

## 区分三种沉淀

- 规格/ADR：系统应该如何工作，以及为什么这样决定。
- 项目记忆：这个项目已验证的约定、陷阱、操作和验收经验。
- 方法论 Skill：遇到一类问题时如何分析、行动和验证。

不要把个人记忆、临时聊天或一次偶然成功直接提升为通用方法。

## 候选门槛

方法论候选至少包含：

1. 适用问题和不适用边界。
2. 原方法造成的具体失败或成本。
3. 新做法的步骤和停止条件。
4. 反例、风险与回退方式。
5. PR、提交、部署、线上验收或可重复实验等证据。

只在结果已由真实链路证实时创建候选。没有证据的想法保留为建议，不写成强制规则。

## 版本流程

候选先评审和去重，再修改 Skill 草稿并运行固定案例；通过后发布新的不可变版本。项目显式选择升级，不让“最新版”静默改变运行行为。

删除过时方法时说明替代方案和迁移影响。Skill 保持短入口，细节放按需参考；同一规则不要同时复制到 `AGENTS.md`、Skill 和多个参考文件，权威来源只保留一处并从其他位置链接。
