# 可逆交付与验证

## 改动前

- 确认授权范围、当前分支/环境和工作区已有改动的归属。
- 阅读与接口、数据、部署或体验相关的规格和 ADR。
- 定义失败收口；涉及数据删除、覆盖、生产写入或外部消息时先解析精确目标。
- 接口、数据结构或部署行为变化时同步文档；已执行 migration 只能新增，不能修改。

## 实现中

- 先修根因，再处理同范围的低代价完整性问题。
- 固定流程优先写成确定性代码或脚本；模型负责需要语义判断的部分。
- 对外部操作使用幂等键、条件更新或可重试协议，避免超时后重复副作用。
- 保留加载、失败、空状态和恢复路径；后台轮询不能覆盖本地草稿。

## 验收

按风险从内到外验证：

1. 针对核心逻辑的测试或静态检查。
2. 受影响模块的构建与回归。
3. 真实用户操作链路，包括失败和恢复。
4. WAO 默认由用户负责发布后的线上验收；AI 不重复检查部署终态、线上结果和通知回执，除非用户另行要求。

记录实际执行的命令、关键结果和未执行项的原因。失败日志保留相关步骤和完整根因，不用“应该没问题”代替证据。

## 交付

提交和 PR 描述解释改动、原因与验收。WAO 代码任务按 ADR-232 在本地连接既有线上数据库完成相称测试和真实链路验收，提交、推送并合并 PR 后即交付。默认不等待或监控发布、不创建回访、不进行线上二次验收，由用户负责上线后的体验验收。本地受阻时报告缺项，不自动改为线上补验；不得将“已合并”表述为“已上线”。用户另行要求发布跟进或线上排查时，再按对应流程处理。
